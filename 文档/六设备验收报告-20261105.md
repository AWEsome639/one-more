## 二、为什么「内容哈希」而不是 `md5`

`md5` 取的是**整份 dump 的字节**，而状态栏的时钟（`01:06` → `01:07`）每跳一分钟就让它变
⇒ **「md5 变了」既可能是切了页，也可能只是时钟走了一格**。

实证（第 1274 轮，800×1280）：依次点「游戏 / 统计 / 设置」四次的 dump **md5 各不相同**，
但**内容哈希完全相同**（`609d048cc1c2`）⇒ 页签一次都没切成。

`工具/content_hash.py` 的做法：
```
只取所有 text ⇒ 剔除「时间 / 电量」（^\d{1,2}$ / ^:$ / ^\d{1,2}, :, \d{1,2}$ / 100 / 0）
⇒ 排序 ⇒ 哈希
```
⇒ 页面不变则哈希不变，与时钟无关。

   日志：`InputTracking id:2145, eventManager **receive DOWN event twice**`
② 装包后**永久锁屏**：`aa start` 持续报 `10106102`，`dumpLayout` **恒为 0 字节**

**判定：环境阻塞，不是 App 缺陷。**
依据：**同一份 App 在另外 5 台上三页签全通过**（判据 746）。

## 五、本轮修掉的真 bug

### 1. 233×233：统计页标题逐字竖排（18 px 宽 × 246 px 高）
```
根因：`LevelHeader` 的 Row 里 `StreakFlame` 抢走 75 vp ⇒ 标题列只剩 6 vp
修法：极小屏把火焰挪到第二行
验证：`新手上路` **18×246 → 243×63**（高/宽 13.7 → 0.26）
```

### 2. 195×195：标题被截断成「新手」两个字
```
根因：**双重 padding**（StatsTab 的 Column 20 vp + LevelHeader 自己的 20 vp）
     ⇒ 585 px 屏幕只剩 345 px；徽章 168 + margin 48 ⇒ 标题 129 px = 2 个字
排除：竖排也不行（徽章 168 + 标题 63 + 副标题 30 = 261 px > 卡片高 192 px）
修法：按屏高分三档
  · `Bp.tinyWatch()`（高 < 210 ⇒ 195）⇒ 徽章 40 vp + 标题 sm
  · `isWatch() || tinyScreen()`（233 等）⇒ 徽章 56 + 标题 lg
  · 其余 ⇒ 原样横排
验证：`新手上路` **129 px → 207 px**（需要 168 px）✅
```
