# One More `2.0.0` 云测试计划

> 用包：`release/onemore-2.0.0-release-signed-20261120-0933.hap`（release 签名，`29.5 MB`）
> 目的：**用云测试补上「换一台设备也成立」这一档证据**（本机模拟器已不可用，见判据 `3070`）

## 一、为什么必须云测（三条已知风险，每条都指向具体机型形态）

| # | 风险 | 依据 | 需要什么形态 |
|---|---|---|---|
| 1 | **横屏（矮屏 `height < 690`）** | 昨天修了 `9` 款横屏/竖屏缺陷，全部只在**一台** `2560×1600` 模拟器上验过 | 横屏手机/平板 |
| 2 | **电视文字相对小** | `Cell.of` 乘 `Bp.scale()×1.45`，而 `FontSize/Space/Radius` **完全不放大** ⇒ 文字相对小 `31%`（算出来的，判据 `3068` 前身分析） | TV |
| 3 | **`T` 形/折叠形态** | 竖屏验的是 `2224×2496`（`741×832vp`）；折叠屏展开/合上是两种尺寸 | 折叠屏 |

## 二、测试矩阵（按优先级）

### P0 —— 必须覆盖（直接对应已验证/未验证的风险）

| # | 形态 | 关注点 | 怎么判 |
|---|---|---|---|
| 1 | **手机 · 竖屏** | 主力形态：任意 `12` 款游戏能否正常进入、控件不被切 | 截图人工看 |
| 2 | **手机 · 横屏**（`height < 690`） | **昨天修的 `9` 款**：`Simon Command` / `Shadow Pivot` / `Simon Says` / `Memory` / `Crossword` / `Collatz` / `Kakuro` / `Word Mastermind` / `Silhouette Match Ortho` | 这 `9` 款各自截图：按钮/格子/选项是否**完整可见** |

## 三、每台设备要看的四件事（照判据 `2605` 的教训）

1. **关键区域渲染了内容吗**（不是黑屏/空白）
2. **有没有重叠**（`blk=0` 也可能重叠 —— `Memory` 第一次就是这样）
3. **有没有元素消失**（`Memory` 第二次：按钮被挤出裁剪区）
4. **底部 `24px` 是「贴线」还是「被切」**

⇒ 光看「有没有报错」不够 —— 首页能开、游戏能进，也可能整块内容在屏外。

## 四、特别提醒：三类「看起来正常其实坏了」的情况

| 情况 | 为什么会被漏掉 | 怎么办 |
|---|---|---|
| **只显示一半内容** | 没有崩溃、没有报错 | **数控件个数**：`Simon Command`/`Simon Says` 应该各有 `4` 块按钮，只看到 `2` 块就是坏的 |
| **按钮被压扁** | 按钮还在、只是矮了 | 量按钮高度：`Kakuro` 的「重开一题」应约 `132px`，`43px` 就是被压 |
| **文字被切** | 首字还在、后半截没了 | 看完整句子：「`西蒙说 点「绿」`」不能只剩「`西蒙说`」 |

## 六、已知不需要测的

- **不联网**：`INTERNET` 只用于局域网对战；**飞行模式下 `355` 款全能玩**（隐私声明承诺过）。云测试如果只能联外网，这条验不到，但也不影响。
- **端侧 AI 的 RAG**：本模拟器上 `knowledgeProcessor`/`retrieval`/`rag` 运行时全是 `undefined`（判据 `3062`）。**如果某台真机上它们存在，可以顺带验证**（命令：
  `hdc shell "aa start -b com.andrewoscar.onemore -a EntryAbility --ps ragTest true"`，
  然后 `hilog -x | grep RAGTEST`，期望看到 `STEP processor ok` 与 `RESULT PASS`）。
