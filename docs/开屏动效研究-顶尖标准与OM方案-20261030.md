# 世界顶尖 App 开屏动画：拆解 + 可直接落地的 OM 方案

> 研究日期 2026-10-30。全部规律附来源。ArkUI 结论基于官方文档原文 + 对 `Splash.ets`（666 行）的只读核对。

## 一、12 个具体案例 → 顶尖 = 什么

| # | 谁 | 它做了什么 | 可复用的一条规律 |
|---|---|---|---|
| 1 | **Apple TV**（2025 品牌片头） | 用玻璃做巨大 logo，多角度彩色灯光打上去，薄片一层层如书页翻落，最终堆叠成幻彩苹果。全部实拍，无 CGI | **主角不动，光在动。** 官方解说：「运动不来自 logo，而来自摄影机在玻璃前滑行」[来源](https://www.wowlavie.com/article/250026536) |
| 2 | **Apple Music**（2026 新标） | 玻璃槽底刻 logo → 注入矿物油 → 换能器按音符振动 → 实拍涟漪。选矿物油就为黏度像「被声音推皱的玻璃」 | **因果必须真实可解释。** 涟漪由声音引起，不是随机漂移 [来源](https://fastcompanyme.com/co-design/the-new-handmade-apple-music-logo-leans-into-the-science-of-sound/) |
| 3 | **Google Drive** | 先出现**空心**六边形轮廓，等开屏铺满全屏后，六种颜色才从边缘滑入填充 | **轮廓先行、填充后至**——两拍，不是一次淡入 [来源](https://9to5google.com/2022/12/04/android-12-animated-splash-screen/) |
| 4 | **Google Docs / Sheets / Slides / Duo** | 从屏幕**中心**向外扩张；纸的右上折角是在扩张途中才折出来的 | **几何变化放在运动途中**，不要一开始就长完整 |
| 5 | **Google Maps** | 先是一个五色分区的圆环，颜色滑到正确对角位置后，pin 的轮廓才成形 | **先给材料，再给形体**：色块就位 → 形状诞生 |
| 6 | **YouTube** | 空心播放键；两个三角从左滑入，大三角淡红作底、白三角作符号；饱和度一路涨到整体填满 | **同一形体的零件用不同延迟 + 不同透明度分层到位** |
| 7 | **Gmail** | inbox 恰好在「M」**填满前**加载完成并接管 | **动效终点 = 内容就绪点**，不是写死 3 秒 |
| 8 | **Google Calendar** | 边框从四周**向内**填满，同时数字「31」**向外**扩张 | **一内一外同时发生**，画面才有张力；单向运动=平 |
| 9 | **Lando**（Awwwards SOTD） | 品牌物件组装 → 椭圆 wipe 交棒（0.8–1.2s）→ 幕布卸载，加载节点不留任何痕迹 | **交接用 wipe / 相机运动，绝不用硬切** [来源](https://cdn.jsdelivr.net/gh/coroboros/agent-skills@6.2.2/skills/award-design/references/immersive-cinematic.md) |
| 10 | **Siena**（Awwwards SOTD） | 纯黑 + 超大复古衬线「SIENA」+ 一个票根「ENTER →」。就这些 | **顶级的克制 = 一个舞台 + 一个动作**（反例：12 层同时动） |
| 11 | **Lusion**（Awwwards SOTY） | 干脆不做 loader，`none/instant`，直接滚动提示 | **内容已就绪时，不做开屏才是最高级** |
| 12 | **Alto's Odyssey** | 黎明地平线，太阳极缓慢升起，热气球点缀 | **用「一件正在发生的事」代替「一堆在动的装饰」** [来源](https://www.theodysseyonline.com/meditation-in-motion-with-altos-odyssey) |

### 陪审团口径（把「顶尖」量化掉）

- Awwwards 评分：**Design 40% + Usability 30% + Creativity 20% + Content 10%**。也就是说 70% 的分不在「炫」。评委原话：**「Random effects — 没有层级的运动，什么都在飘、都在视差、都在 reveal，于是什么都不重要。这是创意站拿不到高分最常见的原因。」** [来源](https://www.hontran.dev/blog/how-to-win-an-awwwards-site-of-the-day)
- 「两秒的品牌 reveal 是手艺；六秒的进度条是套了戏服的可用性扣分项。」
- Android 12 动态图标开屏：官方**推荐 1000ms**（允许更长）[来源](https://9to5google.com/2022/12/04/android-12-animated-splash-screen/)
- 平台规范（这是最反直觉的一条）：**Apple HIG 明确说开屏「不是艺术表达的机会」「不是品牌机会」，要求 launch screen 几乎等于首屏**，避免闪烁 [来源](https://developer.apple.com/design/human-interface-guidelines/launching)。
  → 但**游戏是例外**：Apple 自己的游戏设计课讲「把首个屏幕设计得符合你游戏的样式，用户会立即沉浸」[来源](https://developer.apple.com/videos/play/wwdc2017/811/)。
  → 结论：**OM 可以做品牌开屏，但必须把「接进首屏」当成开屏的一部分来设计**，否则永远差一口气。

## 二、可量化的标准（时间 × 缓动 × 层级）

### 2.1 时长 token（Material 3，可直接抄）

| token | ms | 用途 |
|---|---|---|
| short3 | 150 | 元素**离场**（最小） |
| short4 | 200 | standard 离场 |
| medium1 | 250 | standard 入场 |
| medium2 | 300 | 屏内移动（起止都在屏上） |
| medium3 | 350 | 强调型构件过渡 |
| long1 | 450 | emphasized 入场 |
| long2 | 500 | emphasized 起止都在屏上 |

[来源](https://pub.dev/documentation/material_design/latest/material_design/M3Motion.html)

### 2.2 曲线库（先分清能不能用）

**能直接用 `curves.cubicBezierCurve()` 的（y 值都在 0–1）**

| 名称 | 参数 | 什么时候用 |
|---|---|---|
| standard / emphasized | `0.2, 0, 0, 1` | 屏内移动、主转场 |
| standard decelerate | `0, 0, 0, 1` | **入场**（最快的减速） |
| standard accelerate | `0.3, 0, 1, 1` | **离场** |
| emphasized decelerate | `0.05, 0.7, 0.1, 1` | **主角入场**（前 20% 走完 80% 距离） |
| emphasized accelerate | `0.3, 0, 0.8, 0.15` | 主角离场 |

[来源](https://www.toolbox365.net/tutorials/easing-curves-m3-ios/)

**不能直接用 `cubicBezierCurve()` 的（y 越界会被夹断）**

| 想抄的曲线 | 值 | 为什么不行 |
|---|---|---|
| M3 Expressive fast spatial | `0.42, 1.67, 0.21, 0.90` | y1=1.67 → 被夹成 1.0，**过冲消失** |
| M3 Expressive default spatial | `0.38, 1.21, 0.22, 1.00` | 同上 |
| iOS 轻弹 | `0.5, 1.5, 0.5, -0.3` | y2<0 被夹成 0 |

**关键发现**：官方文档写明 `cubicBezierCurve(x1,y1,x2,y2)`「确保曲线的值在 0 到 1 之间」，越界按 0/1 处理 [来源](https://gitee.com/openharmony/docs/raw/master/zh-cn/application-dev/reference/apis-arkui/js-apis-curve.md)。
⇒ **过冲 / 预备动作在 ArkUI 里只有两条路**：

1. `curves.springMotion(response, dampingFraction)` —— `dampingFraction < 1` 才会过冲。注意 **duration 对它不生效**，时长由物理决定（要确定性时间表的场景别用它做主干）。
2. **字符串形式的 `cubic-bezier(...)`** —— 同一份 `animateTo` 文档里，字符串形式只约束 **x1、x2 必须在 0–1**，**没约束 y**。所以 `curve: "cubic-bezier(0.42, 1.67, 0.21, 0.90)"` **可能**真的能过冲。
   ⚠️ **需真机确认**：如果成立，这是本次研究最高性价比的一条；如果不成立，退回 springMotion。
   [来源](https://gitee.com/openharmony/docs/raw/master/zh-cn/application-dev/reference/apis-arkui/arkui-ts/ts-explicit-animation.md)

**Already 就在你手里的东西**：`springMotion` 默认参数 `(0.55, 0.825)`，**正好等于 Apple 的 snappy 档**（Apple `spring()` 默认 `response 0.5 / dampingFraction 0.825`；iOS 17 起 `Animation.default` 是 `0.55 / 1.0` 临界阻尼）。[来源](https://developer.apple.com/documentation/swiftui/animation/spring(response:dampingfraction:blendduration:))

### 2.3 过冲纪律（最重要的一条）

M3 Expressive 把动画拆成 **Spatial（位置/尺寸/缩放）** 与 **Effects（透明度/颜色/阴影）** 两个域：

| 速度 | Spatial-standard | Spatial-expressive | **Effects（两套都一样）** |
|---|---|---|---|
| Fast | 0.9 / 1400 | 0.6 / 800 | **1.0 / 3800** |
| Slow | 0.9 / 300 | 0.8 / 200 | **1.0 / 800** |

读法：**Spatial 可以过冲；Effects 永远临界阻尼（dampingRatio = 1.0）且更硬。** 原文理由一句话：**「弹跳的 alpha 看起来是坏的（透明度会冲到负数或超过 1）；补间的位移看起来是机器人。」** [来源](https://github.com/athevon/genjutsu/blob/1f518a71378b15d423389e546e767cffc86e14c3/skills/_jutsu/compose-graphics/references/m3-expressive-deep.md)

⇒ **OM 的落地铁律：位移/缩放给过冲，透明度/颜色绝不给过冲。**

### 2.4 编排（比曲线更决定「贵不贵」）

- **入场是编排，离场是统一的。** 原话「Enter is choreography. Exit is uniform.」→ 离场**不要**逐项错开。
- **逐项错开 50ms/项。**
- **层级顺序**：形状领先 → 颜色/阴影立刻跟上 → 内容延后 100ms。
- **离场比入场快 20–30%**（Material 与 Apple 都这样）。
- 按压反馈地板值 **90–160ms**。

[来源：编排](https://github.com/athevon/genjutsu/blob/1f518a71378b15d423389e546e767cffc86e14c3/skills/_jutsu/compose-graphics/references/m3-expressive-deep.md)｜[来源：离场快 20–30%](https://www.toolbox365.net/tutorials/easing-curves-m3-ios/)

### 2.5 总预算

| 口径 | 数值 |
|---|---|
| Android 官方推荐 | 1000ms |
| Apple HIG | 「尽快」，不许人为加延时 |
| 评委口径 | 2000ms 以内的品牌 reveal 是手艺 |
| 体验研究 | 首印象 50ms 内形成；有意义的运动最多把**感知等待缩短 15%** |

[来源](https://www.uxpin.com/studio/blog/splash-screen/)

⇒ **OM 的完整版应落在 1200–1400ms，二次启动 600–700ms。当前 3120ms 是预算的 2.4 倍。**

## 三、针对「OM」标志的 10 个具体动效建议

前置事实（从代码读出来的）：现在 OM **是一张 `Image` 位图**（`$r('app.media.splash_om')`），只吃 opacity / blur / translate。**位图不可能有「世界顶尖」的动效**——这是根问题，不是美感问题。

### ① 把 OM 拆成 3 个可独立驱动的图元（其余 9 条的前提）
- **O 环**：`Circle().width(d).height(d).fill(Color.Transparent).stroke('#C99E52').strokeWidth(9)`
- **O 心点**：`Circle().width(d*0.26).fill('#E8C87A')`
- **M 山**：`Polygon().width(w).height(h).points([[0,h],[w*0.30,0],[w*0.60,h*0.62],[w*0.90,0],[w,h]]).fill('#FAF8F3')`
- 顺序：点 → M → 环（`Stack` 子节点顺序 = 层序）。**用 M 的实心米白去遮挡金点**，就得到「日出」。
- 为什么：只要拆开，`.translate / .scale / .opacity / .rotate` 全是已验证可靠的属性，不需要 `Shape/Path` 的 viewPort。

### ② 日出：金点从 M 山脊后升起
- `translate({ y: 46 → 0 })` + `opacity({ 0 → 1 })`，**420ms**
- 曲线：`curves.springMotion(0.34, 0.68)`（欠阻尼，末段轻微越过 0 再回落 ~2vp）
- 为什么：M 是山、O 心是太阳——这是这套品牌唯一自带叙事的一对元素。**一个动作讲完整个标志**，符合「一个可被说出口的瞬间」。

### ③ 环从 12 点方向画出来（真正的描边生长）
- `Circle().strokeDashArray([len, len]).strokeDashOffset(len → 0)`，`len = π*d`
- **620ms**，曲线 `curves.cubicBezierCurve(0.05, 0.7, 0.1, 1)`（emphasized decelerate）
- 为什么：这是 Google Drive/Docs 的「轮廓先行」手法。当前代码里的「描边生长」其实不存在——它只是让位图在 ~74ms 内从透明变不透明。
- ⚠️ 需真机确认：`strokeDashOffset` 能否被 `animateTo` 插值（数组属性动画）。

### ④ 环闭合那一下：整体回弹
- 环到 0° 的同一帧，`scale({ 1.05 → 1.0 })`，**260ms**，`springMotion(0.34, 0.62)`
- 为什么：Disney 的 follow-through。没有这一下，环画完就是「停住」，像 PPT。**这是最便宜的一次「贵」**。

### ⑤ M 山形两级折角先后到位
- 外峰（[0,h]→[w*0.30,0]）先，内谷（[w*0.60,h*0.62]）晚 **70ms**，各自在 `clip` 内 `translate({ y: 14 → 0 })`，各 **420ms**，`cubicBezierCurve(0.05,0.7,0.1,1)`
- 为什么：overlapping action。同一条山脊上有先后，眼睛才读得出「这是一座山」而不是「一个白色形状」。

### ⑥ 金属高光：4 段短弧绕环
- 4 个 `Circle()`，同 d、`stroke('#F0D9A8')`、`strokeWidth(9)`、`strokeDashArray([len*0.055, len])`，四个 `rotate({angle})` 初值 0/90/180/270、透明度 0.85/0.4/0.15/0.4
- 整组 `rotate({ angle: 0 → 90 })`，**520ms**，`Curve.Linear`
- 为什么：金的「贵」来自**会动的高光**，不是金色本身。用 dash 拼弧＝不依赖渐变、不依赖 `clipShape`，全部是已验证属性。扫光**必须 linear**，金属反射本来就是匀速。
- 替代方案（若 dash 不可行动画）：`Column().linearGradient()` + `.clipShape(new CircleShape({width:d,height:d}))`，但会连环心一起提亮，观感差一档。

### ⑦ 金点落位触发一次「顶光过曝」
- 环形 `radialGradient` 光晕：`opacity 0 → 0.9`（**120ms**，`standard decelerate 0,0,0,1`）→ `0.9 → 0.25`（**300ms**，`emphasized decelerate`）
- 为什么：一次瞬间过曝 + 回落 = 摄影机的快门/闪光，是最强的「质感」信号。当前是 600ms 线性渐强，那是「补光」不是「闪光」。
- 注意：**只让 Effects 走两段 tween，不要过冲**（见 2.3）。

### ⑧ 标题不用「逐字 + 模糊」，改「从一条金线后抽出」
- 一根 1vp 高、宽度=标题区宽的 `Column().linearGradient(金→透明)`，**不透明度 0.6**
- 标题 `translate({ y: 18 → 0 })`，**380ms**，`cubicBezierCurve(0.05,0.7,0.1,1)`；金线同步 `opacity 0.6 → 0`，**500ms**
- 为什么：`blur(10)` 逐字入场是「廉价清晰化」的通用套路，且 10vp 模糊+8 个字 = 8 个离屏层。**位移动 + 遮挡条**是 0 成本的「字幕式」入场，更像电影。

### ⑨ 结束不要放大淡出，改成「落下去、接上来」
- logo 组：`scale 1 → 0.94` + `opacity 1 → 0`，**260ms**，`cubicBezierCurve(0.3, 0, 0.8, 0.15)`（emphasized accelerate，离场加速）
- 同时给 `Index` 加 `pageTransition()`：`PageTransitionEnter({ duration: 320, curve: curves.cubicBezierCurve(0.05,0.7,0.1,1) }).slide(SlideEffect.None).opacity(0 → 1)` + `scale(1.03 → 1)`
- 为什么：`router.replaceUrl` 现在是硬切。两页共用 `#0D1320`，**只要背景一致、只有一个 scale 方向的差，读起来就是「内容自己浮现」而不是「换页」**——这正是 Apple HIG 的 continuity 原则，也是 Gmail「M 填满前 inbox 就接管」的手法。
- 当前是 `scale 1 → 1.06` 放大退场，方向反了：放大=推远，观众会觉得「被推开」。

### ⑩ 金点落位那一帧：一次极短的声音 + 触感
- 触感：`Haptics` 已有，在 T+420 触发一次（不是只在 boost）
- 声音：`media.createSoundPool(2, audioRendererInfo)` + `SoundPool.load(fd, offset, length)` 播一个 120ms 的极轻瞬态（低频一击 + 极短金属尾）
  - ⚠️ 坑：`load(uri)` **不支持 rawfile 目录**，必须走 `fd` 重载 [来源](https://gitee.com/openharmony/docs/raw/master/zh-cn/application-dev/reference/apis-media-kit/js-apis-inner-multimedia-soundPool.md)
- 纪律：**一次瞬态，不是一段 jingle**；跟随系统静音；提供关闭开关；只在完整版播
- 为什么：Apple TV / Apple Music 两代品牌片头都是**先有声音、再由声音驱动画面**。声音是「配置拉满」里唯一还空着的一格。

### ⑪（配套）两个版本，别每次都放 3 秒
- 完整版 1380ms：`now - lastOpen > 6h` 或首次安装
- 短版 ~700ms：跳过星云/星尘，logo 从 `scale 0.96 + opacity 0` 起，`480ms` 落位，`220ms` 交接
- 为什么：355 款小游戏的集合会被高频打开。每次冷启动 3.1 秒 = 对熟练用户收税。Apple HIG 与体验研究都明确反对人为延时。

## 四、当前实现缺什么（直说）

### 致命的（决定「丑」）

1. **主角是一张位图。** `Splash.ets:474` `Image($r('app.media.splash_om'))` 只吃 opacity/blur/translate ⇒ 12 层全是背景，**唯一该被看的东西没有动效**。这是「就算是对的也太丑」的根因。
2. **OM 在 ~494ms 就已经完全出现，之后 2.6 秒是死场。** 推算：`pStroke` 用 `settle = cubicBezierCurve(0.22, 1.0, 0.36, 1.0)`，这条曲线在 7% 行程就冲到 0.42（`seg(pStroke,0,0.42)` 的满值点），即 `420 + 980×0.075 ≈ 494ms` 后 logo 已 100% 不透明且 blur=0。
3. **1620ms → 2500ms 有 880ms 纯死场**：logo 已定、只有副标题(1900)与标语(2150)各闪一下。**死场是业余动画的第一特征。**
4. **「L4b 填充点亮」根本不存在。** `pFill` 只被 `Splash.ets:454` 拿去乘光晕强度，logo 自己的任何属性都没读它。注释与实际不符。
5. **三条曲线 y 全 ≤ 1 ⇒ 零过冲、零预备动作、零重量。** `settle` 的 y1=1.0 是「一步到位再爬」的形状，用在 980ms 的「描边生长」上，观感就是一坨糊上来，不是画出来。
6. **一条 `easeOut` 用了 9 次。** 曲线没有层级 = 时间表有层级但质感只有一档。
7. **退出是 `scale 1 → 1.06` + 淡出 + `router.replaceUrl` 硬切。** 方向反了（放大=推开），且是硬切。整个开屏最丑的一帧是最后一帧。
8. **logo 起步 `blur(14)`。** 高端是「清晰 + 有光在动」，不是「从失焦里浮现」。14vp 模糊还是一层 saveLayer。

### 结构性的

9. **12 个 `setTimeout` 做时间表**（180/260/300/420/1180/1380/1500/1900/2150/2500/3120）。冷启动 JS 线程忙时会漂移；无法整体取消；`boost()` 又在同一批 `@State` 上并行 `animateTo` ⇒ 两套写同一状态，竞争。建议整体换 `keyframeAnimateTo`（API 11+，`UIContext` 成员）或单个 `AnimationStatus` 驱动的进度值 + `seg()`（你已经有 `seg()`，很适合）。
10. **星尘 `2600ms` 用 `Curve.Linear` 漂移。** 线性位移是机械感，不是漂浮感。48 颗 + 每颗 `blur(0.4)`。
11. **「胶片颗粒」是 10 个 1.8vp 的点**（`:585-597`）。这不是颗粒，是 10 个白点。真颗粒用一张低分辨率噪声 `Image` 平铺 + `ImageFit.Repeat` + `opacity 0.03` 更省也更像。
12. **颜色 bug**：`:547` `.fontColor('#CC9E52')` 注释写「提到 0xCC（80%）」，但 6 位 hex 是 `#RRGGBB` ⇒ 实际是**全不透明**的 `rgb(204,158,82)`，不是 80% 的金。同文件 `:518` 的 `#B8C99E52`（8 位 alpha）才是对的做法。两者不一致。
13. **死代码**：`:353` 的 `mPath`、`:369` `strokeW`、`:372` `oLen`、`:382` `mLen`、`:342` `omD` 全部无人引用；`:488-496` 的 `Text('OM')` 兜底是 `opacity(0)` × 又乘 `0.0`。
14. **3120ms 的 `HOLD` + 每次冷启动都放。** 见 2.5。

### 需要真机确认的

15. **「Shape/Path/Circle/Polyline 在此页全部不渲染」**（`:468-470` 注释）。这条如果不解决，第三节 ①③④⑤⑥ 全部无法落地，所以我给一个可测假设：
    - 最可能成因：**`opacity(0)` 起步 + `blur()` 同一节点 = saveLayer**，形状层在该合成路径下被裁掉且不重绘。
    - 验证顺序：① 单开一个空白页放 `Circle().width(200).height(200).fill('#C99E52')`（显式宽高、无 blur、无百分比 `position`）；② 若出现 ⇒ 是本页合成问题，把形状层初始 `opacity` 改 `0.001`、去掉同节点 `blur`、把 `position` 改成 `translate`；③ 若仍不出现 ⇒ 是 ArkUI 版本问题，退回「三层 PNG」方案（把环/点/M 各自导出 PNG，仍可独立动画，效果打 8 折但不至于没救）。
    - 另：`Polygon().points()` 必须在组件自身盒内给 vp 坐标且**显式设 width/height**（官方示例即如此），百分比尺寸 + points 是我怀疑的第二个坑 [来源](https://gitee.com/openharmony/docs/raw/master/zh-cn/application-dev/reference/apis-arkui/arkui-ts/ts-drawing-components-polygon.md)。

### 已放弃的（写清楚，免得再试）
- `blendMode(OFFSCREEN)`：吞相邻节点。
- `Shape/Path` + viewPort：按包围盒填充，做不了等宽描边。
