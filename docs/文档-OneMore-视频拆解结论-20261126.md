# One More 视频拆解结论（一页）· 2026-11-26

> 目的：按奥森要求，先给结论与方案，不交成片。
> 证据分两类：**外部公开资料**（附链接）与**我们自己的参考库实测**（`D:\ref-videos` 15 条）。

## 一、爆款共有的 4 个结构特征（外部证据）

1. **前 3 秒是二选一考试，不是开场白**：观众在这 3 秒内决定「继续看/划走」，所以第一帧必须是全片最抓人的**一个具体画面**，不是 logo、不是标题卡、不是黑屏字幕。
   —— [Script2Shorts](https://script2shorts.app/blog/how-to-make-game-trailer)、[Full Charge](https://www.fullcharge.games/post/how-to-make-an-indie-game-trailer-that-actually-gets-clicks)
2. **顺序是「类型 → 钩子 → 内容」，且钩子要尽早**：先让对方 1–2 个镜头认出「这是什么东西」，紧接着立刻抛出「它跟别人不一样的那一点」，不要先铺陈功能清单。
   —— [Derek Lieu（游戏预告剪辑师）](https://www.derek-lieu.com/blog/2022/10/24/how-to-hook-the-audience-and-how-quickly-to-do-it)
3. **无声也要成立**：社媒上大量视频是静音播放，画面本身要能说清「这是什么、有什么好玩」；音乐只负责节拍，不承担信息。
   —— [Script2Shorts](https://script2shorts.app/blog/how-to-make-game-trailer)
4. **时长按渠道收紧**：商店页 45–90 秒，社媒 30–60 秒；超过这个长度转化掉。
   —— 同上；[itch.io 指南](https://itch.io/blog/1030474/creating-a-trailer-that-sells-your-game-a-complete-guide-for-indie-and-aaa-developers)（三幕：Hook 0–10s → 内容 → 收尾）

**AI 生成的补充纪律**（若用 AI 出画面）：一条片只承担**一个任务**；先写「节拍（beats）」再写提示词；**一个镜头只做一件可见的变化**；脚本（说什么）与分镜（看到什么）分开写。
—— [Astorie](https://astorie.ai/how-to/how-to-make-short-ai-videos)、[Soulvid 分镜指南](https://www.soulvid.ai/blog/tutorials/ai-video-storyboard/)、[vidmuse 工作流](https://vidmuse.ai/blog/idea-to-video-workflow)

## 二、我们自己的实测（参考库 15 条，Mac 已拆）

- 九条 90 秒内的参考里，**没有一条用「产品界面截图」开场**；最贴近的 HarmonyOS NEXT 品牌片 60s/11 个镜头，2.5 秒才出 logo，全程没有 App 界面——靠氛围与标志。
- 《追逐末日之光》开场是**一整个动画场景**（海边夕阳），3 秒不切——「一帧好画面」就是钩子。
- 中位镜头长度 1.2s–5.3s 都有：**不是越快越好**，共同点是「开头 3 秒只讲一个东西」。

## 三、能抄 / 不能抄（对着 One More）

**能抄**
- 第一帧用「最不像小游戏合集」的那一帧：一颗宝石被交换、一块砖被击碎、一条线被接通的**瞬间**。
- 「类型 → 钩子」压缩成一句话：**355 款，每一局都很短**；钩子用**真实秒数**证明（12.3 秒一局）。
- 无声可读：所有信息用画面+短字幕承担，音乐只卡点不叙事。
- 结尾只做一件事：**让观众记住「355 款 · 不用联网」并去找图标**（不喊口号、不列功能）。

**不能抄**
- 不能抄「单人开发者出镜讲故事」——我们无真人出镜。
- 不能抄「3A 级动画场景开场」——我们没有 3D 场景，硬做只会露怯（这是 ep2 的教训）。
- 不能抄「功能清单式蒙太奇」——355 款不是卖点清单，而是「随便点开都有得玩」的安全感。
- 不能抄「特效字幕堆节奏」——奥森已明确否掉这套模板感。

## 四、三个可执行方案（每个都写到能开拍）

### 方案 A｜「12 秒一局」（推荐）
- **0–3s**：黑场直接进真机——宝石交换的「咔」一声 + 三连消，屏幕右下角小字 `12.3s` 起跳。无 logo、无标题。
- **3–10s**：这一局**完整播完**（真机 12.3 秒那局），只在最后 1 秒压成 2 倍速；画面始终是同一块棋盘，不切镜头。
- **10–25s**：连切三款（打砖块 / 弹珠消 / 四子棋），每款 4–5 秒真实操作，字幕只写动作结果（「一板一球」「三消打泡泡」），不写功能。
- **25–40s**：镜头拉回首页，手指在 355 张卡上快速滑两屏，字幕：`355 款 · 不用联网 · 每局几十秒`。
- **40–45s**：停在图标与「One More」字样，最后一句字幕：`今天玩哪款？`
- **证明 355 的方式**：真机列表滑动（真实张数），不用动画数字造假。
- **工作量**：3 段真机录屏 + 1 段首页滑动，剪辑 1 天内可完成。

### 方案 B｜「一屏装不下」
- **0–3s**：从一款游戏画面**拉远**，变成 355 张卡组成的瀑布流（真机 A-Z 列表快速滚动），配一句字幕：`355 款，装在一个 App 里`。
- **3–20s**：随机点开三款，每款只播「第一次得分/第一次通关」的那 3 秒（真实反馈音）。
- **20–35s**：回到首页，手指连续点「随机来一局」三次，每次直接进不同游戏——用**随机**证明「款多且都能玩」。
- **35–40s**：图标 + `不用联网，随时开一局`。
- **风险**：开场是「列表」而非「游戏」，钩子弱于 A；适合做第二条/测试版。

### 方案 C｜「倒计时挑战」
- **0–3s**：大字 `12` 出现，立刻切真机一局，倒计时随游戏进程走。
- **3–30s**：连续三局，每局开头重新计时，屏幕累积 `已玩 3 款 / 还剩 352`（真实数字递减）。
- **30–40s**：停在首页，字幕 `355 款，今天玩到第几款？` + 图标。
- **风险**：倒计时是「模板感」的近亲，容易回到奥森否掉的路子；除非全程无花字，只用数字。

**推荐 A 的理由**：三条里只有 A 的**第一帧就是游戏本身**（符合外部证据的「第一帧=最抓人画面」），且「12.3 秒一局」是**我们独有的、可验证的事实**（Mac 已录到完整单局），不依赖特效、不依赖出镜、一个人可完成。

## 五、明确不做

- 不做 logo/标题开场；不做黑屏字幕开场；
- 不做「功能清单」式旁白；
- 不做与画面无关的 BPM 卡点特效字幕；
- 不在视频里念版本号/包号（版本变动太勤）。

## 六、怎么判断这条成不成（拍完再谈优化）

- 3 秒留存（后台可看）≥ 同账号历史中位数；
- 完播率 ≥ 40%（45 秒片）；
- 评论里出现「叫什么名字/哪里下」≥ 3 条。
达不到就按同一结构换钩子（换第一帧），**不换结构**。
