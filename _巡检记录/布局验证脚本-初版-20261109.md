# 布局验证脚本初版（2026-11-09 04:38）

## 为什么写

**判据 1846 发现 `uinput -K -t <ASCII>` 能搜索进游戏。**

**⇒ 「165 款横屏棋盘溢出」这个 goal 条目，之前因为 `inputText` 不生效而验不了 —— 现在能验了。**

**⇒ 写了 `工具/verify_game_layout.py`**：
```bash
python3 工具/verify_game_layout.py Nonogram Hitori   # 指定游戏
python3 工具/verify_game_layout.py --list 5          # 从清单取前 5 款
```

## 判据

| 状态 | 条件 |
|---|---|
| **`OK`** | **内容底 ≤ `1516`**（内容区底）|
| **`TIGHT`** | **内容底 `1516–1584`**（手势条会压）|
| **`PUSHED_OUT`** | **内容底 > `1584`** |

## ⚠️ 初版有 bug（如实说）

**试跑 2 款**：
```
PUSHED_OUT   Nonogram   {'max_bottom': 1600, 'count': 355}
PUSHED_OUT   Hitori     {'max_bottom': 1600, 'count': 355}
```

**⇒ 「`count=355` 说明『搜索没生效』」**（**还是「全量 `355` 款」**）
**⇒ 「`max_bottom=1600` 是「首页的」，不是「游戏内的」**

**⇒ 所以「`PUSHED_OUT` 是假阳性」** —— **「不是「Nonogram 溢出」，是「根本没进游戏」」。**

## 这是「判据 1819 第五类」的现成案例

**现象**：**「`PUSHED_OUT`」**（**看起来「Nonogram 溢出」**）
**机制**：**「搜索没生效，`dump` 到的是首页」** ⇒ **「根本没进游戏」**

**⇒ 「现象对、机制错」** —— **「如果只看 `PUSHED_OUT` 就下结论，会误报 2 款假的溢出」。**

## 明早怎么修（三个可能）

1. **「点搜索框」的坐标不对** —— **`1280, 435`** 可能不是「搜索框中心」
   - **修法**：**先 `dump` 找「搜索框」的 `bounds`，再点它的中心**
2. **「搜索框打开」的时机** —— **「点 `🔍` 后要「等动画」**（**我 `sleep 0.8` 可能不够**）
3. **「`uinput` 输入」后「要等搜索结果」** —— **`sleep 1.2` 可能不够**

## ⚠️ 而这条也值得记

**「自动化的第一步，永远是『确认前置条件成立』」**：
- **「搜索」是「进游戏」的前置
- **「`count < 355`」是「搜索成功」的判据**
- **⇒ 「脚本里要加『前置检查』：`count == 355` ⇒ `SEARCH_FAIL`，不要继续」**

**⇒ 我「初版没加这个检查」** —— **「所以它「安静地」给出了 2 个假 `PUSHED_OUT`」。**
**⇒ 这就是「没有前置检查的自动化」有多危险。**
