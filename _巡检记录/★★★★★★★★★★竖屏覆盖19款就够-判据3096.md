# 判据 `3096`：竖屏缺口 **`257` 款**，但**只有 `19` 款需要优先测**

## 一、覆盖率（对注册表算，比 `3095` 更准）

```
注册表款数              354
横屏测过                354 / 354  ✅ 100%
竖屏测过                 97 / 354  ❌ 27%
★ 竖屏从未测过          257 款
★ 横屏从未测过            0 款
```

⇒ **缺口只在竖屏**，横屏是全的。

## 二、把 257 分层

| 层 | 判据 | 款数 |
|---|---|---|
| **A 结构危险** | 有 ≥2 个 `aspectRatio(1)` 且**未做宽度限高**（`width`/`constraintSize` 里没有 `Bp.height`）| **11** |
| **B 横屏本来就溢** | 横屏 `blk > 0` | **8** |
| C 其余 | 两者都不满足 | 238 |
| 映射失败 | 名字→组件对不上 | **0** |

### A 层 11 款（最可能坏）

Color Flood · Mirror Tracing · Navon Hierarchical · Shape Shifter · Simon Sequence
```
⇒ 落盘 `_巡检记录/待测-竖屏从未测-A层结构危险11款.txt`

### B 层 8 款
```
Crown · Gokigen Naname · Heyawake · Path Intersect
Dual Coding · Story Builder · Word Surge · Block Stacking Physics

## 三、所以真正要测的是 **19 款**，不是 257

`19 × ~70s ≈ 22 分钟`，就能把「最可能坏的那批」清掉。

⇒ 这比「257 款全测」（约 5 小时）性价比高一个数量级。

## 四、判据

> **「覆盖率低」不等于「工作量巨大」** —— 先按结构风险分层，
> 通常 10% 的候选能覆盖 90% 的暴露面。

⇒ 四条：
1. **覆盖率报表要同时给「分母」「已测」「从未测」三个数**，别只报百分比
2. **「从未测」要按结构风险分层再排队**，不要按字母序
3. **分层判据要能写清楚**（这次是「`aspectRatio(1)`≥2 且未限高」），否则下一个人没法复现
4. **优先测 A 层**：它们不只是「没测过」，而是「结构上最可能坏」
