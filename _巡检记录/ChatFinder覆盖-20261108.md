# ChatFinder v1 覆盖扫描 —— 2026-11-08

> 执行：verifier-eng2 ｜ **只读** `core/ChatFinder.ets`(185 行) + `core/GameRegistry.ets`(355 款)，未改任何 .ets
> 方法：把 `parse()/scoreOf()/suggest()` **逐行复刻成 Python**，用真实 `GAMES` 数据跑 20 句人话

## 0. 结论先说

| 指标 | 数值 |
|---|---|
| 20 句里**完全答不出**（走追问） | **7 句 / 35%** |
| 20 句里答得出但**明显错** | **≥4 句** |
| 20 句一共覆盖到的游戏 | **23 / 355 = 6.5%** |
| **永远不可能被推荐**的游戏 | **332 款 / 93.5%**（沉默的多数） |
| `scoreOf` 里引用了、但数据中**根本不存在**的 tag | **4 个：`quick` `multiplayer` `board` `card`（各 0 款）** |
| `Easy` 难度的游戏数 | **0 款**（NORMAL 354 / HARD 1） |

⇒ **v1 的实际覆盖 ≈ 6.5%**；它的有效信号几乎只剩「类别」一个维度。

## ① 关键词表覆盖了多少款

6 组 `CAT_WORDS` 与 6 个 `GameCategory` 一一对应，**按类别算可以覆盖全部 355 款**：

| 组 | 关键词（部分） | 类别 | 可覆盖款数 |
|---|---|---|---|
| 1 | 逻辑/推理/动脑/解谜/拼图/logic/puzzle | LOGIC | **44** |
| 2 | 数字/数学/算/math/number | MATH | **59** |
| 3 | 记忆/记/memory/memor | MEMORY | **74** |
| 4 | 文字/词/word/letter | WORD | **53** |
| 5 | 空间/旋转/图形/spatial/shape/rotation | SPATIAL | **79** |
| 6 | 经典/classic | CLASSIC | **46** |
| | | 合计 | **355（100%）** |

**但「覆盖率 100%」是假的**，因为 `suggest()` 用 **`slice(0,3)` 只回 3 条**，而同分时按 **id 字典序**排序 ⇒
每个类别永远是**同 3 款**（该类 id 最小的三个）出线。所以：

> **能进 top-3 的游戏上限 ≈ 6 类 × 3 款 + 少量 tag 加分款 ≈ 20~30 款（<10%）**
> 20 句实测只覆盖 **23 款（6.5%）**，其余 **332 款（93.5%）在任何问法下都不会出现**。

## ③ 缺什么维度（每个维度的代价）

| 缺的维度 | 用户会怎么问 | 现状 | 多少款会匹配失败 |
|---|---|---|---|
| **否定/情绪（安静、放松、不想动脑）** | 「想玩个安静的」「不想动脑」「想放松」 | 词表里只有**肯定词**（动脑/烧脑）；「放松」不在表 ⇒ 空 | 20 句里 3 句直接空转；「不想动脑」还会**反向推荐** |
| **「像某款」相似推荐** | 「有没有像 2048 的」 | 无此路径 | **355 款**（任何一款都没法作为「参照物」） |

| **难度（简单/难）** | 「简单点」「太难了」 | 有字段但**数据坏了**（EASY 0 / HARD 1） | **355 款**（等于没有难度维度） |

## ④ v2 建议：优先级最高的 3 个新维度

按「覆盖款数 × 用户会问的比例 ÷ 实现成本」排序：

### 🥇 P0：修「难度」数据（覆盖 0 → 355 款，成本 = 一次数据整理）
- **为什么第一**：`EASY=0`、`HARD=1` ⇒ 现在「简单点 / 太难了 / 适合小孩」三类最常见问法**全部失效**（20 句里占 3 句）。
- **⚠️ 先说一个连带发现的坑**：`baseXp` **355 款全是 12**（常量）⇒ 不能当难度代理（我一开始就在这上面写错过，已更正）。
- **从现有 tag 直接推**（不新增字段，数据已经在）：
  · 有 `easy`(48) 或 `normal`+`short` ⇒ **EASY**
  · 有 `hard`(58) 或 `brainy`(58) ⇒ **HARD**
  · 有 `medium`(103) ⇒ **NORMAL**
  · 兜底按 `short` 有无分两侧
- 我按这个规则跑出来：**EASY 162 / NORMAL 135 / HARD 58**（现在数据是 NORMAL 354 / HARD 1 / EASY 0）⇒ 「简单/难」从**完全不可答**变成可答。
- 也就是说：**这条不需要新增字段，只需要把 `GameMeta.difficulty` 按已有 tag 重算一遍**（或干脆让 `scoreOf` 直接读 tag，绕开坏字段）。

### 🥈 P1：修「时长」判据（覆盖 0 → 166 款，成本 = 改 1 行）
- `scoreOf` 里查的是 `quick`（**数据 0 款**），而实际存在的是 **`short`(166)** 与 `timed`(32)。
- 把 `it.short` 的判据从 `['quick','timed','endless']` 改成 `['short','timed','quick']` ⇒ 「十分钟/短一局」立刻命中 166 款。
- 进一步可做**时长分档**：`short` ⇒ ~3-5 分钟；`timed` ⇒ 有倒计时（更紧张）；其余 ⇒ 长局。

### 🥉 P2：「像 X 的」相似推荐（覆盖 355 款，成本 = 一个新函数，零新字段）
- 用户给一个名字（或用最近玩过的一款），用**现成字段**算相似度：
  `score = 3×(同 category) + 2×(tags 交集数) + 1×(同 difficulty) - 0.1×(id 相同则排除本身)`
- 词表只需加一句：「像」「类似」「跟…差不多」⇒ 从句子或当前游戏取参照物。
- 这是**唯一能让 355 款都成为入口**的维度（每款都能当参照物）。

### 顺带建议（低成本、收益明确）
1. **否定词**：遇到「不/别/没」+ 肯定词 ⇒ 反转或丢弃该意图（至少别把「不想动脑」推成逻辑题）。**20 句里 1 句直接反了**。
2. **删死判据**：`multiplayer`/`board`/`card`/`quick` 四个 tag 在数据里是 0 款 ⇒ 要么补 tag，要么别在 `scoreOf` 里查（现在「要联机的」必空转）。
3. **top-3 的平局别按 id**：改成「同分随机（带稳定种子）或按 `baseXp` 降序」，让 355 款有机会轮换出线 —— 这是「沉默的多数」的直接解药（现在每类永远同 3 款）。
4. **「棋牌」误判**：`名称含「牌」` 会把「数牌记忆」判成棋牌 ⇒ 建议改成 tag 白名单（先给 13 款棋牌手工打 `board` tag）。

## 边界

- 只读扫描 + 逻辑复刻；**没有真机验证**（v1 的 UI 层不在本报告范围）。
- 20 句是我按「用户会怎么问」拟的，不是真实日志（项目里没有用户输入日志）。
