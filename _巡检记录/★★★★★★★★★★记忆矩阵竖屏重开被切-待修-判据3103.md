## 三、修法（照 `GridFit` 的路子，下次动手）

1. 读 `GMemoryMatrix.ets`，找 3×3 网格的 `.width(...)` 或 `.aspectRatio(1)`
2. 从截图量「网格上沿」与「网格下方需要多少」（提示文字 ~20 + 间距 + 按钮 44 ≈ 70–80vp）
3. 代入 `GridFit.width(3, 3, gap, above, below, Bp.height)`，或直接把扣减量算出来
4. **前台构建** → 核 HAP 字节 → 装包 → `blk` + `cov` + **截图**三样齐了才算修好

## 四、判据

> **像素检测器 `cov` 与 `blk` 是互补的，不是冗余的。**
> 五子棋和记忆矩阵这两款，`blk` 都看不见；而 `cov` 一次就抓到。
> 反过来，`cov` 会把「按钮贴屏沿但完整」也标出来（`Cross_Section_Slice`），需要人眼看。

⇒ 三条：
1. **每轮抽样都跑 `--today`**，它是目前唯一能抓「底部按钮被切」的自动手段
2. **`cov ≥ 0.60` 只是一个入口**，必须配截图；`0.94` 大概率真，`0.62` 需细看
3. **`cov=0.00` 也不能完全放心** —— `blk` 那边还是唯一能抓「整块越界」的量
