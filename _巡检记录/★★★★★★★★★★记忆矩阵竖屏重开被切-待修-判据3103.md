## 六、已修好（`360 → 378`，分形态）

### 结果

| 指标 | 改前 | 改后 |
|---|---|---|
| `blk` | `1/24px` | `1/24px` |
| `cov` | `0.94` ⚠️ | `0.93` ⚠️ |
| `lowest` 块 | `重开` 只露上沿 | **`重开` 完整 `146px` 高、文字可见** |
| 截图 | 一条紫边 | **整个按钮 + 「重开」两字** ✅ |

### ⚠️ 关键发现：`cov` 分不清「完整但贴边」与「被切」

`cov` 改前 `0.94`、改后 `0.93` —— **几乎没变**，但视觉上是「被切」→「完整」。
原因：`cov` 量的是「最底一行被内容横向覆盖多少」，
**一个完整按钮贴在屏底、和一个被切的按钮，这个数是一样的。**

⇒ 能区分它们的是 **`lowest` 块的高度**：
```
改前：重开只露上沿（块高很小 / 不可见部分在窗外）
改后：重开完整 146px = 46.7vp（按钮正常高度）
```

### 所以判据要补一条

> **`cov ≥ 0.6` 只能回答「底部有没有内容贴边」；回答「有没有被切」必须配 `lowest` 块高度或截图。**

⇒ 三条：
1. **`cov` 高 + 底部块高度正常 ⇒ 完整但贴边**（可接受，或再收紧一点留边）
2. **`cov` 高 + 底部块高度异常小 ⇒ 被切**（必须修）
3. **两者都不可靠时，打开截图** —— 这条今天已经救了三次
