## 1. `GBreakout` 精确补丁（唯一确认必爆）

**结构**：`build()` → 游戏根 `Column({ space: Space.sm })` → 场地包装 `Column()`（`layoutWeight(1)` 领剩余高）→ 场地 `Stack()`：

```
602        }                       ← Stack 闭合
603        .width('100%')
604        .aspectRatio(1)
605-610    （注释：这是 2026-10-29 修的「限高 58%」，后来被改成 100%）
611        .constraintSize({ maxHeight: '100%' })
612        .backgroundColor(this.theme.surface)
```

**两行补丁（推荐：width 封顶 + 高度换确定值）**

- 补丁 ①（L603）：
  - **原串**：`        .width('100%')`
  - **新串**：`        .width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 360)))`

- 补丁 ②（L611）：
  - **原串**：`        .constraintSize({ maxHeight: '100%' })`
  - **新串**：`        .constraintSize({ maxHeight: Math.max(140, Bp.height - 360) })`

**效果（横屏 853×533）**：min(813, 173) = **173vp** 边长 ⇒ 场地 173×173，下方「发球/重开」+ 状态行有 ≈170vp 空间。
**竖屏（800×1280）**：min(760, 920) = **760vp** ⇒ 与现在的观感一致，不会变小。

⚠️ 只做补丁 ① 也能成立（`aspectRatio` 会按宽反推高）；补丁 ② 是**去掉那个假百分比**，建议一起做。

## 2. 10 处 `'70%'`/`'50%'`：逐个列（文件 / 行 / 父级 / 建议）

### 2.1 百分比底座到底是谁？—— 本仓库内有硬证据

`GReversi` 自己的注释（`GReversi.ets` L660-668）写着：
> ② 加 `.maxHeight: '70%'` ⇒ 横屏 373vp，仍溢出
> ③ 改成 `.maxHeight: '45%'` ⇒ 横屏好了，但**竖屏 1280vp 下只剩 576vp**

`1280 × 45% = 576` **正好对上** ⇒ 百分比解析的是 **窗口/屏幕高度**，不是游戏区高度。
⇒ 横屏 533 时：`'70%'` = **373vp**（预算 343 ⇒ **超 30vp**）；`'50%'` = 267vp（安全）；`'46%'` = 245vp（安全）；`'100%'` = **533vp**（超 190vp）。

## 3. 全库百分比型约束清单（共 19 处，去注释）

### 3.1 `maxHeight` 百分比（11 处）

| 值 | 处数 | 文件:行 |
|---|---:|---|
| `'70%'` | 9 | `GLifeGame:445` `GLockPattern:412` `GMahjongSolitaire:538` `GMatch3:542` `GMazeNav3d:502` `GMirrorMaze:466` `GSnake:594` `GSumSnake:522` `GTapa:707` |

| `'100%'` | 1 | **`GBreakout:611`（533vp，必爆）** |

### 3.2 `minHeight: '100%'`（7 处，**良性**）

`GBejeweled:873` `GBlockEscape:791` `GCheckers:1030` `GColorFlood:645` `GFillomino:743` `GMirrorTracing:537` `GNavonHierarchical:545`

全部是同一个写法：
```
}.width('100%')
.constraintSize({ minHeight: '100%' })
.justifyContent(FlexAlign.Start)
```
⇒ 语义是「**至少撑满父容器**」（让底部控件贴底/居中），**不会让内容长得比父容器更高** ⇒ **不需要改**。

### 3.3 `maxWidth` 百分比

**0 处**（全库没有任何 `maxWidth: 'x%'`）—— 也就是说「限宽」这件事，全库只有 `GGo9` 用了 `maxWidth`，其余都靠 `.width(Math.min(...))` 或百分比 `maxHeight`。

## 4. 建议的收敛方向（不做，只提给下一轮）

1. **`maxHeight` 百分比全库 11 处 ⇒ 统一换成确定值**：`Math.max(140, Bp.height - 360)`（横屏 173 / 竖屏 920）。
   理由：百分比底座是**窗口高**（§2.1 硬证据），横竖屏差 2.4 倍，**一个百分比不可能同时满足**（GReversi 已踩过 3 次，注释里记着）。
2. **加一条静态检查**（可进 `工具/`）：`grep -rn "maxHeight: '[0-9]*%'" games/` 必须为空；`minHeight: '100%'` 白名单放行。
3. **`aspectRatio(1)` + `maxHeight: '100%'` 这个组合是死路**（`GBreakout` 就是它）：并列两条规则时高度取「父级 100%」，等于把整屏预算吃光。
