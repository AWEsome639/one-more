# ★★★★ `Kakuro Mini` 确认功能级：数字键只剩顶端 `12px`

> `2026-11-14 12:5x`。用 `bounds` 的高度证实的，不是猜。

## 一、证据

```
lowest = '6'   bounds x 60-534, y 1588-1600
⇒ 该文字节点**可见高度只有 12px（4vp）**
```

**一个数字字形的正常高度是 `40`–`60px`（`FontSize.lg` 级）。**
**⇒ 只剩 `12px` ⇒ **只有顶端 `12px` 在屏内，其余全在屏幕外**。**

**⇒ 所以那个键：**
- **文字几乎看不见**（只有上沿一条）
- **键的可点区域大部分在屏外** ⇒ 按到的概率很低

**⇒ 功能级确认。**

## ⇒ 判据（`2184`）

**「同一个偏移量调了三次还不够」是一个强信号：问题**不在那个参数上**。**

**⇒ 判据：一个参数若被调过 `≥3` 次仍不达标，说明它不是有效杠杆。
⇒ 继续调它只会得到「每次都差一点」的结果。**

**⇒ 而正确的做法是：去算「各项实际占用」与「预算」的差，
找出那个「估得比实际小」的项（这次是「键盘 ~90vp」和「提示 17vp」）。**

## ⇒ 判据（`2185`）

**文字的 `bounds` **高度**也是信息：**
- 高度正常 ⇒ 完整可见
- **高度异常小（如 `12px` vs 正常 `50px`）** ⇒ **被裁了，且能估出裁掉多少**

**⇒ 判据：`bounds` 的 `y2 == 1600` 只说「到边」，而**高度异常小**说「裁掉了多少」。
⇒ 后者比前者信息量大得多，而且是免费的（同一行数据里就有）。**
