# 重要发现：**`Cell.of()` 自己已经在矮屏上乘 `0.85`** —— 我的 `Bp.isShort()` 分档是**双重压缩**

## 代码（`core/Design.ets:104-108`）

```ts
static of(base: number): number {
  let shrink: number = 1;
  if (Bp.height > 0 && Bp.height < 600) {
    shrink = 0.85;                      // ★ 矮屏（533）时自动 ×0.85
  }
  return Math.round(base * Cell.k * Bp.scale() * shrink);
}
```

**⇒ `533` 横屏下，`Cell.of(62)` 实际 = `62 × 0.85 ≈ 53vp`（不是 `62vp`）。**

## 这意味着什么（判据 1988）

> **`Cell.of(N)` 返回的值**已经**是矮屏压缩后的结果。**
> **⇒ 在它外面再包 `Bp.isShort() ? Cell.of(小) : Cell.of(大)`，
> 等于**把压缩做了两遍** —— 矮屏上得到的是「`N × 0.85 × 0.85`」。**
>
> **⇒ 正确写法二选一：**
> **① 只改 `base`**：`Cell.of(Bp.isShort() ? 34 : 62)` —— 这**是我今晚用的**，
>   矮屏得 `34×0.85 = 29vp`（而不是我以为的 `34vp`）
> **② 或者不改 `base`，改 `Cell.k`** —— 但那是全局的，会影响 `355` 款
>
> **⚠️ 关键是：我今晚所有「`Cell.of(小)`」的心算都**高估了结果** `15%`。**

## 它顺带解释了两件事

**① 为什么 `Stroop` 的按钮是 `129px`（`43vp`）而不是我算的 `53vp` 或 `29vp`**
   —— `43vp` 介于两者之间，说明那个按钮的尺寸**不是**由 `Cell.of(62)` 单独决定的
   （可能还有 `Cell.k` 或别处覆盖）

**② 为什么 `Cell.tap(44)` 有「触控下限」**（判据 1899）：
   `Cell.tap(x) = max(Cell.of(x), 44)` —— **`44` 是压缩后的绝对值**，
   而 `Cell.of(44) = 37vp` ⇒ **`Cell.of` 永远到不了 `44`** ⇒ 触控尺寸必须用 `Cell.tap`

## 对我今晚工作的影响（诚实评估）

**我改的那些 `Cell.of(Bp.isShort() ? A : B)`：**
- **方向是对的**（矮屏更小）
- **但绝对数值都偏大 `15%`**（我以为的 `34vp` 实际是 `29vp`）
- **⇒ 这不影响「有没有效果」，只影响「效果多大」**

**⇒ 所以今晚「零效果」的那几刀，**不是**这个原因造成的 —— 那是另一个问题。**
