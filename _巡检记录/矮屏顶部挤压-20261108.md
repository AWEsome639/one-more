# 矮屏「顶部展开挤没列表」—— 2026-11-08

> 执行：**perf-hunter** ｜ **只读分析 + 只写这个 md**（没改任何 .ets、没编译）
> 触发：验 `LazyForEach` 时"甩回最顶部"复现：顶部整块展开 ⇒ 网格区只剩 ~8px ⇒ **卡片一个都不渲染**。
> 设备：`127.0.0.1:5557`（模拟器 853×533 vp @3x = 2560×1600 px）｜包 `updateTime=13:37:45`
> ⚠️ 这不是 `LazyForEach` 引入的：`ForEach` 时代**同样被挤**，只是卡片仍在组件树里 ⇒ `dumpLayout` 照列 355 张 ⇒ **看不出来**。`LazyForEach` 只是让它**显形**（网格高 0 ⇒ 什么都不建）。

## 0. 三个数字（先给结论）

| 问题 | 答案 |
|---|---|
| ① `effCollapsed()` / `onScrollIndex` 当前阈值 | `Bp.isShort()` = `height < **690**`；**但 `effCollapsed()` 完全不看它**，只看 `this.topCollapsed`；`onScrollIndex`：`first ≥ 2` 收起、`first ≤ 1` 展开（900ms 防抖 / 手动后 2s 不抢） |
| ② 853×533 下顶部展开后网格剩多少 | **8 px（≈2.7 vp）** —— 对照收起态 **697 px（≈232 vp，正好 2 行卡）**，**少了 229 vp** |
| ③ 改成什么阈值 | **不用改阈值**：`690` 这个数本身是对的（硬下限算出来 **644 vp**）。**要改的是"展开路径没 consult `isShort()`"** ⇒ 1 行修法：`effCollapsed()` 加 `|| Bp.isShort()` |

## 2. 当前代码为什么不拦它

```ts
// GamesTab.ets :2250（现取）
private effCollapsed(): boolean {
  if (this.uiMode === 'elder' && !this.elderExpanded) { return true; }
  return this.topCollapsed;          // ← 只看这一个布尔，**没有 Bp.isShort()**
}

// GamesTab.ets :1340（Grid 的 onScrollIndex，现取）
let want: boolean = this.topCollapsed;
if (first >= 2) { want = true; }     // 滚过 2 行 ⇒ 收起
else if (first <= 1) { want = false; } // ★ 滚回顶部 ⇒ **展开**（矮屏也照展开）
```

`Bp.isShort()`（`core/Bp.ets:259`）**只有 `aboutToAppear` 用它把 `topCollapsed` 初始化成 `true`**；
一旦 `onScrollIndex` 把它翻回 `false`，**没有任何地方再拦**。

**阈值本身是对的**：`Bp.ets` 注释里算过「展开态需 482 vp + 标签栏 60 + 1 行卡 142 = 684 vp ⇒ 620 太宽容，改成 690」。
我按实测重算（本题要求 ≥2 行卡）：
```
展开顶部 404 vp + 2 行卡（2×84 + 行距 12 ≈ 180 vp）+ TabBar 60 vp = **644 vp**
```
⇒ **644 < 690**，所以 **690 这条线是合理且有余量的**；533 vp 的横屏**远远不够**。
⇒ **问题不是阈值设小，而是"展开"这条路径根本没查它。**

## 3. 用户影响（实测，不是观感）

1. **列表彻底不可用**：展开后网格 2.7 vp ⇒ **一屏看不到任何游戏**（不是"只能看一行"，是 0 行）。
2. **⚠️ 可能是死锁**：`onScrollIndex` 的"收起"分支靠**网格滚动事件**触发，而网格高度≈0 ⇒ **滚动手势打不到它**。
   我实测：进入该状态后**往下甩 2 次，顶部没有收起**、卡片仍为 0。
   ⇒ 用户唯一的出路是**重启 app**（我验过：重启后恢复 8 张卡、Grid 697 px）。
3. **逃生口穷举结果（2026-11-08 补测，包 13:37:45，即**未含**修法 A 的版本）**：

   | 尝试 | 结果 |
   |---|---|
   | 往下甩 2 次（滚动） | ❌ 顶部不收、卡片仍 0 |
   | 点分类 chip「经典 46」 | ❌ 卡片仍 0、无 `Grid` 节点 |
   | 点「按喜好挑游戏 → 展开 ▼」再「收起 ▲」 | ❌ 面板开合了，网格仍未恢复 |
   | 点「🎮 全部」分段 | （被前一步挡住，未测到） |

   ⇒ **两个主要控件都救不回来，死锁确认**（比"未穷举"更硬）。
4. **另一个坑（判据级，我自己踩了）**：**不能拿「今天这一局」判断顶部是否展开** —— 收起态也会渲染它（`GamesTab.ets:1150` 的 `if (this.effCollapsed() && …) { this.dailyStrip() }`）。
   判"顶部整块展开"要看 **「随机来一局」或「🎮 全部」分段行**是否出现（这两块只在展开态渲染）。

## 4. 建议修法（按代价排序）

| 方案 | 改动 | 效果 | 风险 |
|---|---|---|---|
| **A（推荐，1 行）** | `effCollapsed()` 返回 `this.topCollapsed \|\| Bp.isShort()` | 矮屏**永不展开** ⇒ 从根上不可能挤没；今日挑战/随机仍有 `dailyStrip()` 在收起态提供 | 矮屏用户失去"展开看完整日卡/随机卡"的形态（但收起态已有等价入口：`GamesTab.ets:1150` 的 `dailyStrip()` 在收起态照常渲染） |
| **B（等价，只堵滚动路径）** | `onScrollIndex` 展开分支加 `&& !Bp.isShort()` | 只堵"滚动到顶自动展开"；若别处还有设 `topCollapsed=false` 的入口就漏 | 与 A 同，但覆盖面小 |
| C（想做"矮屏也能展开"） | 展开时把今日挑战卡/随机卡**折叠成一行**（现在两张卡共 360 px = 120 vp） | 可省 ~60–90 vp，533 vp 仍然不够（差 229 vp） | **收益远不够**，不建议 |
| D（抬阈值） | `isShort()` 690 → 900+ | 只是把更多机型拉进"收起"，**不解决本机 533 vp 的问题**（533 早已 < 690） | 误伤 700–900 vp 的正常机型 |

**推荐 A**：一行、可回滚、语义直白（"屏幕矮就不允许展开"），且与 `Bp.ets` 里既有的 684/690 推导互补。

## 5. 复现步骤（给下一个人）

```bash
# 前提：中文、游戏页、筛选面板收起（判据 1813/1814）
hdc -t 127.0.0.1:5557 shell "uitest uiInput swipe 1280 1250 1280 250 140"   # 往下甩，滚到列表深处
hdc -t 127.0.0.1:5557 shell "uitest uiInput swipe 1280 700 1280 1400 120"   # 快速往回甩到顶部（多来几次）
# 此时 onScrollIndex 会把 topCollapsed 置 false ⇒ 顶部展开
# 判定：dump 里没有 Grid 节点、卡片 0 张；再往下甩 2 次仍然回不来 ⇒ 死锁
```
⚠️ `dumpLayout` 记得用**唯一路径**、并**连拍两次比对**（这台机器 dump 经常超时，固定路径会读到旧文件）。

## 6. 与 LazyForEach 的关系（避免误判）

- **不是它的锅**：布局挤压在 `ForEach` 时代就存在，只是那时 355 张卡**始终在树里**，`dumpLayout` 照样列出 ⇒ 谁都没发现列表其实"看见了 0 张"。
- **它让问题显形**：`LazyForEach` 下网格高≈0 ⇒ `totalCount` 之外什么都不建 ⇒ dump 0 张。**这是"更诚实的观测"，不是新 bug。**
- ⇒ 修这条**与 `LazyForEach` 迁移无关**，两者可以独立推进。
