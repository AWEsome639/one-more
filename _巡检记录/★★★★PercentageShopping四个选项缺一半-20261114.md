# ★★★★ `Percentage Shopping`：**四个选项里两个点不到**

> `2026-11-14 12:4x`。判据 `2204`（回代码核）的结果，比先前判的「选项值看不清」严重。

## 一、代码

```ts
L24:  const PICK: number = 4;                        // 四个选项
L406-409: Row({ space: Space.sm }) {
            Text(String(i + 1))                      // ← 选项序号 1/2/3/4
```

**⇒ `lowest = '3'` 就是**第三个选项的序号**。**

## 二、⇒ 后果

```
四个选项 × 43vp = 172vp
而 '3' 的 bounds y1 = 1595（只露 5px）
⇒ 选项 3 与 4 都在屏幕边缘/屏外
```

**⇒ **四个选项里两个点不到。****

**⇒ 这比「选项值看不清」严重：**
- 「看不清」⇒ 还能靠位置猜
- **「点不到」⇒ 如果正确答案是 `3` 或 `4`，玩家**无法选择** ⇒ 只能瞎点 `1/2`**

**⇒ 而四选一 ⇒ 至少 `50%` 的题目（正确答案在 `3`/`4` 时）变成纯运气。**

## 三、⇒ 严重性重估

**先前我把它排在功能级第 `5`（「有替代：能看题推」）。**
**⇒ 那是错的 —— 替代路径只对「答案在 `1`/`2`」时成立。**

**⇒ 正确排序：它应在 `3`–`4` 之间（缺一半选项 ⇒ 一半题目答不了）。**

| 序 | 游戏 | 缺什么 | 一半以上题目受影响？ |
|---|---|---|---|
| `1` | `Magnets` | 全部行列提示 | ✅ 全部 |
| `2` | `Kakuro Mini` | `6/7/8/9` + 删除 | ✅ 大部分（两位数题）|
| **`3`** | **`Percentage Shopping`** | **选项 `3`/`4`** | **✅ 约 `50%`** |
| `4` | `Pythagorean Triple Builder` | 确认键 | ✅ 全部（交不了）|
| `5` | `Fraction Matcher` | 选项 `B`/`C`/`D` | ✅ 大部分 |

**⚠️ 其实 `4` 和 `5` 也都很严重（确认键/三选项全缺）。**
**⇒ 所以**五款都是「大部分题目受影响」的级别**，之前的「有替代/无替代」区分过度精细了。**

## ⇒ 判据（`2208`）

**「有替代路径」这个判断，要看**替代路径覆盖多少比例的场景**。**
**⇒ 这次我说 `Percentage Shopping`「有替代（能看题推）」——
但它只对「正确答案在可见的两个里」成立 ⇒ 只覆盖 `50%`。**

**⇒ 判据：说「有替代」时，必须给出**覆盖率**。
⇒ 覆盖 `< 80%` 的，不该算「有替代」；应直接归入「大部分场景不可用」。**

## ⇒ 判据（`2209`）

**「N 选 1 里缺 k 个选项」的严重性 ≈ `k/N`。
⇒ 而 `lowest` 只给出**第一个被裁的**那个（`'3'`）⇒ 需要看 `PICK` 才知道总数。**

**⇒ 判据：被裁元素若是「等距排列的一组」，`lowest` 给的是**起始位置**；
⇒ 要看总数（`PICK`/`ForEach` 的长度）才能算出「缺了几个」。
