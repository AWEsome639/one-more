## ① 5 分钟自检（代码层，不用设备）

按顺序跑，四条全过才算“代码看着对”。

### 1. RTL 静态陷阱检查器

```bash
cd "/Users/a0000/dev/One More"
python3 tools/check_rtl.py; echo "退出码=$?"
```

**期望**：

```

  ② 绝对对齐（TextAlign.Left/Right）：0 处
  ③ 单边绝对边距（margin/padding 只有 left 或 right）：0 处
  RTL陷阱：0 处

```

> 这三类都是「看着正常、只有阿语用户看到反的」。
> ① 的白名单放行 `games/` 里的玩法箭头（物理/规则方向不该镜像）。
> **这条已挂进 `工具/check_assertions.sh`**（纯闸门，不动 TOT）。

### 2. 双重镜像（最容易犯的错）

```bash
grep -rn "isRTL() ? TextAlign" entry/src/main/ets/ | wc -l
```

**期望 `0`**。`TextAlign.Start/End` **本来就会**随布局方向翻；
写成 `isRTL() ? End : Start` 是**双重镜像**，阿语下反而变回 LTR。

### 3. 没镜像的裸箭头

```bash
grep -rn "Text('›')\|Text('‹')" entry/src/main/ets/ | wc -l
```

**期望 `0`**。正确写法是 `Text(this.rtl() ? '‹' : '›')`。
（`start/end` 那类整句说明里的方向词不算——检查器只认**纯符号**。）

### 4. 平台侧的语言通知（**判据 1797，这条没有就全白干**）

```bash
grep -c "^[[:space:]]*i18n\.System\.setAppPreferredLanguage(" entry/src/main/ets/core/I18n.ets
```

**必须 = 1**（当前实测 `1`）。

> ⚠️ **别图省事写 `grep -c "setAppPreferredLanguage"`** —— 那样会把**注释也算进去**：
> 该文件里出现 3 次，2 次在注释、1 次是真调用。真调用被删掉后仍会显示 2 ⇒ **假绿**。
> 我实测过：加 `^[[:space:]]*i18n\.System\.` 锚定后，真调用被注释掉会**立刻变成 0**。
>
> 这正是今晚反复吃亏的那类错 —— **`check_dup_symbol.py` 就是因为写死阈值长期“死绿”**。
> 判据：**护栏要在“被保护的东西没了”时变红，否则它只是装饰。**

> **为什么这条是命门**：app 只在**自己的状态**里换语言（`I18n.cached` + AppStorage +
> preferences），系统侧一直是 `zh-CN` ⇒ `Direction.Auto` 永远解析成 LTR。
> 镜像不是靠“容器上加个属性”就能来的。

### 判据 1：逐元素坐标对比（**最硬的判据**）

同一台设备、同一个设置页，切阿语**前后各 dump 一次**，比较同一元素的 `bounds[0]`（x）：

| 元素 | 中文 | 阿语（修好之前） | 修好之后应该 |
|---|---|---|---|
| 分区标题 | `外观` **x=96** | `المظهر` **x=96** ← 一模一样 = **没镜像** | **x 明显变大**（靠右） |

> **为什么用坐标不用肉眼**：阿拉伯文本身就右对齐，**肉眼看不出布局有没有翻**。
> 我第一次就是“看着像镜像了”，量了坐标才发现一个像素都没动。

### 判据 2：底部 tab（**顺带测 hit test**）

- 阿语下三个 tab 顺序应镜像：`الإعدادات` 在**左**、`إحصائيات` 中、`الألعاب` 在**右**
- **点最左那个，必须真的进设置**（按位置点，不是按标签猜）

> ⚠️ verifier-eng2 提过一个更严重的怀疑：**RTL 下 hit test 可能仍按 LTR 算** ⇒
> “点错页签/一次点击同时换页签+换语言”。**点错比不镜像严重得多**，这条必测。

### 判据 3：顶栏四按钮

- 阿语下四个圆按钮应在**左上**（`One More` 标题在右上）
- **待验**：今晚有一次疑似“错位一格”（点了 🔍 却触发 💬），未复现也未定性 —— 见 ④

### 判据 4：角标位置

- 游戏卡的角标（🏆/🔥 + 天数）在 RTL 下应在**左下**
- 中文下在右下 ⇒ 位置翻转 = `padding({ end })` 生效

### 判据 5：阿拉伯数字

- 应显示 `٣٥٥`（阿拉伯-印度数字），不是 `355`
- 千分位应是 `١٬٥١٠`（`٬` U+066C），不是拉丁逗号

## ③ 已知坑（按踩坑顺序，每条都真实踩过）

### 坑 1（判据 1795）：`direction` 加在 `Tabs/TabContent` 的根上**完全无效**

v2 就是这么干的：`GamesTab` 根 `Stack`、`StatsTab`/`SettingsTab` 根 `Scroll` 各加一份
⇒ **真机一个像素都没动**。

### 坑 2（判据 1796）：`direction` 只对**容器主轴**生效，`Column` 文档明写不生效

SDK `common.d.ts:20246-20248` 原文：

> *“Sets how elements are laid out **along the main axis of the container**.”*
> *“**The setting does not take effect in the `Column` component.**”*

⇒ 它只对 **`Row`/横排 `Flex`** 有意义；`Stack`/`Scroll` 没有主轴概念，`Column` 明写无效。

**这条坑的通用教训（比 RTL 本身值钱）**：
> **`direction` 在 `CommonMethod` 里，所以任何组件都能 `.direction(...)` 且编译通过 ——
> 但“能编译过” ≠ “会生效”。我一整天都在犯这个错。**
> 我在报告里写过「`direction` 会继承给子组件」——**是错的**：它只影响该容器自己的主轴。

### 坑 3（判据 1797）：必须 `i18n.System.setAppPreferredLanguage(lang)`

这是 v3 的**钥匙**，也是唯一真正让整页镜像的东西（官方 FAQ「如何实现镜像语言功能」的第 2 步）。
加在 `I18n.set()` 末尾，`try/catch` 静默（无权限/语言包缺失时不该让换语言失败）。

⚠️ 副作用（**这是对的行为**）：系统侧语言也会变 —— 系统弹窗、输入法候选、日期格式跟着切。

### 坑 4（判据 1800）：`margin`/`padding` 的 `start`/`end` 要 `LengthMetrics.vp()`

```ts
.margin({ start: LengthMetrics.vp(0), end: LengthMetrics.vp(Space.xs) })   // ✓
.margin({ start: 0, end: 8 })                                             // ✗ 编译挂
```

**反证价值**：它说明 `start/end` 是**新 API**、有类型要求，
而 `direction` 很可能也是**部分容器才支持** —— 两条线索指向同一个教训。

### 坑 5：**切阿语后重启会退回中文**（verifier-eng2 发现）

⇒ **验证时必须“切完立刻测”，中途不要重启、不要 `force-stop`、不要让它被切后台。**
今晚我因为这个白跑了两轮：切到阿语 → app 被别的进程切后台 → 重启后回到中文 → 白测。

## 附：今晚的 3 版演进（为什么要这么久）

| 版本 | 做法 | 结果 | 学到什么 |
|---|---|---|---|
| **v1** | `Index` 根 `Stack` 加 `direction` | ❌ 完全无效 | “根级一挂就整页镜像”是错的假设 |
| **v2** | 三个 Tab 根（`Stack`/`Scroll`）各加一份 | ❌ 一个像素没动 | 推测“不穿透自定义组件”（坑 1）|

**真正的教训**：v1/v2 花了 4 小时，是因为我一直假设“这是个 CSS 式的继承属性”。
查 SDK 那 5 分钟（`direction` 的两句原文）比前面 4 小时的试错都值钱 ——
**先用文档证伪假设，再动手改代码。**
