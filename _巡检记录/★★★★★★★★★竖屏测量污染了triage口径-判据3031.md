# 判据 3031：我用竖屏测量**污染了自己的口径** —— 横竖屏的 `blk` 不可比

## 一、我干了什么

今晚为了拿竖屏数据，我跑了 `13`（A 档）+ `18`（抽查）+ 若干次补丁验证的竖屏测量，
全部写进了**同一个台账** `layout-canonical.tsv`（此前 `2446` 行几乎全是横屏）。

## 二、造成了什么

`triage.py` 的逻辑是「同一款取**最后一次**」⇒ **竖屏记录把横屏发现盖掉了**：

| 款 | 横屏（今晚的主要发现）| 竖屏（覆盖后）| 后果 |
|---|---|---|---|
| `Shadow Pivot` | `blk=72px` / **`120.0%`** | `blk=24px` / `18.0%` | **从 A 档消失** |
| `Simon Command` | `blk=72px` / 两块屏外 | `blk=72px` / `4.0%` | A 档显示的是竖屏数字 |

⇒ **今晚最重的那两条发现，在我自己的报表里被自己抹掉了。**

## 三、根因：`blk` 的阈值随屏幕高度变

```
over = y2 − (GAME_BOTTOM + SLACK)
横屏 GAME_BOTTOM=1516（屏 1600）  竖屏 GAME_BOTTOM=2412（屏 2496）
```

⇒ **两个形态的 `blk` 数值不能放在一起比**，必须分开统计。

## 四、修的过程里踩的两个坑（都记下来）

### 坑 ① `board=WxH` 是**棋盘**尺寸，不是屏幕尺寸

我第一版 `_cfg()` 按 `board=` 分形态 ⇒ **分类全错**：
`Snake 3D` 的 `blk` 从 `63` 变成 `96`、`Wordle` 从 `40` 变成 `48`（挑到了别的记录）。

⇒ 又一次「拿了一个看起来像那么回事的字段」（`3015` `mtime`、`3014` 名单、`3029` 抽样，这次是 `board=`）。

### 坑 ② 按坐标量级（`>1600` ⇒ 竖屏）有缺口

`Odd Rotation` 竖屏的 `lowest='1/10'` 坐标是 `[339,709][465,775]` —— **全部 < 1600** ⇒ 被误判成横屏。
（它的元素本来就在屏幕上半部，坐标小。）

## 五、最终修法：让台账自己记屏幕尺寸

### `工具/shot_game.py`
台账格式加一个字段：
```
... board=%s scr=%dx%d max=%d ...
```
值来自 `int(os.environ.get('SHOT_SCREEN_W','2560'))` / `SHOT_SCREEN_H`

⚠️ **差点写出 `NameError`**：原想直接用 `SCREEN_W`/`SCREEN_H` 变量，但它们只在
`L282-288` / `L359-365` 两个**函数内部**赋过值，`_walk` 的作用域里没有 ⇒
**每次测量都会炸**。改成从 env 现读（与测量配置同源）。
⇒ 加完必须**跑一次冒烟测量**确认没炸：实测 `[1/1] Shadow Pivot OK 107.4s` ✅

### `工具/triage.py`
1. `_cfg()`：**优先读 `scr=WxH`**，没有才退回坐标量级
2. `last[]` 按 `(game, cfg)` 分组 ⇒ **另一种形态的记录不进本次统计**
3. 加 `--portrait` 开关；默认仍按横屏（与 `2446` 行历史一致）
4. **取「最后一次成功」的记录** —— 失败记录（`NO_CARD`/`WRONG_GAME`/`TIMEOUT`）只是「这次没测到」，
   不代表版面状态。今晚两次失败验证落进台账后，`Shadow Pivot` 的横屏 `blk=72px` 就被顶掉了。

### 修后
```
横屏 A 档 13 款   ← 与污染前一致，Shadow Pivot 120.0% 在位
竖屏 A 档  2 款   ← Simon Command 4.0%（blkh=599）、Simon Says 1.5%（blkh=1653）
```

## 六、★ 竖屏测量的完整配方（`5` 个环境变量，缺一个就错）

```bash
DSH_EMU_INST=onemore_fold \
SHOT_SCREEN_W=2224 \
SHOT_SCREEN_H=2496 \
SHOT_GAME_BOTTOM=2412 \
SHOT_GESTURE=2480 \
python3 工具/verify_layout.py --names-file <名单>
```

| 变量 | 值 | 不设会怎样 |
|---|---|---|
| `DSH_EMU_INST` | `onemore_fold` | 工具会**自动换成 `onemore7`（横屏）** |
| `SHOT_SCREEN_W` | `2224` | **漏设 → 台账写 `scr=2560x2496`（宽度是错的）** ← 我今晚就漏了 |
| `SHOT_SCREEN_H` | `2496` | 默认 `1600` ⇒ 阈值算错 |
| `SHOT_GAME_BOTTOM` | `2412` | 默认 `1516` ⇒ 全部 `blk` 假值 |
| `SHOT_GESTURE` | `2480` | 手势条判断错 |

⇒ `GAME_BOTTOM` 的推法有规律：**屏幕高 − 84**（横屏 `1600−84=1516`、竖屏 `2496−84=2412`）。

## 七、判据

> **把两种「量纲不同」的数据写进同一个台账，必须在写的那一刻就带上「量纲标识」；
> 事后靠推断分类一定会错。**

⇒ 三条：
1. **测量记录必须自带「用什么设备/什么配置测的」** —— 不能靠坐标或文件名反推
2. **改「取哪条记录」的逻辑时，先问「失败记录算不算」** —— 今晚失败记录顶掉了成功的版面发现
3. **加字段后必须跑一次冒烟测量** —— 这次靠它抓到了 `SCREEN_W` 作用域会 `NameError`
