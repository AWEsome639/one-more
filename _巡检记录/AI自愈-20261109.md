## 0. 判断（先给结论）

**不能自愈 —— 这是产品缺陷，不是观测结果。**

- 一旦 `LocalLLM.init()` 失败，**`inited` 永远是 `true`**，之后**任何提问都直接走规则版**；
- **诊断卡的「点一下刷新」只重读 `stat`，不重试 `init()`**；
- ⇒ **用户把系统模型装好/修好之后，必须杀进程重启 app，否则永远用不上端侧 LLM**，
  而 UI 上看到的仍是「`init-false` + 问答次数 0」，用户会以为"这功能坏了"。

## 1. 代码证据链（判据 1824：读函数体，不看名字）

`core/LocalLLM.ets`：
```ts
static async init(): Promise<boolean> {
  if (LocalLLM.inited) {              // :63  ★ 一旦 inited 就短路
    return LocalLLM.stat.ready;       //      直接返回上次的结果（false 也一样）
  }
  LocalLLM.inited = true;             // :66  ★ 在 syscap 检查【之前】就置真
  if (!LocalLLM.available()) { ... return false; }   // :67 no-syscap —— 不重置 inited
  try { const ok = await localChatModel.init(); ... return ok; }  // :74–80 init=false —— 不重置
  catch { ... return false; }         // :81–88 init-failed —— 不重置
}
```
- **三条失败路径都没有 `inited = false`** ⇒ 失败即永久缓存。
- `reset()` 确实存在（`:159`），注释写着「诊断/测试用；**正式流程不需要**」——
  **全库 0 处调用**（`grep -rn "LocalLLM.reset"` 只命中定义本身）。
- `LocalLLM.init()` 的**调用方只有两处**：`ChatFinder.ets:478`（聊天）、`Index.ets:168`（启动探一次）。
- **诊断卡刷新**（`SettingsTab.ets:702–706`）：
```ts
.onClick(() => {
  Haptics.tap();
  // ★ 判据 1824 的落地：`LocalLLM.stat` 没有观察源 ⇒ 点一下把它的当前值抄进 @State
  this.refreshDiag();      // ← 只 copy stat，不 init、不 reset
})
```

## 3. 用户影响（为什么这是产品缺陷）

1. 系统模型（`localChatModel`）装好之前，用户用过一次「AI 找游戏」⇒ 该 app 进程内**永久降级**；
2. 用户之后在系统里装好模型、回到 app 继续用 ⇒ **仍是规则版**，**没有任何提示告诉他"要重启"**；
3. 诊断卡上永远是「`init-false`」——**看起来像是设备不支持**，实际是**缓存没刷新**。

## 4. 修法建议（**未实施，先给方案**）

**方案 A（最小改动）**：失败时把 `inited` 重置，并加**冷却**：
```ts
// 失败分支统一走这里
LocalLLM.inited = false;
LocalLLM.lastFailMs = Date.now();
// init() 开头加：
if (LocalLLM.inited) { return LocalLLM.stat.ready; }
if (Date.now() - LocalLLM.lastFailMs < RETRY_COOLDOWN_MS) { return false; }  // 例如 60_000
```
- 效果：**下一次提问会自动重试**（最多 60s 一次），用户装好模型后**最多等 1 分钟**就自愈；
- 代价：重试会再拉起一次系统「模型管理应用」（实测 1118ms，**不阻塞 UI**，但会多一行日志）。

**方案 B（用户显式重试，零自动重试）**：
诊断卡的「点一下刷新」改成 **`LocalLLM.reset(); LocalLLM.refreshDiag()`**，并在 `init-false` 的文案里加一句
「装好系统模型后，**点这里重试**」。
- 效果：**用户有自愈入口**，且不会在后台反复拉起系统模型；
- 代价：用户必须知道"点一下"（文案要写清楚）。

**推荐：B + A 的冷却组合** —— B 给用户主动入口，A 兜住"用户离开设置页后自动再试一次"。
