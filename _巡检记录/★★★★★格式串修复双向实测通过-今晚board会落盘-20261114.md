# ★★★★★ 格式串修复**双向实测**通过 ⇒ 今晚 `board=` 会落盘

> `2026-11-14 21:x`。判据 `2277` 的做法：新写法要能跑、旧写法要能复现错误。

## 一、正向（修后）

```python
fmt = "lowest=%r %s blk=%d/%dpx cov=%d board=%s max=%d -> %s @%s"
args = ("'2＋'", "[60,1521][861,1600]", 2, 48, 3,
        "1560x1560@500,40", 24, "/path/x.jpeg", "2026-11-15T00:10:00")
```

**⇒ 输出：**
```
lowest="'2＋'" [60,1521][861,1600] blk=2/48px cov=3 board=1560x1560@500,40 max=24
  -> /path/x.jpeg @2026-11-15T00:10:00
```

**⇒ ✅ **`cov=3` 与 `board=1560x1560@500,40` 都正确出现在行里。***

## 二、反向（修前）

```python
fmt % args[:8]      # 只给 8 个
```
**⇒ ✅ `TypeError: not enough arguments for format string`**

**⇒ 两侧都验 ⇒ 修复是真的。**

## 三、⇒ 这意味着今晚第一次能拿到什么

| 字段 | 以前 | 今晚 |
|---|---|---|
| `blk` | 有（`303` 行，崩溃行之前算好）| 有 |
| **`cov`** | **永远 `0` 行** | **每行都有** |
| **`board`** | **永远 `0` 行** | **每行都有**（若该款有方形块）|

**⇒ ⇒ 所以今晚跑批的产出不只是一批新截图，而是**台账第一次带上 `cov` 与 `board`**。**

## 四、⇒ 而这决定明早能不能验

**明早的三个判断全依赖这两个字段：**
1. **盘面是否被切** ⇒ 靠 `board` 的 `y+H`
2. **盘面实测高 vs 期望 `240vp`** ⇒ 靠 `board` 的 `H`
3. **文字是否被别的元素盖住** ⇒ 靠 `cov`

**⇒ 若格式串没修 ⇒ 三个都验不了 ⇒ 今天所有分析无法收口。**

## 五、⇒ 而这处 bug 是我今天**唯一一次「在关键路径上」的修复

**其余改的都是工具/文档；只有这一处直接决定今晚产出。**

**⇒ 而它被发现纯属偶然（我在查另一个问题时顺手 `grep` 了那行格式串）。**

## ⇒ 判据（`2372`）

**「顺手看到一个 bug」往往比「专门去找」更有价值 —— 因为专门找只会找自己想到了的。**
**⇒ 这处格式串 bug 若没被顺手发现，今晚会全崩，而**我会以为「跑完了」**（因为脚本会继续跑下一款）。**

**⇒ 判据：一天里最值的修复常常来自「顺手」；所以「顺手」这个动作本身要保留（多 `grep`、多读几行）。**

## ⇒ 判据（`2373`）

**写台账/写日志的那一行，值得**单独测一次格式化**。**
**⇒ 因为它一旦有问题，前面的计算全部白做，而且**表现为「没数据」而非「报错」**（脚本继续跑下一款）。**

**⇒ 判据：落盘那一行是「沉默失败」的高发处 ⇒ 单独验它。**
