## ⚠️ 先回答你的 `GSlide15` 疑问：**不是下限把盘面抬回去了**

封顶式（`:680`）：

```ts
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 360)))
```

代入 853×533（`Space.lg = 18`）：

```
Bp.width − 2×18 = 817
Bp.height − 360 = 173
Math.max(140, 173) = 173      ← 下限 140 **没有生效**（173 > 140）
min(817, 173) = 173
```

**⇒ 盘面确实被压到 173vp 了，封顶是**对的**。**

**下限 140 什么时候才会生效？** 当 `Bp.height ≤ 500` 时（`Bp.height−360 ≤ 140`）。
533 的屏上不会 ⇒ **你的第一个猜测（下限抬回去）不成立。**

**那 1600 从哪来？** 我按块表算下来只**超 ~14vp**（见下），**够不到 53 那 ~58vp**。
两种可能，我倾向前者：

1. **又是编译缓存** —— 今晚已经踩过两次（`GameHost` 的 `-120`、3 个组件的 `SymbolGlyph`）。
   **建议先跑 `grep -c "Math.max(140, Bp.height - 360)" <转译产物 GSlide15.ts>`**，
   =1 才说明封顶真进了包（我查了本地 debug 缓存，**这个文件没有转译产物**，所以没法替你确认）
2. 有一条 `Text(this.hintMsg…)` **没有 `maxLines`** —— 触发提示时如果是长句会换行撑高（最多可加 34~51vp）

**两种情况的对策我都给了补丁**（1-A 收紧封顶、1-B 压按钮、1-C 给 hintMsg 加 maxLines）。

### 1. 最底块

**`Row({ space: Space.md })` 三按钮行（`:703`），高 44——固定值。**

行内三个按钮的高度：

| 按钮 | 高度写法 | 矮屏值 |
|---|---|---:|
| 提示 | **`.height(44)`（写死）** | **44** ⬅ 撑住整行 |
| 打乱重开 | `.height(Bp.isShort() ? Cell.of(32) : Cell.tap(32))` | 30 |
| 重玩本局 | 同上 | 30 |

**⇒ 「提示」是这一行里唯一没做矮屏感知的**，也是行高被锁在 44 的唯一原因。

### 2. 补丁

**1-A：封顶公式收紧（`−360` → `−400`）**

```diff
-      .width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 360)))
+      .width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 400)))
```
**效果**：533−400 = 133 ⇒ 下限 140 生效 ⇒ 盘面 173 → **140** ⇒ **−33vp**
（竖屏 744：344 → 344，仍受 `−400` 约束 ⇒ 344；比原 384 小 40，仍够玩）

**1-B：提示按钮做矮屏感知**

```diff
-          .height(44)
+          .height(Bp.isShort() ? Cell.of(32) : 44)
```
**效果**：行高 44 → 30 ⇒ **−14vp**

**1-C（建议）：给 hintMsg 加行数上限**（防长提示撑高）

```diff
       Text(this.hintMsg.length > 0 ? this.hintMsg : (this.won ? TG('🎉 归位完成！') : TG('点空白格旁边的方块，让它滑过去')))
         .fontSize(FontSize.sm)
+        .maxLines(2)
+        .textOverflow({ overflow: TextOverflow.Ellipsis })
         .fontColor(this.won ? Palette.emerald : this.theme.inkSoft)
```

**合计 −47vp** ⇒ ≈293~327 ✓

## ② `GSlidePuzzle.ets`（592 行）

### 🔴 真因：`FIXED` 常量与注释不一致

```ts
// :440 注释写的是：
//   ④ 用实测数据反推：需要棋盘 ≤ 205vp ⇒ 比例取 0.70。
//      横屏 (533-260)*0.70 = 191vp ⇒ 「重开」约 480vp（安全）
// :443 代码写的是：
const FIXED: number = 200;
```

**代码按 200 算 ⇒ `(533−200)×0.70 = 233`，而注释的意图是 191。差 42vp。**
（那条注释还说「第 1020 轮：与 GBejeweled 同步」—— 同步后忘了改数字。）

### 3. 最底块

**按钮行（`:483`），高 44——固定值**（行内 `.height(44)` 与 `Cell.tap(44)` 混用）。

### 补丁

**2-A：把 `FIXED` 改回注释里的意图值**

```diff
-    const FIXED: number = 200;
+    const FIXED: number = 260;
```
**效果**：`(533−260)×0.70 = 191` ⇒ 盘面 233 → **191** ⇒ **−42vp**
（竖屏 1280：`(1280−260)×0.7 = 714`，受 `max(160, 宽度−40)=813` 限 ⇒ 仍是 714，**竖屏不变** ✓）

**2-B：根 Column 间距 `md` → `xs`**

```diff
-    Column({ space: Space.md }) {
+    Column({ space: Bp.isShort() ? Space.xs : Space.md }) {
```
**效果**：4 个间隙 (16→6) ⇒ **−40vp**

**合计 −82vp** ⇒ ≈355 → 再叠加 2-C 的按钮感知可达 341 ✓

**2-C（可选）：按钮行做矮屏感知**

```diff
-          .height(44)
+          .height(Bp.isShort() ? Cell.of(32) : 44)
```
（该行 `.height(44)` 在文件里**唯一**，已验证）

| 项 | 说明 |
|---|---|
| **vp 全是估算** | `fontSize×1.2`、`Cell.of×0.95` 折算；**没编译没真机**。留的余量按 20~30 设计 |

| **`Cell.tap` 的下限 44** | 我**没有**动任何 `Cell.tap`；动的是 `Cell.of` 与写死的 `.height(44)` —— 前者无下限，后者是按钮容器不是触控面 |
