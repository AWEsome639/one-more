## 1. 检查器做了什么（口径）

**输入**：`entry/src/main/ets/{components,pages,games}/*.ets`（367 个）+ 两个字典：
`core/I18n.ets` 的 `EXTRA`（427 条，`L()/this.t()` 用的）+ `core/GameI18n.ets` 的 `DICT`（4563 条，`TG()` 用的）。

**判据链**（三步都要满足才报）：

1. **纯符号节点**：`Text('✅')`、`Text(this.x ? '▲' : '▼')` 这类 —— 参数里所有字符串字面量都∈符号表、
   去掉字面量后只剩 `this.xxx ? :` 这种骨架（不是别的函数调用）。
2. **相邻兄弟**：另有一个 `Text(this.t(TG('xxx')) / this.t('xxx','en') / TG('xxx') / L('xxx'))`，
   与符号节点**同缩进**、行距 ≤ 8、中间没有「比标签更浅的 `}`」（不跨容器）。
   ★ 额外认一种写法：符号被 `if (...) { Text('⭕') }` 包一层（缩进 +2）—— 渲染出来仍是并排兄弟。
   ★ 三元的**两个分支都要查**（C-2 的 ⭕ 只在第二支）。
3. **字典边界命中**：`xxx` 在 **任一语言**的译文里**以该符号开头或结尾**。

**不算命中的**（写进代码注释，避免下次误报）：
- 符号出现在句子中间（如 ja「大→小は掛け算」）—— 那是正文，不是视觉锚；
- 标签参数里已经**运行时剥符号**（`stripArrow(...)` / 含符号的 `.replace(...)`）—— 可见结果不重复，记为「已净化」；
- 跨容器（如 `Row { Text('▲') }` 与 `Column { Text(t('收起')) }` 是两个容器）。

**覆盖统计**：脚本每次都打印「纯符号 Text / 标签 Text / 配对」三个数；
若**纯符号 Text = 0** 直接退出码 2（防「解析器瞎了所以 0 处」的假绿）。

**证据**（`core/I18n.ets:1619`，11 个语言值**全部**以 ⭕ 开头）：

```

  ja: "⭕ 未プレイ・1回で達成",  ko: "⭕ 아직 없음 · 한 판 하면 완료",
  es: "⭕ Nada aún: juega una",  fr: "⭕ Rien encore — jouez",
  de: "⭕ Noch nichts — spiel eine", pt: "⭕ Nada ainda — jogue uma",
  ru: "⭕ Пока пусто — сыграйте", it: "⭕ Ancora nulla — gioca",
  ar: "⭕ لا شيء بعد — العب جولة", zh-Hant: "⭕ 還沒玩 · 來一局就打卡" }
```

**为什么漏到今天**：lead 修 C-2 时的注释写的是「未打卡那支译文**不带符号**，保留 ⭕ 作视觉锚」——
但字典里那一支**带** ⭕（只有 zh 原文和 en 入参不带）。
⇒ **未打卡状态下 11 种语言仍显示「⭕ ⭕ …」**（已打卡那支因为删了独立 ✅ 所以已经正常）。

**修法（各 1 行，二选一，与 C-1 保持同一套口径最稳）**：
- **推荐**：照 C-1 的做法 —— 组件统一负责画符号，标签**统一剥掉**译文自带的符号
  （`stripArrow()` 扩成 `stripMark()` 同时剥 ▲▼✅⭕ 等），这样 zh/en 也有符号、11 语言不重复；
- 或者：删掉 `Text('⭕')`，同时给字典里那 11 条**去掉 ⭕**（但 zh 原文 `还没玩 · 来一局就打卡` 也就没锚了，zh/en 界面会突然少个图标）。

## 5. 已知边界（写清楚，免得当成「全清了」）

1. **只看相邻 `Text` 兄弟**：不覆盖「`Text` 与 `Button` 混排」「符号在父容器、标签在子容器」等结构（那两种今天扫到的都是正常用法）。
2. **只查开头/结尾**：句子中间的符号（正文）不算 —— 这是有意的，否则 `大→小` 这类会全是噪音。
3. **只认三种标签形态**：`this.t(...)` / `this.tn(...)` / `TG(...)` / `L(...)`。
   `Text(displayName(g))`（游戏名走 `GAME_NAME` 字典）**没覆盖** —— 游戏名里出现符号的概率极低，先不做。
4. **净化识别是名单制**：`stripArrow/stripArrows/trimArrow/stripMark/stripSymbol/stripEmoji/stripLeadingMark` + 含符号的 `.replace(...)`。
   将来如果有人写 `cleanMark()`，需要往 `SANITIZE_RE` 里加名字（脚本头部有注释）。
5. **跨文件/运行时不涉及**：这是静态检查，语言切换、`@Builder` 记忆化等运行时问题不在射程内。
6. **依赖 `tools/check_i18n.py` 的解析器，但带自包含兜底**：
   `tools/check_i18n.py` 正被队友频繁改动（2026-11-07 22:39 刚改过一次），
   若它改名/重构导致导入失败，本检查器自动切到内置的 `local_parse_dict`（同一套括号栈算法），
   两条路实测**字典条数与结论完全一致**（427 / 4563 / 1 处）。
