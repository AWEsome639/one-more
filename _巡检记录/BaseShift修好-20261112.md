# `Base Shift`（进制移位）修好：**`D` 从「完全在屏外」到「可见可选」**

## 之前为什么失败

**我第一次改的是 `L532` 的 `Cell.of(46)`** —— **那是「重开」按钮**（矮屏本来就 `visibility(None)`），
**改它对选项毫无影响 ⇒ 截图里选项反而显得更挤。**

## 真正的刀口（`probe` 数据反推）

```
Column h=492 y=[1108..1600]   ← 选项区总高 492px
Row    h=132 y=[1468..1600]   ← 单行 132px = 44vp
```

**`132px` = `Cell.of(52)`（`52 × 0.85 = 44.2vp`）—— 而 `Cell.of` 是**可以缩的**（判据 1899 只限制 `Cell.tap`）。**

**⇒ 4 行 × `132` = `528px` > 可用 `492px` ⇒ 超 `120px`。**
**⇒ 选项行 `Cell.of(52)` → 矮屏 `Cell.of(34)`：每行省 `46px`，4 行省 `184px`。**

## 结果

| | 改前 | 改后 |
|---|---|---|
| `A` | 可见 | 可见 |
| `B` | 可见 | 可见 |
| `C` | **只露顶边** | **完整** |
| **`D`** | **完全在屏外** | **可见（`D 121`）** |
| `max_bottom` | `1578` | `1569` |

**⇒ 从「只有 2 个选项可选、游戏玩不了」变成「4 个都能选」。**

## 判据 1958（立）

> **`probe` 给出的「行高像素」要换算成 `vp` 再对代码：`132px ÷ 3 = 44vp`，
> 而 `Cell.of(52)` = 44vp、`Cell.tap(52)` = 52vp —— `Cell.of` 与 `Cell.tap` 在同参数下差 `8vp`。**
>
> **⇒ 反推时必须两个都算一遍，取匹配的那个** —— 我第一次就是因为「看到 44 就以为是 `Cell.tap(44)`」而放弃（以为不可缩）。
> **实际上它是 `Cell.of(52)`（= 44vp）—— 完全可以缩。**
