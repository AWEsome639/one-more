# 判据 1821 撤销（2026-11-08 立，同日撤销）

## ❌ 原判据（错误）
> `position({ x: '50%' })` 的百分比字符串**不生效** ⇒ 所有元素会叠在容器中心。

## ✅ 真机反证（`verifier-dev`，一次定性）

**打开「华容道」**（`GKlotski:708`，10 个棋子全用 `position({ x: blocks[i].x*100/COLS + '%' })`）：
- **截图**：张飞/曹操/赵云/马超/关羽/黄忠/4 个卒，**各在各的格子**，**没有叠左上角**
- **`dump` 棋子中心**：`x = 456 / 1137 / 1232 / 1280 / 1327 / 1422 / 2103`，`y = 790 / 1039 / 1184 / 1233 / 1280 / 1329 / 1377`
  ⇒ **位置各不相同**

**⇒ `position({ x: '…%' })` 是生效的。**

## 当初为什么会误判

**`GPong` 的球/球拍全叠在 `x≈1268` 中线** —— 表面看像「`position` 没生效」。

**真因（后来用 `hilog` 数值证明）**：
- **`.aspectRatio(0.7)` 把 `Canvas` 撑到 `813.33 × 1161.90vp`**
- **`1161.9 × 3（density 480）= 3486px`**，**屏幕只有 1600px** ⇒ **可见仅 21%**
- **而那两根「叠在中线的竖条」**：**`0.495 × 813vp ≈ 402vp → 页面 x ≈ 1267`**
  —— **正是中线（10 段）里露出来的顶部 2 段**（**宽 1%≈24px、高 4%≈139px**，**与节点 `[1267,1065][1292,1205]` 完全吻合**）

**⇒ 是「容器撑爆被裁剪」，不是「`position` 不生效」。**

## `code-hunter` 的三条反证（其中两条是独立的）

1. **`git show 5174e4c8`**：提交信息「**🚨 真 bug：开屏颗粒全部跑到屏幕外**」
   **diff 只两行**：`x: (... * (this.vw > 0 ? this.vw : 440)) + 'vp'` → `x: (((i * 37 + 11) % 100)) + '%'`
   **从 `vp` 改成 `%` 把 bug 修好了，而且没动容器**
   ⇒ **如果 `%` 被忽略，200 颗颗粒会全塌到 (0,0)，那不叫修好**
2. **判据 1821 自己的「决定性对照实验」用的是打砖块连拍 `md5` 全不同**
   —— **而 `GBreakout` 的球拍/球/砖块全是百分比定位**（`:591/:600/:745`）
   ⇒ **打砖块会动就说明 `%` 生效**

## 教训（这条比判据本身值钱）

**「元素叠在容器中心」有两个完全不同的原因**：
1. **`position` 没生效**（**元素真的都在原点**）
2. **容器撑爆被裁剪**（**元素位置是对的，只是大部分在屏外**）

**区分方法：量容器尺寸。**
- **容器 > 屏幕** ⇒ **是裁剪**（**判据 1822**）
- **容器正常** ⇒ **才是 `position` 的问题**

**我当时跳过了「量容器」这一步，直接从「看起来叠在中心」推到「`position` 不生效」。**
