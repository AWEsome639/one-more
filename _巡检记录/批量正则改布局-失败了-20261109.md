# 批量正则改 53 款统计卡：**编译失败，已整目录回退**

## 我做了什么

**统计卡「竖排两行 → 横排一行」已经成功 4 次**（`Tetris` / `Nim` / `Bridges` / `Corsi Blocks`），
于是想「一次改 53 款」：

```python
pat_label = Column\(\{ space: 2 \}\) \{\n(body 1-8 行内出现 FontSize.xxs)
tail      = }.layoutWeight(1).padding(Space.sm).backgroundColor(this.theme.surface)
```

**⇒ 改了 53 款。**

## 结果：**编译失败**

```
GEventTimelineMemory.ets:374  arkts-no-implicit-return-types / arkts-no-any-unknown
```

**原因**：**`Column({ space: 2 })` 在 ArkTS 里不只有「统计卡」一种用法** ——
有的文件里它是**别的容器**（甚至包着 `@Builder` 调用），**正则把它们也改成 `Row` 了**。

## 处置

**`git checkout -- entry/src/main/ets/games/` 整目录回退**（HEAD 是绿的）⇒ **无残留**。

## 判据 1863（立）

> **「批量正则改 ArkTS 布局」不可行** —— 因为
> 1. **`Column` / `Row` 是容器类型，改错了不一定编译报错（报错了也要等 10 分钟一次全量）**
> 2. **`arkts_check` 在这台机器上不可用**（缺 node：`neither DevEco tools/node nor Command Line Tools node/`）
> **⇒ 只能「一次一款 + 一次编译 + 一次真机量」**，或者**先补 `arkts_check` 的 node**

## 而它反过来证明了一件事

**这条「统计卡横排」的修法本身是对的**（4 次都有效），
**错的是「我一次改 53 个」的方法** —— **边际收益快，但风险是「一次废掉 53 款」。**

**⇒ 正确做法：按扫描结果排序，一次 1–2 款，改完立刻编译+真机量。**
