# 剩余三处被切按钮：各自的**精确障碍**（明天照着改，不用重推）

> `2026-11-15 12:51`。`Kakuro` 已修好（`60→132px`，配方：找最大弹性元素、按缺口算 vp、再压一档）。
> 下面三处用同一思路查过，**各有各的障碍**，逐条记清。

## 一、⇒ `Countdown Math`（缺 `63px`）

**代码事实：**

```
L542  .width(Math.min(Bp.width - 2*Space.lg, Math.max(240, Bp.height - 360)))
L548/563/578/593  4 个运算符 .layoutWeight(1).height(Cell.of(52))
L617  .height(Cell.of(40))
L630  提示按钮 .width(120).height(Cell.tap(44))
```

**⇒ 障碍：`L542` 的 `-360` 外面包着 `Math.max(240, …)`，而 `533-360 = 173 < 240` ⇒
   **它已经卡在 `240vp` 下限，改 `-360` 完全无效**（这解释了为什么 `Kakuro` 的 `-360→-390` 手法在这里不能用）。**

**⇒ 剩余杠杆：运算符 `Cell.of(52)→Cell.of(44)`（省 `~15px`）+ 数字行 `Cell.of(40)→Cell.of(34)`（省 `~10px`）
   ⇒ 合计 `~25px`，**不够 `63px`**。**

**⇒ 结论：必须 `dump` 看「`目标` 卡片占多少」——若那张卡是固定高度，它就是唯一的大杠杆。**

## 二、⇒ `Snake 3D`（缺 `50px`）

**代码事实：**

```
L47   const BTN_H = 44      ← 开始/重新开始按钮，已是触控下限
L703  .height(Cell.of(38))  ← 方向键行（共 2 行）
```

**⇒ 障碍：底部按钮 `BTN_H=44` 不能缩；方向键 `Cell.of(38)`=`23vp`=`69px`/行 × 2 行 = `138px`。
   压到 `Cell.of(30)` 只省 `26px`（不够）；压到 `Cell.of(24)` 省 `48px` ≈ 够，但**单个方向键只剩 `15vp`
   （`45px`），低于 `44vp` 触控下限**。**

**⇒ 结论：必须先 `dump` 看「三层棋盘」占多少 —— 三层 `5×5` 盘才是最大的弹性块，
   缩棋盘比缩方向键更划算（格子缩一点仍可点，`Kakuro` 的 `34vp` 格子已验证）。**

## 三、⇒ `Wordle`（缺 `104px`）

**⇒ 已知三变量冲突（判据 `2699`）：棋盘 `120vp` 已到下限、`KEY_H` 是 `b2cacc75` 十四次收敛的成果、
   底部按钮 `44vp` 是触控下限。缺口又最大（`104px` = `35vp`）。**

**⇒ 唯一可行：`dump` 后把「键盘容器」从「3 行固定 `KEY_H`」改成「3 行 `layoutWeight(1)` + 容器定高」，
   让键盘吃剩余、把省下的给底部 —— 即 `Pipes` 配方**用在键盘容器上**，而不是棋盘上。**

## 四、⇒ 三处的共同下一步

**⇒ 每一处都必须**先 `dump`**，因为「最大的弹性元素」各不相同：**
- `Countdown Math` → 可能是 `目标` 卡片
- `Snake 3D` → 三层棋盘
- `Wordle` → 键盘容器

**⇒ 而 `Kakuro` 之所以一次命中，是因为它的弹性元素写在注释里（作者已定位到棋盘）。

## ⇒ 判据（`2716`）

**「按缺口缩最大弹性元素」这个配方，**前提是能找到那个元素**。
`Kakuro` 能找到（变量 `Bp.height - 360` 直接控制棋盘）；**
**`Countdown Math` 找不到（同一变量被 `Math.max(240, …)` 钉死在下限）⇒ 配方失效。**
**⇒ 判据：套配方前先确认「那个尺寸变量**当前没有被 clamp 到底**」；
    若已到下限，必须先找**另一个**变量，而 `dump` 是唯一可靠的办法。**
