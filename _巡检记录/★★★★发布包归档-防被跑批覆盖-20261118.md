# 发布包归档：防止被夜间跑批的 debug 编译**静默覆盖**

> `2026-11-18 03:54`。**又一个「代码对了、但机制会坏事」的坑。**

## 一、⇒ 风险

**⇒ 验证过的 release 包放在 `entry/build/default/outputs/default/entry-default-signed.hap`。**
**⇒ 而 `00:00` 的夜间跑批会**重新编译**（默认 debug）⇒ **同一个路径被 debug 包覆盖**。**
**⇒ 结果：你以为拿到的是验证过的 release 包，实际是 debug 包 —— 而且文件名一模一样，看不出区别。**

## 二、⇒ 处置

**⇒ 已归档到**不会被清理、也不会被构建覆盖的位置**：**

| 项 | 值 |
|---|---|
| 路径 | `release/onemore-1.0.1-release-20261118-0354.hap` |
| 大小 | **`29,556,695` 字节** |
| `SHA256` 前 24 位 | `c531201745537968d1340d4c` |
| git | **不进仓库**（`29.5 MB` 二进制会撑大仓库）⇒ 已加进 `.gitignore` |

## 三、⇒ 以后怎么取

**⇒ 发版时用 `release/` 下的那份（带日期与 `release` 字样），不要用构建目录里的 `entry-default-signed.hap`。**
**⇒ 想确认是不是同一份：`shasum -a 256` 比对前 `8` 位。**

## ⇒ 判据 `2890`

**⇒ 任何**验证过但仍放在构建输出目录**的产物，都必须**复制到独立目录**并记下大小与哈希。**
**⇒ 因为构建输出目录是**临时区**：下一次编译（尤其夜间自动跑批）会静默覆盖它，而文件名不变。**
**⇒ 同类风险：`entry-default-unsigned.hap`、未来的 `.app`/`.zip` 包。**
