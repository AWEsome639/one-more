# ★★ 装包校验闸原本**是空的** —— 真机格式是毫秒 epoch，不是我假设的日期串

> `2026-11-14 12:0x`。**这是今天最后一个、也是最讽刺的一个 bug：我为堵「测旧包」写的闸，自己从来没生效过。**

## 一、我假设的格式 vs 真实格式

**我写的正则**（假设 `bm dump` 输出带日期串）：
```
20[0-9]{2}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}
```

**而真机格式是毫秒 epoch 数字** —— 证据在我自己的台账里
（`_巡检记录/12语言真机2-20261108.md`）：

```
"updateTime": 1794075532557  ⇒ 2026-11-08 02:18:52
```

**⇒ 两者永远匹配不上 ⇒ 闸门永远走「读不到 `updateTime`」分支。**

## 二、而我差点让它变成「永久挡住」

**原版那个分支是 `exit 1`。**
**若我没在 `11:5x` 把它改成「警告 + 放行」（判据 `2090`），今晚的结果会是：**

```
⚠️ 读不到 updateTime ⇒ 不要硬跑 ⇒ exit 1
```

**⇒ 一次都没跑成的夜晚。** 而原因只是**我的正则写错了格式**。

**⇒ 两个 bug 互相掩盖**：格式错 ⇒ 永远走错误分支；若那个分支是 `exit 1` ⇒ 整夜白等。
**两个都改掉之后，闸才真的能工作。**

## 三、修法

```bash
_raw=$(echo "$DUMP" | grep -oE '"updateTime"[^,}]*' | head -1)
DEV_T=$(echo "$_raw" | grep -oE '20[0-9]{2}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}')   # 日期串
DEV_MS=$(echo "$_raw" | grep -oE '[0-9]{13}')                                              # 毫秒
if [ -z "$DEV_T" ] && [ -n "$DEV_MS" ]; then
  DEV_T=$(date -r $(( DEV_MS / 1000 )) '+%Y-%m-%d %H:%M:%S')                               # 转换
fi
```

**离线验证（三种输入）：**

| 输入 | 输出 |
|---|---|
| `"updateTime": 1794075532557` | **`2026-11-08 02:18:52`** ✅ **与台账原文逐字一致** |
| `"updateTime": "2026-11-14 07:31:03"` | `2026-11-14 07:31:03` ✅ |
| `"updateTime": 456` | `<解析不出>` ✅ 太短，正确拒绝 |

## 四、为什么这条差点滑过去

**我写这个脚本时没有任何设备**，`bm dump` 的输出是**凭空假设**的。
而「假设的格式」正好写成了一个看起来很合理的日期串 —— **它不会报错，只会静默走另一条分支。**

**⇒ 真正的救命是那个 `find`：**
```bash
grep -rhoE '"updateTime"[^,}]{0,40}' _巡检记录/*.md
```
**它在 `1794075532557` 那一行命中 —— 一个今天下午写的脚本，被自己一周前的台账文档纠正了。**

## ⇒ 判据（`2091`）

**写「解析外部输出」的代码之前，先在仓库里搜一遍这个输出**有没有被抓下来过。
- 有 ⇒ 拿真实样本写正则，并**用样本做离线验证**（这次三步验证，`3/3` 对）
- 没有 ⇒ 把「解析失败」的路径设成**警告而非阻断**（判据 `2090`），因为你的假设很可能错

**⇒ 判据（`2092`）：两个 bug 互相掩盖时，只修一个会得出错误结论。**
这次：格式错（A）+ 失败分支太狠（B）。
- 只修 A ⇒ 闸能工作，但你不知道它原来从没工作过
- 只修 B ⇒ 闸能放行，但它永远不校验
- **两个都修，才发现「它一直是空的」这个事实本身**

**⇒ 所以：修一个 bug 时若发现「它旁边还有一个」，不要只修眼前那个 —— 
要问「这两个合起来，会让什么结论变成假的」。**
