# ★★ 明早流程：用 `fixed_audit.py --opt` 拿到每款正确的 `cap`

> `2026-11-14 13:5x`。今晚数据的**真正用途**在这里。

## 一、今晚数据到手后的三步

### 第 1 步：跑 `fixed_audit.py --opt`

```bash
python3 工具/fixed_audit.py --opt
```

**它算：**
```
FIXED_px = max_px − board_H_px        ← 第 4 列 max_bottom，**不是** max= 字段（判据 2024）
FIXED_vp = FIXED_px / 3               ← 2560×1600@480 ⇒ 3px = 1vp
最优 X   = FIXED_vp + MARGIN(30vp)    ← 每款的正确偏移量
```

### 第 2 步：⚠️ 人工确认「最大方形块」是不是真棋盘

**工具自己写明的局限：**
> 「最大方形块」不一定是棋盘（**大按钮/弹窗也可能**）⇒ 名单要人工确认

**⇒ 所以拿到名单后，逐个看 `board=WxH` 的**尺寸是否符合棋盘**：
- `4×4` 棋盘 ⇒ 每格 `W/4` 应 ≈ `Cell.of(88)` 或类似
- `3×3` 键盘 ⇒ `W/3` ≈ `Cell.tap(44)`
- **若 `W` 是个按钮宽度 ⇒ 那不是棋盘 ⇒ 该款要排除或手工指定**

### 第 3 步：把 `-360` 换成每款的 `cap`

**这才是正解。**
**⚠️ 但 `cap` 是**每款一个值** ⇒ 不能批量替换成一个新常量。**

**⇒ 两种落地方式：**
| 方式 | 做法 | 适用 |
|---|---|---|
| **A** | 每款改成 `Math.max(140, Bp.height - <该款 FIXED+30>)` | 只需改那个数字 |
| **B** | 新增工具函数 `Layout.capFor(fixedVp)`，各款传自己的 `FIXED` | 更集中，但要改签名 |

**⇒ 推荐 `A`**（每款直接写死自己的值，`-360` → `-<FIXED+30>`）
⇒ 因为 `A` 只改一个数字、与现有形态一致、且**回退容易**。

## 二、⇒ 但明晚第一次编译仍只能做「止血」

**因为 `board=` 是今晚产出的 ⇒ 明晚编译时数据刚到手，**来不及把 `355` 款都算完并人工确认**。**

**⇒ 所以顺序是：**
```
今晚：跑数据 → board= 到手
明早：fixed_audit --opt → 人工确认名单 → 得出「每款 -360 差多少」的分布
明晚：第一次编译仍做 240→140 那 18 处（止血，无条件正确）
      + 勾股数 + GSnake3D
第二次编译：按逐款 cap 批量替换偏移量（正解）
```

## 三、⇒ 而「差多少」的分布本身就是结论

**若 `FIXED` 分布集中在 `330`–`390` ⇒ `-360` 大部分对，只需修少数离群款。
⇒ 若分散在 `211`–`350` ⇒ **大部分款都错**，必须逐款化。**

**⇒ 所以明早第一件事不是「数多少款溢出」，而是**先看 `FIXED` 的分布形状**。**
⇒ 它会决定「逐款化」是「修少数离群」还是「全量重写」。

## ⇒ 判据（`2225`）

**一个「正确答案需要逐项计算」的问题，先看**那些逐项值的分布**，再决定策略。**
- **分布集中** ⇒ 全局常量近似可接受，只修离群
- **分布分散** ⇒ 必须逐项化

**⇒ 判据：不要一看到「应该逐款算」就立刻逐款化 —— 先看分布。
⇒ 若 `90%` 的款都在一个窄区间内，全局常量 + 少数例外，比全量逐款化**成本低得多。**
