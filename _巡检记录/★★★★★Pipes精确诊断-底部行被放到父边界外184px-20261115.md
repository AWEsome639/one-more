# ★★★★★ `Pipes` 精确诊断：底部行被放到**父边界外 `184px`**、高度被压成 `65px`

> `2026-11-15 10:25` dump（`120` 节点）。**两次尝试都失败，但这次把数字拿全了。**

## 一、⇒ 父链与预算（dump 实测）

```
Column  h=1399  y=117 -1516      ← 页面（.height('100%')）
 └ Column  h=1030  y=381 -1411   ← 内容区
    └ Column  h=970   y=381 -1351  ← 内层（父给了 970px）
       ├ Row   h=114  y=411 -525    ← 「AI 代打」按钮行
       ├ Row   h=140  y=555 -695    ← 统计行
       ├ Column h=780 y=725 -1505   ← 网格（5 行）
       └ Row   h=65   y=1535-1600   ← 底部行（说明 + 提示按钮）
```

**⇒ 子元素合计：`114 + 140 + 780 + 132(底部行应需) + 间隙 ≈ 1200px`，而父只有 `970px` ⇒ **超 `~230px`**。**

**⇒ 结果：底部 `Row` 被放到 `y=1535`（父底 `1351` 之外 `184px`），高度被压成 `65px`，
   而里面的 `Button` 需要 `Cell.tap(44)` = `44vp` = `132px` ⇒ **按钮溢出自己的行、被行边界裁掉**。**

**⇒ 注意：**不是屏底裁的，是它自己的父 `Row` 太小**（`65px` vs 按钮 `132px`）。**

## 二、⇒ 两次失败为什么失败

| 尝试 | 改法 | 结果 |
|---|---|---|
| ① `PIPE_CELL=46` | 格子改显式 `46×46` | **更糟**：底部行从“露顶端”变成“完全不见” |
| ② （未做） | — | — |

**⇒ ① 失败原因推测：格子显式尺寸后，`Row({space: Space.xs})` 的 `5×46 + 4×6 = 254vp` 超过行宽 `240vp`，
   布局反而重新分配；且网格容器（无 `layoutWeight`、`wrapContent`）没被约束 ⇒ 空间没真正让出来。**

## 三、⇒ 下次的正确改法（有把握的一条）

**必须让「网格 5 行的高度」由容器高度分配，而不是由格子宽度决定：**

```typescript
// 现在：格子 layoutWeight(1).aspectRatio(1) ⇒ 高度由宽度(240/5=48vp)决定 ⇒ 5 行 240vp
// 改成：每一行 Row 加 .layoutWeight(1)，格子 .height('100%').aspectRatio(1)
Column({ space: Space.xs }) {
  ForEach(this.rowIdx(), (r) => {
    Row({ space: Space.xs }) {
      ForEach(...) => Stack(){...}.height('100%').aspectRatio(1)
    }.layoutWeight(1)          // ★ 行高由容器分配
  })
}.height(184)                  // ★ 容器显式高度（= 323vp 可用 − 85vp 固定 − 6vp 间隙 − 44vp 底部）
```

**⇒ 这样 5 行各得 `~36vp`、格子 `36×36`，底部行拿到完整 `132px`。**

**⚠️ 风险：`layoutWeight(1)` 在 `Column` 里对 `Row` 生效需要容器有确定高度 ⇒ 所以容器 **必须** 加 `.height(184)`。**

## ⇒ 判据（`2695`）

**当「底部行高度被压」时，先查**它父容器的高度预算**，而不是查屏底。**
**⇒ 今天 `Pipes`：父 `970px`、子需 `1200px` ⇒ 底部行被压到 `65px`、位置越出父界 `184px`。
    `blk=2/48px`、`over=0px` 都反映不出「父容器预算不足」这一类。**

**⇒ 判据：`dump` 里算「子元素高度之和 vs 父高度」；子 > 父 ⇒ 排最后的那一项会被压/被挤出，
    与 `blk`/`over` 无关。**`over` 只比单个父子，不比「所有子之和」。**
