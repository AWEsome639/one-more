# 判据 1843（2026-11-09 03:25 立，`ai-fixer-b` 提炼）

## 1843 · 问一句：「这串题面字是『输入』还是『输出』？」

**来源**：**`GConsonantReconstruct`** 的修复（**今晚最深的一层**）。

### 问题结构

**原来 UI 是**：
```ts
Text(skeleton(this.cur().w))   // ← 题面由「答案」现算出来
```

**⇒ AI 只能读答案**（**因为「题面」就是「答案」的函数**）
**⇒ 玩家也只能猜**（**因为「题面」不独立存在**）

**修法**：
```ts
@State skelText: string = '';              // ← 题面变成独立字段
// reset()/nextQ() 里写入
this.skelText = skeleton(POOL[order[i]].w);
// UI 改渲
Text(this.skelText)
```

**⇒ 题面变成「输入」**（**AI 和玩家都读它**）。

## 判据

> **看到 UI 里有「现算的字符串」时，先问一句：**
> **「这串字是『输入』还是『输出』？」**
> **是「输出」（由答案派生）⇒ 先挪成独立 `@State`，再谈 AI。**

## 为什么这条重要

**「AI 抄答案」有三种形态**：

| 形态 | 例子 | 修法 |
|---|---|---|
| **① 直接读答案字段** | `this.ans` / `opts[i].ok` | **改 AI** |
| **② 读「答案的函数」** | **`skeleton(this.cur().w)`** | **先修题面，再改 AI**（**本判据**） |
| **③ 题库查表** | `GCrossword` / `GWordSurge` | **无规则，跳过** |

**⇒ 形态 ② 最隐蔽**：**代码里看不到 `this.ans`，`grep` 也搜不到** ——
**因为「答案」藏在「题面的生成式」里。**
