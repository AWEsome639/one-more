# 判据 `3102`：像素检测器**只能扫「当前构建拍的截图」** —— 旧截图会给出 78% 的假阳性

## 一、现象

`detect_bottom_clip.py` 在全库「每款取最新一张」上跑：

```
共 356 款有截图
⚠️ cov ≥ 0.60 的: 277 款（78%）
```

⇒ 看起来「七成游戏底部被切」—— **完全是假的**。

## 二、诊断

抽几款**今天新拍**的验证：

```
截图-Peg_Solitaire-112709.jpeg   cov=0.00
截图-Bridges-112935.jpeg         cov=0.00
截图-Sudoku_Hex-104914.jpeg      cov=0.00
截图-Gomoku-111701.jpeg          cov=0.00
截图-Be jeweled-113522.jpeg      cov=0.00
```

⇒ 检测器本身没问题。那 `277` 里绝大多数是 **`cov=1.00`** ——
来自**旧版本 UI / 搜索页 / 首页 / 键盘盖屏**，与当前代码无关。

## 三、正确用法：只扫当天拍的

加了 `--today` 模式（按文件 `mtime` 过滤到当天 + 每款取最新）：

```
python3 工具/detect_bottom_clip.py --today
# → 今天拍过截图的 19 款，cov ≥ 0.60: 0 / 19
```

⇒ **当前构建下，今天量过的 `19` 款没有一处底部被切。**

## 四、判据

> **同一个「截图」目录里混着好几个版本的 UI —— 拿它当数据集跑检测器，量到的是历史，不是现在。**

⇒ 四条：
1. **像素/截图类检测器必须带「时效过滤」**（`mtime` 当天 / 某个 commit 之后），否则误报率会到 `78%`
2. **「每款最新一张」仍不够** —— 只要这款今天没拍，它的「最新」就是几天前的
3. **验证检测器要分两步**：先在小样本（已知好/已知坏）上回归，再在大样本上看误报率
4. **`cov=1.00` 是个信号**：整行被铺满 ⇒ 要么是全屏棋盘（正常）、要么是键盘/搜索页（伪影）
   ⇒ **见到 `1.00` 先怀疑「这不是游戏内截图」**
