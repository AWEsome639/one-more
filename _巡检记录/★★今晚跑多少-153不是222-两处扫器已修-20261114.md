## 三、我修的两处（`--dry` 实测发现，都有证据）

### ① 批大小 `40 → 12`：把越界从 `1h43m` 压到 `~31m`

`06:45` 的检查**只在每批跑完之后**（`sweep_all.sh:149`），批 `40` 款 ⇒
`40 × 155s = 1.72h` ⇒ **最坏会跑到 `~08:00`，冲进奥森睡醒的时间**。

**改成 `12`**（`12 × 155s ≈ 31` 分钟）⇒ 最坏越界 `31` 分钟。
代价：多几次 `python` 启动（约多 `13` 分钟）。**换掉最多 `70` 分钟越界，值。**

### ② 顺序 bug：打印说「缺数据 `5` 款顶到最前」，实际排在第 `39`–`43` 位

原逻辑：
```python
if gaps: todo = gaps + [...]        # 先拼 gaps
if prio: todo = prio + [...]        # 后拼 prio ⇒ 把 gaps 顶到后面去了
```
**⇒ 实际顺序是 `prio → gaps → 其余`，与打印的相反。**

**改法**：`gaps` 的定义与 `prio` 过滤留在原位（`L86` 要引用它），只把「拼到最前」挪到 `prio` 之后。
**⚠️ 我第一次改时把 `gaps` 的定义也挪走了 ⇒ `NameError` ⇒ 整个优先排序被跳过、待测从 `245` 变 `210`。**
**`--dry` 立刻抓到了**（`（优先排序跳过: name 'gaps' is not defined）`）——**这就是为什么每改一处都要立刻跑一次 `--dry`。**
