# `verify_layout.py` 加了「设备看门狗 + 失败重试」

## 为什么（今天 `23/25` 全挂的直接教训）

**今天跑批 `25` 款只成 `2` 款** —— 跑完 `hdc list targets` 是 `[Empty]`：
**模拟器在批中静默消失了。**

**「每 `15` 款重启一次」根本不够** —— 它假设「设备一直在」。
**⇒ 必须在**每款之前**探活。**

## 加了两件事

### ① `device_alive()` + `ensure_device()`

```python
def device_alive():      # 跑 hdc list targets，看有没有 IP:端口 行
def ensure_device():     # 不在就 kill -9 残留 → -stop → -start → 轮询 200s 到活 → tconn
```
**每款开始前都调 `ensure_device()`** ⇒ 设备中途崩了会在下一款前被拉回来。

### ② 失败款自动重试一轮

**第一轮「测不到」的款，第二轮再跑一次**（`--no-retry` 可关）。
**理由**：第一轮的失败多半是「设备刚好不在」，而第二轮开始前 `ensure_device()` 已经把设备保活。

**⇒ 判据 1947（立）**：
> **「每 N 个重启一次」是**被动**策略，假设对象一直在；「每次之前探活」才是**主动**策略。**
> **⇒ 长跑脚本要在**每个工作单元之前**确认依赖可用，而不是「每隔 N 个单元维护一次」。**
