## 一、电视适配**已经存在**（不是 deferred）

### `core/Bp.ets`

| 机制 | 代码 | 效果 |
|---|---|---|
| **`scale()`** | `if (Bp.dev === BpDev.TV) return 1.45;` | **所有 `Cell.of()` / 尺寸 ×`1.45`** |
| **`cols()`** | `if (Bp.dev === BpDev.TV) return base + 2;` | 列表/网格 **多排 `2` 列**（不浪费大屏）|
| **`isShort()`** | `return Bp.height < 690 && !Bp.isTv();` | TV **永不进「矮屏」分支** ⇒ 不会误缩 |
| **`isTv()`** | `Bp.dev === BpDev.TV` | 设备类型判据（`module.json5` 的 `deviceTypes`）|

### `core/Tv.ets`（`199` 行）

**遥控器焦点导航**：`focusOutline()` 自绘焦点框、`handleKey()` 方向键/确认键处理、`on()` 开关。

### 全库用法

**`isTv()` 用在 `5` 个文件**：`Bp` / `Tv` / `Design` / `Common` / `GamesTab`
**⇒ 也就是：**共享组件层已适配，游戏内靠 `scale()` 自动放大****（`355` 款游戏**不用逐个改**）。

## 三、为什么我不动 `1.45 → 1.8`

**① `1.45` 是有人**算过**的**（`Bp.ets` 注释写「`3` 米视距，必须大」）；
**② 调大 `×1.8` 会让所有 `Cell.of()` 再涨 `24%`** ⇒ **矮屏上会溢出，大屏上可能反而挤**；
**③ 而我们**没有 TV 设备** ⇒ 改了也无法验证 ⇒ **等于制造一个「看起来更好」的未知状态**。

**⇒ 判据：**没有验证手段的参数改动，不做。****
**⇒ 这条和今天反复犯的错是同一个：**「我觉得会更好」不是证据。****

## 六、`GameHost` 那句「上下键暂不处理」到底指什么

**读原文（`pages/GameHost.ets:3878-3886`）才明白：**

> **✅ 唯一有效的做法：自己实现方向键导航**
> · **顶栏 `5` 个按钮**：稳定 id `hdr-0..4` + 显式 `requestFocus`（差异 `24699`，已验证）
> · **棋盘 `1166` 处格子**：需要先给每处一个稳定 id —— **独立工程**
> **⇒ 所以这里保留顶栏的显式移动；上下键暂不处理（棋盘还没接进来）。**

**⇒ 所以「棋盘还没接进来」指的是 **`GameHost` 这一层**（宿主页面）不去管棋盘焦点，
**而不是「游戏没做电视适配」** —— 棋盘焦点是**各游戏用 `Tv.handleKey` 自己处理的**。**
