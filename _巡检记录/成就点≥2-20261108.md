## 0. 结论（先说，因为它推翻了原计划）

**「连玩 2 遍 ⇒ `●●○○`、再玩一遍 ⇒ `●●●○`」这个预期是错的。**
四个点**不是按"通关过几次"点亮，而是按通关次数的【阈值】**（`components/Common.ets:925–928`）：

```ts
const n = clearsMap.get(id) ?? 0;
if (n >= 100) { return 4; }   // ●●●●
if (n >= 50)  { return 3; }   // ●●●○
if (n >= 10)  { return 2; }   // ●●○○   ← 「≥2 实心」要的是这个
if (n >= 1)   { return 1; }   // ●○○○
return 0;                      // 没通关：整组不画
```

⇒ **要看到 `●●○○`，必须把同一款玩到【10 次通关】**；玩 2、3 次仍然是 `●○○○`。
⇒ 当前数据里 **通关次数最大值 = 12**（`音标猜词`），所以**全库只有 1 款是 tier 2**；**tier 3（≥50）/ tier 4（≥100）一款都没有**。

## 5. 本轮踩到的坑（判据级）

1. **别用搜索去截"右下角角标"**：`uitest uiInput inputText` 会弹软键盘，键盘从 y≈960 起，
   而搜索结果的第一张卡底边正好 ~960 ⇒ **角标被压在边缘**。
   收键盘的两种办法都会**连带清掉搜索态**（`keyEvent Back` 关搜索栏、点空白失焦也丢）。
   ⇒ **要么不用搜索、靠滚动定位；要么截图上方的卡（第 2 行起）。**
2. **`inputText` 需要先点一次输入框**：只靠 `inputText x y` 有时不落字（我这次连试两次都是空框），
   先 `click` 聚焦再 `inputText` 就成功。
3. **共享设备上语言会随时变**：这次操作途中经历 **阿语 → 韩语 → 德语 → 中文**。
   同一份脚本里用中文文案找控件会在下一轮失效 ⇒ **判据 1814 必须每步查，不是只查一次**。
