# 判据 `3087`：`--nonshort` 读的是**再也不会更新的旧文件** ⇒ 「竖屏 `42` 款过期」是个假数字

## 一、怎么发现的

今晚在横屏复核 `生命游戏` 时，顺手查了台账里这款的记录，看到：

```
layout-canonical.tsv 第 2832 行:
  2026-11-20T21:55:34  生命游戏  OK  2496  … blk=3/72px … scr=2224x2496
```

**竖屏的记录写进了「横屏台账」**。于是查两条台账的 `scr=` 分布：

```
layout-canonical.tsv   竖屏行 164 · 横屏行 738     ← 两个方向混在一起
layout-nonshort.tsv    竖屏行 0                   ← 「竖屏台账」里没有新数据
```

## 二、根因

`shot_game` 的 `finish()` **只写 `layout-canonical.tsv`**（竖屏也写进去，靠行内 `scr=WxH` 区分）。
而 `layout-nonshort.tsv` 是 `11-16` 那一批的历史文件，**之后再没有新数据进来**。

⇒ `check_ledger_freshness.py --nonshort` 读的正是这个旧文件
⇒ 它把**今天刚量过的款**全报成「陈旧」

## 三、影响

| 修前 | 修后 |
|---|---|
| 竖屏「过期 `42` 款」| 竖屏「过期 `5` 款」|
| 实际是拿 `11-16` 的数据比今天的代码 | 用今天的竖屏测量比今天的代码 |

⇒ 那 `5` 款里 4 款滞后 `0 h`（量在改之后），**真正陈旧的只有 `Collatz`**（滞后 `16 h`）。
⇒ 我把 `Collatz` 补测了：竖屏 `blk=0/0px`，干净。

## 四、修法

```python
# 读同一个 canonical，按 scr= 的宽高关系筛竖屏行
_CANON = os.path.join(ROOT, '_巡检记录', 'layout-canonical.tsv')
LEDGER = _CANON
NONSHORT_MODE = '--nonshort' in sys.argv

def _is_portrait_row(line):
    m = re.search(r'scr=(\d+)x(\d+)', line)
    return bool(m) and int(m.group(2)) > int(m.group(1))
```

⇒ 读取时 `if NONSHORT_MODE and not _is_portrait_row(line): continue`

## 五、判据

> **一个「只读不写」的文件，迟早会变成谎话。**
> 写入口只有一个（`finish()`），读入口有两个（一个读新、一个读旧）—— 读旧的那个必然失真。

⇒ 四条：
1. **改任何「统计/体检」脚本前，先确认它读的文件是不是还在被写**
   （`grep` 一下写入口；`ls -lt` 看最后修改时间）
2. **同一个数据的两个「视图」要用同一个来源过滤，不要用两个文件** ——
   否则早晚出现「A 说有 42 个问题、B 说只有 5 个」
3. **数字突然变小不一定是修好了，也可能是换了个更准的尺子** —— 这次 `42 → 5` 是后者
4. **工具报出的「过期/异常」清单，要先抽一两条核对真值**再决定动不动手
   （这次抽到的 `Collatz` 是真陈旧，其余 4 条是 `0 h` 假报）
