# 判据 1978 的落地：`shot_game.py` 默认采 **3 次**，报中位数

## 为什么（今晚我犯同一个错两次）

**第一次**：`Base Shift` / `Fraction Matcher` —— 我看 `max_bottom` 变大就回退了 `8` 款有效改动，
其实那两次量的**不是同一个节点**（判据 `1973`）。

**第二次**：我给新指标 `blk` 「校准」，每款只测**一次**就宣布「`5/5` 成功投用」，
队友用台账序列证明它**比 `max_bottom` 更抖**（`Wordle` `1→0→0→2`）⇒ 撤销（判据 `1978`）。

**⇒ 两次的同一个根因：单次测量。**
**⇒ 判据 1978 我自己写下来过，却没对自己的新工具执行。**

## 改动

**`工具/shot_game.py` 现在默认打 `3` 次 `dump`：**

```python
_samples = []              # 3 次采样的 max_bottom
_n_samples = 3             # 传 --samples1 可退回单次（筛选用）
...
_mb_median = median(_samples)
_mb_span   = max - min     # 抖动跨度
mb = _mb_median if _mb_median is not None else _max_y2(d2, 0)
```

## 为什么用**中位数**而不是最大值/平均值

- **最大值**：会被一次性浮层拉高（`Wordle` 的 `1600` 就是这么来的）
- **平均值**：会被单次异常带偏
- **中位数**：3 次里取中间那个 —— **对「偶发生灭」的节点免疫**

| **筛查**（先看个大概）| `python3 工具/shot_game.py "<游戏>" --samples1` | `~100s` |
