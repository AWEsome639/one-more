# 判据 1978 的落地：`shot_game.py` 默认采 **3 次**，报中位数

## 为什么（今晚我犯同一个错两次）

**第一次**：`Base Shift` / `Fraction Matcher` —— 我看 `max_bottom` 变大就回退了 `8` 款有效改动，
其实那两次量的**不是同一个节点**（判据 `1973`）。

**第二次**：我给新指标 `blk` 「校准」，每款只测**一次**就宣布「`5/5` 成功投用」，
队友用台账序列证明它**比 `max_bottom` 更抖**（`Wordle` `1→0→0→2`）⇒ 撤销（判据 `1978`）。

**⇒ 两次的同一个根因：单次测量。**
**⇒ 判据 1978 我自己写下来过，却没对自己的新工具执行。**

## 改动

**`工具/shot_game.py` 现在默认打 `3` 次 `dump`：**

```python
_samples = []              # 3 次采样的 max_bottom
_n_samples = 3             # 传 --samples1 可退回单次（筛选用）
...
_mb_median = median(_samples)
_mb_span   = max - min     # 抖动跨度
mb = _mb_median if _mb_median is not None else _max_y2(d2, 0)
```

## 为什么用**中位数**而不是最大值/平均值

- **最大值**：会被一次性浮层拉高（`Wordle` 的 `1600` 就是这么来的）
- **平均值**：会被单次异常带偏
- **中位数**：3 次里取中间那个 —— **对「偶发生灭」的节点免疫**

## ❌ 实测失败：三次采样**把 `mb` 变成了 `0`**，已回退

**现象**：改完后 `Wordle` 报 `OK 0`（`lowest`/`blk` 都正常，只有 `mb` 是 `0`）

**根因**：额外的 `dump` 在游戏还没画完时抓到空树 ⇒ `_max_y2` 返回 `0`
⇒ `median([1600, 0, 0]) = 0`

**修了一次**（只收 `> 0` 的样本）——**仍然 `0`** ⇒ 说明 `_samples` 整个是空的，
不是「混入 0」而是「一个都没取到」。

**⇒ 回退。**

### 回退时又踩一个坑

`git checkout -- 工具/shot_game.py` 恢复的是 **HEAD**，
而**坏掉的版本就在 HEAD 里**（`b6bc5efe` 同时提交了 `blk` 与三次采样）
⇒ **回退后仍是 `mb=0`**。

**正确做法**：`git show e5278e11:工具/shot_game.py > 工具/shot_game.py`
（`e5278e11` = `blk` 校准成功那一版）⇒ **恢复后 `Wordle` 立刻回到 `1600`**

**⇒ 判据 1982**
> **「回退」必须回到**已知能用的那个 commit**，不是 `HEAD`** ——
> 如果一个 commit 同时包含「好改动」与「坏改动」，`git checkout` 会把两个都带回来。
>
> **⇒ 正确姿势：`git show <已知良好 commit>:<文件> > <文件>`，然后**立刻跑一次同一个测试**确认恢复。**
