# 按钮被挤出全扫 · 2026-11-08（只读）
> 背景：今天修了 `GKakuro`（`-310`）与 6 款矮屏；本报告扫「同类问题」——**根容器 Column + 棋盘正方形（aspectRatio(1)）把按钮顶出屏幕**。
> 设备参考分辨率：**853×533 vp**（2560×1600 @480dpi）；可用高按 GKakuro 口径 `Bp.height - 260 = 273vp`。

## 0. 一页结论
| 项 | 结果 |
|---|---|
| 含 `aspectRatio(1)` 的款 | **162 款**（其中根容器 Column 153、Scroll 8） |
| 已有显式限高/可滚（视为已处理） | **82 款**（`constraintSize` / `Bp.height ±` / `boardPx` / `width(Math.min(...))` / Scroll） |
| **未限高候选（需人工复核）** | **80 款**（下表） |
| 真机抽查 | 5 款：4 款进入且**提示/AI 代打都在屏内**（`y=543..657`）；1 款搜索受干扰未进 |
| 新发现 | 迷你数谜/数方 的**棋盘底边到 y=1600**（被底栏压住）——按钮没事，但棋盘下沿被裁 |

> 说明：棋盘「按宽撑满」时正方形高≈棋盘宽（853vp），理论上远超可用高 273vp ⇒ 必然溢出。但很多款的 `aspectRatio(1)` 是**小格子/图标**，不是整块棋盘，所以不能一刀切；下表是「需要逐款确认」的候选。

## 1. 已确认修过的（不用再查）
- `GSudoku`（数独）：`boardPx = min(可用宽, 52% 屏高)` 限高
- `GKenken`（聪明格）：`width(Math.min(Bp.width - 2*Space.lg, max(200, Bp.height - 360)))`
- `GKakuro`（数谜）：`constraintSize({ maxHeight: Bp.height - 310 })`（今天修）
- 根/内容 `Scroll` 的 8 款：`GBejeweled` / `GBlockEscape` / `GCheckers` / `GFillomino` / `GLighthouses` / `GMinesweeper` / `GMirrorTracing` / `GNavonHierarchical`（内容可滚，不算顶出）

## 4. 建议
1. **自动化兜底**：给 `verify_ai_win.py` 加一条断言——进游戏后 dump 必须含「提示 / AI 代打」且 `y2 ≤ 1336`（底栏上沿），否则记 `PUSHED_OUT`；这条能在下次夜跑里覆盖 355 款；
2. 静态尺子：在 `check_layout_overflow.py` 加第 4 类——`Button(TG('提示'))` 行号在 `aspectRatio(1)` 棋盘之后且文件无限高（`constraintSize`/`Bp.height`）⇒ 报候选；
3. 棋盘到屏底的 2 款（迷你数谜/数方）单独记：棋盘底边 1600 被底栏压住，建议与 GKakuro 同样把棋盘容器限高到 `Bp.height - 260` 以内；
4. 本轮抽查未发现「按钮被顶出」的新实例，但 80 款候选未逐一人工确认——建议按上表优先看 `ar≥3` 的款。
