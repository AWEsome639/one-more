## 2. ★ 关键发现：系统自带「本地对话模型」API（不用搬模型）

`SDK/hms/ets/api/@hms.data.localChatModel.d.ts`（144 行，Data Augmentation Kit）：

```ts
declare namespace localChatModel {
  interface Config { isStream: boolean }                       // 支持流式
  interface QuestionInfo { questionId: number; content: string } // content ≤ 4500 字节
  interface Answer { questionId: number; content: string; isFinished: boolean }
  function init(): Promise<boolean>;                            // 会拉起「模型管理应用」
  function chat(info: QuestionInfo, config: Config, callback: AsyncCallback<Answer>): Promise<void>;
}
export default localChatModel;
```
- **无 `@permission`**、`@stagemodelonly`、`@since 6.0.0(20)`；错误码完整（超时 1021900001 / 加载失败 0002 / 请求失败 0003 / 忙 0004 / 参数 0005）
- 设备 syscap 已声明 **true**，且设备 API=**26** ⇒ 可用
- ⚠️ 项目 `compatibleSdkVersion = 5.0.0(12)`（`targetSdkVersion 26.0.0`）⇒ 低版本设备上要加 `canIUse('SystemCapability.DataAugmentation.LocalChatModel')` 运行时守卫
- ⚠️ `init()` 会**拉起系统的模型管理应用**：模型是否已就位取决于系统（可能需要用户下载一次）

## 3. ② SDK 里的 MindSpore Lite（② 的答案）

| 项 | 结论 |
|---|---|
| ArkTS API | `@ohos.ai.mindSporeLite`（**public，`@syscap` 有，`@since 10`，无 `@systemapi`/无权限**）|
| 加载 | `loadModelFromFile(path, ctx?)` / `loadModelFromBuffer(ArrayBuffer)` / `loadModelFromFd(fd)` ✅ 三种 |
| 推理 | `model.getInputs(): MSTensor[]` → `model.predict(inputs): Promise<MSTensor[]>`；另有 `resize()` / `runStep()` |
| 输入输出类型 | `MSTensor`：`shape: number[]`、`dataSize`、`getData(): ArrayBuffer`、`setData(ArrayBuffer)` ⇒ **纯张量，没有 tokenizer** |
| **NPU 路径** | ✅ `Context { target?, cpu?: CpuDevice, **nnrt?: NNRTDevice** }`，`NNRTDevice { deviceID?: bigint, performanceMode? }`、`NNRTDeviceType` ⇒ **Neural Network Runtime（NPU）可指定** |
| NDK | `native/sysroot/usr/include/mindspore/{model,tensor,context,data_type,format,status,types}.h` 齐全；`aarch64-linux-ohos/libmindspore_lite_ndk.so` 只有 **9.0K（导入桩）** ⇒ 真实现在系统侧 |

## 4. ③ 为什么推荐「系统模型」而不是「自己搬模型」

| 维度 | 路线 1：系统 localChatModel | 路线 2：MindSpore Lite + 自备 0.5B |
|---|---|---|
| 工作量 | **~30 行**（`init()` + `chat()`） | **周级**：还要实现分词器 + 逐 token 解码 + KV-cache + 采样 |
| 包体积 | **0 增加**（仍 ~45MB） | +300MB~1GB（进 HAP）或首次启动解压 |
| 模型来源 | 系统自带（`init()` 拉起模型管理） | 自己找/转/压/塞 |
| 转换工具 | 不需要 | **本机没有**：无 `converter_lite`、无 `mindspore_lite` pip 包 ⇒ 要去 Linux/Windows 转 |
| NPU | 系统自己调度 | 需自己配 `nnrt` + 真机验证（本机是模拟器，验不了） |
| 风险 | 依赖系统模型是否就位（`init()` 可能弹模型管理页） | 依赖 `.ms` 转换成功 + 性能达标 |

## 5. ④ 最小可行 demo（路线 1，建议直接做）

**目标**：把 ChatFinder v1 的「规则 NLU」换成「本地小模型抽意图」，检索仍用现有 `scoreOf`（**不换检索，只换理解**）。

```
用户：「我想找个不太难、能玩几分钟的」
  ↓ localChatModel.chat()（prompt 里只放 6 个类别 + 3 种难度 + 时长词表，<1KB）
  ↓ {"category":"LOGIC","difficulty":"EASY","short":true}
  ↓ 复用 ChatFinder.scoreOf()（现有 355 款数据）→ top3
```
**为什么这样切**：`content ≤ 4500 字节` 放不下 355 款目录（光中文名就 ~3.5KB）；
而「抽意图」只需要词表，**prompt < 1KB**，完全在限制内，且检索完全本地、可控、可测。

**验收判据**（可写成断言）：
1. `init()` 返回 true（模型就位）；
2. 20 句样本（我上一份 `ChatFinder覆盖-20261108.md` 里那 20 句）抽意图**≥ 16 句与人工标注一致**（v1 现在只有 13 句有结果、4 句明显错）；
3. 首 token 延迟 < 2s、整句 < 8s（模拟器上放宽）；
4. 断网可答（离线验证）。

**若一定要自己搬模型（路线 2 的 demo）**：
- 模型：Qwen2.5-0.5B-Instruct（中文/多语言）或 MiniCPM-0.5B；
- 转换：PyTorch → ONNX → `converter_lite`（MindSpore Lite 转换，**Linux/Windows**）→ `.ms`（int8）；
- **dev 阶段别进 HAP**：`hdc file send model.ms /data/local/tmp/`，用 `loadModelFromFile(沙箱路径)` 加载，先量 **tokens/s**；
- 只有「首 token < 2s + ≥10 tok/s」才值得继续做 tokenizer。

## 6. 边界与未验证项

- **没装任何东西、没下模型**（按你要求只读）。
- 设备是**模拟器**：无真实 NPU ⇒ 性能数字只能当「下限参考」；
  `/system/lib64`、`/dev` **无权限** ⇒ 「库在不在设备上」**无法直接核实**（只能从 syscap + SDK 侧推断）。
- `@hms.data.localChatModel` 的**实际可用性**（`init()` 能否成功、系统模型是否已下载）**未实测** —— 需要写 demo 才能验；这是本报告唯一的关键未知。
- 包体积上限：本地文档只给「单 HAP 超限 ⇒ 拆包（`INSTALL_FAILED_SIZE_TOO_LARGE`）」，**没有给出具体数值**，不臆测。
- MindSpore Lite 的 `.ms` 转换工具链**本机不存在**，转换可行性未实测（属公认工具链，但未在本机跑通）。
