# ★★★ bash 坑：双引号里的**反引号**会被当命令执行

> `2026-11-14 21:x`。`git commit -m "... `1/3` ..."` 时炸出来的。

## 一、⇒ 现象

```bash
git commit -m "★★ ...；`1/3` 有严重问题 ⇒ ..."
# bash: line 57: 1/3: No such file or directory
```

**⇒ 而 commit 成功了、但信息里的 `1/3` **变成了空**：**
```
…（余量排优先级」； 有严重问题 ⇒ 51-150px 那 8 款很可能还有…
```

**⇒ 判据：`信息里 1/3 出现次数: 0`。**

## 二、⇒ 原因

**在**双引号**里，反引号是**命令替换**的语法（等价于 `$(...)`）。**
**⇒ 所以 `` `1/3` `` 会让 bash **执行** `1/3` 这个命令 ⇒ 失败 ⇒ 替换成空字符串。**

**⚠️ 而我**经常**在提交信息里用反引号包代码（`\`blk\``、`\`lowest\``）⇒ 这个坑会反复出现。**

## 三、⇒ 为什么之前没炸出问题

**因为之前反引号里多是单词（`` `blk` ``、`` `lowest` ``、`` `Scroll` ``）⇒ bash 执行 `blk` 失败 ⇒ 同样被替换成空！**

**⇒ ⇒ 也就是说：**我以前那些带反引号的提交信息，内容可能都被悄悄吃掉过。****
**⚠️ 只是没检查过，所以不知道。**

## 四、⇒ 修法

**① 用单引号（推荐）：**
```bash
git commit -m '…`1/3` 有严重问题…'     # 单引号里反引号不执行
```
**② 或用 heredoc：**
```bash
git commit -F - <<'MSG'
…`1/3`…
MSG
```
**③ 或把反引号换成普通引号/书名号。**

## ⇒ 判据（`2476`）

**在 shell 双引号字符串里，`$`、`` ` ``、`\` 都会被解释。**
**⇒ 所以「把 markdown 文本（含反引号）塞进 `-m`」必须用单引号或 heredoc。**

**⇒ 判据：命令行里传「含代码标记的文本」时，默认用单引号；双引号只用于需要变量展开的场合。**
