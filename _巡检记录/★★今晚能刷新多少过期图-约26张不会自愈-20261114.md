# ★★ 今晚能刷新多少过期图：约 `26` 张**不会**自愈

> `2026-11-14 21:x`。接 `stale_shots.py`（全库 `177` 张里 `69` 张过期）算「今晚能修掉多少」。

## 一、⇒ 数

| 项 | 数 |
|---|---:|
| 全库截图 | `177` |
| **过期（图早于代码）** | **`69`（`39%`）** |
| 当前 | `105` |
| 未验 | `3` |
| **今晚队列** | `245` 款 |
| **今晚能跑** | 约 `221` 款（`62%` 覆盖）|
| **⇒ 过期图里会被刷新** | 约 `69 × 62% ≈ 43` 张 |
| **⇒ 过期图里不会自愈** | **约 `26` 张** |

**⇒ 所以明早还会有约 `26` 张过期图 ⇒ 那些款的结论仍是旧数据。**

## 二、⚠️ 而我先前那个「是否在队列」的判断不可靠

**我只拿「今天改过的 `38` 款」去比 ⇒ 得出「`34` 款不在队列」。**
**⇒ 但队列是 `245` 款（`38` 改过 + `5` `KNOWN_GAP` + 其他从未测过的 `202`）⇒ 那 `34` 款里至少 `5` 款（`Polyomino Tiling`/`Counting Sheep`/`Object Displacement` 等 `KNOWN_GAP`）**其实在队列里**。**

**⇒ ⇒ 所以「`34`」这个数是错的；正确口径应按「队列覆盖率」估 ⇒ 约 `26` 张不会自愈。**

## 三、⇒ 明早的具体动作

```bash
# ① 跑一次，看过期数降了多少（今晚会刷新约 43 张）
python3 工具/stale_shots.py --count

# ② 看剩下的过期款（约 26 款）—— 这些明天不能引用其结论
python3 工具/stale_shots.py --all

# ③ 对其中仍然关心的款，单测一次（shot_game.py <名字>，约 110s/款）
```

## 四、⇒ 所以「今晚跑完就全新鲜了」是错的

**今晚覆盖 `62%` ⇒ 还有 `38%` 的款、约 `26` 张过期图 ⇒ **不能一次性刷新干净**。**
**⇒ 这是一个「跑几晚才能全刷新」的过程。**

**⇒ 而 `stale_shots.py --count` 就是这个过程的进度表。**

## ⇒ 判据（`2500`）

**「批量重测」不等于「全部刷新」。**
**⇒ 覆盖率 = 本轮重测数 / 需要刷新的总数；而「需要刷新」本身要靠「图 vs 代码时刻」去数。**

**⇒ 判据：报「重测完了」之前，先报「过期数从多少降到多少」；后者才是进度。**

## ⇒ 判据（`2501`）

**而我这次差点用「改了 `38` 款」当「队列成员」的全部依据 ⇒ 漏了另外 `207` 款。**
**⇒ 队列的构成有好几股来源（改过、缺数据、从未试过），只看一股就会算错覆盖率。**

**⇒ 判据：算「覆盖率」前，先把分母（应覆盖的全体）的来源逐条列出。**
