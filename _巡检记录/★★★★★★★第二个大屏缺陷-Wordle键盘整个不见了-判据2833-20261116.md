# 第二个大屏缺陷：`Wordle` 的**键盘整个不见了**

> `2026-11-16 16:40`。**比第一个严重：`Mental Mapping` 是切掉一半，这个是**整个控件不存在**。**

## 一、⇒ 证据

**⇒ 截图 `截图-Wordle-124409.jpeg`（折叠屏 `2224×2496`）：**
- **头部、`提示`/`AI 代打`、三个统计（`机会 5` / `已猜 0/5` / `用时 3秒`）都正常**
- **`5×5` 字母格占满整屏，第 `5` 行被屏底切着**
- **下方**没有任何键盘** —— 屏幕上根本找不到字母键**

**⇒ 也就是说：这一局从第一步开始就**无法输入**。**

## 二、⇒ 而所有既有指标都报「没事」

**⇒ 台账里 `Wordle` 这一行：`lowh=66`、`blk=2/48px`、`max=48` ⇒ 看着像「贴着底、轻微溢出」。**

| 指标 | 为什么没发现 |
|---|---|
| `blk` | 只算「越界像素」⇒ 键盘**不存在**时它是 `0` 或很小 |
| `lowh` | 取最低元素 ⇒ 这里最低的是统计里的 `5`（`66px`），**不是键盘** |
| 配对比较 | 手机 `lowest` 是 `5`、折叠屏也是 `5` ⇒ 同元素、没变小 ⇒ 判「一致」 |
| 空白分析 | 键盘缺席的地方被网格占着 ⇒ 也不是「空白」 |

**⇒ 判据 `2833`：`blk`/`lowh`/配对比较/空白，四种指标都是**「已有元素的位置与尺寸」**这一族 —— 它们**压根问不到「某个元素在不在」**。**

## 三、⇒ 这一类可能不止一款

**⇒ `Wordle` 的特征是「棋盘 + 屏内键盘」。同族至少还有：`PTB` / `Kakuro Mini` / `Akari` / `Sudoku` 系 / `Alphabet Sudoku` / `KenKen`。**
**⇒ 它们在大屏上是否也把键盘挤没了？→ **这一轮跑批的截图里挨个看**。**

## 四、⇒ 修法方向（待验证，先不动）

**⇒ 与 `Mental Mapping` 同族但不是同一个修法：**
- **`Mental Mapping`**：底部方向键被切 ⇒ 缩网格（`70%`→`50%`，已做、已验证）
- **`Wordle`**：键盘**完全没空间** ⇒ 更可能是**网格 `layoutWeight(1)` + 键盘固定高度**，或**大屏下网格改小/改宽**

**⇒ 必须先读 `GWordle` 的布局再动 —— 按判据 `2816`：**先看那张屏的 dump 与代码，再写选择器/改动**。**

## ⇒ 判据（`2833`）

**「元素变小/越界」与「元素整个不在」是两类坏法，而现有四种指标全属前者的家族。**
**⇒ 补法：**对每款维护一份「关键控件清单」**（键盘/棋盘/选项行/底部按钮），逐个判「在不在」——**这比量尺寸更接近「能不能玩」。**

# 【`16:40` 补充】不是一款，是**一类** —— `Kakuro Mini` 同样没有键盘

## 一、⇒ 第二张截图

**⇒ `截图-Kakuro_Mini-124519.jpeg`（折叠屏）：**
- **头部、`提示`/`AI 代打`、两个统计（`步数 0/40` / `完成线 0/6`）正常**
- **`3×3` 格子每个约 `250×250px`，占满整屏，最下一行被屏底切着**
- **下方**没有任何数字键盘** —— 而手机版有 `1–9` + `⌫`**

**⇒ 和 `Wordle` 完全同形：棋盘吃光高度 ⇒ 键盘无处安放。**

## 二、⇒ 于是它是一个「类」

| 款 | 折叠屏上的表现 | 台账读数 |
|---|---|---|
| `Wordle` | 键盘整个不见 | `lowh=66 blk=2/48` ⇒ 看着「没事」 |
| `Kakuro Mini` | 键盘整个不见、底行被切 | `lowh=44 blk=2/48` ⇒ 看着「没事」 |
| `Alphabet Sudoku` | 待看（`lowest` 是提示行）| `lowh=51` |

**⇒ 特征：`最低元素` 变成了**统计数字或提示行**，而不是键盘键 ⇒ 键盘根本不在无障碍树里。**

**⇒ 这是一个**可靠的新信号**：键盘类游戏若 `lowest` 落在「数字/提示」上、且没有键盘键的文本，就很可能键盘失踪。**

## 三、⇒ 修法方向（同族，一个改法可能覆盖多款）

**⇒ 现布局大概是：棋盘 `width('100%') + aspectRatio(1)`（或 `layoutWeight`）⇒ 大屏上棋盘按**宽度**撑成巨大正方形 ⇒ 高度不够装键盘。**
**⇒ 正确做法：**棋盘 `layoutWeight(1)`（吃剩余空间、有上限）+ 键盘固定高度（`Cell.tap` 之类）** ⇒ 键盘永远在、棋盘自适应。**
**⇒ 这与判据 `2146`（「参考实现即规格」）一致：`GGo9.boardMax()` 就是「按屏高算棋盘上限」的写法。**

## ⇒ 判据（`2833` 续）

**「键盘在不在」这件事，`blk`/`lowh`/配对比较/空白**四种指标全查不到**。**
**⇒ 而它恰恰是「能不能玩」的分界：棋盘再漂亮，没有键盘就是废的。**
**⇒ 所以跑批之后必须补一步：**对每款 dump 一次，检查「关键控件清单」里的元素是否存在**（键盘键 / 棋盘 / 选项行 / 底部按钮）。**
