# ★ 修正：**头部只有 ~`104vp`，不是 `300vp`** —— 而「`211~350`」那个数是**头部+底部的合计**

> 由队友 `82fcab75` 的静态分析逼出来的（它算 `Stroop` 的声明总高 `403~413vp`，
> 加上它算的头部 `104vp` ⇒ `507~517vp`，而**实测 `max=1570px = 523vp`** ⇒ 差 `6~16vp`）。

## 一、它怎么算出 `104vp` 的

**按代码拼：状态栏 `39vp`（dump 里 `117px/3`）+ 顶栏 `45vp` + `padding` `20vp` = **`104vp`**。**
**⇒ 而它把 `Stroop` 逐块加起来 `343vp` + 间距 `60~70vp` = `403~413vp`**
**⇒ `403~413 + 104 = 507~517vp`，实测 `523vp` ⇒ **误差 `6~16vp`（`1~3%`）。**

**⇒ 这个误差比我的 `300vp` 假设（会算出 `703~713vp`，超 `170~180vp`）**好一个数量级**。**

## 二、所以我一直说的那个数是什么

**我算的是 `max_px − 519`（盘面 `173vp`）⇒ 得到 `211~350vp`。**
**⇒ 那个量的名字是**「头部 + 底部」的合计**，而我一直简写成「头部」。**

**⇒ 现在有了拆分：**
```
头部  ≈ 104vp   （状态栏 39 + 顶栏 45 + padding 20）—— 全库共用，几乎不变
底部  ≈ 107~246vp（= 上次算的 211~350 减去 104）
盘面  = 该款自己的值（173 / 240 / 其他）
```
**⇒ 三者相加 ≤ `533vp`。**

## 三、这个拆分**不改变**已经做过的判断

| 判断 | 是否受影响 |
|---|---|
| **`X = -360` 保持不动** | ❌ **不受影响** —— 用的是**合计** `211~350`，那个数没变 |
| **`floor=240` 那 `18` 款该不该降** | ❌ **不受影响** —— `--floor` 公式是 `240 − blk/3`，与拆分无关 |
| **盲区 ④（盘面没用满）的规模** | ⚠️ **受影响** —— 见下 |

## 四、而它**打开了一个新方向**（盲区 ④ 的解法）

**若某款底部内容很小（例如 `Stroop` 的底部只有说明文字 `17vp`），那么盘面可以大到：**
```
盘面 ≤ 533 − 104 − 底部
⇒ 底部 17vp 的款：盘面可到 412vp
⇒ 底部 107vp 的款：盘面可到 322vp
```
**⇒ 而 `-360` 一律给 `173vp` ⇒ **对底部小的款，浪费了 `150~240vp` 的盘面**。**

**⇒ 这正是盲区 ④ 的**具体解法**：不是「全局改 `X`」，而是「**按每款的底部内容定盘面**」。**
**⇒ 而每款的底部 = `max/3 − 104 − 盘面`（今晚的 `board=` 与 `max` 一联立就能算）。**
