## 一、`NOT_HOME`（`87` 次，`15.0%`）—— 已修

我以为「某些游戏的结算弹层没有可点关闭件，`Back` 永远被吃」。

这两个修复，只应用在了路径 A，没应用在路径 C。**

# 五、补记：`NOT_HOME` 诊断为什么必须用 `%r` 而不是 `%s`

## 我加的诊断

```python
_last = []
try:
    _dd = dump('nothome')
    _last = [t for t, _ in texts(_dd)][:6] if _dd else []
except Exception:
    _last = ['<dump failed>']
finish(name, 'NOT_HOME', t0, None, 'could not reach home; last texts=%r' % (_last,))
```

## 如果用 `%s` 会怎样

**台账是 TSV**，`shot_game` 每款写一行：
```
ts \t name \t outcome \t max_bottom \t elapsed_s + extra
```
而 `_last` 里装的是**原始 dump 文字**。**只要某个游戏文案里含制表符或换行**，
`%s` 就会把它们原样写进第 `5` 列 ⇒ **整行多出字段** ⇒
`triage.py` / `fixed_audit.py` 的 `f[4]`（extra）读到的是**截断的内容**，
严重时 `f[3]`（`max_bottom`）都可能被挤位。

## `%r` 为什么安全（实测）

```python
_last = ['正常文字', 'a\tb', 'c\nd', "it's"]
note = '...last texts=%r' % (_last,)
#  → ...last texts=['正常文字', 'a\tb', 'c\nd', "it's"]
#  含制表符? False     含换行? False     字段数: 5 ✅
```

**⇒ `repr()` 会把 `\t` / `\n` **转义成字面反斜杠序列**（`\t` 两个字符，不是制表符），
所以无论 dump 里有什么，写进 TSV 都只有一行、只有 `5` 个字段。**

## 附带好处：`%r` 保留引号，能分辨「空串」和「没有」

| 值 | `%s` 输出 | `%r` 输出 |
|---|---|---|
| `[]` | `[]` | `[]`（一样）|
| `['']` | `[]` ← **看不出有个空串** | `['']` ✅ |
| `None` | `None` | `None`（一样）|

**⇒ 明早读 `last texts=` 时，「`[]`」= dump 空，`['']` = 有节点但没文字，两者含义不同。**

## ⇒ 判据（`2086`）

**往 TSV/CSV 里写「来自外部的自由文本」时，必须用 `repr()` 或显式转义，不能用 `%s`。**
**这条不是洁癖：一旦某行多出字段，下游所有按列号取值的代码都会静默读错 —— 而且不会报错。**
**⇒ 更一般的判据：任何「拼接式写结构化文件」的地方，先想「输入里含分隔符会怎样」。**
