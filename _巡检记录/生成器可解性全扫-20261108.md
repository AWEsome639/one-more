# 「随机生成 + 不验证可解」全扫（2026-11-08）

> 只读扫描（未改任何 .ets）。范围 355 款。
> **结论：除已修的 3 款外，没有发现新的 >5% 不可解生成器。**
> 剩 2 款「题库型」需要规则级求解器才能下结论（`GNurikabe` / `GNoriNori`），本轮未做。

## 一、方法与漏斗

| 步骤 | 判定 | 款数 |
|---|---|---|
| 全库 | `games/*.ets` | **355** |
| ① `reset()` / `aboutToAppear()` 里含 `Math.random` | 正则 + 花括号定位函数体 | **95** |
| ② 其中**没有**「求解/验证」痕迹（`solve/dfs/bfs/plan/verify/solvable`）**且没有**「先造答案」痕迹（`solution/answer/sol[...]`） | 文本特征 | **61** |
| ③ 61 款按生成方式分类 | 见 §二 | — |
| ④ 真风险（随机 + 不验证 + 目标依赖生成结果） | 逐款看生成器 | **0 新增**（已修的 3 款除外） |

> 说明：② 的 61 款里**大部分根本不存在“可解性”概念**（反应力/记忆/猜词类），
> 只有「棋盘/机关类」才需要“生成后保证有解”。所以真正要看的只有 §二 的 2、3 两类。

## 二、61 款的分类

### A 类 · 内容随机（无「可解性」概念）—— 安全，共 43 款
`GAbReversalOddball GBlinkDetector GBinomialMatch GBoxCompletion GBubbleShooter GCollatz GColorMatch
GCryptogram GD2Attention GDoodleJump GDualMirror GFactBinder GFeatureMatrixRecall GFeatureMatrixRecallAll
GFindWord GGravitySort GHueSort GLifeGame GMemory GNumberBondsAll GPatternSequenceDraw GRoomInspector
GColorFlood GFreecell GMastermind GMathGuess …`
理由：随机只决定“出什么题/摆什么内容”，每题都有确定答案或无限可玩（如 `GColorFlood` 任意局面都能解、`GMastermind` 答案必存在）。

### B 类 · 按构造生成（先造答案 / 带兜底）—— 安全，共 9 款
| 游戏 | 为什么一定可解 |
|---|---|
| `GMathMaze` | 先 `genPath()` 造路，再沿路填数值 ⇒ 路径本身即解 ✓ |
| `GModuloPath` | 随机游走失败时**兜底** `path = [0,1,2,3,4,5]`（`:128`）⇒ 一定有路 ✓ |
| `GInterlockPuzzle` | 依赖只指向 `j < i` ⇒ **DAG**，永远存在可拆顺序 ✓ |
| `GKakurasuSums` | `while (!ok && guard < 40)` 生成后自检重试 ✓（`:?`） |
| `GNonogram` | 从 `NONO_ART` 题库取图案，线索由图案反推 ⇒ 图案即解 ✓ |
| `GCrossword` | 洗牌词表后按行填词，答案来自所填词 ✓ |
| `GPaperFolding` | 目标固定 `HOLES = 3` 孔，任意位置都打得出来 ✓ |
| `GLetterGridSwapper` | 交换排序，最少交换 ≤ n−1（4×4 最坏 15）✓ |
| `GCircuitConnect` | **本轮已修为「先造答案再打乱」**（见上一份报告）✓ |

### C 类 · 题库型（手工布局，运行时不验证）—— 5 款，其中 3 款本轮已验证
| 游戏 | 题库 | 本轮验证结论 |
|---|---|---|
| `GPipes` | `PIPE_LIB`（3 条 5×5） | **3/3 全部可解 ✓**（回溯求解：在“端口不朝棋盘外 + 上下左右双向匹配”约束下，3 条分别 32/51/81 节点解出） |
| `GPathFinder` | `MAZE_LIB`（3 条 7×7）+ `MAZE_PAR=[12,28,16]` | **`par` 与真实最短路逐条相等 ✓**（BFS：12/28/16）⇒ `budget = par × {2.6,2.0,1.5}` ≥ 1.5×最短路 ⇒ 一定走得通 |
| `GPathIntersect` | `LINK_LIB`（4 组端点） | 自带**回溯规划器** `piPlanAll()`（`reset()` 里会算），规划不出来 AI 会停 ⇒ 属“已验证”结构；题库布局未逐条跑（代价高） |
| `GNurikabe` | `CLUE_LIB` | ⚠️ **待人工**：需要 Nurikabe 规则求解器（黑白格 + 不许 2×2 黑 + 连通 + 区域大小）才能判定 |
| `GNoriNori` | `REGION_LIB` | ⚠️ **待人工**：同上（NoriNori/Nurikabe 变体） |

## 五、建议

1. **不用再动 352 款**：它们要么没有“可解性”概念，要么是按构造/带兜底/题库型（GPipes、PathFinder 已实测可解）。
2. **唯一遗留**：`GNurikabe` / `GNoriNori` 的题库需要规则级验证（写求解器约 100 行）；若想省事，可给它们加一条“生成后调用求解器，失败则换题库/重试”的保险（与 `GMazeNav3d` 同款做法）。
3. 以后再新增“随机生成 + 目标依赖生成结果”的款，建议直接套两种范式之一：
   - **先造答案再打乱**（`GCircuitConnect` 新写法）
   - **生成后 BFS/回溯校验，失败重生成**（`GMazeNav3d` 写法）
