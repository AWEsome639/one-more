# 🔴 **严重**：`数字大小`（Stroop Number Size）的**答案按钮被挤出屏幕** ⇒ 玩家根本没法答题

## 怎么发现的

**`14` 款验证跑完，`Stroop Number Size` 报 `OK / max=1279 / blk=0` —— **指标全绿**。
但我看截图时发现：**右边只有一个橙色圆角露出来**。**

**⇒ 那是「比 5 大」按钮的**一个角**；「比 5 小」完全在屏幕外。**

## 根因

```ts
Row({ space: Space.md }) {
  HintBar({...})              // 提示 + AI 代打（占很宽）
  Button(TG('比 5 大'))        // layoutWeight(1)
  Button(TG('比 5 小'))        // layoutWeight(1)
}.width('100%')
```

**⇒ 三样东西**挤在同一行**：`HintBar` 已经把宽度吃掉大半，两个答案按钮被压到右边界外。**

## 修法

**答案按钮**单独一行**：**
```ts
Row({ space: Space.md }) { HintBar(...) }
Row({ space: Space.md }) { Button('比 5 大')  Button('比 5 小') }
```

## 修后（截图 + 数值双证）

| | 修前 | 修后 |
|---|---|---|
| `max_bottom` | `1279` | `1423`（多了一行，所以更高） |
| `blk` | `0/0px` | `0/0px` |
| **截图** | **只见橙色一个角** | **「比 5 大」橙 +「比 5 小」蓝，两个都完整可见** |

**截图：`_巡检记录/截图-Stroop_Number_Size-165010.jpeg`**

## ★★★ 判据 1998（今天最重要的一条）

> **`blk` 只量**垂直**越界。横向被挤出屏幕，`blk` 永远是 `0`。**
>
> **⇒ 「数值全绿」不等于「能用」；必须看截图。**
>
> **依据**：这款 `max=1279`、`blk=0/0px`、`floor` 都没碰 —— **指标完美**，
> **但玩家一个答案都点不到**。而 `14` 款验证里我是靠**看截图**才发现它的。

## 这条对 objective 的意义

**objective 的 `14` 款验证「通过 `12` 款」，如果我只报数字，会得出「全好了」的结论。
实际上一款**根本不能玩**。**

## 同批还修了 `Cube Net Fold`（也是靠截图发现的）

**修前**：`max=1600`、`blk=1/24px`，截图里底部 **`可填 A/B/C` 三个按钮只露出上半截**。

**修法**：盘面封顶从 `Bp.height - 360` 收到 `Bp.height - 400`（再让 `40vp`）。

**修后**：`max=1464`、`blk=0/0px`，截图里**三个按钮完整可见**（圆角、文字都在）。

### 但截图还暴露了另一个问题（未修）

**立方体展开图的 6 个面，在深色主题下几乎看不见** —— 只看到 6 个小点（`·`）。
**⇒ 那些点其实是**空格子占位符**，面本身的背景色（`theme.surface`）在深色底下**与背景太接近**。**

**⇒ 这是**对比度**问题，不是尺寸问题。要修得改配色（给面加描边或更亮的底色）。**
**⇒ 记下来，不在这一批改（配色改动影响全局主题，要单独评估）。**
