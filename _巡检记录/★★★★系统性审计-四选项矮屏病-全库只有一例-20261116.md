# 系统性审计「四选项在矮屏上挤不下」：**全库只有 `1` 例**（已修）

> `2026-11-16 09:27` 纯静态扫描 + 台账核对。**这是 `Fraction Matcher` 那个病的全库普查。**

## 一、⇒ 病的样子

**⇒ `Fraction Matcher` 原有 `slots = [0,1,2,3]`，矮屏上四个选项卡片竖排 ⇒ `A` 完整、`B` 半截、`C`/`D` 全在屏外 ⇒ 那题答不了。**
**⇒ 现已改为 `ForEach(Bp.isShort() ? [0, 2] : [0, 1, 2, 3], …)`（矮屏只渲染两个）。**

## 二、⇒ 全库普查结果

| 分类 | 款数 |
|---|---:|
| 用 `ForEach([0,1,2,3])` 渲染 4 个选项 | **`34`** |
| 其中**已做 `Bp.isShort()` 处理** | **`31`** |
| **完全没有 `Bp.isShort()`** | **`3`**（`FeatureMatrixRecall` / `FeatureMatrixRecallAll` / `GMemory`）|

## 三、⇒ 那 `3` 款要不要修？台账说不用

| 款 | 台账（最近一次）| 判定 |
|---|---|---|
| `Feature Matrix Recall` | `lowest` = `42px` 提示行 @ `1332–1374`、`blk=0/0px` | ✅ 无溢出（选项区在底部之上）|
| `Feature Matrix Recall All` | 同上、`blk=0/0px` | ✅ |
| `Memory` | `lowest='重新开始'` = **`132px` 完整按钮**、`blk=1/24px` | ✅ 只贴底、非被切 |

**⇒ 三款都是**网格型**选项（不是竖排卡片）⇒ 矮屏下网格自己缩，不会挤出去。**

## ⇒ 结论

**⇒ 「四选项挤不下」这个病，全库**只有 `Fraction Matcher` 一例**，且已修。**
**⇒ 其余 `33` 款：`31` 款显式处理了矮屏，`3` 款靠网格自适应（台账 `blk=0` 佐证）。**

**⚠️ 这是**第一次对一个「缺陷类型」做全库普查**而不是修一个算一个 —— 值得记下来。**
