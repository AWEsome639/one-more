# 判据 `3125`：横屏两款（`Checkers` 已修好验证、`Collatz` 已改未验证）

## 一、`Checkers` 跳棋（横屏）—— **已修好并验证**

### 缺陷
`截图-Checkers-045000.jpeg`（`2560×1600`）：棋盘**最下面一排红棋子被屏底切掉**，只剩上半个圆。
而台账 `blk=0px` `blkh=0px` ⇒ 三个指标全判「干净」。

### 根因
```typescript
const h = Math.max(120, (Bp.height - FIXED) * 0.70);   // FIXED=200
// 横屏：h = (533 − 200) × 0.70 = 233 ⇒ 棋盘占 233，下方只剩 100 给按钮与说明
```

### 修法
```typescript
const h = Math.max(120, (Bp.height - FIXED) * (Bp.isShort() ? 0.60 : 0.70));
// 横屏 0.60 ⇒ 200（省 33vp）；竖屏 0.70 逐字不变
```

### 验收
```
onemore7（2560×1600）  78.8s  OK  blk=0/0px  lowest='0' [440,633][473,696]
截图确认：棋盘完整、黑白棋子两排全在、下方还有余量
```
⇒ **横向与纵向都不再被切。**

### 副作用（可优化，不算缺陷）
⇒ 棋盘现在偏小、下方留白多。`0.60` 偏保守，`0.65` 可能更紧凑 ——
但按「先不切、再紧凑」的次序，这一步先保完整。

## 二、`Collatz` 考拉兹（横屏）—— **已改代码，未验证**

### 缺陷
`截图-Collatz-235606.jpeg`（`2560×1600`）：底部
「提示：考拉兹猜想 —— 任何正整数这样算下去最终都会落到 1」**被屏底切掉**。

### 修法
```typescript
Text(TG('提示：考拉兹猜想 ……'))
  ...
  .visibility(Bp.isShort() ? Visibility.None : Visibility.Visible)   // 新增
```
⇒ 横屏高度只有 `533`，这行属于次要说明 ⇒ 按仓库既有做法在矮屏隐藏；竖屏逐字不变。

### 为什么没验证
`onemore7` 上测 `考拉兹` 两次都 `TIMEOUT`（`300.2s`），随后设备掉线
（`[Fail]ExecuteCommand need connect-key`）。同一设备上 `Checkers` 能测成功 ⇒ **不是设备整体不可用**，
更像是这一款的导航/渲染慢。**待下次在 `onemore7` 上单独补测。**

## 三、判据

> **三指标全「干净」在横屏尤其不可信 —— 横屏只有 `533vp` 高，控件贴边/被裁的窗口极窄，
> 而「被裁掉的部分不会报越界」（判据 `3122`）。**

⇒ 四条：
1. **横屏必须单独用视觉模型审**（`blk` 在横屏一直 `0–24`，等于没管）
2. **`blkh=0` 在横屏不是「没问题」**，只是「没有块越过阈值」
3. **`ls -t | head -1` 取到的是「最新」不是「横屏」** —— 筛属性要先进筛选条件（判据 `3123` 第九节）
4. **横屏的次要说明可以隐藏**（`.visibility(Bp.isShort() ? None : Visible)`），
   这是仓库既有的成熟做法，比硬挤更稳
