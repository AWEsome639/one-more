# 游戏内「图标/文字错位（显示不下）」静态扫描 · 2026-11-07

> **只读扫描**，未改任何 `.ets`、未编译、未碰 hdc/模拟器。
> 对象：`entry/src/main/ets/games/` —— 615 个 `.ets` / 170,249 行（355 款游戏）。
> 方法：注释剥离 → 解析 ArkUI `Text(...)` 修饰链 → 用 `core/GameI18n.ets` + `core/I18n.ets`
> 的 10 语言词典算**最坏语言**的宽度（CJK 1.0em / 拉丁 0.55em / 空格 0.30em / emoji 1.2em），
> 再和容器可用宽比（440 宽手机 ≈ 408vp、360 宽 ≈ 328vp、233 表 ≈ 201vp）。
> ⚠️ 算式只能**排序**，不能下「一定错位」的结论（判据 589）；但反过来「算出来就差很多」的一定要看。

---

## 0. 一句话结论

- **440 宽 + 中文**：HUD 三/四宫格**一点都不挤** —— 最紧的标签（「已找到素数」5 字）只占格宽 **46%**；
  261 处「一排多个 Text」里中文**没有一行**超过可用宽。⇒ **如果用户是在中文 + 手机竖屏下看到的错位，
  锅不在「标签太宽」，而在 ⑥ emoji 图标行盒**（首页就是靠「emoji 换成固定尺寸位图」修好的）。
- **真正能算出「放不下」的**全在三类场景：**多语言**（de/ru/fr/it/ar）、**窄屏（≤360 / 233 表）**、
  **固定高度容器**（tip 行 / 选项格）。
- 已经排查干净的：**按钮 901 个全部 ≥1.3 倍余量**；`maxLines(1)` 全部都有省略号（0 处裸裁）；
  `Stack + BottomEnd` 角标压字 **0 处**；`Text` 固定 `width(<60)` 只有 7 处且全是数字值。

## 1. 用户看得见的（按证据强度排序）

### ①【高 · 一定会裁】4 款「tip 行」固定 `height(20)` —— 长语言/窄屏第二行直接被切

| 文件:行 | 现场代码 |
|---|---|
| `GCountdownMath.ets:599` | `Text(this.tip).fontSize(FontSize.sm).fontColor(this.theme.inkSoft).height(20)` |
| `GCryptoArithmetic.ets:430` | 同上 |
| `GDigitSwapEq.ets:437` | 同上 |
| `GDivisibilityDash.ets:362` | `Text(this.tip)...height(20)` |

- **为什么错位**：`height(20)` 只够**一行** sm(14) 文字（行高 ≈19–20），而 `this.tip` 是整句
  （如「点数字 → 点运算符 → 点数字」「✗ 运算符 {0}，再点一个数字」）。中文在 440 宽 ≈154vp 放得下，
  但 `GCryptoArithmetic` 的法语提示实测需要 **384vp**：440 手机（408vp）勉强一行，**360（328vp）就换行 ⇒ 被 20vp 裁掉第二行**；
  233 表（201vp）更必裁。
- **一句话修法**：去掉 `.height(20)`，或改 `.minHeight(20)` + `.maxLines(2).textOverflow({ overflow: TextOverflow.Ellipsis })`。

### ②【高 · 长语言/窄屏】「一排多个 Text 都不给 layoutWeight」的 261 行里，20 行会超宽

扫描：`Row` 直接子层 ≥2 个 `Text`、且都没有 `layoutWeight/width/flexGrow` ⇒ 共 **261 行**。
中文全部 ≤211vp（最大一行 `GPerspectiveTaking.ets:324` 211vp），但最坏语言下：

| 文件:行 | 最坏语言总宽 | 现场 |
|---|---|---|
| `GRelationalMemory.ets:274` | **443vp** | `答对` · `题号` · `记忆 5 秒` 三个 Text 并排 |
| `GFaceNameAssociation.ets:323` | 411vp | `阶段` · `记脸` · `题号` · `答对` 四个并排 |
| `GFaceTraitAssociation.ets:323` | 411vp | 同上 |
| `GShellGame.ets:286` | 388vp | 5 个 `Text` 并排（猜中/洗牌/次/状态/快选） |
| `GDividedAttention.ets:303` | 384vp | `左` · `✘ 误报` · `左` · `✘ 误报` |
| `GDefinitionDash.ets:297` | 381vp | `题号` · `答对` · `失误` · `倒计时` |

- 统计：440 宽下 3 行超 408；**360 宽下 20 行超 328**（常见小屏手机）。
- **为什么错位**：没有权重 ⇒ ArkUI 按内容分宽；总宽超了要么挤成一团，要么某个 Text 折成两行 ⇒ 同一行文字基线不再齐。
- **一句话修法**：给最长的那一项加 `.layoutWeight(1)`（或统一 `.maxLines(1).textOverflow(...)`）。

### ③【中 · 只在外语下露馅】HUD 标签一换行，下面的数值就不再对齐（36 格）

扫描 HUD 形状（`Row` 里 N 个 `layoutWeight(1)` 子块 + `Column` 里的 `Text(TG(...)).fontSize(xxs)`）：
**2 列 37 行 / 3 列 672 行 / 4 列 80 行**，没有 5 列以上。中文 440 宽最紧 0.46（「已找到素数」60vp / 129vp 格），
但最坏语言下 **36 格 > 1.0**：

| 文件:行 | 标签 | 格宽 | 最坏语言需要 | 代表 |
|---|---|---|---|---|
| `GPrimeHunter.ets:313` | 剩余素数 | 129 | **152vp (ar)** | `Text((TG('剩余素数'))).fontSize(FontSize.xxs)` |
| `GSieveVisualizer.ets:384` | 已找到素数 | 129 | **152vp (ar)** | 同上 |
| `GDefinitionDash.ets:318` | 倒计时 | 94.5 | **119vp (it)** | 4 宫格 |
| `GContextClues.ets:273` | 题号 | 94.5 | **113vp (fr)** | 4 宫格（另有 `GConundrumAnagram:283`/`GDoubleNBack:273`/`GSilentLetterSearch:280` 同款） |
| `GAbReversalOddball.ets:314` | 得分 | 94.5 | **106vp (ar)** | 4 宫格（另有 10 款同款） |

- **为什么错位**：`Column` 里是 `Text(标签, xxs)` + `Text(数值, md)`，没有 `maxLines`；标签一折行，
  该格的数值就整体下沉 ⇒ **三个格子的数字不在一条水平线上**（就是「错位」的样子）。
- **一句话修法**：给 HUD 标签统一加 `.maxLines(1).textOverflow({ overflow: TextOverflow.Ellipsis })`
  （或长语言下换短标签，如 `剩余素数`→`素数`）。

### ④【中 · 只在外语下露馅】选项格固定高 —— 长译文 3 行被裁

| 文件:行 | 现场 | 固定高 | 撑得住几行 |
|---|---|---|---|
| `GContextClues.ets:305/315/325/335` | `Text(opts[i]).fontSize(FontSize.md).width('100%').height(Cell.of(44))` | 44vp | md 16 ≈ 2 行（22×2） |
| `GDefinitionDash.ets:334/340/346` | 同上 | 46vp | ≈2 行 |
| `GWordLadderStep.ets:334` / `GWordSurge.ets:329` | 选项 Text | 52vp | ≈2 行 |
| `GDelayedMatchSample.ets:332/341/353/362` | `fontSize(FontSize.xxl).height(Cell.of(64))` | 64vp | xxl 24 ⇒ 2 行上限 |

- **为什么错位**：选项是**数据**（词/句），没有 `maxLines`；德语/俄语长词在窄格折成 3 行时，
  第 3 行被固定高裁掉 ⇒ 只显示半行字。
- **一句话修法**：加 `.maxLines(2).textOverflow({ overflow: TextOverflow.Ellipsis })`，长语言下字号降一档。

### ⑤【中 · 固定窄框】两处「固定宽 56/64 + 变长标签」

| 文件:行 | 现场 | 问题 |
|---|---|---|
| `GMancala.ets:584` | `Column({space: Space.xs}) { Text(...TG('对手')...).maxLines(2) }.width(56).height('100%')` | 「对手」→ 法语 `Adversaire` 5.5em×12=**66vp > 56−8**；不裁（有 maxLines/省略号），但折成 2 行后**数值被挤下去**，与棋盘中格不在一条水平线 |
| `GGearRotation.ets:308` | `Column({space: Space.xs}) { Text('⛓') Text(TG('啮合')/TG('皮带')).maxLines(2) }.width(64)` | 「啮合」→ 俄语 6.35em×12=**76vp > 64−0**，折成 2 行；左右两格是 1 行 ⇒ **三格的齿轮/标签高度不一致** |

- **一句话修法**：宽度给到 72/80，或标签用 `.fontSize(FontSize.micro)`。

### ⑥【可能正对应用户所见】emoji 当图标：68 处 `Text('🍕')` 没有固定尺寸

- 项目自己在 `components/Common.ets:1058` 记过这个根因：
  「图标是 **Text(emoji)**，大小/基线/行高全由**系统 emoji 字体**决定 —— macOS 与鸿蒙用的不是同一套字体
  ⇒ 图标会顶到盒子的边缘、视觉上就『贴着标题』。现在换成**固定尺寸的位图**。」
  2026-11-07 首页那次修复也是同一路（`GameCard` 图标改位图）。
- 游戏内**没有任何 `Image` 图标**（全项目 games/ 只有 2 个 `Image(` 且都不是图标），
  图标仍全是 emoji Text —— 且 68 处里**没有一处**给 `.width()/.height()`：
  代表：`GGearRotation.ets:299/312`（⚙️）、`GShadowPivot.ets:298`（🔄）、
  `GCognateCatch.ets:306`（↔）、`GMatrixMultiplier.ets:356/371/372`（× = ?）、
  `GWordAssociationRecall.ets:336`（→）、`GWordPairAssociateMemory.ets:321`（↔）、
  `GRelationalMemory.ets:290`（↔）、`GContinuousPairedAssociate.ets:397`（→）。
- **为什么错位**：同一行里 emoji 的行盒比数字高/低 ⇒ 数字或箭头上下跳半个字；
  不同设备 emoji 字体不同 ⇒ 量出来的宽高也不同。
- **一句话修法**：给图标 Text 固定盒子（`.width(28).height(28).textAlign(TextAlign.Center)`），
  或照首页的做法换成固定尺寸位图 / `SymbolGlyph`。

### ⑦【低 · 只在 233 表上】中文 HUD 标签正好卡在边缘

233×233（手表）下 3 宫格格宽 ≈60.3、「去掉 padding」后 ≈52：
「已找到素数」60vp = **0.99 格宽**；同款 `GReversi:593`（电脑（白））、`GNoriNori:588`（已满足区域）、
`GNurikabe:643`（已满足提示）、`GSlitherlink:550`（已满足线索）、`GFeatureMatrixRecall:349`（要点的颜色）都是 0.99。
⇒ 字号再大一点（长辈模式 +42%）或文案再加一个字就折行。
- **一句话修法**：`Bp.isWatch()` 时这些标签换 3 字以内；或统一 `maxLines(1)` + 省略号。

## 3. 方法学与盲区（别把这报告当唯一证据）

- 只解析**字面量**标签（`TG('…')` / `TG2('…',…)` / 裸中文串）；`String(...)`、模板串、变量拼接**不扫**。
- **`@Builder` 间接层没解析**：像 `this.stat(0)` 这种把 `Text` 藏在 builder 里的 HUD（蜘蛛纸牌那套）不在统计内；
  本报告里 HUD 数字来自**内联写**的那批（355 款里绝大多数是内联）。
- 宽度模型是保守近似；**emoji 行盒、字体回退、`Cell.of` 在长辈模式 ×1.33** 都只能估。
- 结论一律以真机截图为准（判据 588/589）；本报告只回答「哪里最可疑、按什么顺序看图」。

## 4. 一句话修法汇总（按投入产出）

1. 4 款 tip：删 `.height(20)`（5 分钟，零风险）。
2. HUD 标签：全局加 `.maxLines(1).textOverflow(Ellipsis)`（36 格受益，一处模板改法）。
3. 261 行无权重 Text：给最长项 `.layoutWeight(1)`（20 行在 360 宽受益）。
4. 选项格：`.maxLines(2).textOverflow(Ellipsis)`。
5. 图标：照首页把 emoji 换成固定盒子/位图（68 处，工作量大但根治「图标文字错位」）。
