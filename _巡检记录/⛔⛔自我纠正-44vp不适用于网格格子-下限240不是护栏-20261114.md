# ⛔⛔ 自我纠正：`44vp` **不适用于网格格子** ⇒ 「`240` 是护栏」这个结论作废

> `2026-11-14 16:1x`。我上一条（`★★★★★19处下限240全都不该删`）的推理基础是错的。

## 一、⇒ 错在哪

**我用了「`44vp` 触摸门槛」去论证「盘面不能缩到 `173vp`」。**

**⚠️ 但代码里只有 `Cell.tap()` 强制 `44vp`：**
```ts
// Design.ets:137-140
static tap(base: number): number {
  const v: number = Cell.of(base);
  return v < Layout.touchMin ? Layout.touchMin : v;   // ★ 只有 tap 强制 44
}
```
**⇒ 而 `Cell.of()` **不**强制 ⇒ 网格格子若用 `Cell.of()` 或直接除法，就没有 `44vp` 下限。**

## 二、⇒ 反证：`GGo9` 的格子是 `19.2vp`

**`GGo9`：`N = 9`（9 路）、盘面 `maxWidth = boardMax()` = 横屏 `h - 360` = **`173vp`**。**
**⇒ 每格 = `173 / 9 = **`19.2vp`**` —— 远低于 `44`。**

**⚠️ 而 `GGo9` 是整个项目里**被认为做对了的参考实现**（注释里有三尺寸真机实测记录）。**

**⇒ ⇒ 所以「格子必须 ≥ `44vp`」**不成立** ⇒ 我上一条那张「`5×5` 降到 `34.6vp` 不可玩」的表，前提是假的。**

## 三、⇒ 那 `240` 这个下限是什么

**现在只能说：它是个**历史值**，不是算出来的。**
**⇒ 证据：`29` 处里 `19` 处是 `240`、`8` 处是 `200`、还有 `220`/`300` 各 `1` —— 若是按格子尺寸算的，应该与网格维度相关，而 `15×15`（`Gomoku`）和 `4×4`（`2048`）**用的是同一个 `240`**。**

**⇒ ⇒ 同一个值配 `4×4` 和 `15×15`，说明它**不是**按格子尺寸算的。**

## 四、⇒ 所以修正后的结论

| 原结论 | 修正 |
|---|---|
| ~~「`19` 处下限 `240` 是护栏、全不能删」~~ | **❌ 前提错** |
| **「`44vp` 只约束 `Cell.tap()` 的按钮，不约束网格格子」** | ✅ 有代码与 `GGo9` 实测支撑 |

**⚠️ 所以「降下限」既不是显然可行、也不是显然不可行 —— **缺一个测量**：**
**⇒ 需要知道「多小的格子还能准确点中」。`GGo9` 的 `19.2vp` 是唯一的已知点，且它是「已接受」的。**

## 五、⇒ 那明天该怎么做

**不要基于「`44vp`」去改任何下限。**
**⇒ 若今晚数据显示某款盘面被裁、且它是 `4×4`/`5×5`（格子 `60vp`/`48vp`，**远高于** `Go9` 的 `19.2vp`）：**
**⇒ 可以**先试降下限**（`240 → 200`：`5×5` 每格 `40vp`、仍比 `Go9` 大一倍）⇒ 省 `40vp = 120px`。**

**⇒ 这比「缩上方」省得多，且不影响上方元素。**

## ⇒ 判据（`2522`）

**引用一个「最小值/门槛」去否定改动前，先确认**那个门槛适用于这一类元素**。**
**⇒ `Layout.touchMin = 44` 只写在 `Cell.tap()` 里 ⇒ 它约束按钮，不约束网格格子。**

**⇒ 判据：拿一个门槛当论据前，先找到它的**作用点**（哪个函数/哪类元素）；作用点不对，论证作废。**
