# ★★★ 诚实结论：`240 → 140` 可能只是**改善**，不是**修好**

> `2026-11-14 16:4x`。上一轮说「一个常数修 `15` 款」，这一轮算完发现：**只腾 `67vp`，多数款仍不完整。**

## 一、算式

**`max(240, 533−360) = 240` → `max(140, 533−360) = 173` ⇒ 盘面缩 `67vp`。**

**⇒ 那 `67vp` 回到盘面下方 ⇒ 多显示「`67 ÷ 每格高`」行。**

| 行数 | 改后每格 | 多显示 |
|---:|---:|---:|
| `4` | `43.2vp` | **`+1.5` 行** |
| `5` | `34.6vp` | `+1.9` 行 |
| `6` | `28.8vp` | `+2.3` 行 |
| `8` | `21.6vp` | `+3.1` 行 |
| `15` | `11.5vp` | `+5.8` 行 |

**⇒ 而它们现在**只露 `1`–`2` 行**。改后：`4` 行盘面露 `2.5`–`3.5` 行（仍缺）、`6` 行露 `3.3`–`4.3` 行（仍缺）。**

**⇒ 所以对多数款，`240 → 140` 是**从「露 `1` 行」到「露 `3` 行」**，不是「完整」。**

## 二、⚠️ 而这个模型本身也可疑

**从 `Skyscrapers` 截图量出：**
- 盘面卡片顶 ≈ `716px = 239vp`
- 第 `1` 行格子 ≈ `1161–1527px = 387–509vp` ⇒ **行高约 `122vp`**
- 第 `2` 行上缘 ≈ `1567px = 522vp`

**⇒ `4` 行 × `122vp` = `488vp` ⇒ 盘面应有 `488vp` 高。**
**⇒ 而限宽 `240vp` 下 `4` 行每行应 `60vp`。**

**⇒ 二者矛盾 ⇒ 说明「限宽 → 行高」的对应关系我还没搞清**
（可能：`aspectRatio(1)` 的盘面被 `layoutWeight` 撑高、或格子不按 1:1）。

## 三、⇒ 所以正确的表述

| 说法 | 可信度 |
|---|---|
| 「`240 → 140` 会缩小盘面 `67vp`」 | ✅ **算术确定** |
| 「因此会多显示一些行」 | ✅ **方向确定** |
| 「因此**修好**那 `15` 款」 | ❌ **不确定，可能仍不完整** |
| 「行高 = 限宽 ÷ 行数」 | ❌ **与截图实测矛盾** |

**⇒ ⇒ 结论：`240 → 140` 该做（无条件正确、方向对），但**不能承诺它修好**。
⇒ 真实效果必须**编译后看图**才知道。**

## 四、⇒ 而这正好支持「第一批只改一款」的安排

**先改 `GSkyscrapers` 一处 ⇒ 编译 ⇒ 看图，就能知道：**
- **它从「露 `1` 行」变成「露几行」**
- **那个「行高 `122vp`」之谜的答案**

**⇒ 这个数据点决定后续 `13` 处**要不要配合别的改动**（如同时收上方元素）。**

## ⇒ 判据（`2249`）

**「改一个参数会改善」与「改一个参数会修好」是两件事。**
**⇒ 判据：算出「改动能腾出多少」之后，还要算出「需要多少」。
⇒ 若 `腾出 < 需要` ⇒ 只能承诺「改善」，且必须**先测一款**再决定后续。**

**⇒ 这次 `腾 67vp` vs 「需要显示 `2`–`5` 行」⇒ 明显不够 ⇒ 所以第一批只改一款、看数据再说。**

## ⇒ 判据（`2250`）

**两个来源的量（截图 `122vp` vs 算式 `60vp`）矛盾时，**不要选一个信**。**
**⇒ 它们是两个独立的观测，矛盾说明**模型缺一环**（这次可能是 `layoutWeight` 撑高或非 1:1 格子）。

**⇒ 判据：实测与算式矛盾时，先说「模型不完整」，再用一个新观测（编译后看图）去补那一环。
⇒ 不要用「可能我量错了」把它压过去 —— 那会一路错下去。**
