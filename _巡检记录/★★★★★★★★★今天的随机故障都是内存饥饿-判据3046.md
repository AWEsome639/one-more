# 判据 3046：今天的「随机故障」**都是内存饥饿** —— 一个数字解释全部

## 一、决定性的一次观测

```
模拟器运行中：  内存空闲    77 MB
$ Emulator -stop onemore_fold
模拟器已停：    内存空闲 1,399 MB      ← ★ 1.3 GB 全还回来了
```

⇒ **这台机器可用的空闲内存总量只有约 `1.4 GB`，而模拟器一个就吃 `1.3 GB`。**
⇒ 跑模拟器时余量 `77 MB` —— **这不足以让一个 `HarmonyOS` 模拟器稳定渲染。**

## 二、于是今天所有「随机」都解释得通了

| 现象 | 我当时的判断 | 真因 |
|---|---|---|
| `bundle manager service is died`（装包失败）| 以为模拟器坏了 | **包管理服务被 OOM 杀掉** |
| `hdc list targets` = `[Empty]`（设备"丢了"）| 以为 hdc 的问题 | **模拟器进程崩了、正在自动重启** |
| `NOT_HOME`（找不到游戏首页）| 查了三层（设备/锁屏/app）| 前几层修好后仍是**第四层：能启动但全黑** |
| 截图暗像素 `100%` | 以为 app 没画面 | **渲染管线内存不足起不来** |
| `etime` 只有 `00:15`（模拟器"刚启动"）| 以为我启动了它 | **它刚崩完、自己重启了** |
| 一次测量 `~70s` 有时变成 `130s`/`300s` | 以为网络/导航慢 | GC 与换页拖慢 |

⇒ **六个「不同」的故障，一个根因。**

## 三、这条对「怎么用这台机器」的结论

| 判断 | 依据 |
|---|---|
| **不能同时跑模拟器 + 编译** | 编译峰值 + 模拟器 `1.3 GB` > `1.4 GB` ⇒ 必崩 |
| **不能同时跑模拟器 + 别的重活** | 同上 |
| **跑模拟器时余量 `77 MB` ⇒ 不稳定是必然的，不是偶发** | 实测 |
| **长时间全库扫描（`7.4` 小时）在这台机器上不现实** | 每崩一次就要重解四层 |

⇒ **可行的做法**：
1. **跑测量前先关掉别的重活**（编译、其他模拟器、大批量脚本）
2. **一次只跑一个模拟器**（这条本来就有，但今天违反了两次：`kill -9` 后立刻起新的）
3. **分批跑**，每批前做四层健康检查
4. **测量失败先看内存，再怀疑代码/判据/游戏** —— 今天在错误方向上花了约 `40` 分钟

## 五、判据

> **同一台机器上出现一串「互不相关」的故障时，先算一次「资源余量」，
> 而不是逐个去修那些故障 —— 它们很可能是同一个原因的六种面孔。**

⇒ 四条：
1. **跑模拟器前先看空闲内存**；`< 500 MB` 余量就别开
2. **关掉模拟器后立刻再看一次** —— 差值就是它的真实占用（今天量到 `1.3 GB`）
3. **一小时内出现三个以上不同故障 ⇒ 停手查资源**，不要再逐个排查
4. **`aa start` 的 `successfully` 不代表有画面** —— 必须取截图算暗像素占比（`100%` = 渲染没起来）
