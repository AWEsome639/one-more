# `Number Bonds`（数字键）：**选项从「第 4 个半切」到「四个完整」**（判据 1956 第二例）

## 改前（`max_bottom = 1584`）

**截图 `NumberBonds-修前.jpeg`**：四个选项行 `1 9` / `2 8` / `3 11` / `4 10`，
**第 4 行只露出上半截** ⇒ **玩家选不了第 4 个选项**。

## 诊断（`probe`）

```
Column h=498 y=[1102..1600]   ← 选项区：498px ÷ 4 行 = 124px/行
Row    h=102 y=[1498..1600]   ← 第 4 行（只剩 102px，还差 ~84px）
```

## 改法（判据 1939）

**需腾 `84px` ÷ `4` 行 = `21px/行`** ⇒ 选项行 `Cell.of(36)` → **矮屏 `Cell.of(28)`**
（`36→28` = `8 × 0.85 ≈ 6.8vp = 20px/行 × 4 = 80px`）

## 改后（`max_bottom = 1583`）

**截图 `NumberBonds-修后.jpeg`**：**四个选项全部完整可见**，底部说明行 `目标数 = 左半 + 右半，把缺的那半补上` 也完整。

**⇒ `max_bottom` 只从 `1584` 变到 `1583`（`1px`），但用户从「选不了第 4 项」变成「四项都能选」。**

## 判据 1956 的第二次验证

| | 数字 | 视觉 |
|---|---|---|
| `Math Maze` | `1600 → 1597`（`3px`）| 按钮从「露 35px」到「完整」|
| `Number Bonds` | `1584 → 1583`（`1px`）| 选项从「第 4 个半切」到「四个完整」|

**⇒ 两次都是「数字几乎不动、视觉真修好」。**
**⇒ `max_bottom` 作为「合格线」是彻底不可靠的 —— 它只能当筛查器，结论必须来自截图。**
