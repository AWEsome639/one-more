## 二、⇒ `Skyscrapers` 的特殊性

**`const N = 4`（游戏逻辑 `4×4`）、渲染 `6×6`（含上下线索行 + 左右线索列）。**
**⇒ 所以 `44 * (N + 2)` 既自解释又正确：`N` 是游戏格数、`+2` 是线索。**
**⚠️ 不要写成 `44 * 6` —— 那会让下一个人以为 `6` 是魔法数。**

## 三、⇒ `Norinori`/`Pipes` 有 `const N = 5`

**它们**既是动态渲染（`rowIdx()`）又有 `const N = 5`**。**
**⇒ 查一下：`N` 与 `diffTotal` 是同一个东西吗？若 `N` 恒为 `5` 而 `diffTotal` 可变，就要用 `diffTotal`。**

**⚠️ 这条明天改之前必须确认（否则按 `N` 写会错）。**

## ⇒ 判据（`2290`）

**「我记的 `N`」与「`const N` 的值」不一致时，先分清**它们是不是在数同一个东西**。**
**⇒ `Skyscrapers`：我记 `6`（渲染格数）、`const N` = `4`（游戏格数）⇒ 两个都对。**
**⇒ 若不查就「纠正」成 `4`，会把线索框漏掉 ⇒ 格子变 `4×` 大。**

**⇒ 判据：两个数不一致时，先问「各自数的是什么」，再决定哪个用于哪个式子。**

## ⇒ 判据（`2291`）

**同一批改动里，有的能用常量、有的只能写字面量 —— 这取决于**那个文件有没有那个常量**。**
**⇒ 判据：写 `44 * N` 之前先 `grep "const N"`。
⇒ 没有 ⇒ 写字面量并在注释里写明「`N` = 网格边长」。**
