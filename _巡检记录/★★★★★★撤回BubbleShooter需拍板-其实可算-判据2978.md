# ⇒ **撤回**：`Bubble Shooter` **不需要拍板**，它和 `Magnets` 是同一个病，可以算出来

> `2026-11-19 01:00`。我 `01:2x` 曾判「`ROWS 9→6` 是结构性的、需奥森拍板」——**现在撤回**，因为换了个问法就解出来了。

## 一、⇒ 病根：**宽度是用高度算出来的**

`GBubbleShooter.ets:533`：
```ts
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 360)))
//                                  ↑ 用高度推宽度             ↑ 533-360 = 173vp
```
**⇒ 手机 `533×2560`（宽 `493vp` 可用），棋盘宽度却只给了 **`173vp`** ⇒ **只用掉屏宽的 `35%`。**
**⇒ ⇒ 与 `Magnets` 同型（判据 `2976`）：**一个维度的尺寸用另一个维度算出来**。**

## 二、⇒ 气泡小的直接原因：高度只分了 `26%`

`441` 行：
```ts
const avail = Math.max(120, Bp.height * (Bp.isShort() ? 0.26 : 0.30));   // 533×0.26 = 139vp
return Math.max(10, (avail - gap) / ROWS);                              // 139/9 ≈ 14vp
```
**⇒ `0.26` 是**拍的**，不是算的。它上方注释还写着「横屏 `533` ⇒ `160vp`」——那是 `0.30` 分支的值，`isShort()` 为真时走的是 `0.26` ⇒ **注释与代码不符**。**

## 三、⇒ 算一下：屏幕其实有 `187vp` 用不上

| 区域 | 估算 |
|---|---|
| 标题栏 | `73` |
| 待发射行（`Cell.of(34)`）| `29` |
| 消息行 | `14` |
| `重开` 按钮（`Cell.of(46)`）| `39` |
| 底部提示 | `12` |
| 各处 padding | `40` |
| **棋盘** | **`139`（现）** |
| **合计** | **`346` / `533`** ⇒ **剩 `187vp` 没用** |

**⇒ 把 `0.26` 改成 `0.47`（`= 250vp`）：**
```
棋盘 250 + 其余 207 = 457vp < 533 ✅
cell = 250 / 9 = 27.8vp  （现在是 14vp ⇒ 翻倍）
```
**⇒ ⇒ **`ROWS` 一颗都不用动**。**

## 四、⇒ 结论修正

| | 我 `01:2x` 说的 | 实际 |
|---|---|---|
| 性质 | 「数学上不可能」 | **可以算，只是常数拍错了** |
| 修法 | `ROWS 9→6`（改玩法）| **`0.26 → 0.47`（改一个数）**|
| 是否需要拍板 | 需要 | **不需要** |

**⇒ 仍需注意：`2975` 说过网格格不受 `44vp` 约束 ⇒ 这里的判据不是「够不够 `44vp`」，而是**「能不能看清并瞄准」**。`27.8vp` 的气泡直径 ≈ `83px`，带数字标号可读。**

## ⇒ 判据 `2978`

**⇒ 当一个尺寸「看起来小」时，先问：**它是由哪个维度算出来的？** 今天 `Bubble Shooter` 的宽度来自高度、`Magnets` 的格子来自高度 ⇒ **两个都是「只算一个方向」。**
**⇒ ⇒ 并且：**「需要拍板」往往是「我还没算」的委婉说法。** 先把两个不等式都写出来，大部分「结构性」会退化成「一个常数」。**
