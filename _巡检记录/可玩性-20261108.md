## ① 死循环：244 个 `while`，全部有出口

**方法**：对每个 `while (COND) {BODY}` 做括号配平，检查 BODY 里是否
① 修改 COND 里的变量 ② 对 COND 里的数组做 `push/pop/splice/...` ③ 有 `break`/`return`。

```
扫描 244 个 while（355 个文件）
⇒ 无出口候选：0
```

**我第一版判据出过 91 个误报** —— 因为我只检查了"变量被 `=`/`++` 修改"，
而实际写法是 `while (out.length < k) { out.push(...) }` —— **`push` 也是出口**。
加上 `.push/.pop/.splice` 识别后归零。

> 这条值得记：**判断循环会不会死，要看"条件里的量有没有被推进"，而不是"有没有计数器"**。

典型的安全写法（占多数）：
```ts
let guard = 0;
while (!ok) { ... if (++guard > 200) break; }      // 有 guard ✓
while (bag.length < 4) { bag.push(...) }            // push 一直在推进 ✓
```

## ④ 棋盘尺寸 vs 常量：0 处

**背景**：今天的 `GMathMaze` 是 `GOAL = 24` 写死，而棋盘按难度是 4×4=16 ⇒ **目标永远达不到**。
修法已确认：`GOAL = CELLS - 1`（**由棋盘派生，不写死**）。

**三轮筛查**：

| 判据 | 结果 |
|---|---|
| `const N/SIZE` + `GOAL/PASS/TOTAL > N²` | **0**（`GMathMaze` 现在 `N=5`，`GOAL` 从 `CELLS` 派生）|
| 含动态棋盘（`sizeNow`/`diffTotal`）且 `length` 与硬编码数比较 | 230 个文件命中 —— **判据太宽，不可用**（大多是 `length === 0` 这类）|
| **动态棋盘文件里的固定上界 `for` 循环**（`i < 4/5/6/7/9/16...`）| 17 处，**抽 3 处看全部良性** |

抽检的 3 处：

| 位置 | 实际含义 | 判定 |
|---|---|---|
| `GKakuroMini:322  for i<9` | Kakuro mini 是**固定 9 格**盘 | ✓ 良性 |
| `GChainReaction:181  for tries<6` | **重试计数器**，不是棋盘上界 | ✓ 良性 |
| `GCompassMaze:60   for k<6` | 「再拆几道墙」的**固定次数** | ✓ 良性 |

## ⑤ `computeHint()` 未初始化变量：0 处

**背景**：今天 `GSymbolLogic` 的提示出过 `undefined`。已确认修好：

```ts

if (idx < 0) { return Hint.make([], TG('想一想：第一个符号是几'), ...); }
return Hint.make([idx], TG2('答案是 {0}', String(this.ans)));
```

**四项检查**：

| 判据 | 结果 |
|---|---|
| `let x;` 声明后从未赋值、却在提示里使用 | **0** |
| `this.xxx[...]` 索引取值后直接拼字符串 | **9 处候选**，查了最可疑的 3 处 |
| 字段**声明时无初始值**（`@State private x: string;`）且在 `computeHint` 里用 | **0** |
| 模板 `${...}` 里取未初始化变量 | **0** |

9 处候选里查的 3 处：

| 位置 | 代码 | 判定 |
|---|---|---|
| `GTargetNumber:228` | `this.opts[i]`（`i = ansIdx`）| **低风险**：`ansIdx=0` 有初值、每轮 `reset` 里重设 ✓ |
| `GWordGridConnection:259` | `this.cells[a]` | **低风险**：`cells=[]` 有初值、有 `length < lim` 守卫 ✓ |
| `GCryptogram:204` | `this.word` | **低风险**：`cur()` 取当前项，取不到时提前 return ✓ |

## ⑥ 这个结论能证明什么、不能证明什么

**能证明**：
- 今天修的 5 类 bug，在 355 款里**没有第二例**（同样的代码形态一处都没有）
- `GMathMaze` 的修法（常量由棋盘派生）在全量范围内没有遗漏同类
- `GSymbolLogic` 的 `undefined` 形态没有复发

**不能证明**：
- **不能保证每一款打开都能玩** —— 静态扫描抓不到：
  - 运行时状态机错误（`state` 走到一条没有出路的路径）
  - 布局溢出（`GKakuro` 那种"按钮被挤出"，只有真机渲染才知道）
  - 生成器失败（随机数生成不出合法棋局，但没有 guard）
  - 平台 API 在真机上行为不同
- 我的 ④ 判据在第二层（230 个文件）就失效了，**只能靠抽样**，
  而 17 处只抽了 3 处（**14 处未看**）

**⇒ 真正的"每款都能玩"只能靠运行时：真机/模拟器逐款打开一次。**
那需要 355 次启动 + 交互，不是静态扫描能替代的。这条我做不到（只读边界 + 单次会话时长）。
