# 新度量轴：**大屏的竖向空白**（`88` 张里 `25` 张中间空 > 15%）

> `2026-11-16 13:27`。**不是「被切」，是「没利用」。**

## 一、⇒ 怎么量的

**⇒ `工具/measure_waste.py`：读截图 → 逐行判「有没有非背景像素」（差异 > 18 且占比 > 1.5%）→ 算**
- **`占用`**：内容底 / 屏高（**几乎全是 99%**，因为底部导航条总在 ⇒ 这个数没用）
- **`最大空白`**：首个内容行与最后内容行之间，最长的连续空行 / 屏高（**这个才有用**）

**⚠️ 量的是截图，不是 dump —— dump 只有节点的 bounds，算不出「节点之间空了一大块」。**

## 二、⇒ 结果（`88` 张折叠屏截图）

| 判定 | 张数 |
|---|---:|
| ok（空白 ≤ 15%）| `63` |
| **⚠ 中间空 > 15%** | **`25`** |

**⇒ 最狠的几款：**

| 款 | 最大空白 |
|---|---:|
| `Path Recall` | **`53%`** |
| `Kakurasu Sums` | **`49%`** / `44%`（两次）|
| `Binary Matrix Rank All` | **`45%`** |
| `Cryptogram All` | `33%` |
| `Context Clues` / `Breakout` / `Block Stacking Physics` / `Binomial Match` | `28%` |

## 三、⇒ 这算什么「坏」

**⇒ 不是缺陷（没有东西被切、没有元素点不到），是**品质问题**：**
**⇒ 大屏给了 `798vp` 高度，而界面把内容堆在上半部，中间空掉三分之一到一半 —— 那部分**没有承担任何信息**。**

**⇒ 对「每一帧、每一处细节都值钱」的标准来说，这和切掉一样刺眼：一个是被切掉，一个是根本没放东西。**

## 四、⇒ 为什么之前所有指标都看不见它

| 指标 | 为什么看不见 |
|---|---|
| `blk` | 只算「越界」⇒ 空白不是越界 |
| `lowh` | 只看最低元素 ⇒ 底部导航条总在 `99%` 处 |
| 配对比较 | 只看「同一元素是否变小」⇒ 空白与元素大小无关 |
| 截图人工看 | 我今天才第一次认真看折叠屏的游戏截图 |

**⇒ 判据 `2830`：**「没有内容」和「内容不对」是两种坏法，而`blk`/`lowh` 只覆盖后者。**
**⇒ 量「没有内容」需要**逐行看像素**，不是看节点。**

## 五、⇒ 下一步

**1. 先按空白排序，取前 `5–8` 款**截图人工复核**（自动化只报数，判好坏还得看）。**
**2. 确认「确实难看」的，再谈修法（大屏下 `layoutWeight` 撑开、或把选项行做等分、或给内容区 `justifyContent`）。**
**3. ⛔ 不要在只有 `1` 张样本时定阈值 —— 现在的 `15%` 是**初值**，等跑批结束（`354` 款全量）再校准。**

# ⛔ 【`13:28` 自我推翻】这个轴**不成立** —— 是尺子太粗（判据 `2831`）

## 一、⇒ 怎么发现的

**⇒ 我按空白排序取最狠的 `Path Recall`（`53%`）去**看截图** —— 结果图上根本没有「空一大块」：**
**⇒ 那是一片 `5×5` 的**淡黄色格子**（`#FFFDE8` 一类），和白色背景的差异小于我设的阈值 `18` ⇒ **被判成空白**。**

## 二、⇒ 降低阈值后重测

**⇒ 背景差异阈值 `18 → 8`、非背景像素占比 `1.5% → 1.0%` ⇒ 重跑全部 `89` 张：**

```
共 89 张，可疑 0 张
```

**⇒ 全部 `ok`。`Path Recall` 从 `53%` 掉到 `1%`。**

## 三、⇒ 结论（老实说）

**⇒ 「大屏竖向空白」这个轴，**目前没有任何证据支持**。`25/88` 那个数是阈值造成的假象。**
**⇒ 我是先看到数、再去找解释的 —— 而真正该做的顺序是**先看一张图，再决定要不要量**。**

## 四、⇒ 为什么这是今天最该记的一条

**⇒ 今天已经被自己的仪器骗了六次：**
1. **`blk`**（只统计越界）
2. **台账 `t[:26]` 切片**
3. **dump `tx[:40]` 切片**
4. **我的 `grep` 匹配到自己的注释**
5. **`pgrep -f qemu-system` 数不到折叠屏实例**
6. **这次的「空白阈值 `18`」**

**⇒ 六次里，有五次是**同一个错**：把一个「为了某种目的设计的指标」当成「事实本身」。**

## ⇒ 判据（`2831`）

**如果一个指标需要不断调阈值才能停止报告问题，那它多半在量错东西。**
**⇒ 正确流程：**先看一张图确认现象存在 → 再设计能量化它的指标 → 再调阈值**。**
**⛔ 反过来（先跑指标、再看数、再找解释）就会得到 `25/88` 这种漂亮但虚假的结论。**
