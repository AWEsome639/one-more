# ★★★★ 两种改法的**最终形式**（今天最后一块）

> `2026-11-14 16:1x`。把 `16` 款的改法写成可直接抄的两段代码。

## 一、「换下限」（`13` 款：已有 `Math.max(240, …)`）

**现状：**
```ts
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(240, Bp.height - 360)))
```

**改成（只动第二个参数的下限）：**
```ts
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(44 * N, Bp.height - 360)))
```

**⇒ **保留 `Bp.height - 360`**：高度富余时仍按高度撑满（这是原设计意图，是对的）；只在高度不够时由 `44 * N` 兜底。**

**⚠️ `N` 用实际渲染格数：**
- `Skyscrapers` ⇒ `44 * (4 + 2)`
- `Crown`/`Hitori`/`Heyawake` ⇒ `44 * 6`
- `HitoriAll` ⇒ `44 * 8`
- `CountdownMath`/`Memory` ⇒ `44 * 4`
- `Dominosa`/`PathIntersect`/`ModuloPath` ⇒ `44 * 5`
- `SchulteTable`/`Norinori`/`Pipes` ⇒ `44 * (this.diffTotal > 1 ? this.diffTotal : 2)`

## 二、「补上限」（`3` 款：只有 `.width('100%')`，没有任何上限）

**现状：**
```ts
.width('100%')
```

**改成：**
```ts
.width(Math.min(Bp.width - 2 * Space.lg, 44 * N))
```

**⚠️ **不需要 `Bp.height - 360`**：这三款原本就没有那个高度自适应项，
而 `44 * N` 已保证「格子 `44vp` + 盘高 `44 * N`」⇒ 对 `N <= 8` 都在 `401vp` 预算内。**

**⇒ 三款的值：**
| 游戏 | `N` | 改成 |
|---|---:|---|
| `Block Count 3D` | `3` | `.width(Math.min(Bp.width - 2*Space.lg, 44 * 3))` |
| `Binary Matrix Rank` | `4` | `… 44 * 4 …` |
| `Pattern Sequence Draw` | `3` | `… 44 * 3 …` |

## 三、⇒ 为什么两段代码不一样

| 项 | 换下限（`13` 款）| 补上限（`3` 款）|
|---|---|---|
| 原来有什么 | `Math.min(屏宽, Math.max(240, 高-360))` | 只有 `'100%'` |
| 保留什么 | **保留 `高-360`**（高度富余时撑满）| **不需要**（原本没这个语义）|
| 加什么 | 把 `240` 换成 `44*N` | 加整个 `Math.min(屏宽, 44*N)` |

**⇒ ⇒ **不能把两段合成一段**：硬把 `Bp.height - 360` 塞进那 `3` 款，会改变它们原本的「撑满宽度」语义
（变成「按高度自适应」）⇒ 那是另一个改动，不该混在这次里。**

## ⇒ 判据（`2285`）

**「改一个常数」与「加一条约束」是两种改动，不能因为目标相同就写成同一段代码。**
**⇒ 这次 `13` 款是改常数（`240 → 44*N`），`3` 款是加约束（无 → `Math.min(…)`）。
⇒ 前者保留原有语义，后者引入新语义。**

**⇒ 判据：批量改时，先按「这次是**替换**还是**新增**」分组。
⇒ 替换要保留周围语义；新增要想清「为什么原来没有」。**

## ⇒ 判据（`2286`）

**`BlockCount3D` 那三款原本「没有上限」不是遗漏，而可能是**作者以为 `width('100%')` 就够**。**
**⇒ 所以补上限时要写清「为什么现在需要它」（`3×3` 在 `821vp` 屏上会撑到 `274vp`/格）。**

**⇒ 判据：给别处的代码补一条约束时，在注释里写「不加会怎样」——
⇒ 否则下一个人会以为「这条约束是多余的」而删掉它。**
