# ⛔ 磁盘告急 `1.2 GB` ⇒ 删废弃模拟器释放 `10.2 GB`

> `2026-11-14 13:5x`。**若没发现，今晚 `00:00` 的运行会直接失败。**

## 一、怎么发现的

**一次 `git push` 报：**
```
error: update_ref failed for ref 'refs/remotes/origin/main':
  cannot lock ref ... Unable to create .../main.lock: No space left on device
```

**⇒ 磁盘满了。**

## 二、当时的状态（红线）

| 挂载点 | 容量 | 已用 | 可用 | 使用率 |
|---|---:|---:|---:|---:|
| `/System/Volumes/Data` | `228Gi` | `191Gi` | **`1.2Gi`** | **`100%`** |

**⇒ 按 `AGENTS.md`：磁盘 `< 10 G` 必须停。而当时只有 `1.2 G`。**

## 三、⇒ 这会毁掉什么

**今晚的运行需要：**
- `hdc install -r` 装包（写 `/data`，但临时文件在 Mac 侧）
- **`221` 张截图**（每张约 `150KB` ⇒ `33MB`）
- 台账逐行写入

**⇒ `1.2 GB` 看似够，但 `hdc install` 与 `shot_game` 的临时文件会瞬间吃掉几百 MB
⇒ **大概率在跑到一半时失败**，而且失败方式会是「截图丢失」「台账写不进去」这种难查的错误。**

## 四、✅ 处置（`AGENTS.md` 预先批准的杠杆）

**删掉 `5` 个废弃的模拟器实例：**

| 实例 | 大小 |
|---|---:|
| `onemore2` | `1.7G` |
| `onemore3` | `2.8G` |
| `onemore4` | `1.7G` |
| `onemore5` | `1.9G` |
| `onemore6` | `2.1G` |
| **合计** | **`10.2G`** |

**⇒ 删前逐个验证无进程运行（`5/5` 无进程）。**
**⇒ **没有动 `onemore` / `onemore7`**（在用的）。**

**结果：**
```
释放 10,416 MB
⇒ /System/Volumes/Data 从 1.2Gi 可用 → 11Gi 可用（100% → 95%）
```

## 五、✅ 事后验证

| 项 | 结果 |
|---|---|
| 工作树 | `0` |
| `HEAD` | `c0cc6128` |
| `git fsck` | 无错误 |
| `.git` 大小 | `187M` |
| 本地 = 远端 | ✅ 一致 |

**⇒ 且那次「报错」的 `push` **实际是成功的**（`local == remote`）——
报错只发生在写**本地** remote-tracking ref 时，远端已收到。**

## 六、⚠️ `11 GiB` 仍然偏紧（`95%`）

**今晚 `221` 张截图 + 台账 ≈ `35MB` ⇒ 够。**
**但后续几晚的编译（每次 `~1.5GB` 的 `build/` 产物）会再吃掉一些。**

**⇒ 建议：明晚编译前再确认一次可用空间 ≥ `5 GiB`。**

## ⇒ 判据（`2198`）

**「磁盘满」这件事，最危险的时刻是**在长任务中途**，而不是发现它的那一刻。**
**⇒ 这次若没在那次 `push` 报错时发现，今晚会跑到一半失败，而失败形式是
「某款截图缺失」「台账某行写坏」 ⇒ **极难归因**。**

**⇒ 判据：开窗前必须查一次 `df -h`，阈值 `< 10 GiB` 就先腾。
⇒ 而「腾」的优先级：废弃模拟器 > 旧编译产物 > 缓存；**在用的实例与 `~/.dsh/work` 不动**。**

## ⇒ 判据（`2199`）

**`git push` 报 `No space left on device` 时，**先查「远端到底收到没有」再决定要不要重推**。**
**⇒ 这次远端**已收到**（`ls-remote` 与本地 `HEAD` 一致），报错只影响本地 ref 缓存。
⇒ 若不查就重推，会产生重复提交或更乱的 ref 状态。**

**⇒ 判据：任何「写到磁盘失败」的错误，都要先确认「它写的是哪一份」——
远端已成功的，本地那份失败无害。**
