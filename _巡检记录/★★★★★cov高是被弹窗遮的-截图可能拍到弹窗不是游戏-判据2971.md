# `cov` 高多半是**弹窗遮的**；而且截图可能拍的是弹窗、不是游戏

> `2026-11-19 01:10`。看图巡检第 `6`、`7` 张的发现。

## 一、⇒ `cov` 不能当缺陷信号

**⇒ 全库 `cov > 0` 的款有 **`356` 个** —— 几乎每一款都有「被遮挡节点」。**
**⇒ 抽查最高那个：`Word Snake Trail` `cov=81`** —— 图上看是**结算弹窗**（「再来一局? / 得分 0 / 用了 2.3 秒 / 下一款 / 再来一局 / 返回列表」）盖住了整屏。
**⇒ ⇒ `cov` 统计的是「节点被别的节点覆盖」，**弹窗/浮层/遮罩全算** ⇒ 它是**中性指标**，高不等于坏。**

## 二、⇒ 更要紧的：**这张截图不是游戏画面**

**⇒ `Word Snake Trail` 的这次测量（`20:29:28`）截到的是**结算弹窗**。**
**⇒ ⇒ 那么这次测量的 `blk`/`board`/`lowest` 等字段，量的是**弹窗的布局**，不是棋盘的布局。**
**⇒ 这类测量的有效性问题比「某个游戏坏了」更根本 —— 它会让**指标描述的对象都不是你以为的那个**。**

## 三、⇒ 怎么识别（不花设备的方法）

**⇒ 看截图**是最直接的。但可以先用廉价代理缩小范围：**
- **`cov` 极高**（如 `> 30`）⇒ 很可能是全屏弹窗；
- **`board=` 与常见棋盘尺寸差异大**且 `cov` 高；
- 同一款多次测量里 `blk` 忽大忽小、`lowest` 文本是按钮文案（如「再来一局」「下一款」）。

**⇒ ⇒ 反过来：**看到 `lowest` 是按钮文字而不是题面文字，就要怀疑拍到弹窗了。**（`Magnets` 的 `lowest='现 0'` 是题面，`Word Snake` 的应是按钮文案。）**

## ⇒ 判据 `2971`

**⇒ 「测量值描述的是哪个界面」必须可验证 —— 截图是唯一凭据。**
**⇒ 一个数字只有配上「它量的是什么」才有意义；今天 `Magnets`（棋盘缩水）与 `Word Snake`（拍到弹窗）是两个方向：前者量对了地方但指标看不见问题，后者**量的根本不是游戏**。**
