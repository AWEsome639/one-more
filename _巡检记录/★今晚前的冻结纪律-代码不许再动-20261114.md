# ★ 今晚前的冻结纪律：**代码不许再动**，工作树必须干净

> `2026-11-14 11:3x`。**这是从「可复算」这条目标要求反推出来的约束，不是保守。**

## 为什么

`sweep_all.sh` 写基线快照时会记录：

```
| git HEAD | `7eb47f16` |
| 工作区脏 | 1 个文件 |
| HAP | `46538864` bytes |
| HAP sha256 | `d9d7650c6062ea2e…` |
```

**⇒ 「工作区脏」这一栏是「可复算」的一部分。**
**若今晚跑的时候工作区有未提交改动，那份快照就说不清「到底跑的是哪份代码」。**

## 所以现在的三条约束

| # | 约束 | 理由 |
|---|---|---|
| 1 | **不再改 `.ets` 源码** | 改了就要编译，而编译与真机验证只能在他睡觉时做；不编译又不提交 ⇒ 工作树脏 |
| 2 | **不再改 `工具/*`** | 今晚要跑的就是现在这版；改了等于换管线（判据 `2056`）|
| 3 | **只写 `.md` 文档** | 文档不进 HAP、不影响快照里的「脏」判定（**⚠️ 但会进快照那一行「脏 N 个文件」！**）|

**⚠️ 等等 —— 第 `3` 条有问题。**
文档也在仓库里 ⇒ **写 `.md` 也会让工作树「脏」**。
**⇒ 正确做法：每写完一份文档就立刻 `commit` + `push`，保持 `git status --porcelain` 为 `0`。**

**⇒ 这就是我一直在做的（今天 `90` 次提交、每次写完就推）——现在明白它为什么是必须的，不只是好习惯。**
**⇒ 快照里那句「工作区脏 1 个文件」是 `10:06` 那份留下的（当时正在写它自己）。今晚跑之前必须确认是 `0`。**

## 今晚开跑前的最后一道自检（补进执行卡）

```bash
git status --porcelain | wc -l     # 必须是 0
```

**若不为 `0`** ⇒ 先提交或 stash，**否则今晚那份快照的「可复算」是假的。**

## 那「emoji 67 行」这类活什么时候做

**排在今晚之后、且需要一个能编译的窗口。**
- 它是**壳层**改动（`SettingsTab` / `StatsTab` / `GamesTab` / `Index` / `Common`）
- 改完必须编译 + 真机看观感
- **今晚之前做 = 制造一个「改了没编译」的脏树 = 毁掉今晚的可复算性**

**⇒ 所以：不是「优先级低所以不做」，是「现在做会破坏今晚」。两件事完全不同。**

## ⇒ 判据（`2079`）

**「可复算」不只要求「记录下参数」，还要求**跑的时候状态是干净的**。**
快照记了 `git HEAD` 和 `HAP sha256`，但如果工作树是脏的，
**别人拿到这两样也复现不出同一份代码** —— 因为实际跑的可能包含未提交的改动。

不是 `0` ⇒ 那份记录只有参考价值，没有复算价值。**
