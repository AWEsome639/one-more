## 剩下的假设（需要**代码级**排查，不是改布局）

**`ForEach` + `@Builder` 的组合在这个文件里可能没生效**：

**`KEY_ROWS` 是 `['QWERTYUIOP','ASDFGHJKL','ZXCVBNM⌫⏎']`（常量，非空）**

## 第八次：发现并修掉一个**真实的 `ForEach` key 重复 bug**（但症状未变）

**代码审查发现**：棋盘内层

**key 是 `'c' + c`，5 行都是 `c0..c4` ⇒ **`ForEach` 的 key 在整棵树里重复**（ArkUI 要求唯一）。**

**⇒ 改为 `'c' + r + '-' + c`（带行号）** —— 这是**正确的修复**（重复 key 会导致节点复用错误）。

**⇒ 这个 bug 是真的，但它不是「不渲染」的主要原因。**

## ⚠️ 自我更正：判据 1961 是**错的**

**我写了「`ForEach` 的 key 只用列会跨行重复 ⇒ ArkUI 复用错节点」，并据此改了 `Wordle` 的棋盘 key。**

**⇒ 但改完症状完全没变 —— 这本身就说明「那不是 bug」。**

**更可能的真相：ArkUI 的 `ForEach` key 是**每个 `ForEach` 实例内部**的作用域** ——
**每一行的内层 `ForEach` 各自独立，`'c0'..'c4'` 在各自实例里都唯一 ⇒ 重复不成立。**

**⇒ 我把「跨实例的相同字符串」误当成「同一实例内的重复 key」。**

### 这条更正的价值

**它同时解释了两件事：**
1. **为什么改 key 之后一点变化都没有**（因为它本来就不是 bug）
2. **为什么全库那么多游戏都用 `'c' + c` 却都正常**（`GGo9`、`GGravitySort` 等都这样）

### 由此立**正确的**判据 1962

> **`ForEach` 的 key 只要在**同一个 `ForEach` 实例内**唯一即可** ——
> **兄弟 `ForEach` 之间出现相同 key 字符串是正常的，不是 bug。**
>
> **⇒ 自查：我要修的「key 重复」，是不是把「跨实例的相同字符串」当成了「实例内重复」？**
>
> **依据**：我改了 `Wordle` 的棋盘 key（`'c'+c` → `'c'+r+'-'+c`），**症状零变化**；
> 而全库大量游戏用同样的 `'c' + c` 写法却很正常。

### `Wordle` 的改动要不要留

**留着** —— `'c' + r + '-' + c` 也是合法且更明确的写法，**不会造成任何问题**。
