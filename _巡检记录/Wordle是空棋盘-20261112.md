# `Wordle` 的真问题不是溢出 —— 是**棋盘和键盘根本不渲染**

## 两次截图对比（改前 / 改后 / 回退后）

| 版本 | 截图 | 屏幕内容 |
|---|---|---|
| 我封棋盘宽度后 | `截图-Wordle-173913.jpeg` | 页头 + `提示`/`AI 代打` + 统计 + **一片黑** |
| **回退后（原版）** | `截图-Wordle-175142.jpeg` | **完全一样：一片黑** |

**⇒ 说明「一片黑」**不是我改出来的**，原版就是这样。**

## 那 `max_bottom = 1600`、`lowest = '5'` 是什么

**`lowest='5'` 是统计卡的「机会 `5`」** —— 不是棋盘、不是键盘。
**`max_bottom = 1600` 是那个空容器的底边。**

**⇒ `Wordle` 被我的扫描归进「溢出 `1600`」是**误判**：它一格内容都没画出来，所谓「溢出」是空容器的尺寸。**

## 我的处置（已做完）

1. **`git revert` 掉我那一刀**（它没修好任何东西，也没造成回归 —— 回退后截图逐像素同源）
2. **重新编译 + 装机 + 复测**：`Wordle 1600`、截图仍是空棋盘
3. **记录真相**：这是「不渲染」，不是「溢出」

## 判据 1960（立）

> **`max_bottom` 高 + `lowest` 是**统计卡数字**（而不是盘面/按键/选项）时，
> 先怀疑「内容根本没渲染」，而不是「内容被挤出屏幕」。**
>
> **依据**：`Wordle` 的 `lowest='5'` 是「机会 `5`」；棋盘格子一个都没画。
> **⇒ 判据 1957 的升级版：先分清「被挤出去」与「没画出来」——两者的修法完全相反。**

## 现在对 `Wordle` 的判断（诚实版）

| 假设 | 证据 | 状态 |
|---|---|---|
| 是溢出（内容被挤出去）| 缩宽度两次都没让它出现 | **否** |

| 是「空棋盘本来就该是黑的」 | 开局没有任何猜测 ⇒ 格子无字；若格子底色≈黑，则**看起来就是一片黑** | **可能性最高** |

**⇒ 第三次尝试必须是「取证」而不是「改代码」：**
1. 在游戏里**点键盘输入一个字母**，看格子是否出现字
2. 或 `dump` 里搜键盘字母（`Q W E R T Y...`）—— 若 dump 有而屏幕看不到，就是**对比度**问题不是渲染问题

**⇒ 这正是判据 1960 说的：先分清「被挤出去」与「没画出来」（我还得加一句：还有「画了但看不见」）。**

## 三次尝试的汇总

| # | 改法 | `max_bottom` | dump 里有键盘字母吗 |
|---|---|---:|---|
| ① | 封下面 `width('100%')` | `1600` | **无** |
| ② | 棋盘 `72% → 32%` | `1591` | **无** |
| ③ | 根容器包 `Scroll` | **`1351`** | **无** |

**⇒ 三种改法都动了尺寸，但**内容始终没出现在 `dump` 里**。**

## 由此排除的假设

- **不是「被挤出屏幕」**：`Scroll` 之后内容总能滚到，仍无字母
- **不是「宽度太大」**：`32%` 之后仍无字母
- **不是崩溃**：`hilog` 里没有 `Wordle` 相关异常（只有 `GameService`/主题的常规警告）

## 剩下的假设（需要**代码级**排查，不是改布局）

**`ForEach` + `@Builder` 的组合在这个文件里可能没生效**：
```ts
Column({ space: Space.xs }) {
  ForEach(KEY_ROWS, (row: string, ri: number) => {
    Row({ space: Space.xs }) {
      ForEach(charsOf(row), (ch: string) => { this.keyView(ch) }, ...)
    }
  }, ...)
}.width('100%')
```
**`KEY_ROWS` 是 `['QWERTYUIOP','ASDFGHJKL','ZXCVBNM⌫⏎']`（常量，非空）**
⇒ **要么 `charsOf()` 返回空，要么 `@Builder` 在这种嵌套里不渲染。**

**⇒ 明天第一件事**：在 `charsOf` 里加一行 `console.log`，或把内层 `ForEach` 临时换成一个硬编码 `Text('Q')`，
**用「最小可复现」确认是哪一环不渲染。**

## 第四次：**像素级取证**（决定性证据）

**把截图裁出棋盘+键盘区，提亮 `3` 倍** ⇒ `_巡检记录/Wordle-提亮3倍.png`

**结果**：统计卡以下**整片纯黑** —— 提亮三倍也一个像素都没有。

**⇒ 与 `dump` 的结论一致（`dump` 里也没有键盘字母）：
`Wordle` 的棋盘和键盘确实**完全没有渲染**，不是「太暗看不见」。**

## 最终判定

| 证据 | 结论 |
|---|---|
| `dump` 无键盘字母（`0` 个单字母节点）| 无障碍树里没有它们 |
| 提亮 `3` 倍后整片纯黑 | 像素层面也没有它们 |
| `hilog` 无 `Wordle` 异常 | 不是崩溃 |
| 三次改布局（宽度 `100%`→封顶、`72%`→`32%`、包 `Scroll`）| 尺寸变了、内容仍不渲染 |

**⇒ 这是 `GWordle` 自身的渲染 bug**（`ForEach` + `@Builder` 那一层），
**必须先做「最小可复现」才能修 —— 不是布局问题。**
