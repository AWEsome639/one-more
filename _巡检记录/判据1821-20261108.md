# 判据 1821（2026-11-08 立）

## 1821 · `position({ x: '50%' })` 的百分比**不生效** —— 所有元素会叠在容器中心

**发现**：`GPong`（乒乓）的球和球拍**全部堆在屏幕中线 `x≈1268`**，球完全看不见。

**证据链**（`verifier-dev`，三步定性）：
1. **`tick#1..#2301` 连续执行**、`wait` 正常 14→0、无看门狗日志 ⇒ **逻辑层完全正常**
2. **但 tick 活跃窗口（` bx=75→89→70`）抓 5/3 张截图，`md5` 全部相同** ⇒ **画面不动**
3. **UI 本身活着**：点「暂停」→ 状态立刻变、截图 `diff` **4.18%** ⇒ **用户事件能重绘，定时器驱动的 `@State` 不能**

**对照实验（决定性）**：**打砖块（`breakout`，同为 `setInterval + @State` 动画）连拍 3 张 `md5` 全不同**
⇒ **不是模拟器渲染层问题** ⇒ **`GPong` 特有**

**根因**：`GPong` 用 `position({ x: (bx) + '%', y: (by) + '%' })` 定位球和球拍。
- **`Position` 的 `x`/`y` 类型是 `Length`，但字符串百分比不同于 `width`/`height`**
- **⇒ 百分比被忽略，所有元素落到容器默认位置（居中）**
- **顺手验证**：**球拍 `Row().width(PADDLE_W + '%')` 的宽度百分比生效了**（两根条有宽度）
  ⇒ **只有 `position` 的 `%` 不生效**，与「`Length` 不接受 `%`」的判断一致

**修法**：**用 `onAreaChange` 拿到的 `fieldW`/`fieldH` 换算成数值**
```ts
// 原来（失效）
.position({ x: (bx - BALL_R) + '%', y: (by - BALL_R) + '%' })
// 改成（数值 vp）
.position({ x: (bx - BALL_R) / 100 * fieldW, y: (by - BALL_R) / 100 * fieldH })
```

## 为什么这条判据值钱

**它的表现是「画面不动」，而不是「报错」** —— 最容易被误判成：
- **定时器没跑**（日志证明在跑）
- **`@State` 没更新**（日志证明在变）
- **模拟器渲染层 bug**（对照实验证明不是）

**⇒ 只要看到「元素全部叠在容器中心」，第一反应应该是 `position` 的百分比。**

## 判据

**`width`/`height` 接受 `%`（字符串），`position` 的 `x`/`y` 不接受（必须数值）。**

**推论**：凡是「用百分比做绝对定位」的地方，都要问一句**「这个 `%` 会被当成长度吗」** ——
**`Position` 是 `Length` 类型，但它的 `%` 语义与 `width`/`height` 不同。**

## 同一天的另一条相关判据（1819）

**「用户事件能重绘，定时器驱动的 `@State` 不能」** —— 这个组合本身就是强线索：
**说明 `@State` 在变、有重绘能力，问题出在「值如何映射到位置」这一层**。
