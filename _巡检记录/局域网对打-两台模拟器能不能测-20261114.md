# 局域网对打：**现在有两台模拟器，今晚可以试一次**

## 一、实现方式（读代码确认）

**`Lan.ets` / `LanRace.ets`（`195` 行）**
```
L118  udp.setExtraOptions({ broadcast: true })
L135  address: { address: '255.255.255.255', port: DISCOVER_PORT, family: 1 }
```
**⇒ 设计是 **UDP 广播发现 + 各端本地算排名**（「不用服务器、不用星型转发」）。**
**⇒ 没有「手动填 IP」的入口 ⇒ **只能靠广播发现**。**

## 二、所以能不能用两台模拟器测？**取决于模拟器的网络模式**

| 网络模式 | 广播能不能跨过去 | 能不能测 |
|---|---|---|
| **QEMU user-mode NAT**（常见默认）| ❌ **不能**（`10.0.2.x` 各实例隔离，`255.255.255.255` 不出宿主）| ❌ |
| **桥接 / tap** | ✅ 能（同一子网）| ✅ |

**⇒ 现在我**不知道** HarmonyOS 模拟器用哪种 ⇒ **今晚实测**（两条命令的事）。**

## 三、今晚的测法（`5` 分钟）

```bash
# ① 两台都起来
Emulator -start onemore7 &
Emulator -start onemore_tv &

# ② 都装上 HAP、都进任意一款支持联机的游戏
# ③ 在其中一台点「局域网」⇒ 看它能不能扫到另一台开的房间

# 若扫不到，再查两台各自的 IP 与网段：
hdc -t <phone> shell ifconfig | grep inet
hdc -t <tv>    shell ifconfig | grep inet
#   ⇒ 若两台同一个网段（如都是 192.168.x.x）⇒ 是桥接 ⇒ 广播应该能过
#   ⇒ 若各自 10.0.2.15 ⇒ 是 NAT ⇒ 广播过不去（预期结论）
```

## 四、两种情况分别记什么

| 结果 | 记录 |

| **扫得到** | ✅ **局域网对打可以在模拟器上验证** ⇒ objective 第 `5` 项最后一项解锁 |

**⇒ 第二种结果也是有价值的：它把「不知道能不能」变成「知道为什么不能」。**

## 六、前置条件核查（`14:50`）—— 权限齐，不会弹窗

**`entry/src/main/module.json5` 声明了：**
```
ohos.permission.INTERNET
ohos.permission.GET_WIFI_INFO
ohos.permission.VIBRATE
```

**⇒ `INTERNET` 与 `GET_WIFI_INFO` 都是**普通权限**（安装即授予，不弹窗）**
**⇒ 所以今晚点「局域网」不会卡在权限弹窗上。**

**⇒ 于是今晚 LAN 的唯一变量就是**网络模式**（NAT / 桥接），与权限无关。**

**⇒ 三个前置（两台实例 / 权限 / 广播代码就绪）全过 ⇒ 只剩实测。**
