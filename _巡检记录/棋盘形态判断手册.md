# 棋盘形态判断手册（判据 1966）

> 起因：`Wordle` 改了 **14 次**才搞明白 —— 一直在「溢出」这个错误方向上改百分比宽度。
> 真正要先回答的不是「怎么缩」，而是 **「这个棋盘是 A 型还是 B 型」**。
> 相关判据：**1966**（形态区分）｜**1963**（百分比宽度不可靠）｜**1964**（缩不动先看节点尺寸）｜**1928**（`maxHeight` 只裁不缩）
> 素材：`Wordle是空棋盘-20261112.md`、`B类19款补丁方案.md`、`百分比棋盘清单.md`

---

## 0. 判定流程（3 步，先看 `.aspectRatio(1)` 长在谁身上）

```
第 1 步：在 build() 里找 `.aspectRatio(1)`，看它修饰的是「棋盘容器」还是「格子」
   │
   ├─ 在**棋盘容器**身上（Column/Stack 自己就有 .width(...).aspectRatio(1)）
   │     ⇒ 【A 型】⇒ 限**高**：.constraintSize({ maxHeight: ... })
   │        （aspectRatio 会拿高度反推宽度 ⇒ 限高同时把宽也收下来）
   │
   └─ 只在**格子**身上（Row 里的 `.layoutWeight(1).aspectRatio(1)`，容器自身无 aspectRatio）
         │
         ├─ 容器是 `.width('100%')`
         │     ⇒ 【B 型】⇒ 限**宽**：`.width(Math.min(...))` 或 `.constraintSize({ maxWidth: ... })`
         │        ★ 千万别用 maxHeight —— 格子高度由宽度决定，maxHeight 只裁不缩
         │
         └─ 容器是 `.width('NN%')`
               ⇒ 参考 A 型（先试限高），但打标：**百分比 + aspectRatio 基准不可靠**
                 （判据 1963）⇒ 要么给绝对值（vp），要么用 maxWidth/maxHeight 约束换掉百分比
```

**一句话记法**：**`aspectRatio` 在盘上是 A（限高），在格上是 B（限宽）；百分比一律不可靠，给绝对值。**

**10 秒识别命令**（只读）：
```bash
# 找棋盘容器的形态（.width 与 aspectRatio 是否在同一组件链上）
grep -n -B2 -A3 "aspectRatio(1)" entry/src/main/ets/games/GXxx.ets | head -40
```

## 1. A 型：棋盘容器自身有 `.aspectRatio(1)` ⇒ 限高

**特征**：`.aspectRatio(1)` 紧跟在**棋盘容器**的 `.width(...)` 后面（`GPathRecall:339`、`GPolyominoTiling:361`、`GYajilin:449`、`G2048:813`）。

**为什么限高有效**：`aspectRatio(1)` 表示「高 = 宽」；只约束 height 时，布局引擎会反过来按「高度」推宽度 ⇒ 宽度也一起被收住。

```ts
// ── A 型棋盘：aspectRatio 在容器上 ──────────────────────────────
Column() {
  // 格子里怎么写都行（Grid/ForEach/Stack…）
}
.width('86%')                 // 百分比可以留（这里的病灶是"高被宽锁死"，不是百分比本身）
.aspectRatio(1)               // ★ A 型特征：aspectRatio 在棋盘容器身上
// ★ 限高：留够 HUD + 说明 + 按钮后，剩下的高度就是棋盘高度；
//   aspectRatio 会按这个高度反推宽度 ⇒ 整块盘缩进屏幕
//   常数按该款 chrome 调：GYajilin/PathRecall 用 -380/-400，2048 用 '46%'
.constraintSize({ maxHeight: Math.max(120, Bp.height - 380) })
```

**落地要点**
- 常数先抄同款邻近值（`-360 / -380 / -400`），改完必须**真机 dump 看棋盘节点自身 bounds**（判据 1964），不要用 `max_bottom` 反推。
- 有下限 `Math.max(120, …)` 时注意「下限反噬」（`GYajilin` 的注释：下限 140 曾把棋盘留太大，按钮又被顶出去）。

## 2. B 型：容器 `.width('100%')` + 内部方形格 ⇒ 限宽

**特征**：容器是 `.width('100%')`，**格子是 `layoutWeight(1) + aspectRatio(1)`**（如 `GCountingSheep:327-337`、`GCrossSectionSlice:299`、`GNumberBondsAll:394`、`GWordle` 的键盘/棋盘早期形态）。

**为什么限宽有效**：格子高 = 格子宽（`aspectRatio` 在格子上），格宽 = 行宽 / N；行宽由容器宽决定 ⇒ **限住行宽，整盘高度自然下降**。

```ts
// ── B 型棋盘：容器 100%，方形格在 Row 里 ────────────────────────
Column() {
  ForEach(this.rows, (r: number) => {
    Row({ space: Space.xs }) {
      ForEach(this.cols, (c: number) => {
        Stack() { /* 每格内容 */ }
          .layoutWeight(1)      // ★ B 型特征：格宽由 layoutWeight 分配
          .aspectRatio(1)       //   格高 = 格宽 ⇒ 整盘高 = 行宽
      }, (c: number) => 'c' + c)
    }
    // ★ 限宽（限宽即限高）：行宽 = min(可用宽, 可用高 - chrome)
    .width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 360)))
  }, (r: number) => 'r' + r)
}
.width('100%')
```

**等价的安全写法（只加约束、不改宽度语义）**：
```ts
// 加在「行」或「包住所有行的容器」上；Bp.isShort() 只在矮屏生效，竖屏/平板零影响
.constraintSize({ maxWidth: Bp.isShort() ? Math.max(140, Bp.height - 360) : 9999 })
```

**落地要点**
- **绝对不要**给 B 型容器加 `maxHeight`：格子按宽度算高度，maxHeight 只会把容器压矮 ⇒ 下半截**被裁掉**（判据 1928 / `GNumberBondsAll` 注脚）。
- 盘面越扁，每格越小：8×8 在 173vp 盘面上单格 ≈21.6vp，是「可点下限」附近（`B类19款` 的表）。

## 3. 反例清单（都是实测踩出来的）

| 游戏 | 真实形态 | 错在哪 | 正确刀 |
|---|---|---|---|
| **`GWordle`**（棋盘 + 键盘） | **B 型**（格子在 `Row` 里 `layoutWeight + aspectRatio`），但棋盘容器写 `.width('72%')` | **百分比宽度缩不动**：`'72%' → '32%'` 完全没效果（判据 1963），改九次都像「没效果」 | **给绝对值**：`.width(Bp.isShort() ? 120 : 614)`；实测 `120` 时三行键盘全出、游戏可玩 |
| **`GPathRecall`** L339 | **A 型**：`.width('86%').aspectRatio(1)` | 没限高 ⇒ 86%×813≈699vp 高，直接撑爆 533 屏；**零高度兜底**与 Wordle 同形 | 限高：`.constraintSize({ maxHeight: Math.max(120, Bp.height - 400) })`（现仓库已加 ✓） |
| **`GPolyominoTiling`** L361 | **A 型**：`.width('86%').aspectRatio(1).padding(Space.xs)` | 同上（padding 还会再高一点） | 同上（现仓库已加 ✓） |
| **`GNumberBondsAll`** L394-399 | **B 型**：格子 `layoutWeight(1)+aspectRatio(1)`，容器 `.width('100%').layoutWeight(1)` | 曾只给 `maxHeight` ⇒ 只裁不缩；正确注脚已写进代码（判据 1928） | **`maxWidth`** 是真正起作用的那一刀（现写法 `maxHeight + maxWidth` 双约束，其中 maxWidth 是关键，maxHeight 是无害冗余） |
| （补充）棋子/装饰 16 处 | 百分比是**相对父格子**（如 `GGo9` 棋子 80%） | 父格已有尺寸 ⇒ 这些 `aspectRatio(1)` 只是画圆/方块，**不会反向撑高** | **不要动**（换成绝对值反而会让不同格子大小不一） |

## 4. 四种错误后果对照表

| # | 错误做法 | 现象/后果 | 怎么识别 | 正确做法 |
|---|---|---|---|---|
| 1 | **A 型却限宽**（或只改父容器宽度） | **改了没效果**：`aspectRatio` 仍按宽度撑高度 | `probe` 看棋盘节点：高度 ≈ 宽度，`maxWidth` 加了也不变 | 限**高**（`maxHeight`），让 aspectRatio 反推宽度 |
| 2 | **B 型却限高** | **内容被裁**：容器矮了，但格子仍按宽算 ⇒ 下半截/下面兄弟节点被裁掉 | 棋盘节点高度变小、但**格子高度没变**；`max_bottom` 可能不变甚至变大 | 限**宽**（`maxWidth`/绝对宽度），限宽即限高 |
| 3 | **改错节点**（改了外层 Row/父 Column，撑高的是里层棋盘） | **改了没效果**：目标节点尺寸一点没变 | `probe` 分类，量「棋盘那个节点自己」的 bounds；`max_bottom` 不变≠没生效 | 把约束加在**棋盘容器**（或包住所有行的那一层）上 |
| 4 | **A/B 型 + 百分比宽度**（`'72%'→'32%'`） | **百分比不生效 / 基准不是父宽** ⇒ 缩不动，像「改了没用」 | 同一个棋盘：百分比档位变化时节点宽**不变**；换绝对值立刻变 | 给**绝对值 vp**（Wordle 120）或改用 `maxWidth`/`maxHeight` 约束 |

**口诀**：**A 限高、B 限宽；百分比不可靠，绝对值/约束才动；先量节点尺寸，再看 `max_bottom`。**

## 5. 改完怎么验（三条，缺一不可）

1. **量目标节点自身**：`probe_batch`/`dump` 里找棋盘那个 `Column/Stack` 的 `bounds`（A 型看 height ≈ 设的 maxHeight；B 型看 width ≈ 173vp 档）
   （判据 1964：**不要用 `max_bottom` 反推「有没有生效」** —— `'32%'` 和 `220` 都叫「缩棋盘」，前者没动、后者立刻见效）
2. **看兄弟节点在屏内**：按钮行/键盘/说明的底边 ≤ 内容区底（横屏 `1516px`；`≤1600` 只说明没出屏，不代表压到导航区）
3. **看内容有没有被裁**：B 型若容器变矮但格子没跟着小 ⇒ 判据 1928（maxHeight 只裁不缩）

> 另：**「一片黑」不一定是没渲染**（判据 1965）—— 先输入一次/点一下，看 `dump` 里有没有格子内容，再决定是不是布局问题。
