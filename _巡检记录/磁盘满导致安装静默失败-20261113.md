# 🔴 今晚最大发现：**模拟器磁盘满了 ⇒ `hdc install` 静默失败 ⇒ 我所有的改动都没进包**

## 怎么发现的

**`Stroop Test` 改了 `5` 刀全零效果、日志也打不出来。做「可见标记」测试（把 `通关线 10` 改成 `通关线 10 ★MARKER★`）：
编译成功、`AppMod finish`、但屏幕上**还是没有 MARKER**。

**⇒ 于是直接看安装输出，发现被 `tail -2` 藏掉的真正错误：**
```
[Info]App install path:…/entry-default-signed.hap
msg:error: failed to install bundle. code:9568288
error: install failed due to insufficient disk memory.
AppMod finish      ← ⚠️ 这行即使失败也会打！
```

**⇒ `AppMod finish` 不是「安装成功」的标志 —— 它只是一个进度事件。**

## 磁盘实况

```
/data  5.7G 用 5.0G 剩 311M  95%
/data/local/tmp = 2.6 GB（32886 个文件！）
```
**⇒ 那 `32886` 个文件是我今晚累积的 `dumpLayout` JSON 和截图。**

## 清理

```bash
find /data/local/tmp -maxdepth 1 -type f -name '*.json' -delete
find /data/local/tmp -maxdepth 1 -type f -name '*.jpeg' -delete
find /data/local/tmp -maxdepth 1 -type f -name 'shot_*' -delete
```
**⇒ `2.6 GB → 48 MB`，`32886 → 123` 个文件。**

## 清理后立刻见效

| 项 | 清理前 | 清理后 |
|---|---|---|
| 安装输出 | `insufficient disk memory` | **`install bundle successfully`** |
| `★MARKER★` 是否显示 | **否** | **是** ✅ |
| `Stroop Test` | `1600`、`blk=3/72px` | **`1570`、`blk=0/0px`** ✅ |

**⇒ 那张大卡 `.height(180)`（`180vp = 540px`）降到 `130vp` 的改动**一直是有效的** —— 只是从来没装进去。**

## 判据 1989（今晚最该记住的一条）

> **`AppMod finish` ≠ 安装成功。**
> **⇒ 安装必须检查输出里有没有 `install bundle successfully`；`successfully` 不出现就是失败。**
>
> **⇒ 更根本：`hdc install` 失败时**退出码可能仍是 `0`**，屏幕上的应用还是旧的 ——
> **所有「改了没效果」的排查，第一件事都应该是「确认新包真的进去了」**（用一个可见标记或版本号）。**

## 判据 1990（设备维护）

> **模拟器 `/data/local/tmp` 是**累积型**的** —— 每次 `dumpLayout` 都留一个 JSON，每次截图都留一个 JPEG。
> **⇒ 长时间测量必须定期清**（`find … -delete`，别用 `rm *`，会 `Argument list too long`）。
> **⇒ 或让工具**用完即删**（`shot_game.py` 现在把 dump 落在 `/data/local/tmp` 且不清理）。**

## 对今晚结论的影响（诚实评估）

**⚠️ 需要重新验证的**：所有在「磁盘满」之后做的、**只靠 `max_bottom` 判断「没效果」**的改动。
**✅ 仍然可靠的**：有**可见证据**的（截图变化 / `MARKER` 类验证）：
`Wordle` 键盘出现、`Word Search` 字母变大、`Tenner Grid` 数字变大、`Find Word` 格子变大、
`Object Displacement 1576→1486`、`Counting Sheep 1499`。

**⇒ 而 `Stroop` 那 `5` 次「零效果」，其实是 `5` 次「没装进去」。**
**⇒ 我今晚写的那几条「怎么改都不动」的判据（1970/1987），根因就是这个。**
