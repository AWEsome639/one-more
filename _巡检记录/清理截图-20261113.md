# 清理 `_巡检记录` 截图：`337MB → 74MB`（腾出 `263MB`，走 quarantine 可回滚）

## 背景

**他说「内存不够了」⇒ 顺手查了磁盘，发现我自己的测量截图堆了 `2261` 张 / `317MB`。**

## 清理规则（不一把梭）

**保留三类：**
1. **文档里引用过的（证据）**：`65` 张 / `9.3MB` —— 用正则从 `_巡检记录/*.md` + `交接-*.md` 里抠出来的文件名
2. **最近 `36` 小时内产生的**：`348` 张 —— 当前工作上下文
3. 其余：**`1848` 张 / `263MB`**

**⇒ 移入 `~/.dsh/quarantine/shots-20261113/`（**不是 `rm`**，随时可搬回）。**

## 结果

| 项 | 前 | 后 |
|---|---:|---:|
| `_巡检记录` | `337 MB` | **`74 MB`** |
| 截图张数 | `2261` | **`413`** |
| Mac 磁盘可用 | `19 Gi` | **`24 Gi`** |

## 为什么这么做（而不是直接删）

**① 截图是**可再生的**（重跑 `shot_game.py` 就有），但 `quarantine` 更稳 —— 万一哪张是证据，搬回来就行
**② 保留「被文档引用的」是关键：**证据链不能断**
**③ 保留最近 `36` 小时：**当前正在做的事情不能丢上下文**

## 顺带

**`entry/build` 还有 `302MB`** —— 但它是编译产物，删了下一次编译要从头（`14` 分钟 vs `3` 分钟），
**⇒ 现在不删，等真需要空间再说。**

## 以后

**`shot_game.py` 已经「用完即删」设备端的 dump/截图（判据 1990），
但**本地 `_巡检记录` 会继续长** ⇒ 每隔几天按这个规则清一次。**

---

## ⚠️ 补记：**有 `22` 张是「`git add -f` 跟踪过」的**，移走会让工作区变脏

**清理后 `git status` 显示 `22` 个 `D`（deleted），都是 `_巡检记录/截图-*.jpeg`。**

**原因**：这些截图我早先用 `git add -f` 提交过（因为 `_巡检记录/` 在 `.gitignore` 里），
**⇒ 它们**在 git 索引里**，我从磁盘移走 ⇒ git 认为「被删了」。**

**处置**：`git checkout -- _巡检记录/` 把它们从 git 恢复回来
⇒ **工作区干净、文件还在（`435` 张 / `77MB`）**，而且 `quarantine` 里还有副本。

**⇒ 判据 1991**
> **清理被 `git add -f` 跟踪过的文件之前，先 `git ls-files <目录> | wc -l` 看一眼** ——
> **`.gitignore` 里不代表没被跟踪**；`-f` 提交过的文件，移走会让工作区出现 `D`。

**净效果没变**：`337MB → 77MB`（省 `260MB`），只是那 `22` 张留在了原处。
