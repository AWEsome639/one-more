# 电视 `P1` 的两处改动，**对手机是零影响的（可静态证明）**

## 改动

```ts
// core/Bp.ets:isShort()
- return Bp.height < 690;
+ return Bp.height < 690 && !Bp.isTv();

// core/Design.ets:Cell.of()
- if (Bp.height > 0 && Bp.height < 600) { shrink = 0.85; }
+ if (Bp.height > 0 && Bp.height < 600 && !Bp.isTv()) { shrink = 0.85; }
```

## 证明

**`Bp.isTv()` 的定义（`Bp.ets:318`）：**
```ts
static isTv(): boolean { return Bp.dev === BpDev.TV; }
```

**⇒ 手机上 `Bp.dev` 是 `PHONE`/`TABLET`/`PC`，**永远不等于 `TV`** ⇒ `isTv()` 恒为 `false` ⇒ `!isTv()` 恒为 `true`。**

**⇒ 两个条件化简后：**
| 函数 | 手机上的行为 |
|---|---|
| `isShort()` | `height < 690 && true` ≡ `height < 690` —— **逐字节相同** |
| `Cell.of()` | `height < 600 && true` ≡ 原条件 —— **逐字节相同** |

**⇒ 这两处对手机是**零变化**，只对 `Bp.dev === TV` 生效。**

## 这条证明的价值

**它不能替代真机验证（TV 上到底对不对，还是要电视截图），
但它能保证**「这两个改动不会让手机变差」** —— 而这是我最担心的风险。**

**⇒ 所以这两处即使今晚没验到，**也不会拖累已有成果**。**

## 同理：`GGeometricVision` 的 `gridB` 限宽

**两块对称；手机上 `533` 屏下都是 `173vp`（和 `gridA` 改完一致）**
**⇒ A/B 对称性恢复，而这正是玩法要求的。**
