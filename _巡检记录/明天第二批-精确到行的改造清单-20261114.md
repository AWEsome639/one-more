## 一、`ConnectFour`（`7` 列 × `6` 行，标准四子棋）

**现在是**假兜底**（只限高，方形盘不会被缩小）：**
```ts

.constraintSize({ maxHeight: Math.max(140, Bp.height - 420) })
```

**改成限宽（照 `KakuroMini` 的成熟写法）：**
```ts
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(200, Bp.height - 340)))
```
**⇒ 盘面 `193vp` ⇒ `7` 列 ⇒ **每格 `27.6vp`**（现在 `16.1vp`，`+71%`）**

## 四、`Gomoku`（`15×15`，标准五子棋）

**今天我已经把它从 `width('100%')` 改成 `-360`（属那 `37` 处之一）。**
**⇒ 但 `15` 列 ⇒ 每格 `11.5vp` ⇒ **全库最小，无先例**。**

**两个选项：**
**✅ 已查清（`08:15`）—— 改法和我原来写的不一样，而且**更安全**。**

**关键发现：`GGomoku:475`**
```ts
return LanMatch.isActive() ? SIZE : GameDiff.sizeNow(15);
```
**⇒ 棋盘边长**本来就是难度驱动的**：`GameDiff.sizeNow(15)` = `round(15 × sizeScale('gomoku'))`。**

**⇒ 而且 `GGomoku:96` 的注释证明代码**已支持变长棋盘**：**
> 「一律用本局边长 `size`（难度会改棋盘；**写死 `SIZE` 会在 `11/20` 路时算错坐标**）」

**所以正确的改法是 —— **改 `sizeNow` 的基础值，不动 `const SIZE`**：**
```ts
// GGomoku:475
return LanMatch.isActive() ? SIZE : GameDiff.sizeNow(11);   // 原来 15
```

| 改动 | 影响 | 结果 |
|---|---|---|
| ✅ **`sizeNow(15) → sizeNow(11)`** | **只影响单机的棋盘边长** | 普通档 `11` 列 ⇒ **每格 `15.7vp`**；简单档按 `sizeScale` 更小 ⇒ 更大格子 |
| ❌ ~~`const SIZE 15 → 11`~~ | **会连带改局域网模式**（`LanMatch.isActive() ? SIZE`）| **不要这么改** |

**⇒ 所以这一处比原来估的安全：代码本来就按变长棋盘写，只是基础值给大了。**
