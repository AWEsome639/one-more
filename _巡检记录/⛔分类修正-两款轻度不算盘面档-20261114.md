# ⛔ 分类修正：`CountdownMath` 与 `BinaryMatrixRank` 属**轻度档**，不算盘面档

> `2026-11-14 16:3x`。逐个查格子尺寸时发现的。

## 一、`BinaryMatrixRank`：格子是固定 `44vp`，盘面没问题

```ts
427|      Column({ space: Space.xs }) {
436|              .width(44)          ← **固定 44vp**
```

**⇒ `4×4` 网格、每格 `44vp` ⇒ 盘面 `176vp` ⇒ **完全放得下**。**
**⇒ 队友说的是「选项 `C 秩 = 0` **整行下缘被切**（文字完整、可点）」⇒ 那是**选项卡**问题，不是盘面。**

## 二、`CountdownMath`：同理

**队友原文**：「`4` 个选项卡**下缘被切**（数字完整、可点）⇒ 轻度」。

**⇒ 它虽然有 `Math.max(240, H-360)`、盘面 `4×4` 也该是 `176vp`，**
**⇒ 但被切的是**选项卡**，不是盘面 ⇒ 也属轻度档。**

## ⇒ 判据（`2288`）

**「盘面被切」与「选项被切」是两档，虽然都叫「被切」。**
**⇒ 前三轮我一直按「`blk ≥ 24`」归堆，而 `blk` 不区分切的是什么 ⇒ 于是把两款轻度混进了盘面档。**

**⇒ 判据：按「修法」分档时，必须查到**被切的那个元素**，不能只凭「有元素被切」。
⇒ 这次查格子尺寸（`.width(44)` vs `layoutWeight`）才分出来。**

## ⇒ 判据（`2289`）

**我这一轮修的是「分类」，而不是「发现新问题」——`BinaryMatrixRank` 的 `.width(44)` 一开始就在那里。**
**⇒ 而我没看到，是因为我在「有没有 `max(240, …)`」这个维度上找，而它没有那个式子 ⇒ 我就把它归到「无上限」类，却没查它的格子是不是已经固定尺寸。**

**⇒ 判据：归类的依据必须是**那个元素的定义**（格子怎么定尺寸），不是**它缺哪个模式**（没有 `max(240)`）。
⇒ 「缺某个模式」只说明它不属于那个模式，不说明它属于你猜的那一类。**
