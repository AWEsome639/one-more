# 判据 3038：`Perspective Shift View` 修好 —— **要限的是宽度，不是高度**

## 一、改动（加一个 `maxWidth`）

`entry/src/main/ets/games/GPerspectiveShiftView.ets:401-405`

```typescript
.constraintSize({
  maxHeight: Math.max(100, Bp.height - 440),                              // 原样保留
  maxWidth: Math.max(100, Bp.height - (Bp.isShort() ? 200 : 600))         // ★ 新增
})
```

### 为什么是宽度
`mini()` 是 `.width('100%').aspectRatio(1)` ⇒ **高度由宽度决定**。
`maxHeight: 392vp`（`1176px`）**永远碰不到**，因为宽度只有 `342vp`（`1025px`）。

⇒ 限 `maxWidth` 后 `aspectRatio(1)` 让**高度跟着缩** ⇒ 这才是能生效的那一侧。

| 元素 | 改前 | 改后 |
|---|---|---|
| 俯视图 `mini(-1)` | `342vp`（`1025px`）| **`232vp`（`696px`）** |
| 三个选项 `mini(k)` | `226vp` | **`226vp`（不变，`226 < 232`）** |
| 横屏 | `maxHeight: Math.max(100, 533−440)=100vp` 已压住 | **不变** |

## 二、★ 中间那一版差点变成新缺陷（`2605` 第 N 次兑现）

### 第一版：`N = 556` ⇒ 宽度 `276vp`
```
blk=1/24px   lowest='重开' [62,2487][2162,2496]   blkh=9px
```
- `blk` 从 `4/96px` 降到 `1/24px` —— **数字看着大幅改善**
- 但 `blkh=9px` ⇒ **底部那个元素只有 `9px` 高**

⇒ 截图确认：**三个面板完整了，但「重开」按钮被压成一条 `9px` 的紫色细条**。

⇒ **`blk` 降了 3/4，代价是把按钮压扁了。** 只看数字就会宣布「修好了」。

### 重算（这才是关键）

| 量 | 值 |
|---|---|
| 面板要装下需省 | `260px` |
| 第一版省了 | `260px` |
| 按钮被压缩 | `114px` |
| **总缺口** | **`260 + 114 = 374px`** |

⇒ 棋盘必须 `1088 − 374 = 714px = 238vp` ⇒ `N = 832 − 238 = 594`，取 **`600`**（棋盘 `232vp = 696px`，省 `392px`）。

## 四、判据

> **`aspectRatio(1)` 的元素，`maxHeight` 往往碰不到、`maxWidth` 才有效 —— 因为宽度是先定的那一侧。**

⇒ 四条：
1. **改 `constraintSize` 前先算「上限 vs 实际」** —— 这次 `392 > 342` ⇒ `maxHeight` 是死的
2. **`blk` 降了不等于修好** —— 第一版 `4/96 → 1/24`，代价是把按钮压成 `9px`；
   **必须看 `blkh` 和截图**
3. **`blkh` 是「被压扁」的探测器** —— 正常按钮 `120~160px`，出现 `9px` 就是有元素被挤没了
4. **缺口要一次算全** —— 面板装下（`260px`）不等于整体装下（`260 + 114 = 374px`）；
   中间那一版就是只算了前半截
