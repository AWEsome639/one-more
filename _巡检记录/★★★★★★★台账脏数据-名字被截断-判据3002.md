# 判据 3002：`--names-file` 里被切坏的一行，会在台账里留下**永久的假失败**

## 现象

新鲜度工具一直报：

```
❓ 找不到 .ets（类名映射失败）：1 款 —— odular Clock Arithmetic
```

第一反应是**工具坏了**（首字母 `M` 被吃掉）。逐层查证：

| 检查 | 结果 |
|---|---|
| 台账第 `1265` 行原文 | `2026-11-16T12:38:21 \t odular Clock Arithmetic \t TIMEOUT …` —— **真的就是 `odular`** |
| 注册表真名 | `Modular Clock Arithmetic`（`modular_clock_arithmetic`）|
| `.ets` 文件 | `GModularClockArithmetic.ets` **存在** |
| `class_name('Modular Clock Arithmetic')` | `GModularClockArithmetic` ✅ 正确 |
| 台账里 `Modular Clock Arithmetic` 的记录 | **另有**，且末次 `OK` |

⇒ **工具是对的，脏的是台账。**

## 根因

`shot_game.py` 的 `finish(name, …)` 直接把 argv 里的名字写进台账。
而 `--names-file` 是**按行读**的 —— 当时那一行被切坏了（少了首字母），
于是 `shot_game` 拿着 `odular Clock Arithmetic` 跑、`TIMEOUT`、原样写进台账。

⇒ **台账是不可变的（只追加），所以这条脏数据永远不会自己消失**，
而它每次都会让「类名映射失败」计数停在 `1`。

## 判据

> **只追加的台账里，一条被切坏的输入会变成永久的假信号。**

⇒ 三条：
1. **名单驱动脚本必须打印未匹配项**（这条已在 `2580`/`2581`）——
   但**写入端**也要防：`shot_game.py` 应在 `finish` 前校验 `name` 在注册表里，
   不在就写 `BAD_NAME` 而不是带着错名字写一条看起来正常的记录。
2. **看到「N 款映射失败」先分清是工具错还是数据错** —— 今天差点把工具当坏的。
3. **脏数据用映射兜住，别删** —— 台账是证据，映射是解释。

## 修法（已落地）

`check_ledger_freshness.py` 的 `CLASS_OVERRIDE` 加一条：

```python
'odular_clock_arithmetic': 'GModularClockArithmetic',
```

⇒ 报告从「`1` 款映射失败」变成 **`0`**，且这条记录参与新鲜度统计（不装作不存在）。
