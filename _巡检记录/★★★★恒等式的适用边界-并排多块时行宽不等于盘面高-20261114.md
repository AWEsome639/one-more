# ★★★★ 「盘面高 = 行宽」的**适用边界**：并排多块时行宽 ≠ 盘面高

> `2026-11-14 21:x`。扫全库下限时发现 `GSnake3D` 被误判，找到恒等式的边界。

## 二、⇒ 但 `GSnake3D` 的 `300` 不导致 `353vp` 的盘面高

```ts
// GSnake3D:529-533
// 2026-11-14 真机截图（blk=4/96px，全库最重）：**三块 4×4 网格并排，最下面一行全被切**
//   三块各占 `~827px` 宽 ⇒ 方格 `aspectRatio(1)` ⇒ 高也 `~827px` ⇒ 加头就超
//   ⇒ 限整行宽度（三块等分缩小）⇒ 判据 1966「限宽即限高」
//   `533` 屏下封顶 `Bp.height-180 = 353vp` ⇒ 每块 `~115vp`、每格 `~29vp`
.width(Math.min(Bp.width - 2*Space.lg, Math.max(300, Bp.height - 180)))
```

**⇒ 那 `353vp` 是**三块的总宽**。**
**⇒ 每块 `353/3 ≈ 118vp` 宽 ⇒ `aspectRatio(1)` ⇒ **每块高也 `118vp`**。
**⇒ ⇒ 而**行高 = 一块的高**（并排）⇒ **高度贡献是 `~118vp`，不是 `353vp`**。**

**⇒ `118 + 上方（HintBar 38 + 间距 + 统计）≈ 208vp < 343` ⇒ **放得下**。**

## 三、⇒ 所以恒等式有边界

**「盘面高 = 行宽」成立的**前提是：那一行里只有**一块**盘面**。**
**⇒ 并排 `K` 块时：`盘面高 = 行宽 / K`。**

| 情况 | 盘面高 |
|---|---|
| 单块行（`Skyscrapers`/`Crown`/…）| `行宽` |
| **并排 `K` 块（`GSnake3D`，`K=3`）** | **`行宽 / K`** |

**⇒ 而 `layoutWeight(1)` 会让 `K` 块等分 ⇒ 每块宽 `行宽/K`。**

## 四、⇒ 这条边界的实际影响

**我先前用「盘面高 = 行宽」算了 `12` 款，它们是**单块** ⇒ 结论有效。**
**⇒ 而扫描时若把 `GSnake3D` 也算进「盘面 = `353`」⇒ 误判为「超 `100vp`」。**

**⇒ ⇒ 所以扫描脚本必须区分「单块行」与「多块行」。**

## ⇒ 判据（`2361`）

**一个恒等式（这里是「限宽即限高」）在**并排**元素上会失效。**
**⇒ `判据 1966`「限宽即限高」原本对单块成立；作者在 `GSnake3D` 里也用了它（限整行宽度），但他自己写清了「三块等分」 ⇒ 他知道边界。**

**⇒ 判据：引用一个恒等式时，先确认**它的前提**在当前结构里成立（这里是「行内只有一块」）。
⇒ 前提不成立 ⇒ 结论要除以块数。**

## ⇒ 判据（`2362`）

**这次误判来自「`grep` 到 `max(300, …)` 就套恒等式」——与判据 `2336` 同一类错。
⇒ 而正确的做法是**读那行上下的注释**：作者 `L529-532` 写清了「三块并排」。
⇒ 判据：`grep` 命中的每一处，都要读上下文；尤其当数值「明显偏大」时（`300` 对 `240`）。**
