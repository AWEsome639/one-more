# 判据 3057：`Simon Says` 修好 —— **两个问题叠在一起：第二行没有约束 + 下限吃掉算式**

## 一、两个真因（缺一个都修不好）

### ① 第二行 pad **根本没有宽度约束**
`GSimonSays.ets:504` 的 `.width(Math.min(...))` 收尾的是**第一个 `Row`（A/B）**；
`:505` 开始的**第二个 `Row`（C/D）** 只有 `.width('100%')` —— **没有约束** ⇒ 整行在屏外。

⇒ 这就解释了截图里**只有 `2` 块**（不是「被切」，是**第二行从来没进屏**）。

### ② `Math.max` 的下限把算式吃掉（今天第 `4` 次）
作者原来的算式（`:438-443` 注释，判据 `1966`）：
```
2 × Math.max(140, Bp.height - (Bp.isShort() ? 200 : 230))
```
横屏 `533−200 = 333` ⇒ `2×333 = 666vp` ⇒ pad `328vp(985px)` ⇒ **高 `851px`**
⇒ 两行 `1702px` ≫ 可用 `820px` ⇒ 第二行整行在外。

⇒ 我先把 `200 → 398`：`533−398 = 135 < 140` ⇒ **下限 `140` 生效** ⇒ 行宽仍 `280vp` ⇒ 不够。

## 二、最终改法（两处）

```typescript
// ① 第一行（:504）与 ② 第二行（:569 新增）用同一算式：
.width(Math.min(Bp.width - 2 * Space.lg, 2 * Math.max(125, Bp.height - (Bp.isShort() ? 410 : 230))))
```
- 下限 `140 → 125`、`N` → `410`
- **横屏**：`2 × 125 = 250vp` ⇒ pad `120vp` ⇒ 两行+间距 `250vp ≤ 可用 273vp` ✓
- **竖屏**：`min(701, 2×max(125, 832−230=602)) = 701vp` ⇒ **与改前完全一致 ⇒ 不受影响**

## 四、判据

> **「只有一半内容」有两种成因：被切（尺寸大）和没进屏（容器漏了约束）。
> 前者调尺寸，后者补约束 —— 而它们在 `blk` 上都表现为「有几块越线」。**

⇒ 四条：
1. **看 `cov` 和截图能区分**：`cov` 少 + 截图只有一半 ⇒ 先怀疑「第二行没有约束」
2. **同一个组件里两组相同结构，要检查约束是否两处都写了** —— 这次就是只写了一处
3. **`Math.max(下限, 算式)` 的下限要算一遍** —— 今天 `4` 次被下限吃掉（`240`/`200`/`140`/虚构 `392`）
4. **改完必须看截图** —— `blk=0` 可能只是「第二行进屏了但第一行被压小」
