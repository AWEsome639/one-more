# 判据 `3115`：`Block_Count_3D`（数方块）竖屏 **`重开` 被切掉大半** —— **固定行高**型

## 一、缺陷

```
台账：blk=1/24px   blkh=57px   lowest='重开' [62,2439][2162,2496]
```
⇒ 完整按钮应 ≈ `137px` ⇒ **缺 `80px` ≈ 25.6vp**。

## 二、与前面几族**长得不一样**

前面 `Ghost_Tap` / `Reflex_Tap` 是 `width('100%') + aspectRatio(1)`（宽度驱动高度）。
本文件 **根本没有 `Bp.height`**，格子是**固定行高**：

```typescript
ForEach(this.rowIdx /* [0,1,2] 三行 */, (r) => {
  Row({ space: Space.xs }) {
    ForEach(this.colIdx, (c) => {
      Column() { ... }
      .height(Bp.isShort() ? 76 : 112)     // ★ 固定行高
```

⇒ 3 行 × `112` = `336vp` + 间隙 ⇒ 竖屏（`798.7`）装不下下面的提示/选项/按钮。

## 三、修法（按 `blkh` 缺口分摊）

```diff
-              .height(Bp.isShort() ? 76 : 112)
+              .height(Bp.isShort() ? 76 : 100)
```

⇒ 缺 `25.6vp` ÷ 3 行 ≈ `8.6` ⇒ `112 − 9 = 103`，取 `100`（略留余量）。
⇒ 横屏保持 `76` 逐字不变。

| `lowest` 底 | `2496`（屏沿）| **`2480`**（屏内）|

## 四、判据

> **「固定行高」型的溢出，`blkh` 缺口 ÷ 行数 就是每行该减多少 —— 比按 chrome 估算快且准。**

⇒ 四条：
1. **先分清是哪一族**：`width('100%')+aspectRatio`（宽度驱动）还是**固定行高**（高度驱动）
   —— 两族的修法完全不同（前者改 `.width()`，后者改 `.height()`）
2. **固定行高型**：缺口 `vp ÷ 行数` 就是每行的削减量，一次到位
3. **仍然分形态**（`isShort() ? 旧值 : 新值`），横屏零风险
4. **`grep Bp.height` 找不到的款不要以为「没有高度问题」** —— 这一款全程没用 `Bp.height`，
   照样溢出 `80px`（判据 `3082`「扫不到 ≠ 没有」的又一例）
