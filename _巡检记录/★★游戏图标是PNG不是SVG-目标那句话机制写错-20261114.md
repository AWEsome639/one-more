# ★★ 游戏图标迁的是 **PNG 位图**，不是 SVG（目标那句话的机制写错了）

> `2026-11-14 14:4x`。查壳层 emoji 迁移范式时发现的。

## 一、目标写的

> **emoji**：游戏图标 `355` 款**早已迁 SVG**；剩 `67` 行壳层 emoji

## 二、实际机制（`components/Common.ets:19-35`）

```ts
// ─── ICON_MAP:BEGIN（由 tools/gen_icon_map.py 生成，勿手改）───
/**
 * 游戏图标资源表（全部游戏，每款一张预渲染位图）。
 *
 * 图标由 `tools/gen_game_icons.py` 生成到 `resources/base/media/gico_<id>.png`：
 *   · 改前 354 款共用 69 个 emoji（327 款跟别人撞脸）
 *   · 改后每款一张 192px 位图，感知哈希 354/354 互不相同
 */
const ICON_MAP: Record<string, Resource> = {
  'bejeweled': $r('app.media.gico_bejeweled'),
  …
}
export function iconOf(id: string): Resource | undefined { return ICON_MAP[id]; }
```

**⇒ 实情：**
| 项 | 目标说 | 实际 |
|---|---|---|
| 机制 | **SVG** | **`192px` PNG 位图** |
| 数量 | `355` | **`354` 款**（注释原文）+ `ICON_MAP` 有 `356` 条 |
| 共用 emoji | — | **改前 `354` 款共用 `69` 个 emoji（`327` 款撞脸）** |
| 现状 | 已迁 | ✅ **已迁**（`media/gico_*.png` 共 `356` 个）|

**⇒ 所以**实质是对的**（每款有独立图标、不再撞脸），**只有「SVG」这个词写错了**。**

**⛔ 而全项目**没有任何 `.svg` 文件**（`find -name "*.svg"` 零命中）。**

## 三、⇒ 这对「壳层 `67` 行 emoji」意味着什么

**游戏图标的迁移路径是：**
```
emoji（69 个共用）→ tools/gen_game_icons.py 渲染 → gico_<id>.png（192px）
                  → gen_icon_map.py 生成 ICON_MAP → iconOf() 取 $r()
```

**⇒ 壳层那 `67` 行可以照抄同一套：**
1. 把那 `67` 处 emoji 列出来（`5` 个文件、行号已知）
2. 用同款渲染脚本出 `sic_<name>.png`
3. 加进一个 `SHELL_ICON_MAP`
4. 各处 `<Text(emoji)>` 换成 `<Image($r('app.media.sic_xxx'))>`

**⚠️ 但壳层 emoji 与游戏图标的**用途不同**：**
- 游戏图标：卡片上的「识别标志」⇒ 值得做成位图
- 壳层 emoji：菜单项/统计标签的「装饰前缀」⇒ 做成位图**收益小**（`67` 处、每个约 `10-14vp`）

**⇒ 所以这条的真实判断是：**风格统一 vs 收益**。
⇒ 而目标已经说了「排在布局清零之后」⇒ **优先级本来就低，这个判断可以维持。**

## ⇒ 判据（`2233`）

**「已迁 SVG」与「已迁 PNG」在**后果**上不同：**
- **SVG** ⇒ 矢量、任意缩放不糊、可改色
- **PNG** ⇒ 固定 `192px`、放大要重出

**⇒ 判据：报「已迁某格式」前，先确认那个格式**实际是什么**（这次全项目零 `.svg`）。
⇒ 因为「已解决」这个结论若基于错的格式，后续所有「照抄那个范式」的计划都会错。**

## ⇒ 判据（`2234`）

**「迁了 `354` 款」与「迁了 `355` 款」差 `1` 款 —— 而目标写 `355`、注释写 `354`、`ICON_MAP` 有 `356` 条。**
**⇒ 三个数都「有出处」，但真值只有一个。**

**⇒ 判据：报数量时若三个来源不一致，先确认「哪个是权威源」
（这次：`ICON_MAP` 的实际条数 `356` 是运行时的真相，注释与目标都是描述）。**
