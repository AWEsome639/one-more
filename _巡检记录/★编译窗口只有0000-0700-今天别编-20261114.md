# ★ 编译窗口只有 `00:00–07:00` —— 白天**不许**编，所以那 `7` 行要等明晚

## 为什么要写这条

**那 `7` 行改动（`Magnets` `1` + `Mandelbrot` `1` + `Wordle` `3` + C 档 `2`）已经**有精确行号**了，**
**⇒ 很容易顺手就改+编译 —— 但编译是 `5` 核跑 `7` 分钟，而现在是他醒着的时候。**

**⇒ 判据（他自己的话）：「别用我电脑呀……真的好卡」**
**⇒ AGENTS 的阈值：单进程 `> 50% CPU` 或 `> 2 GB RSS` 且跑 `> 1–2` 分钟 ⇒ 挪到 `00:00–07:00`。**
**⇒ 一次 `assembleHap` 正好全中 ⇒ **白天不许编。****

## 所以节奏是**每晚一批**

| 夜 | 做什么 |
|---|---|
| **今晚 `00:00`** | **不编译** —— 直接 `install` 今早 `07:31` 那个 HAP（已含 `37` 处）⇒ `verify_changed` ⇒ `triage` ⇒ `sweep_all`（`245` 款）⇒ TV ⇒ LAN |
| **明晚 `00:00`** | **改那 `7` 行 + 编译**（`BUILD_STRICT=1`）⇒ 只为那 `7` 款重测 ⇒ 顺带 `--opt` 放大 `9` 款（如果数据够）|

**⇒ 一晚上只能推进一个「编译 + 验证」循环 —— 这是硬约束，不是选择。**

## 而白天能做的（不占 CPU）

| 能做 | 不能做 |
|---|---|
| ✅ 读代码 / `grep` / 写补丁计划 | ❌ `bash build.sh` |
| ✅ 改工具（`工具/*.py`）/ 跑纯 Python 断言 | ❌ 起模拟器 |
| ✅ `final_check`（`18` 秒，纯文本）| ❌ 跑 `sweep_all` |
| ✅ 写文档 / 算数 | ❌ `hdc install` |

**⇒ 而更省的顺序是：明晚把 `7` 行一次改完、一次编译、一次测 `7` 款 + `9` 款放大**
**⇒ 而不是拆成好几批（每批都要一次编译 + 一次装包）。**

## 判据 `2029`

> **「能顺手做掉」不等于「现在做」—— 先看这件事要占多久的 CPU、而那台机器现在归谁用。**
