## 0 结论

**不是 `flexShrink` 问题，是「纵向总高」超了。** 键盘行 `132px` **一点没被压缩**（`flexShrink(0)` 已在上一轮加过）。
棋盘已经按 `Bp.height − 340 = 193.3vp` 算到位（**公式是对的**），但「棋盘 + 3~5 个间距 + 上下 chrome」**总高仍超 72px**，状态行整个在屏外。

⇒ 只能从**间距**和**棋盘常数**里让。本轮：间距 `md(16)→xs(6)`、棋盘常数 `340→385`、状态行底部留白 `24→8vp`。

## 2 三处改动（都在 GSudoku.ets）

| # | 改动 | 省 |
|---|---|---|
| ① | `Column({ space: Space.md })` → `Bp.height < 600 ? Space.xs : Space.md` | 每个间距 10vp ≈ **30px** × 3~5 个 |
| ② | `boardPx()` 常数 `340` → `385`（棋盘 580 → **445px**） | **135px** |
| ③ | 状态行 `.margin({ bottom: 24 })` → `Bp.height < 600 ? 8 : 24` | **47px**（并把状态行拉回屏内） |

**为什么要动 ③**：原 24vp 的本意是「把按钮行推离手势条」，但布局一超，状态行整个跑到屏外 —— 这 24vp 是**白占**。
现在把它缩到 8vp，省下的 47px 留给键盘行。

## 4 判据 1829 复查（加间距/限高后有没有引入新的挤压）

- 本轮只改 **Column 的 space**、**棋盘的数**、**一个 margin** —— **没有往任何 Row 里塞元素**
- 两道 `flexShrink(0)`（按钮行 / 键盘行）**上一轮已加，本轮原样保留**

⇒ **无新增挤压风险**

def find(n,t):
    if n.get('attributes',{}).get('bounds')==t: return n
    for c in n.get('children',[]):
        r=find(c,t)
        if r: return r
n=find(d,'[60,381][2500,1351]')
prev=None
for c in n.get('children',[]):
    a=c.get('attributes',{}); b=a.get('bounds')
    import re; m=re.findall(r'-?\d+',b); y1,y2=int(m[1]),int(m[3])
    print('%-7s %-18s h=%-4d gap=%s' % (a.get('type'), b, y2-y1, None if prev is None else y1-prev))
    prev=y2
print('内容底 1516 ｜ 余量', 1516-prev)
EOF
