# 判据 1846（2026-11-09 04:28 立，**今晚最重要的发现**）

## 1846 · `uinput -K -t <ASCII>` 能输入文本，但**不支持中文**

### 事故背景

**「`uitest uiInput inputText` 不生效」** 卡了很久（**判据 1767**）：
- **它「直接插入文本」**（**`insertText`**）⇒ **「不触发 ArkUI 的 `onChange`」**
- **⇒ 「搜不到东西」**
- **⇒ 「进不去游戏」**
- **⇒ 「`163` 款横屏棋盘」验不了**

### 今晚的发现

**`uinput`（另一个工具）有个 `-K -t <text>`**：

```
Usage: uinput <option> <command> <arg>...
The option are:
-K  --keyboard
commands for keyboard:
-t <text>  --text <text>  -input text content.
```

**`-K` = keyboard** ⇒ **「走键盘路径，不是插入路径」**。

### 实测（真机）

| 输入 | 结果 |
|---|---|
| **`uinput -K -t 'shudu'`** | ✅ **`'shudu'` 真的出现在搜索框里**（**`[183,381][2374,489]`**）|
| **`uinput -K -t 'sudoku'`** | ✅ **搜到了「`3 款`」+「`六宫数独`」** |
| **`uinput -K -t '数独'`** | ❌ **`The character of index 0 is invalid.`**（**不支持中文**）|

### 判据

> **`uinput -K -t <text>` 能「模拟键盘输入」文本，但**只支持 ASCII**。**
> **中文会报 `The character of index 0 is invalid.`**
>
> **而「游戏的英文名」（`sudoku` / `kenken` / `nonogram` …）都是 ASCII** ⇒ **够用。**
> **⇒ 「搜索」能用，「进任何游戏」能用。**

### 为什么这条路之前没人发现

**因为「`uitest uiInput` 的子命令里没有 `paste`」**：
- **`click` / `doubleClick` / `longClick` / `swipe` / `drag` / `fling` / `keyEvent` / `inputText`**
- **⇒ 「看起来只有 `inputText` 一条路」**

**而 `uinput` 是「另一个工具」**（**不是 `uitest` 的子命令**）。

**⇒ 「查 `uitest --help` 不够，要查『所有可能的输入工具』」。**

### 影响

**「`163` 款横屏棋盘」可以「逐款验」了**：
```bash
# 搜英文名
uinput -K -t 'nonogram'
# 点第一张卡
uitest uiInput click <卡片中心>
# dump 看棋盘/按钮是否在屏内
```

**⇒ 「goal 第 2 条『165 款横屏棋盘溢出』」能「真闭」了。**

### 而这条也值得记（方法层面）

> **「同一个目的，不同工具，机制不同」**：
> - **`uitest` 的 `inputText`** —— **`insertText`（插入，不触发 `onChange`）**
> - **`uinput` 的 `-t`** —— **`-K`（键盘，触发 `onChange`）**
>
> **⇒ 「看到『输入文本』不要假设『都一样』—— 要看它的『机制』。」**
> **⇒ 「工具查不到，就查『隔壁工具』。」**
