# ★★★★★ `Magnets` 定案：**行列提示格几乎全在屏外 ⇒ 游戏无解**

> `2026-11-14 12:2x`。用代码结构 + `bounds` 高度定案的，不是猜。

## 一、`'2＋'` 到底是什么

**代码：**
```ts
L30:   const CLUE_W: number = 44;          // 提示格 44vp 见方
L673:  .width(CLUE_W)
L674:  .height(CLUE_W)                     // ← 行列提示格
L699:  Row().width(CLUE_W).height(CLUE_W)  // 右下角空格
```

**而游戏规则（`L5-7` 注释）：**
> 规则：每块磁铁一端是正极 ＋、另一端是负极 －（不能两端同极）
> 玩法：点格子循环切换 空 → ＋ → － → 空

**而 `L308` 注释：**
> 每行每列的 ＋ 数量必须正好等于该行/列的数字

**⇒ 所以 `'2＋'` = **「这一行/列有 `2` 个正极」的提示**，不是棋盘格内容。**

## 二、它被裁了多少

```
lowest = '2＋'  可见 y 1597-1600  ⇒ 可见高度 3px
而提示格本身 = CLUE_W = 44vp = 132px
⇒ 可见 3px / 应有 132px ⇒ **底部 129px（43vp）在屏幕外**
```

**⇒ **几乎整个提示格都在屏外。****

## 三、⇒ 后果：**游戏无解**

**磁性数独的核心规则是「每行每列的 ＋ 数必须等于该行/列的数字」。
⇒ **看不到那些数字，玩家就无法推理** ⇒ 只能瞎试。**

**⇒ 所以它不只是「内容格被裁」，是**规则信息丢失** ⇒ 比先前判断的「内容格只剩 3px」更严重。**

## 四、⇒ 为什么会这样（与先前诊断一致）

**先前算过：棋盘从 `~367vp` 开始，而棋盘高 `173vp`（`max(140, H-360)`）。
⇒ 棋盘底 `~540vp`，而提示格在棋盘**下方/右侧**（占 `44vp`）⇒ 必然超出 `533vp`。**

**⇒ 根因：**上方占了 `367vp`**（头部 `104` + 三张统计卡 `~138` + 按钮行 `~39` + 题目区 `~86`）。**

## 五、⇒ 修法优先级（现在是 `P0` 最高）

| 方案 | 做法 | 省 |
|---|---|---|
| **A** | **三张统计卡改一行紧凑**（去 `padding`/`shadow`）| `~20vp` |
| **B** | **矮屏隐藏「提示/AI 代打」按钮行** | `~39vp` |
| **C** | 题目区收一档字号 | `~20vp` |
| **D** | 提示格 `CLUE_W` `44 → 36`（仍 ≥ 触控下限的近似值）| `~8vp` |

**⇒ `A + B` ≈ `59vp` > 需 `43vp` ⇒ 够，且余量 `16vp`。**

**⚠️ 但 `A`/`B` 都要改布局结构 ⇒ 不是一行改动。**

## ⇒ 判据（`2203`）

**「看不清」和「无从推理」是两回事。**
**⇒ 这次被裁的是**规则信息**（行列提示），不是装饰、不是内容格。
⇒ 规则信息缺失 ⇒ **游戏从「不好玩」变成「玩不了」。**

**⇒ 判据：判断被裁元素的严重性时，问一句「玩家靠它做决策吗」。
靠它 ⇒ 截断即致命；不靠 ⇒ 只是不好看。**

## ⇒ 判据（`2204`）

**我先前把 `'2＋'` 读成「内容格」⇒ 判成「视觉级」差点放过它。
而查代码 `CLUE_W = 44` 才知道它是**提示格**，且高度 `132px` ⇒ 被裁 `97%`。**

**⇒ 判据：`lowest` 的字符串只是**内容**，要判它属于什么元素，
必须回到代码里找它的构造处（这次是 `CLUE_W` 常量）。
⇒ 而「高度 `3px` vs 应有 `132px`」这个比值，比「`3px`」这个绝对值有信息量得多。**
