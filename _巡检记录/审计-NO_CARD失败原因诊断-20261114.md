### 3.2 三个问答

**① 输入用什么方式？**
`uinput -K -t '<词>'`（不是 `uitest uiInput inputText`）。`verify_game_layout.py:5,103,117` 的判据写的是「**只能 ASCII**」，
但 `shot_game.py:564-565` 的注释又说「中文名才是搜索框真正认的词」。**两条证据互相矛盾，代码里无法定论。**

**但有一条硬约束可以反推**：今晚 `144` 款 `OK`。若 `uinput` 完全打不进中文，则每款的第 1 枚 token（中文名）都落空，
只剩英文 token；而中文界面的卡片标题是中文 ⇒ 英文 token 永远匹配不上 ⇒ **不可能有 144 个 OK**。
⇒ **现场中文输入至少多数可用**（这是推断，但约束很强）。

**② 有没有「输入后等待」？**
有，但只有 `time.sleep(2.4)`（`:633`）**一次**，**没有轮询、没有重试、没有回读输入框**。
对比同仓库更成熟的 `verify_game_layout.py:89-101,120-121`：先 `in_search_mode()` 确认搜索态、打完 `sleep(2.6)`；`verify_ai_win.py:50` 甚至**回读输入框校验词真的进去了**——`shot_game.py` 两样都没有。

**③ 英文名为什么也失败？（关键，已用真实 dump 证实）**
`hit`（`:637`）**不排除搜索框自身**。而搜索框是会进 dump 的——**实锤**（`验收截图-v1.0.1/SEARCH_finds_dominosa_440x744_20261104.json`）：

```
'多米诺'  type=TextInput  bounds=[179,381][1128,495]
'✕'       type=Text       bounds=[1146,390][1242,486]
'全部 · 2 款' [60,728][236,770]
'多米诺拼盘'  [234,1064][606,1120]      ← 卡片标题（中文）
```

⇒ 第 1 枚 token 一旦落进输入框，`want_zh in t` 对**输入框自己**成立 ⇒ `hit=True` ⇒ **循环立刻 break**，
`tokens[:4] + [_base, name]` 里那两枚**完整英文名永远不会被尝试**。

⇒ 更要命的是：**就算尝试了也没用**——卡片标题是中文（`复合连线`/`四子棋`…），
`card` 的判定是 `(want in t) or (name in t)`（`:660-663`），`name` 是英文串，在中文标题里**永远不成立**。
⇒ **英文 fallback 在中文界面是一条死路**：它能让「搜索有结果」，却永远匹配不到卡片。

**这一条同时解释了 §4 的两组 fallback**（见下）。

### 3.3 还有一个**已经踩过、但没修**的坑：没有「已是搜索态」守卫

`verify_game_layout.py:89-101` 专门写了 `in_search_mode()`，注释是：

> 「如果『已经是搜索态』，再点会『关掉它』⇒ 后面 `uinput` 输到『无处的输入框』」

`shot_game.py` **没有这个守卫**（全仓库 `grep in_search_mode` 只命中 `verify_game_layout.py`）。
点击点 `(2276,264)` 是 **toggle**（`GamesTab.ets:1749/1755`：`this.searchOpen = !this.searchOpen`）。
⇒ 只要进入某一轮 token 时**搜索栏本来就是开的**，那一下会**把它关掉**，接着 `(1280,435)` 打到页面空白，`uinput` 打进空气。

而「本来开着」是会发生的：清空 `✕` 的那一步（`:623-627`）只清文本、**不关搜索栏**（`GamesTab.ets:1750` 只有当 `searchOpen` 变 false 时才清空）。

## 5. 结论：按「最可能原因」排序

> 每条都给：**原因 / 证据 / 不改代码怎么验 / 明天改哪里（行号）**。
> 等级：`代码确认`＝读代码即可确定；`数据确认`＝台账/dump 可复算；`推断·需真机`＝必须跑一次 dump。

### P1（`代码确认`+`数据确认`）`hit` 把搜索框算命中 ⇒ 一轮只试 1 个词，英文 fallback 必死

- **原因**：`hit`（`shot_game.py:637`）对**整棵 dump 的所有 text** 做子串匹配，包含刚打进去的输入框自己 ⇒ 第 1 个成功落字的 token 就 `break`（`:638`）；而卡片匹配（`:660-663`）拿的是**中文 `want` / 英文 `name`**，英文 token 对中文标题永远不成立。
- **证据**：`TextInput` 的 text 在 dump 里（§3.2 的真实 dump）；`tokens` 推演（下）；中文标题 dump 见 `验收截图` 的同页 `多米诺拼盘`。
- **token 推演**（用 `game_title_map` 复算，13 款）：
