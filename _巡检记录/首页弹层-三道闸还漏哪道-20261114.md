## 0. 一句话判断

**「三道闸」本身认得准，但漏了两个口子：**

1. **恢复路径（`force-stop → start`）不会重跑闸门清理** —— 闸门循环只在每款开头跑一次（`L476-495`），
   而失败恢复在 `L529-535` 又重启了一次 App，**重启后若弹层再出现，没有任何代码去点它**。
2. **闸门只认中文 + 英文两种文字**（`L482`）—— 而这两个按钮在全库 **10 种语言**里都有本地化（`I18n.ets:1579/1690`）
   ⇒ App 若被留在日/韩/德/俄…等语言，**按钮点不到**。

**并且 `is_home()` 假阴性成立**（✅码）：两个弹层都是**画在首页之上的 `Stack`**（`Index.ets:571-588`），
首页的文字节点**仍在同一棵 dump 树里** ⇒ `is_home()` 看到 `One More` + `全部` 就返回 true，**哪怕屏幕正被遮罩盖着**。

## 4. 为什么这会造成 `NO_CARD`（假阴性链条）

A. `is_home()` 的判据（`L306-320` 现印）：

```python
306:             #   （容器被别的容器盖住是正常布局，不能算缺陷）
307:             if _t1 is None or not str(_t1).strip():
308:                 continue
309:             x1, y1, x2, y2 = r1
310:             if x2 - x1 < 8 or y2 - y1 < 8:
311:                 continue          # 太小的（图标/角标）不算
312:             for j, (_t2, r2) in enumerate(items):
313:                 if i == j:
314:                     continue
315:                 a1, b1, a2, b2 = r2
316:                 # ★ 2026-11-14 修（第二个坑）：**排除「根/全屏容器」**
317:                 #   根窗口节点 bounds ≈ `[0,0][2560,1600]`，它「盖住」所有文字 ⇒
318:                 #   不排除的话 `cov` 会等于文字节点总数（永远巨大、毫无信息）。
319:                 #   判据：覆盖者的面积超过**屏幕 80%** ⇒ 当作根/背景，不算「盖住」。
320:                 if (a2 - a1) * (b2 - b1) > 0.8 * (SCREEN_W * SCREEN_H):
321:                     continue
```

B. 两个弹层都是**同页 `Stack` 叠加**（`Index.ets:571-588`）：ArkUI 的 dump 树里**首页节点与遮罩节点同时存在**。
   ⇒ `is_home()` 拼出的字符串里既有 `One More`、`全部`，也有弹层文字 ⇒ **仍返回 true**
   ⇒ 脚本以为已经在首页，接着点搜索框坐标（`L592-593`）—— 那些点击**落在遮罩上** ⇒ 搜索没生效 ⇒ 卡片找不到 ⇒ `NO_CARD`。

C. 触发概率（🤔判，非确定）：
   - 弹层 1（隐私卡）理论上**同意过就不再弹**（`privacyAgreed` 落盘），**但有一个竞态**：
     `EntryAbility.ets:79` 的 `ProgressStore.init()` 是**异步且不 await**，而 `Index.ets:181` 是 `setTimeout(800ms)` 后调 `maybeShowPrivacy()`；
     `privacyAgreed()` 在 `pref === null` 时**返回 false**（`ProgressStore.ets:1421-1427`，注释明说「宁可多弹一次」）
     ⇒ **慢设备上 init > 800ms 时，已经同意的用户也会再看到隐私卡**。
   - 弹层 2（欢迎卡）需要 `!onboarded()`，同样落盘；竞态同上（`L192-200` 用 8 次重试已缓解）|
   - 弹层 4（输入法/游戏服务）只在**全新实例/首次联网**出现 ⇒ 与「换模拟器/装机」相关
