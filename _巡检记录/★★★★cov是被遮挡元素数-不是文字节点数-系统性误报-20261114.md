# ★★★★ `cov` 是「**被遮挡的元素数**」，不是「文字节点数」—— 而且有系统性误报

> `2026-11-14 23:4x`。跑 `triage.py` 时发现，直接影响明早怎么读那 `240` 款的新数据。

## 一、⇒ 我之前的错误理解

**我今天一直把 `cov=5` 当成「这个游戏有 `5` 个文字节点」（`Word Snake` 的 `cov=82` 我就说成「`82` 个文字节点」）。**

**⇒ `triage.py` 的输出说得很清楚：**

```
【⚠️ 被遮挡】cov > 0（有元素被别的元素整个覆盖）24 款
   ⇒ 必须看截图判真假：可能是真缺陷（盘面盖住统计行），也可能是正常浮层（徽标/角标叠在卡片上）
   ⇒ 合成测试实证：正常布局 cov=0 / 被盖住 cov=2 / 浮层(设计如此) cov=1 ⇒ 天生有误报
```

**⇒ `cov` = **被遮挡（被别的元素整个覆盖）的元素个数**。**

## 二、⇒ 关键证据：`cov>0` 的款里，大部分我刚看过截图、内容全可见

| 游戏 | `cov` | `blk` | 我今天看过的截图结论 |
|---|---:|---:|---|
| `Kakuro Mini` | `5` | `0` | **题卡 + `6` 个键 + 统计行全可见** |
| `Fraction Matcher` | `5` | `0` | **四个选项 `A`/`B`/`C`/`D` 全可见** |
| `PTB` | `5` | `0` | **`⌫`/`0`/确认 那行完整** |
| `Factor Finder` | `5` | `0` | **题面 + `12` 数字 + 说明 + 提示行全可见** |
| `Lock Pattern` | `5` | `0` | **`3×3` 九点 + 说明 + `再看一次` 全可见** |
| `Block Count 3D` | `5` | `0` | **`3×3` 题面三行 + 说明行全可见** |

**⇒ 这 `6` 款我都真机截图看过、内容一处不缺，但 `cov` 全是 `5`。**

**⇒ 所以 `cov=5` **不是缺陷信号** —— 它是某一类固定结构的浮层（很可能是 `HintBar`/统计卡片的阴影或叠层）。**

## 三、⇒ 而 `Word Snake` 的 `cov=82` 要单独看

**`cov=82`、`blk=0`、`max=1460`（`lowest` 是提示行 `[60,1418][2500,1460]`）。**

**⇒ `82` 个被遮挡元素 —— 这一款是「蛇形轨迹」游戏，字母块**天然重叠**（这正是玩法），
   所以 `82` 极可能就是**设计如此**。**

**⚠️ 但要确认必须看它的截图（今天没看过这一款）。**

## ⇒ 判据（`2654`）

**`cov` = 被遮挡元素数，**不是**文字节点数 —— 我今天的口头/笔记里全说错了，此处更正。**
**⇒ 判据：任何指标第一次用时，先读 `triage.py`/`shot_game.py` 里它的定义，别从数值反推含义。
    今天我把 `cov=5` 反推成「5 个文字节点」、把 `cov=82` 反推成「82 个文字节点」，两个都错了。**

## ⇒ 判据（`2655`）

**`cov>0` 自带系统性误报（浮层/角标/阴影都算遮挡）⇒ **不能单独作为缺陷判据**，必须配截图。**
**⇒ 判据：明早拿到 `240` 款新数据时，`cov>0` 只用来**挑候选**、不用来**下结论**；
    判缺陷的唯一依据仍是「截图里内容缺不缺」+「`blk` 溢出多少」。**
