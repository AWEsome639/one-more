# 最大的盲区：**`334/355` 款有一条从未被测量过的布局分支**

> `2026-11-16 09:29`。**这是今天发现的第四个、也是规模最大的一个「没看过的轴」。**

## 一、⇒ 事实

| 项 | 值 |
|---|---:|
| 含 `Bp.isShort()` 分支的款 | **`334` / `355`（`94%`）** |
| 分支出现次数合计 | **`753`** |
| **`isShort == false` 分支被测量过的次数** | **`0`** |

**⇒ 因为我们的模拟器**只有一个尺寸**（`onemore7`，`2560x1600 @480dpi` = `853×533 vp`）⇒ `Bp.height = 533 < 690` ⇒ **`isShort()` 恒为 `true`** ⇒ `else` 那条路**永远不执行**。**

**⇒ 分支最密集的款（改动风险最高）：`GMentalMapping`（11 次）、`GColorMazeNav`（10）、`GFindWord`（10）、`GFractionMatcher`（10）、`GPercentageShopping`（8）、`GWordSearch`（8）。**

## 二、⇒ 为什么这是「世界顶尖」的硬伤

**⇒ 这些分支里放的通常是：字号、间距、选项列数、棋盘上限 —— 也就是说，**同一款游戏在平板和 TV 上是另一套布局，而那套布局从没被人看过。**
**⇒ 判据 `2799` 说过「我截了图 ≠ 我覆盖了那个场景」；现在是「我覆盖了场景 A、场景 B 一次都没跑过」。**

## 三、⇒ 廉价验证办法（今晚做，不用新模拟器）

**⇒ 关键：`Bp.height` 取自 `display.getDefaultDisplaySync()` ⇒ 而 `hdc shell wm size` **可以运行时改显示尺寸**。**

```bash
# 模拟一台更大的设备（2560x1600 竖屏 → 1600x2560）
hdc shell wm size 1600x2560
# 测 3 款分支密集的，看 isShort==false 的布局
python3 工具/shot_game.py "Mental Mapping"
python3 工具/shot_game.py "Color Maze Nav"
python3 工具/shot_game.py "Find Word"
# 恢复
hdc shell wm size reset
```

**⚠️ 三个必须验的点：**
1. **`wm size` 改了之后 `Bp.height` 真的变了吗**（先 dump 一次看 `blk`/`board` 是否变化）
2. **`shot_game.py` 的坐标（搜索框 `2276,264` 等）是按 `2560x1600` 写死的 ⇒ 换尺寸后进不去游戏** ⇒ 可能要先改坐标或改走别的入口
3. **改完必须 `wm size reset`**，否则后续所有测量都错（而且台账分不清）

**⇒ 所以这件事**不能盲试**：先只做第 1 点（改尺寸 → dump 一次 → 看 `board` 尺寸变没变），确认通路再谈测量。**

## ⇒ 判据（`2807`）

**「分支覆盖率」要按**执行过的分支**算，不是按文件数算。**
**⇒ `334` 款里有 `else` 分支，而它们一次都没跑过 ⇒ **这不能算「已覆盖」** —— 与 `blk=0` 的教训同源：**没跑到 ≠ 没问题。**
