## 二、⇒ 但「A 类 7 款都能条件渲染」是错的 —— 必须拆

**查代码发现被挤的文字分两种性质：**

| 游戏 | 被挤元素 | 能条件渲染吗 |
|---|---|---|
| **`Base Conversion Run`** | `this.msg`（`GBaseConversionRun.ets:606`）| **❌ 不能** |
| **`Calculation Sprint`** | `this.msg` | **❌ 不能** |
| `Fractional Pizza` | 纯提示 `Text`（`:346`）| ✅ 可以（已修）|
| `Norinori` / `Area Perimeter Match` / `Visual Search All` / `Collatz` | 待查 | ？|

**⇒ `this.msg` 在这些游戏里**不只是初始提示**，还承载**对错反馈**：**

```typescript
this.msg = TG2("把进制换算对，答错扣 {0} 秒", …)   // 初始提示
this.msg = TG2('✅ 答对！连击 ×{0}', …)            // ← 答对反馈
this.msg = TG2("❌ 错了，扣 {0} 秒…", …)           // ← 答错反馈
```

**⛔ 若按提示的方式条件渲染隐藏它，**玩家就看不到答对/答错了**（反馈消失）。**

## 三、⇒ 所以这两款要用别的办法

**正确的方向（与 `Pipes` 同源）：**不能藏，要给它空间****
- 给「消息行」一个最小高度，并压缩它上面的元素（题目卡或选项行）；
- 或把消息移到页头上方（但会改变交互习惯，需谨慎）。

**⇒ 下次处理这两款：先 dump，看「父预算 vs 子合计」，再按 `Pipes` 配方给消息行留出 `~` 高度。**

## ⇒ 判据（`2703`）

**`lowest` 高度异常的候选中，**必须区分「纯提示」与「状态/反馈行」**：**
- **纯提示**（解释玩法，页头 `?` 可替代）⇒ 可条件渲染隐藏；
- **状态/反馈行**（对错、进度、连击）⇒ **绝不能藏**，只能给它空间。

**⇒ 判据：看到 `this.msg` / `this.hint` 这类字段，先 `grep` 它的**所有赋值处**，
    只要有 `✅`/`❌`/`完`/`错` 等反馈字样，它就**不能**被条件渲染。

**⇒ 这是今天第三个「配方不能无脑套」的实例（前两个：`Magnets` 的 `maxWidth`、`Pipes` 的缩格子）。**
