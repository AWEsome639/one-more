# 判据 3013：给早报做一个**能失败**的审计器

## 一、为什么做这个

判据反复说「每个结论要能复算」。今晚我写了 `17` 节早报、几十个数字，
但**没有一个东西能证明那些数字和台账对得上** —— 全靠我手抄。

⇒ 手抄的数字会漂：早报写 `174` / `96.6%`，台账明天又长了，谁也不知道这 `174` 是哪一刻的。
  更糟的是**抄错**（今晚我就在 `06:26` 把 `96.2%` 写成 `95.6%`、`152` 款写成 `148`，当场自己抓回来）。

## 二、做了一个可执行的审计器

`工具/audit_report.py`：把早报里写死的关键数字放进 `CLAIMS` 表，
**每一个都从 `_巡检记录/layout-canonical.tsv` 原始数据重算一遍**。

审四类：
1. **通过率**（三跑批期 / 单实例后的条数、OK 数、百分比）
2. **`blk>0` 的款数**
3. **`6` 款回滚游戏的末次状态**
4. **精确严重度**（`max / blkh × 100`）

### 输出（今晚数据）

```
[① 通过率]        三跑批期 63/40/63.5%  ✅   单实例后 174/168/96.6%  ✅
[② blk>0 款数]    实测 18  早报 18  ✅
[③ 回滚款]        Wordle/Kakuro Mini/Magnets/Percentage Shopping/Fraction Matcher/2048 全 OK  ✅
[④ 精确严重度]     Shadow Pivot 24/20=120.0% · Collatz 24/80=30.0% · Memory 24/88=27.3%
                  Wordle 20/96=20.8% · Snake 3D 21/132=15.9% · Magnets 24/880=2.7%
                  Divided Attention 24/875=2.7% · Mandelbrot 24/844=2.8%   全部 ✅

✅ 早报每一个数都能从台账重算出来（不符项 0）
```

## 三、★ 关键：做了一个**反向测试**

**一个永远报 ✅ 的校验器等于没有校验。** 所以我故意改错两处再跑：

```
blk>0 款数      实测 18  早报 17        ❌
Wordle          20/96 = 20.8%  早报 25.0%  ❌
❌ 有 2 项与台账不符（不符项 2）
退出码: 1
```

恢复后回到 `0` 项不符、退出码 `0`。

⇒ **它能失败。** 这一步比「它通过了」重要得多。

## 四、判据

> **凡是「报告里的数」，都要有一个能对原始数据重算、并且**能失败**的校验器；
> 只做正向测试（跑通就算对）的校验器是装饰品。**

⇒ 三条：
1. **正向 + 反向都要做** —— 反向测试故意改错一个已知值，确认它报错
2. **校验器的断言表放在脚本里、和报告一起改** —— 改早报忘了同步，审计会当场报出来
3. **退出码要能用** —— `0`/`1`，这样它可以进 CI/跑批的最后一步

## 五、它挡住的是哪一类错

今晚实际发生过三次「数错」：
- `06:26` 把 `96.2%` 写成 `95.6%`、`152` 款写成 `148`
- `3010` 引用 `171%`（粗代理，真实 `2.7%`）
- `3010` 把 `Divided Attention` 排成「明早第一个该看的」

⇒ 前两次是**抄/取数错**，审计器能挡。
⇒ 第三次是**取数口径错**（用了不可靠的分母），审计器挡不了 ——
   那是 `3005`/`3010` 的领域，需要**指标本身先定对**。

⇒ **两类错要两套办法：口径错靠判据，抄写错靠审计器。**
