## ① 「重开」会不会把进度也清了

**语义基线**：本项目的 `reset()` = **本局重来**。它会把 `level / round / stage / qi / done / solved / cleared` 归零 —— 这些字段都是**本局内**的轮次与逐步完成标记，清空正是「重开」该做的。

- **183 款**的 `reset()` 会清 `done/stage/round/level` 之类字段（例：`GSimonCommand:…` reset 里 `done=false`、`GHitori:…` 清 `moves`）。
- 全量核对：**没有任何一款 `reset()` 写 `ProgressStore`**（0 处）⇒ 重开**不会**清掉统计、最佳分、成就、连续天数 ✓
- **唯一真反例**：
  | 文件:行号 | 什么语义 | 用户看到什么 | 一句话修法 |
  |---|---|---|---|
  | `games/GSokoban.ets:161-166`（`onRestart`） | `this.cleared = this.cleared.map(() => false); this.load(0);` ⇒ **把所有已过关记录清零 + 回到第 1 关** | 点了顶栏 ↻ 以为只是重来本局，结果**8 关进度全没了**（而游戏内「重开」按钮 `:744` 是 `load(this.level)`，只重来当前关） | 删掉 `cleared` 清空、改成 `this.load(this.level)`；真要“清除进度”另做入口 |

## ② 退出再进会不会恢复上次状态

- **局内存档：0 款**。`aboutToAppear` 里没有读档逻辑；`aboutToDisappear` 有 235 款，但**全部**只做一件事——停计时器（`clearInterval/clearTimeout`，通常包在 `clearAll()/stop()/halt()/killTimer()` 里）。
- 唯一 `ProgressStore` 触点：`games/GPegSolitaire.ets:81` 的 `Hint.demoOnce('GPegSolitaire')`（只记“演示过了”，与棋局无关）。
- 因此**不存在**「有存档但退出不写 / 进来不读」的坏情况；反过来，**「退出即从头」是全局一致的语义**。
- 如果产品想要「中断恢复」（退出再进能接着下），那是**350+ 款都要加序列化**的功能缺口，属独立专项，不该混在修 bug 里。

## ③ 「再来一局」与顶栏 ↻ 行为是否一致

**宿主层：一致 ✓**
- 结算「再来一局」`pages/GameHost.ets:3645-3656`：`Hint.stopAllAuto()` → `showResult=false` → `nonce+1` → `diffTick+1`
- 顶栏 ↻ `pages/GameHost.ets:1226-1232`：`Hint.stopAllAuto()` → `nonce+1` → `diffTick+1`
- 差别只有 `showResult=false`（必须关弹窗），语义相同。

**游戏层：348/355 一致 ✓**（`onRestart()` → `this.reset()`，与游戏内「重开」按钮同一个函数）

**4 款走 `restartTap()` —— 不是问题（正确设计）**
`GCheckers:341` / `GGo9:937` / `GGomoku:509` / `GMancala:288`：
```
if (!LanMatch.isActive()) { this.reset(); return; }
... 联机时先发 LAN 通知再重置
```
单人时等价于 reset()；联机时必须通知对手，否则两边棋盘不一致。游戏内按钮也调 `restartTap()` ⇒ 两处一致 ✓

**2 款真分歧（要用一条）**
| 文件:行号 | 顶栏 ↻ 做什么 | 游戏内「重开」做什么 | 用户看到什么 | 一句话修法 |
|---|---|---|---|---|
| `games/GHanoi.ets:60-63` | `this.level = GameDiff.pick(2, 3, 5); this.reset(this.level);` ⇒ **随机换一关** | `:433-435` `this.reset(this.level)` ⇒ **重来本关** | 点顶栏 ↻ 后层数从 4 层变成 3 或 5 层，本来想重试本关 | `onRestart()` 改成 `this.reset(this.level)`（“换一关”另做入口或交给难度胶囊） |
| `games/GSokoban.ets:161-166` | 清空 `cleared` + `load(0)` ⇒ **清进度回第 1 关** | `:744` `this.load(this.level)` ⇒ **重来本关** | 同上：顶栏 ↻ 把进度清了 | 去掉 `cleared` 清空、改 `this.load(this.level)` |

**已复核不算问题的**：`GLockPattern:76` 的 `onRestart()` 调 `newGame()`，与游戏内按钮（`:436` → `:445`）**同一个函数** ⇒ 一致 ✓

## ④ 重开后计时器/动画没停？

- 初筛 14 个「`reset()` 里有 `setInterval` 但前面没直接 `clearInterval`」的候选：
  `GAssociativePairs / GBaseConversionRun / GBinaryCode / GCalculationSprint / GCardCountingMemory / GChangeBlindness / GFaceNameAssociation / GFaceTraitAssociation / GFeatureMatrixRecall / GFeatureMatrixRecallAll / GPercentagePeak / GTicTacToe / GVektorVector / GVennNumbers`
- **逐个复核结果：0 真问题**。它们 `reset()` 第一句就是 `this.clearAll()`（或 `this.cleanup()`），而这些助手体里确有 `clearInterval/clearTimeout` ⇒ 属于「助手封装」造成的误报。
- 旁证：235 款 `aboutToDisappear()` 都停计时器；`GFlappy`、`GRhythmMaster` 还额外 `stopAuto()`（代打定时器）✓
- 另外核过 `@Watch('onRestart')` 那条路：`restartToken` 变化 → `onRestart()` → 先 `this.reset()`（内部清计时器）再重开 ⇒ 不会出现两个计时器同时跑。
