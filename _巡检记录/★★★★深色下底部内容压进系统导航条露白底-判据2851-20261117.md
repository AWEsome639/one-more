# 【`10:04` 补充】根因与修法定位（**发现已闭环，实现留给下一轮**）

## 一、⇒ 根因：App **从不设置系统栏配色**

**⇒ 全库 `grep -rn "setWindowSystemBarProperties|navigationBarColor|statusBarColor"` ⇒ **零命中**。**
**⇒ 也就是说：深色主题只把 **App 自己的页面** 变黑；**状态栏/导航条一直是系统默认（浅色）**。**

# 【`10:40` 静态复查】`navigationBarColor` 可能只对**三键导航**生效

## 一、⇒ 证据（本地 SDK `.d.ts`，API 26）

**⇒ `@ohos.window` 的 `SystemBarProperties.navigationBarColor` 原文：**
> **Background color of the three-button navigation bar.**

**⇒ 而界面描述是：「properties of the status bar and three-button navigation bar」。**
**⇒ 也就是说：这个字段**明确写的是「三键导航栏」**。**

## 二、⇒ 而我们设备是**手势导航**

**⇒ `Affix Factory` 深色截图底部是一条**横条**（手势指示条），不是三个按钮 ⇒ 手势模式。**
**⇒ ⇒ 我那个 `ThemeBars.apply()` 很可能**对手势条无效** —— 白条不会消失。**

## 三、⇒ 如果确实无效，正确的做法是另一套

**⇒ 手势模式下，底部那一条属于**窗口内容区**（App 可以画到那里）⇒ 应该：**
1. **`win.setWindowLayoutFullScreen(true)`**（内容延伸到系统栏区域）
2. **让页面根容器自己铺满到底、并用主题底色画满**（这样手势条下面也是黑/白，而不是系统那条）

**⇒ 代价：要动全局壳的根容器（比 `ThemeBars` 大），而且**必须处理「内容被手势条遮住」**的问题（底部加 `expandSafeArea` 的 padding 或保留安全区）。**

## ⇒ 所以验收的顺序必须是（不能跳）

1. **先跑 `verify_navbar.sh`**：如果白条**消失** ⇒ 说明这台设备/这个版本**手势模式下也认 `navigationBarColor`** ⇒ 收工
2. **如果白条**还在** ⇒ 说明文档是对的 ⇒ 换成「全屏 + 自己画底」那一套**（不要在原方案上打补丁）

**⇒ 判据 `2853`：**改之前先读清那个 API 到底管哪个部件。** —— `navigationBarColor` 管的是「三键导航栏」，我差点为它写一轮验收、然后困惑为什么白条还在。**

# 【`10:41` 机制确认】`expandSafeArea` 只在开屏用过 —— 主页与游戏壳都没延伸到导航条

## 一、⇒ 决定性证据

**⇒ 全库 `grep expandSafeArea` ⇒ **只有一处**：`Splash.ets:1297`**
```ets
//   ⇒ 加 `expandSafeArea`：开屏是全屏动画，必须盖住状态栏与导航栏。
.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP, SafeAreaEdge.BOTTOM])
```
**⇒ 而 `Index.ets`（主页壳，底部导航）与 `GameHost.ets`（游戏壳，`build()` 在 `L1004`）**都没有** ⇒ 它们的页面**停在导航条上方**，那一条由**系统**画（浅色）。**

**⇒ 所以白条 = **系统在自己那块区域画了浅色底**，与 App 主题无关。**

## 二、⇒ 为什么 `navigationBarColor` 不是正解

**⇒ 它管的是「三键导航栏」（文档原文），而我们是手势导航 ⇒ 大概率无效（判据 `2853`）。**

## 三、⇒ 正解（两个文件，一步到位）

**⇒ 在 `Index.ets` 与 `GameHost.ets` 的**最外层容器**上加：**
```ets
.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM])   // 让页面画到导航条下
.backgroundColor(<主题底色>)                                      // 让那一条也是黑/白
```
**⇒ 同时在**内容内部**补一个底部安全区（`SafeAreaEdge.BOTTOM` 的 inset 或固定 `~48px` padding）** ⇒ 否则 `Affix Factory` 的提示行会被手势条**压住**（从「露白」变成「被盖」，更糟）。**

## 四、⇒ 验收（两条都要过）

1. **深色**：裁底部放大 ⇒ 白条消失、与页面同色
2. **内容不被遮**：`Affix Factory` 的提示行、`Wordle` 的 `换一题`、`Sokoban` 的 `上一关` **都要完整可见**（这正是今天上午修那五个缺陷的同一把尺子）

**⇒ 判据 `2854`：**「露白」与「被盖」是同一个改动的两个失败方向。** —— 只加 `expandSafeArea` 不加底部内边距，白条会消失，但底部内容会被手势条吃掉；只加内边距不扩展，白条不变。**
