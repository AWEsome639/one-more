# 判据 `3104`：`Magic Squares`（幻方）竖屏 `重开` 被切 —— `360 → 410`，两指标归零

## 一、发现的

`detect_bottom_clip.py --today`（`72` 款新鲜截图）里唯一被标的一款：`cov=0.94`。
截图：`重开` 只露上半，文字压在屏底。

## 二、根因：又一个 `Bp.height - 360`

`GMagicSquares.ets:459`
```typescript
.constraintSize({ maxHeight: Math.max(140, Bp.height - 360) })
```
⇒ 和 `Life Game`(`3086`)、`Memory Matrix`(`3103`) **完全同一个值**。

## 三、修法与两个中间态（每档都量了）

| 竖屏 reserve | `blk` | `cov` | `lowest` 块 | 截图 |
|---|---|---|---|---|
| `360`（原）| `1/24px` | `0.94` ⚠️ | `重开` 只露上半 | 被切 |
| `392` | `1/24px` | `0.94` ⚠️ | `重开` 完整 `131px`、**底边 `2496` 贴屏** | 完整但贴边 |
| **`410`** | **`0/0px`** | **`0.00`** ✅ | `重开` 收进来 + 下方提示行可见 | **完整 + 留边** |

⇒ 最终补丁：
```typescript
.constraintSize({ maxHeight: Math.max(140, Bp.height - (Bp.isShort() ? 360 : 410)) })
```

⇒ `410` 的来历：`392` 时 `重开` 底边正好 `2496`（溢出 `24px` = `7.7vp`），
再加 `10vp` 边距 ⇒ `392 + 18 = 410`。

## 四、⚠️ 全库有 `73` 个文件用 `Bp.height - 360` —— 但**不能一刀切**

```bash
grep -rl 'Bp.height - 360' entry/src/main/ets/games/*.ets | wc -l   # → 73
```

⇒ 今天在 `72` 款新鲜截图里只抓到 `Magic Squares` 一款坏
（加上已修的 `Life Game` / `Memory Matrix`，共三款是 `- 360` 家族的反例）。

⇒ 说明 `360` **不是普遍坏的**，它取决于「棋盘下面还有多少东西」：
- `Life Game`：两排按钮（4 个）⇒ 需要 `402/432`
- `Memory Matrix`：提示 + 一个按钮 ⇒ 需要 `388`
- `Magic Squares`：提示 + 数字键行（56）+ 一个按钮 ⇒ 需要 `410`
- 其余 70 个：棋盘下面东西少，`360` 刚好够

⇒ **不能批量改**。`73` 是「人口」，不是「缺陷名单」。

## 五、判据

> **同一个魔数被复制到 `73` 个文件里时，它看起来像「统一约定」，
> 实际上是「每个场景各算一次、恰好算出同一个数」—— 所以坏的一定是少数。**

⇒ 四条：
1. **看到大面积重复的魔数，先抽样测，不要先批量改**（`73` → 实测 `1` 坏）
2. **`reserve` 的大小由「棋盘下方有什么」决定**，不是一个通用常数
3. **修的时候只改竖屏侧**（`Bp.isShort() ? 旧值 : 新值`），横屏逐字不变 ⇒ 零风险
4. **`392` 这种中间态本身是有信息的**：它证明「完整但贴边」仍然报 `blk=1/24px`，
   必须再加 `~10vp` 才归零
