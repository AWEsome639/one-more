## ⚠️ 而「`max_bottom=1600` 这个判据本身也有问题」

**「`max_bottom` = 「所有节点里最靠下的 `y2`」** —— **「这包括「装饰性背景」「页面根容器」」**。

**⇒ 「应该只看「**有意义的节点**」**（**有 `text` 的、可点的**）」，**而不是「所有节点」**。

**修法**：
```python
nodes = collect(d2, lambda t: len(t.strip()) > 0)   # ← 只收「有文本」的
max_bottom = max((y2 for _, (_, _, _, y2) in nodes), default=0)
```

## 而这条也值得记（判据 1847 候选）

> **「自动化的第一版」几乎总是错的 —— 因为它「安静地」用「错误的前置条件」产出「看起来合理的答案」。**
> **⇒ 「每个自动化脚本都必须有「前置条件断言」+「中间结果落盘」」**：
> - **前置**：「搜索成功了吗？（`count < 355`）」
> - **中间**：「进游戏了吗？（`in_game`）」
> - **落盘**：「点卡片后的 `dump` 存了吗？」（**v3 没存 ⇒ 现在无法判断真假**）
