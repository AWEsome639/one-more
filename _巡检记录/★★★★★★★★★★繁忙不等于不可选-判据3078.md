# 判据 `3078`：**「繁忙」≠「不可选」** —— 我第十几次把代理量当真值

## 一、奥森一句话点破

> 「嗯～不过我觉得繁忙也能跑呀，又不是不让选」

⇒ 他说得对。**我一次都没试**，只是看到「繁忙」两个字就把它归为「不可用」。

## 二、实测（`3` 秒就验完了）

```javascript
const cb = card.querySelector('input[type=checkbox]');
cb.disabled   // → false     ★ 可以选
cb.click()    // → 选上了
```

选上后设备卡显示：
```
MatePad Pro (WEB-W00) · 6.1 · API 24 · 2880×1920 · 预计排队时长5分钟 · 优惠
```

⇒ **「繁忙」的真实含义是「要排队约 5 分钟」**，不是「不能用」。

## 三、这个错误让我损失了什么

第一轮我**跳过了 `4` 台平板**（全部「繁忙」），只选了手机；
第二轮又只选手机，还特意把任务名写成「平板兼容性」—— **名不副实**。

⇒ 而 `MatePad Pro` 是 `2880×1920` ⇒ **横屏原生平板**，正是我最缺的形态（我那 `9` 款修复全在横屏路径上）。
⇒ 一句话让我多做了一个本来会漏掉的形态。

## 四、这是同一类错误的第 `5` 次

`AGENTS.md` 的代理量清单，今天又添一行：

| 维度 | 我用的代理 | 真相 | 判据 |
|---|---|---|---|
| 覆盖率 | 台账名数 | 要逐名对撞 | `3063` |
| 能力 | `syscap` 声明 | 运行时可能 `undefined` | `3062` |
| 活死 | 进程数 | 要看产出增量 | `3067` |
| 常亮 | `setmode 602` 语义 | 是「性能模式」 | `3070` |
| **可用性** | **设备卡上的「繁忙」** | **只是要排队 5 分钟** | **`3078`** |

⇒ 五次都是同一个形状：**一个看起来像那么回事的字符串/数字，被我当成了它背后的属性。**

## 五、正确做法（三条）

1. **先看控件本身可不可操作** —— `disabled` / `readOnly` / `pointer-events` 才是硬判据，
   界面上的状态词（繁忙/占用/排队）只是**描述**，不是**约束**
2. **不确定就点一下** —— 这次成本是 `3` 秒；不点的成本是「漏掉一整个设备形态」
3. **界面文案要读它的**动词**，不是形容词** —— 「繁忙」若是约束，会写「不可用」或直接置灰

## 六、判据

> **界面上的状态词（繁忙/占用/排队/维护中）先当成「提示」，不要当成「限制」。
> 限制只有三种是可验证的：控件 `disabled`、接口报错、文档明写。**

⇒ 两条：
1. **「看起来不行」→ 先试一次再说不行**（`不轻言放弃` 的界面版）
2. **被状态词劝退，要记一笔** —— 否则下次还会被同一句话劝退
