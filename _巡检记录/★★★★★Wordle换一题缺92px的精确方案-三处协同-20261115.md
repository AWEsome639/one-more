# `Wordle` 的 `换一题` 缺 `92px`：精确方案（三处协同，明天做）

> `2026-11-15 13:24`。**今天最后一个真缺陷，方案写死、不仓促动刀。**

## 一、⇒ 缺陷与真实缺口

| 项 | 值 |
|---|---|
| `lowest` | `'换一题'` `[60,1572][857,1600]` |
| 实测可见 | `28px` |
| **设计高度** | **`120px`（`KEY_H = 40` ⇒ `40vp`）** |
| **真实缺口** | **`92px`** |

## 二、⇒ 为什么只能压键盘

| 候选 | 为什么不行 |
|---|---|
| 棋盘 `120vp` | **已到下限**（`5` 列 ⇒ 每格 `24vp`，写 `FontSize.md`=16 已很挤）|
| `KEY_H` 常量 | **`b2cacc75` 十四次收敛的成果**，⛔ 不能直接改数值 |
| `换一题` 按钮行 | **那一行里还有 `Text(this.status)`**（显示对局状态）⇒ **整行隐藏会丢状态** |

## 三、⇒ 方案：把 `Pipes` 配方用在键盘容器上（三处协同）

**当前结构（`L494-508`）：**

```
Column({ space: Space.xs }) {           // 容器：wrapContent 高度
  ForEach(KEY_CHARS) => Row({...}) {    // 3 行，高由键决定
    ForEach(row) => this.keyView(ch)    // keyView 里 .height(KEY_H) = 40vp
  }.width('100%').justifyContent(Center)
}.width('100%')
```

**改成：**

```typescript
Column({ space: Space.xs }) {
  ForEach(KEY_CHARS, (row, ri) => {
    Row({ space: Space.xs }) { … }
    .width('100%').justifyContent(FlexAlign.Center)
    .layoutWeight(1)                     // ★ ① 行按权重均分
  })
}
.width('100%')
.layoutWeight(1)                          // ★ ② 容器吃「剩余」，从而能压缩
// keyView 内部：
.height('100%')                           // ★ ③ 键填满所在行（不再固定 KEY_H）
```

**⚠️ 三个前提（缺一个就会出问题，判据 `2696`/`2706`）：**
1. **页面根 `Column` 已有 `.height('100%')`（`L546` 确认有）⇒ 容器 `layoutWeight` 才有意义。**
2. **容器必须先于行确定高度**（否则第一个子元素会吃掉全部，判据 `2706`）。
3. **`keyView` 的 `.height(KEY_H)` 必须同时改**，否则行压了、键还是 `40vp` ⇒ 溢出到行外。

## 四、⇒ 验证标准

**改完必须同时满足（截图为证）：**
- `lowest` 是**状态文字或按钮，高度 ≥ `120px`**（不再被切）
- **键盘 3 行完整可见**（`QWERTYUIOP` / `ASDFGHJKL` / `ZXCVBNM ⌫ ⏎`）
- **猜词棋盘 `5×5` 完整**（`Wordle` 棋盘今天刚修好「隐形」问题，别改坏）
- `blk` 应降到 `0` 或接近 `0`

**⚠️ 如果改完棋盘或键盘任一项缺失 ⇒ 立即回滚（这是今天 `Scroll` 弄黑键盘的教训）。**

## ⇒ 判据（`2720`）

**要动「作者反复收敛过的常量」（如 `KEY_H`）时，**不改它的数值，而是改它被使用的方式**
（`height(KEY_H)` → `height('100%')` + 行 `layoutWeight`）。**
**⇒ 这样常量本身仍是“每行目标高度”，只是允许在空间不足时按比例压缩，而不是硬撑到溢出。**
