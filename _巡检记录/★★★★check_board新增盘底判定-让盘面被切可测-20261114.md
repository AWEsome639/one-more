# ★★★★ `check_board.py` 新增「盘底是否超出屏底」⇒ 盘面被切**可测**了

> `2026-11-14 15:0x`。今天最大的痛点是「盘面是否完整只能看图」，这条把它变成数值。

## 一、原理

**`board=WxH@x,y` 里的 `y` 是方形块顶边、`H` 是高度 ⇒**

```
盘底 = y + H
超出量 = (y + H) − 1600      （屏幕 1600px）
⇒ > 0 ⇒ 盘面被切（切掉那么多 px）
⇒ <= 0 ⇒ 完整
```

**⇒ 这就是 `blk`/`lowest` 都看不见的那一维。**

## 二、⇒ 合成样本验证

| 样本 | `board=` | 盘底 | 判定 | 对不对 |
|---|---|---:|---|---|
| 完整 | `1560x1560@500,40` | `1600` | ✅ 完整 | ✅ |
| 被切 `64px` | `264x264@1148,1400` | `1664` | ❌ 被切 `64px` | ✅ |

**⚠️ 我第三个样本（`1200x1200@680,700`）没出现，是因为我 TSV 里多写了一个 tab ⇒ 列错位 ⇒ 那条被跳过。
⇒ **是测试数据的问题，不是工具的问题。***

## 三、⇒ 这让明晚的验证从「只看图」变成「先看数、再看图」

```bash
python3 工具/fixed_audit.py --opt     # 逐款 FIXED 与最优 cap
python3 工具/check_board.py --all     # 每款的方形块：像不像棋盘 + 盘底有没有被切
```

**⇒ 有了「盘底超出量」这一列，就能直接回答「改完盘面完整了吗」。**
**⚠️ 但仍要看图，因为 `board=` 找的是「最大方形块」，可能不是盘面（工具自己标注的局限）。**

## ⇒ 判据（`2275`）

**一个「只能看图」的判断，往往缺的不是图，而是**某个已知量的组合**。**
**⇒ 这次 `board=` 早就有 `y` 和 `H`，而 `y + H` 就是盘底 —— 数据一直都在，只是没人加这一列。**

**⇒ 判据：说「这个只能看图」之前，先看现有字段能不能组合出答案。
⇒ 组合（加法/差值）是最便宜的推导，比新增采集便宜得多。**

**⇒ 这次第三条没输出，第一反应是「工具逻辑有问题」；实际是我 TSV 多了个 tab。**
