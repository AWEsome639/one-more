# 判据 1815（2026-11-08 立）

## 1815 · 矮屏必须「常收起」—— 否则是功能性死锁，不是观感问题

**发现**：`perf-hunter` 在验 `LazyForEach` 时甩回最顶部，**网格区变成 0 张卡**。

**根因链**（三步）：
1. `topCollapsed` 被 `onScrollIndex`（`first ≤ 1` 时）**翻回 false** ⇒ **顶部整块展开**
2. 853×533 下顶部整块 = **404vp**，而 TabContent 只有 **406vp** ⇒ **网格剩 8px ≈ 2.7vp**
3. **`onScrollIndex` 的「收起」分支靠网格滚动事件触发** —— 而网格高度 ≈ 0 ⇒ **手势打不到** ⇒ **死锁**

**实测逃生口（三个全失败）**：
- 往下甩 2 次 ❌
- 点分类 chip「经典 46」❌
- 挑面板「展开▼」→「收起▲」❌

⇒ **唯一出路是重启 app。**

**阈值本身是对的**（硬下限重算 = 顶部 404 + 2 行卡 180 + TabBar 60 = **644 < 690**，`690` 有 46vp 余量）。
**抬到 900+ 会误伤 700~900 的正常机型。**

**真正的问题**：`Bp.isShort()` 只在 `aboutToAppear` 用它初始化 `topCollapsed=true`，
**`onScrollIndex` 把它翻回 false 时没有任何地方再拦**。

**修法（1 行）**：`effCollapsed()` 里 `if (Bp.isShort()) { return true; }`

---

## 为什么这个 bug 藏了这么久

**`ForEach` 时代卡片始终在树里** ⇒ `dumpLayout` 照列 **355 张** ⇒ **没人发现列表其实「看见了 0 张」**。

**`LazyForEach` 只是让它显形** —— 网格高度为 0 ⇒ 什么都不建 ⇒ dump 0 张。

## 判据

**「声明支持」≠「真能用」**，**也「能渲染」≠「看得见」** ——
**树里有节点 ≠ 用户在屏幕上能看到它**。

**推论**：凡是「容器高度可能被其他元素挤到 0」的地方，都要问一句
**「用户在这里有没有出路」** —— 靠滚动自愈的机制，在高度为 0 时**永远不会触发**。

## 附带判据（同一天 `perf-hunter` 踩的）

**不能用「今天这一局」判断「顶部是否展开」** —— **收起态也会渲染它**（`GamesTab.ets:1150`：
`if (this.effCollapsed() && …) { this.dailyStrip() }`）。
**判「整块展开」要看「随机来一局」或「🎮 全部」分段行是否出现** —— **这两块只在展开态渲染**。
