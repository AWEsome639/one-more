# 布局判据总表（`1925–1944`，一夜之间踩出来的 `20` 条）

> **用法**：动手前扫一眼这张表，能省掉我一整夜的弯路。
> **来源**：`2026-11-12` 凌晨，从「尺子错」到「改错对象」的全过程。

## 一、关于「尺子」（测量本身可能骗你）

| # | 判据 | 一句话 |
|---|---|---|
| **1925** | **量「内容多高」要数「叶子节点」** | 数「有文字的节点」会漏掉棋盘格/色块/Canvas；数「整棵树」会被根容器（`height:100%`）钉在屏幕底 |
| **1926** | **宣称「清零」前必须说清「这个尺子看不见什么」** | 我用「只量文字」的尺子扫 `178` 款说溢出 `0`，**而它漏了 `19` 款棋盘类** |
| **1933** | **`max_bottom = 1600` 分不出「贴底」和「切掉」** | 两者都给 `1600`；**溢出报告必须配截图** |
| **1937** | **「盘面已封顶却仍 `1600`」大概率是**真裁切**，不是「正常贴底」** | 截图实测 `2/2` 都是真裁切 |
| **1944** | **代码模式扫描只能筛候选，不能当结论** | `52` 个同模式文件里真坏的只有 `1` 个（`1.9%`）⇒ **必须用测量数据交叉验证** |

## 二、关于「改哪一刀」（你最可能改错地方）

| # | 判据 | 一句话 |
|---|---|---|
| **1928** | **`aspectRatio(1)` 的板子：`maxHeight` 只裁不缩，必须用 `maxWidth`** | 限宽即限高；`GGo9.boardMax()` 是同款范式 |
| **1927** | **「缩格」的收益 = `Δvp × 行数`** | 行数少的页面（`1~4` 行）缩格几乎没用 |
| **1938** | **底部被切时，先看「被切的那块上面是什么」** | 上面是大块（棋盘/列表）就压那块，**别压被切的工具栏**（工具栏只有 `40~50vp`）|
| **1939** | **`bounds` 的差值直接告诉你「每行该减多少」** | `需腾像素 ÷ 行数 = 每行像素`，再 `÷3` 得 `vp` ⇒ **改多少不用猜** |
| **1940** | **「压缩」试了 `3` 次都没动 ⇒ 改成「让内容可滚动」** | `Scroll` 不动任何内部尺寸，只让装不下的部分能滚到 |

## 三、关于「改完之后怎么知道有没有用」

| # | 判据 | 一句话 |
|---|---|---|
| **1929** | **知道「谁最靠下」≠ 知道「它是谁」** | 按 `type` + `bounds`（宽高比、行数）**认出节点**再动手 |
| **1930** | **`probe` 显示最深叶子是 `Stack` 且 `y1` 不动 ⇒ 先拍截图** | 很可能是**空容器占位**——「约束加不上」的背后是「那个节点里没有可缩的东西」 |
| **1931** | **「改完截图逐像素一致」= 这一刀完全没作用到布局** | 比 `max_bottom` 不动更狠 |
| **1932** | **先拿 `bounds`，再按 `bounds` 反查代码** | `grep .width('100%')` 命中 `20+` 处，**靠猜我错了七次** |

## 四、关于「你在测哪个游戏」

| # | 判据 | 一句话 |
|---|---|---|
| **1942** | **测量必须用完整名字（含后缀）** | 全库 `15` 对中文名/`20` 对英文名互为前缀；`Kakuro` 会命中 `Kakuro Mini` ⇒ **改 A 测 B，十次白改** |
| **1943** | **前缀审计要中英文各做一遍** | 两套名字不是一一对应（`Visual Search` 同时是两个长名的前缀）**以英文名为准** |

## 五、关于「环境」

| # | 判据 | 一句话 |
|---|---|---|
| **1934** | **模拟器端口会变**（`adb` 占 `5555` ⇒ 退 `5557`；退出后回 `5555`）| 工具必须每次从 `hdc list targets` 取 |
| **1935** | **`aa start` 成功 ≠ 界面出来了** | 进程活着 + 截图全黑 = 渲染挂了 ⇒ 别再重试点击 |
| **1936** | **探测环境的代码必须用绝对路径调外部命令** | 裸 `hdc` 不在 `PATH` ⇒ 静默回落到默认值 ⇒ **把「端口变了」伪装成「设备不在」**（`153` 次 `NOT_HOME` 的真凶）|
| **1923b** | **「批次重启」不能只重启模拟器** | 反复 `force-stop` 会把 App 推进异常态，而 `aa start` 的返回值骗人 |

## 六、两个探针（比任何判据都实用）

```bash
python3 工具/probe_deepest.py     # 最深 6 个叶子：y2/y1/x 范围/宽高/type/text
python3 工具/probe_ancestors.py   # 某个文本节点的完整祖先链（type + bounds）
```

**⇒ 正确顺序永远是：先 `probe` 拿 `bounds` → 按 `bounds` 反查代码 → 改 → **再 `probe` 确认那个节点的数值变了**。**
