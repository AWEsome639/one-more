# 折叠屏工具卡点**修好了** —— 真因是 `_screen()` 默认写死手机尺寸

> `2026-11-18 19:21`。**从「跑满 300s 无输出」到「一次跑通」，靠的是给工具加的三层日志 + 一个真修。**

## 一、⇒ 真因（判据 `2924`）

**⇒ `_screen()` 默认返回 **`2560x1600`**（手机横屏），只有设了环境变量 `ONEMORE_SCREEN` 才变。**
**⇒ 折叠屏是 **`2224x2496` 竖屏** ⇒ 兜底点击坐标算成 `(2276, 264)` ⇒ **x=2276 超出屏宽 2224** ⇒ 点在屏幕外 ⇒ 搜索页永远不开。**

**⇒ 日志一眼看穿：**
```
[search] 候选 1 个: [(2276, 264)]  点击前节点数=175
[search] 点了 (2276,264) ⇒ 节点数=175 (未变)
```

**⇒ 修法：**从每次 `dump()` 的**根节点 bounds 自动读真实屏幕尺寸**，优先于环境变量/默认值。**
```python
_SCREEN_CACHE = [None, None]
# dump() 解析成功后：根节点 bounds = 屏幕
_SCREEN_CACHE[0] = nums[2] - nums[0]; _SCREEN_CACHE[1] = nums[3] - nums[1]
# _screen() 优先返回缓存
```
**⇒ 验证：折叠屏 dump 根节点 `[0,0][2224,2496]` ⇒ `_screen()=(2224,2496)` ⇒ 兜底坐标变 `(1977,412)`（落在屏内）。**

## 二、⇒ 端到端结果（同一次运行）

```
[search] 候选 1 个: [(1938, 274)]        ← 正确找到 🔍（与手动点成功的位置一致）
[search] 点了 (1938,274) ⇒ 节点数=192    ← 搜索页开了
Triple Sequence  OK  2496  69.8s  blk=6/4160px
```

**⇒ **工具在折叠屏上跑通了**（之前三轮全是 `TIMEOUT`）。**

## 三、⇒ 顺带交付的三件套（以后都能用）

| 能力 | 用法 |
|---|---|
| `SHOT_VERBOSE=1` 打每次 dump 的字节数+节点数 | 空树/小树立刻现形 |
| 同上的 tag **自动带调用行号**（`d@L868`） | 一眼看出哪个循环在转 |
| 点击**前后**各打一行（候选、节点数、是否变化） | 区分「点没生效」与「点到别处」 |

**⇒ ⚠️ 必须 `python3 -u` 跑** —— 管道缓冲会让 `timeout` 杀掉时输出全丢（我为此白跑一次）。

## 四、⇒ 新暴露的问题（下一步）

**⇒ 折叠屏 `2224×2496` 竖屏上，`Triple Sequence` `blk=6/4160px`、`lowest` 到 `2496`（屏底）。**
**⇒ 这与我按手机 `Bp.height=533` 调的 `gs()=(Bp.height-280)/3` 不符 —— 折叠屏 `Bp.height≈832` ⇒ 每格 `184vp=552px` ⇒ 3 行 `1656px` 应该装得下。**

**⇒ 所以 4160px 的溢出**不是这个算式造成的**，是更上游的问题 —— 很可能是**折叠屏竖屏下整个页面按横屏假设排的**。**
**⇒ 明天第一步：在折叠屏上 `uitest dumpLayout` 看 `Triple Sequence` 的实际纵向占用（现在工具能进游戏了，可以 dump 了）。**

## ⇒ 判据 `2924`

**⇒ 「工具在某台设备上点不动」时，先查**它以为的屏幕尺寸是多少** —— 写死的屏幕常量会让所有按比例算的坐标系统性偏出屏幕。**
**⇒ 而且这类 bug 的症状是「点了没反应」，**不是报错** ⇒ 只能靠「点击前后节点数」这种观测抓。**
