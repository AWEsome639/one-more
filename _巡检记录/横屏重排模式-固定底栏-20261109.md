# 「横屏重排」模式：**中间 `layoutWeight(1)`,底栏固定**（给 3 款待重排用）

## 为什么需要它

**`Binary Puzzle` / `Target Number` / `Tents And Trees` 三款「调参调不动」**（判据 1869）：
- **删按钮、缩棋盘、降高度，`max_bottom` 都不动**
- **原因：中间有一个「吃剩余空间」的块（`layoutWeight(1)`）** —— **它把腾出来的空间全吃掉**

**⇒ 调参之所以无效，是因为「空间分配」本身错了，不是「尺寸」错了。**

## 模式（可直接套）

```ts
Column() {                 // 根：不要 space（间隙交给各块自己 margin）
  // ① 顶部固定区（页头由 GameHost 提供，这里从 HintBar 起）
  HintBar({ ... })         // 固定高度，不参与剩余分配

  // ② 统计行（矮屏用单行胶囊，判据 1857）
  Row({ space: Space.xs }) { this.stat(0); this.stat(1); this.stat(2) }
    .width('100%')

  // ③ 中部：**唯一**的 layoutWeight 块 —— 棋盘/题面
  Column() {
    this.board()
  }
  .width('100%')
  .layoutWeight(1)          // ★ 它吃「剩下的全部」，所以它必须「能缩」
  .constraintSize({ minHeight: 120 })   // ★ 下限，避免被压成 0

  // ④ 底部固定区：**永远不缩**
  Column({ space: Space.xs }) {
    this.answerPad()        // 按键/候选
    Row({ space: Space.sm }) { /* 重开等次要按钮：矮屏 .visibility(None) */ }
  }
  .width('100%')
  .flexShrink(0)            // ★ 关键：底栏不参与压缩
}
.width('100%')
.height('100%')
.justifyContent(FlexAlign.Start)
```

## 四条要点

1. **只能有一个 `layoutWeight(1)`** —— 两个以上就会「互相让位」，谁也压不住（`Binary Puzzle` 就是这种）
2. **中部要能缩**：`boardPx()` 那种「按可用高反推」的写法优先；**不要 `aspectRatio`**（判据 1822）
3. **底栏 `flexShrink(0)`** —— 否则空间不够时 ArkUI 会先压它（正是「按钮被裁」的直接原因）
4. **次要按钮用 `.visibility(Bp.isShort() ? Visibility.None : Visibility.Visible)`**（判据 1867），**不要 `if`**

## 验收口径（照今晚的规矩）

1. **等演示结束再量**（判据 1865）
2. **`max_bottom ≤ 1516` 才算 `OK`**
3. **截图必须看到「底栏完整 + 中部不贴顶」两件事**
4. **德/俄两种长语言各量一次**（底栏文案最长会把按钮撑宽）

## 适用范围

**不只这 3 款** —— **任何「删了东西不瘦」的横屏页面**都是这个模式。
**⇒ 明天若再遇到，直接套，不要再逐款调参数**（那是判据 1869 已经否掉的路）。
