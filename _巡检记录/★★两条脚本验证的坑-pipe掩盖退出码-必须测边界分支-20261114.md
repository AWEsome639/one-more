# ★★ 两条脚本验证的坑：`pipe` 掩盖退出码 / 必须测边界分支

> `2026-11-14 18:1x`。验 `apply_a_batch.sh` 的边界时，我自己的验证方法先出了错。

## 一、⇒ 坑一：`pipe` 会掩盖退出码

**我最初这样测：**
```bash
bash 工具/apply_a_batch.sh --only 2>&1 | head -2
echo "退出码 $?"        # ← 这是 head 的退出码，不是脚本的
```
**⇒ 输出「退出码 0」，我差点以为脚本没正确 `exit 2`。**

**⚠️ 实际上 `$?` 取的是**管道最后一条命令**的退出码。**

**⇒ 正确测法：**
```bash
bash 工具/apply_a_batch.sh --only >/dev/null 2>&1; echo "退出码 $?"
```

**⇒ 实测五种边界：`--only` 无值 / `--only` 跟选项 / 名字拼错 / 未知参数 ⇒ 全 `2`；正常 `--dry` ⇒ `0`。**

## 二、⇒ 坑二：新脚本必须测**边界分支**

**基线文件那个 bug（`wc … | tr > f || echo 0 > f` 在台账缺失时写出空文件）就是这样发现的：**
**⇒ 我只测了「台账存在」的正常路径，直到专门去构造「文件不存在」才暴露。**

**⚠️ 而它的表现是「基线文件存在但是空的」⇒ 下游拿空串做减法 ⇒ 会报一个看起来毫不相关的错。**

## 三、⇒ 所以新脚本的验收集合

| 分支 | 例子 |
|---|---|
| **正常路径** | `--dry` 全命中 |
| **参数缺失** | `--only` 后面没值 |
| **参数非法** | `--only 2049`（名单里没有）|
| **未知参数** | `--wat` |
| **输入不存在** | 台账文件被移走 |
| **输入为空** | 台账是空文件 |

**⇒ 每一条都要看**退出码**与**输出**两样，不能只看输出。**

## ⇒ 判据（`2551`）

**`cmd | head` 之后 `$?` 是 `head` 的 ⇒ 想验退出码就必须不接管道（`>/dev/null 2>&1`）。**
**⇒ 同类：`cmd | tee log`、`cmd | grep x` 都会掩盖 `cmd` 的退出码（除非开 `pipefail`）。**

**⇒ 判据：验退出码时，命令**不接管道**；要同时看输出和退出码，就分两次跑。**

## ⇒ 判据（`2552`）

**新脚本的验收必须包含「输入不存在」与「输入为空」两个分支。**
**⇒ 这两个分支的 bug 形态通常是「程序继续跑、用空值算出一个看似正常的结果」，比崩溃更难发现。**

**⇒ 判据：写任何读文件的脚本，先想「文件不在 / 是空的」会怎样；那两种情况才是最容易静默错的地方。**
