## 三、⇒ 为什么溢出（读代码推的）

`GShadowPivot.ets` 结构：
- 两块棋盘并排，每块内部是 `Stack().layoutWeight(1).aspectRatio(1)` 的格子；
- ⇒ **格子是正方形、且宽度各占一半** ⇒ 棋盘宽 ≈ `(493 − 12)/2 ≈ 240vp` ⇒ **棋盘高也 ≈ 240vp**；
- 加上头部（`~50`）+ 题号/提示（`~20`）+ 按钮（`Cell.of(46)=39`）+ padding ⇒ **超过 `533` 约 `19vp`**，正好对上 `58px`。

**⇒ 注意 `302` 行的注释（判据 `2900`）已经修过一轮**：「这个 `Row` 只有 width 没有高度 ⇒ 按内容撑高 ⇒ 面板底行溢出。加 `layoutWeight(1)` 让它取剩余空间。」
**⇒ ⇒ 但 `layoutWeight(1)` 只分了「剩余高度」，**棋盘内部的 `aspectRatio(1)` 仍然把高度撑回 240vp** ⇒ 溢出还在。**

## 四、⇒ 建议修法（明天带测量做）

**⇒ 给棋盘容器加高度上限，让 `aspectRatio` 反推宽度（作者 `1906` 在 `GBreakout` 上验证过这条路径有效）：**
```ts
// 两块棋盘的外层 Row（约 303 行）或每块棋盘的 Column（约 310/330 行）
.constraintSize({ maxHeight: Math.max(120, Bp.height - 200) })
```
**⇒ 预测：棋盘高 `240 → 333?`** —— 不，`533-200 = 333 > 240`，**这个 `-200` 太小、不起作用**。
**⇒ ⇒ 正确口径：要先算出「除棋盘外还占多少」。图上除棋盘外约 `290vp`（头部 `50` + 按钮 `39` + 题号/提示 `20` + 上下 padding `40` + 两块棋盘的间隙），所以 `N ≈ 290 + 余量`：**
```ts
.constraintSize({ maxHeight: Math.max(120, Bp.height - 300) })   // 533-300 = 233vp
```
**⇒ 预测：棋盘 `240 → 233vp`（省 `7vp`）** —— 仍不够省 `19vp`。
**⇒ ⇒ ⇒ 所以**真正的余量不在棋盘上，而在「除棋盘外的 290vp」**：要么压头部/按钮，要么让两块棋盘**横竖排布**改成能利用横向空间。这条要带测量才能定，别照上面数字硬套。**
