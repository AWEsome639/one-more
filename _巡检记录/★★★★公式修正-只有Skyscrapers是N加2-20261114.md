# ★★★★ 公式修正：只有 `Skyscrapers` 是 `(N+2)×(N+2)`，其余纯 `N×N`

> `2026-11-14 14:2x`。自我撤回「画错行数」之后的必要修正。

## 一、`Skyscrapers` 的盘面结构（完整核实）

```ts
private skyText(gr: number, gc: number): string {
  if (this.isPlay(gr, gc)) { … }                              // 游戏格 gr,gc ∈ 1..N
  if (gr === 0 && gc >= 1 && gc <= N) { … }                   // 顶部线索行
  if (gr === N + 1 && gc >= 1 && gc <= N) { … }               // 底部线索行
  if (gc === 0 && gr >= 1 && gr <= N) { … }                   // 左侧线索列
  if (gc === N + 1 && gr >= 1 && gr <= N) { … }               // 右侧线索列
  return '';
}
```

**⇒ 所以盘面是 `(N+2) × (N+2)`：`N` 个游戏格 + 上下线索行 + 左右线索列。**
**⇒ `N=4` ⇒ `6×6` = `36` 格，其中游戏格 `16` = `CELLS` ✅。**

**⇒ 而 `ForEach([0..5])` 渲染 `6` **恰好等于 `N+2`** ⇒ 是设计。**

## 二、⇒ 其余 `14` 款是纯 `N×N`

| 游戏 | `const N` | 渲染长度 | 关系 |
|---|---:|---:|---|
| **`Skyscrapers`** | `4` | `6` | **`N+2`** |

**⇒ 只有 `Skyscrapers` 有线索框。**

## 三、⇒ 所以公式要分两种

| 盘面结构 | 款 | 下限算式 | 例（`N`）|
|---|---|---|---:|
| **`(N+2)²`（含线索框）** | `Skyscrapers` | `44 * (N + 2)` | `44*6 = 264vp` |
| **`N²`（纯盘面）** | 其余 | `44 * N` | `44*6 = 264vp` / `44*8 = 352vp` |

**⇒ 而 `Skyscrapers` 现在 `240vp ÷ 6 = 40vp` ⇒ 修改后 `264 ÷ 6 = 44vp` ✅**

## 四、⇒ 但「线索格也要 `44vp`」合理吗

**线索格是**只读**的（不可点），它们只需**看得清**，不需要触控 `44vp`。**
**⇒ 所以严格说：只需要「游戏格 ≥ `44vp`」⇒ 盘宽 ≥ `44 * N`，其中 `N` 是游戏格数
⇒ 而线索格会被压缩到 `< 44vp`（如 `264/6 = 44` 时线索也是 `44`，凑巧相等）。

**⇒ 若只要求游戏格 `44vp`，则盘宽 = `44 * 6 = 264vp`（因为总共 6 列）⇒ 与 `44*(N+2)` 相同。**

**⇒ 所以两种算法结果一致（因为列数就是 `N+2`）。✅**

## ⇒ 判据（`2271`）

**「格子 `44vp`」这条要求要分清**哪类格子**：可点的游戏格必须 `>= 44`，只读的线索格只需可读。**

**⇒ 而这次两者凑巧结果相同（列数 = `N+2`、游戏格 `N`），所以不影响结论。
⇒ 但在别的游戏里若线索格占更多列，就要分开算。**

**⇒ 判据：算「每格多大」时先问「这一格要不要点」。**
