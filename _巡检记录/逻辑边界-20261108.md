## ② `finish()` 重入守卫（按可触发性排序）

### 统计口径

- 「结算函数」= 函数体内出现 `this.onFinish(` 的函数（`finish` / `end` / `judge` / `next` / `pick` 等），共 **355 个**。
- 「自带守卫」= 函数体内有 `if (this.over|done|settled|ended|finished)`，或有闩锁：
  `if (this.settled) return; … this.settled = true;` / `if (!this.done) { this.done = true; … }`。
- 355 个里 **269 个自带守卫/闩锁** ⇒ 剩下 86 个靠调用方；再查调用方函数体内有没有同样的守卫，
  **28 个既无自带守卫、又有无守卫调用方**。

### P0：App 层兜底缺失（影响全部 355 款）

`pages/GameHost.ets:509` 有 `private finished: boolean = false;`，但 `handleFinish()` 入口**不检查它**：

```ts
private handleFinish(r: GameResult): void {
  if (Demo.anyRunning()) { return; }          // ← 只有演示保护
  …ProgressStore.finishGame(...)              // ← 没有幂等，每调一次就记账/加 XP
  GameLog.recordResult(...)
  this.finished = true;                       // ← 只用于「退出时不再补记」
}
```

⇒ **两个后果**：
1. 双 `onFinish` ⇒ XP/局数/日志都翻倍（结算弹窗也会闪两次）；
2. `ProgressStore.finishGame` 内部无幂等判据（已读源码，line 338 起：直接 recordPlay + 加 XP）。
⇒ **建议修复**：`handleFinish` 开头加一行 `if (this.finished) return;`（新局在 `gotoNext` 里已重置 `finished=false`，语义正确）。
