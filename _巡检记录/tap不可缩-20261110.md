# 判据 1899：**`Cell.tap(N)` 有「触控下限」，缩不动**

## 源码

```ts
static tap(base: number): number {
  const v: number = Cell.of(base);
  return v < Layout.touchMin ? Layout.touchMin : v;   // ★ 有下限
}
```

**⇒ `Cell.tap(44)` / `Cell.tap(32)` / `Cell.tap(28)` 全部返回同一个值（`Layout.touchMin`）。**

## 这意味着什么（要更正记录）

**今天 19:50 我提交的「`Cell.tap(44) → 38` 批（15 款，判据 1898）」——
除了 `Sentence Unscramble` 那款，其余**根本没变**（因为 `38 < touchMin`，返回值不变）。**

**⇒ 那次「2/4 改善」的归因是错的**：
- `Sentence Unscramble 1297` 的改善，**很可能来自「它同时也有 `Space.md → xxs`」**，不是 `Cell.tap`
- `Mental Mapping 1597` 同理
- **`Color Maze Nav` 三次缩格（`44→32→28`）全部无效，现在我确认了原因**

## 正确的做法

**要真正缩小触控格子，必须用 `Cell.of(N)`（无限低），或者改 `Layout.touchMin`（全局，风险大）。**
**⇒ 但缩到 `touchMin` 以下会违反触控规范** ⇒ **`Cell.tap` 的格子本就不该再缩**。

**⇒ 判据 1899（立）**：
> **改尺寸前先看那个函数有没有「下限/夹取」** ——
> **`Cell.tap` 有 `touchMin` 下限，改它的入参是**无效操作**（`grep` 看起来改了，运行时不变）。**
>
> **⇒ 判断一个属性「能不能缩」，要读它的实现，不是看它的名字。**

**依据**：`Color Maze Nav` 三连缩（`44→32→28`）三次实测 `max_bottom` 全是 `1600`；
读源码才发现 `tap()` 有 `Math.max` 式夹取。
