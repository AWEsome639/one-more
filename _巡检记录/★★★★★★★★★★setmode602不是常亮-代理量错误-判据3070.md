# 判据 3070：**`power-shell setmode 602` 不是「常亮」，是「性能模式」** —— 我错了一整晚

## 一、事实（命令自己打印的）

```
$ hdc shell "power-shell setmode"
usage: power-shell setmode [<options>]
setmode <power mode: (value is as below)>
  600  :  normal mode
  601  :  power save mode
  602  :  performance mode
```

⇒ **`602` = 性能模式。** 它**不阻止息屏**。
   我从晚上 `21:xx` 起一直假设它是「AC 常亮」，并用它当「屏幕不会睡」的保证 —— **一整晚都是错的**。

## 二、这个错误的形状：又一次「代理量」

`AGENTS.md` 的代理量清单第一条：
> **判断「A 有没有变」时，先问「我拿来代表 A 的那个东西，是不是 A 本身」**

| 维度 | 我用的代理 | 真相 |
|---|---|---|
| 屏幕常亮 | `setmode 602`（我以为的语义）| **性能模式**，与息屏无关 |

⇒ 而且**命令本身就会打印帮助**（`power-shell setmode` 不带参数时）—— 我一次都没查。

## 三、今晚因此浪费了什么

| 时间 | 发生了什么 | 真实原因 |
|---|---|---|
| `23:42`–`23:50` | 扫描静默卡死 `40` 分钟 | 模拟器内存不足起不来（不是这个） |
| `00:2x` | 失败率 `33%`，截图纯黑 | **屏幕真的睡了**，而我以为 `602` 挡住了 |
| `01:0x` | 起保活循环，仍然失败 | 保活方向对，但 `602` 无意义 |
| `01:4x`–`02:0x` | 反复黑屏、`last texts=[]` | 屏幕睡 + 渲染管线退化 |

⇒ **根因之一就是这条错误假设。**

## 四、正确的做法

`power-shell` **没有常亮模式** ⇒ 只能在**每次测量前**唤醒：

```bash
hdc shell "power-shell wakeup"
sleep 2
# 然后立刻测量（不要隔着几分钟）
```

⇒ 并且**不要起「每 30 秒 setmode+wakeup」的循环** —— 它可能打断 UI 交互，反而帮倒忙。

## 五、判据

> **命令的语义要让它自己说：`<命令>` 不带参数跑一次，看 usage。
> 我拿 `setmode 602` 当「常亮」用了一整晚，而它自己打印的 help 里写着「performance mode」。**

⇒ 四条：
1. **任何 `xxx-shell` / `hidumper` 类命令，第一次用之前先跑不带参数的 usage**
2. **「我以为是这个意思」的工具语义，一律视为未验证**（同 `3062` 的 `syscap` 声明）
3. **一个假设错了会连带整晚的结论都错** —— 这次「屏幕睡了」被我误判成「渲染退化/键盘」
4. **保活循环不是万能药**：先搞清「为什么睡」，再决定怎么防
