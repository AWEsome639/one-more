## 0. 先讲清架构（这决定了审计口径）

项目里有**两套互不相通的字典**，这是后面所有结论的前提：

| 字典 | 位置 | 取值函数 | 条目 | 列 |
|---|---|---|---|---|
| `DICT` | `core/GameI18n.ets:25-12164` | `TG() / TG2() / TG4()` | **4543** | en/ja/ko/es/fr/de/pt/ru/it/ar（**无 zh-Hant 列**，繁体走 `toTrad()`） |
| `EXTRA` | `core/I18n.ets:1136-1974` | `L() / L2() / TN()`，再被 `this.t() / this.tn()` 包装 | **420** | en + zh-Hant + 8 语（`en` 列**故意**可缺，英文由调用点第 2 参数给） |

两条回退链（**这是 P0 的判定依据**）：

```ts

if (cur === Lang.ZHTW) return toTrad(zh);
if (row !== undefined) { const en = row['en']; if (en !== undefined) return en; }
return zh;                      // ← 9 语言直接看中文

// core/I18n.ets:2115  L()  —— 缺项退【英文】
if (cur === Lang.ZH) return Digits(zh, cur);
if (cur === Lang.EN) return Digits(en, cur);
const row = EXTRA[zh]; if (row !== undefined) { const hit = row[cur]; if (hit!==undefined && hit.length>0) return Digits(hit,cur); }
if (cur === Lang.ZHTW) return Digits(toTrad(zh), cur);
return Digits(en, cur);         // ← 9 语言看英文
```

### P0-3 RTL：app 内切到阿语时，**布局方向不会跟着翻**

先划清责任边界，免得误判：ArkUI 的 `direction` 默认 `Auto`，**跟随系统 locale**。
所以「系统语言是阿语」的用户大概率本来就拿到 RTL。真正的问题在另一条路：

**app 内的语言选择器只改文案，从不改布局方向。**

```ts
// core/I18n.ets:100-104  —— 切语言只写缓存 + AppStorage
static set(lang: string): void {
  I18n.cached = lang;
  AppStorage.setOrCreate('lang', lang);
}
// 全项目 grep：setAppPreferredLanguage / setLanguage 调用 = 0
// entryability/EntryAbility.ets:40 只 setColorMode，没有 setDirection
```

⇒ 一个**系统是中文/英文、却把 app 切成阿语**的用户，会得到「阿语文案 + 全 LTR 布局」：
`Row` 还是左起、设置项的 `›` 还朝右、带 left 偏置的内边距还在左边。

**证据（骨架确实是纯 LTR 写的）**

| 项 | 数 | 含义 |
|---|---|---|
| `.direction(` 调用 | **0** | 没有一处按语言翻转 |
| `isRTL()` 调用 | **2** | 只有 `GKenken.ets:580`、`GTypoglycemiaDecoder.ets:345`，且只是 `textAlign` |
| 外壳 UI 的 `Row(` | **137** | 排列方向交给容器（目前恒为 LTR） |
| `.padding({ left: …` vs `right:` | 57 : 3 | 布局按左侧锚定写 |
| `.margin({ left:` vs `right:` | 21 : 10 | 同上 |
| `Alignment.Start` : `End` | 5 : 1 | 内容锚点偏 Start |

**最具体的 4 个「箭头不会翻」**（阿语下方向是反的）：

```ts
components/StatsTab.ets:1012    Text('›').fontSize(FontSize.lg).fontColor(this.theme().inkFaint)
components/SettingsTab.ets:395  Text('›')          // 设置项右箭头
components/SettingsTab.ets:747  Text('›')
components/SettingsTab.ets:1160 Text('›')
```

**一句话修法**：切语言时同步方向 —— 最省事是在 `I18n.set()` 里调
`i18n.System.setAppPreferredLanguage(lang)`（会触发 `onConfigurationUpdate`，ArkUI 自动镜像）；
保守做法是根容器 `.direction(I18n.isRTL() ? Direction.Rtl : Direction.Ltr)`，
箭头改成 `I18n.isRTL() ? '‹' : '›'`。改 1~2 处即覆盖 137 个 Row。

> ⚠️ 真机核实点：需确认「系统切阿语」时 ArkUI 是否已自动镜像（若已自动，本条降级为
> 「app 内切语言不生效」这一半）。我无法在静态层面证否，故按 app 内切换路径判 P0。

### P1-1 【504 条手写繁体是死数据】列名写成了 `zhtw`，代码读的是 `zh-Hant`

```ts

```

```ts
// core/GameI18n.ets:2292 起的 503 条，列名是 zhtw

                                     ^^^^ 代码永远查不到这一列
```

- `GameI18n.ets` 里 `"zh-Hant"` 出现 **0** 次，`"zhtw"` 出现 **503** 次
- `I18n.ets:1545` 还有 1 条同样写错（`搜游戏名或玩法`）
- 后果：`TG()` 走 `row['zh-Hant']` → `undefined` → 落到 `toTrad(zh)`，**手写的台湾用语（資料/資訊/設定/螢幕）全部没生效**，繁体用户拿到的是机器转换（自评一致率 97.7%）

**一句话修法**：`sed -i '' 's/"zhtw":/"zh-Hant":/g'` 两个文件（504 处），然后跑一遍繁体实拍对比。

## P2 — 理论风险

### P2-1 德语/葡语长词把短标签撑爆：370 条，531 个调用点

- DICT 里 `max(de,pt,ru) ≥ 25` 字符的条目 **2218** 条，`≥ 35` 的 **1432** 条
- 其中「**中文 ≤7 字、但 de/pt ≥18 字符**」的短标签 **370 条**，落在 **531** 个调用点上
- 这 531 个点里 **527 个没有 `maxLines()` / `textOverflow()` 兜底**

最危险的一批（外壳 UI，按钮/胶囊里）：

| 中文 | 德语 | 倍率 | 位置 |
|---|---|---|---|
| `先填房主 IP` | `Zuerst die Gastgeber-IP eingeben` | **35 字** | `pages/LanLobby.ets:352`（按钮） |
| `开房失败` | `Raum erstellen fehlgeschlagen` | 29 | `pages/LanLobby.ets:298`（按钮） |
| `点一下直接续上` | `Antippen und weiterspielen` | 26 | `components/StatsTab.ets:587` |
| `↻ 右上角` | `↻ oben rechts` | 24 | `pages/GuidePage.ets:314`（示意图标注） |
| `重开这一局` | `Diese Runde neu starten` | 23 | `pages/GuidePage.ets:314` |
| `🏆 解锁成就 ` | `🏆 Erfolg freigeschaltet ` | 25 | `pages/GameHost.ets:3308` |

游戏内窄格（`Cell.of()` 全项目 906 处，329 款游戏在用）同理：格子宽是 `Cell.of(38)`/`Cell.of(56)`
这种固定值，德语长词在 `FontSize.xxs` 下也只剩省略号。

**一句话修法**：给外壳 UI 的 `Button`/胶囊统一加 `.maxLines(1).textOverflow({overflow: TextOverflow.Ellipsis})`；
德语长的那 20 条按「短标签」重译（`开房失败` → `Fehler`）而不是直译。

### P2-2 858 处硬编码里剩下的 773 处：多半是**谜题内容**，属设计取舍

去掉 85 处可见的，剩下 773 处集中在数据表：词库、词源、类别名、故事句、颜色名。
例如 `games/GEtymologyOrigin.ets`（62 处）、`games/GCategoryFluency.ets`（40 处）、
`games/GSemanticDistance.ets`（33 处）。

这些**不是 bug**：词源/同义词谜题的答案本身是中文，翻成 12 语言等于重做 355 款里的几十款题库。
但如果奥森说的「一视同仁」包含**可玩性**，那这是最大的实际缺口 —— 建议单独立项，先挑 10 款最热门的做多语言题库。
