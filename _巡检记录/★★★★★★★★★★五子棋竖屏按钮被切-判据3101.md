# 判据 `3101`：`Gomoku`（五子棋）竖屏 **`悔棋`/`重开` 两个按钮被切** —— `390 → 425`

## 一、怎么发现的（这次不是靠 `blk`）

`blk` 一直报 `0` —— **这个缺陷 `blk` 完全看不见**（被切的按钮不是「块底越界」那种）。

是靠**新写的像素检测器**发现的：
```bash
python3 工具/detect_bottom_clip.py 截图-Gomoku-202127.jpeg
# → cov=0.73  ⚠️
```
截图判读：底部「悔棋」「重开」两个按钮**只露上沿**。

## 二、修法

`GGomoku.ets:1060`：
```typescript
// 改前
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(240, Bp.height - (Bp.isShort() ? 360 : 390))))
// 改后（竖屏 390 → 425）
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(240, Bp.height - (Bp.isShort() ? 360 : 425))))
```

`425` 的来历（从截图量）：
```
棋盘上沿 ≈ 305vp（截图 y≈318 预览px × 0.96）
棋盘下方需要：提示文字 ~20 + 间距 ~6 + 按钮 ~44 + 间距 ~6 + 提示行 ~20 ≈ 120vp
⇒ 棋盘可用 = 798.7 − 305 − 120 = 373.7vp
⇒ 竖屏扣 = 798.7 − 373.7 = 425
原 390 ⇒ 棋盘 408.7 ⇒ 下方只剩 85vp（不够 120）
```

## 三、验收：两个指标同时转干净

| 指档 | 改前 | 改后 |
|---|---|---|
| `blk` | `0/0px`（**看不见**）| `0/0px` |
| **`cov`（像素检测器）** | **`0.73`** ⚠️ | **`0.00`** ✅ |
| 截图 | `悔棋/重开` 只露上沿 | **两个按钮完整 + 提示行完整** |

⇒ 横屏走 `360`，**逐字不变**。

## 四、判据

> **`blk` 会漏掉一整类缺陷：被切的是「组件的上沿贴屏底」，而不是「块底越过阈值」。**
> 这次 `blk=0` 而按钮确实被切 —— 靠像素检测器才抓到。

⇒ 四条：
1. **`blk=0` 不能证明「没问题」**（判据 `2605` 的又一个实例）
2. **像素级检测器 `cov` 是必要的补充**：它量的是「最底一行被内容横向覆盖多少」
3. **两个指标**（`blk` / `cov`）+ **截图** 三者要一起看，任一单独都不够
4. **`cov` 也会误报**（`Kakuro-000005` 的 `cov=1.00` 其实是**键盘盖屏**的测量伪影）
   ⇒ 只能用于**游戏内截图**，且仍需人眼确认
