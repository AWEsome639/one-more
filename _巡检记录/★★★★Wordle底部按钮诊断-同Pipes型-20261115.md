# `Wordle` 底部 `换一题` 按钮：与 `Pipes` 同型（父预算不足），但挤压变量冲突

> `2026-11-15 11:15` 诊断。**未改，留待明天。**

## 一、⇒ 现象

**`lowest='换一题' [60,1572][857,1600]` ⇒ 按钮只有 `28px`（`9vp`）可见，够不到 `44vp` 触控下限（判据 `2601`）。**

## 二、⇒ 结构（代码 + 截图）

```
L462 Column（页面根，.height('100%')）
 ├ L473 Row   统计行
 ├ L480 Column 棋盘（120vp = 360px）
 ├ L494 Column 键盘（3 行，KEY_H = 十四次收敛的结果，⛔ 不许动）
 └ L510 Row   底部（换一题 按钮 .layoutWeight(1).height(KEY_H)）← 被压到 28px
```

**⇒ 与 `Pipes` 完全同型：底部行没有足够预算。**

## 三、⇒ 为什么不能照 `Pipes` 直接套

**`Pipes` 的解法是「容器显式高度 + 行 `layoutWeight` + 格子不定高」，那里格子是可缩的。
`Wordle` 里三个变量互相冲突：**

| 变量 | 状态 |
|---|---|
| 棋盘 `120vp` | 已很小（每格 `24vp`，`FontSize.md`=16 装进去很挤）；再缩格子就装不下字母 |
| `KEY_H`（键盘行高）| **`b2cacc75` 十四次收敛的结果，⛔ 绝不能动** |
| 底部按钮 `44vp` | 触控下限，也不能缩 |

**⇒ 三者都要保 ⇒ 只能从「间隙」和「统计行高度」抠，量级不够（需 ~`100px`，间隙最多省 `~30px`）。**

## 四、⇒ 唯一可行方向（明天做）

**把键盘从「3 行固定 `KEY_H`」改成「3 行 `layoutWeight(1)` + 容器显式高度」，让键盘吃掉剩余空间、
把省下的给底部按钮 —— 即把 `Pipes` 的配方**用在键盘容器上**，而不是棋盘上。**

**⚠️ 风险：改键盘行高会影响 `b2cacc75` 的成果（它当年就是为解决键盘出屏而收敛的）。
⇒ 必须先 dump，确认「键盘容器当前高度 vs 3 行 `KEY_H` 之和」，再决定。**

## ⇒ 判据（`2699`）

**同一类缺陷（底部行被压）在不同游戏里的解法**可能相反**：`Pipes` 能缩格子，`Wordle` 不能（格子已到下限、
键盘行高是收敛成果）。**
**⇒ 判据：套用配方前先列「哪些变量可动、哪些是硬约束」；可动变量省不够 ⇒ 换方向，别硬压。**
