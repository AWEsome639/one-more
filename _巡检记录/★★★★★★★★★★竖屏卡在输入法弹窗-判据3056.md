# 判据 3056：**竖屏测量一整天失败，真因是「系统输入法设置向导」挡住了 app**（第五层）

## 一、决定性证据

今天竖屏测量反复 `NO_CARD` / `NOT_HOME` / `TIMEOUT (search:…)`，我一直归因给模拟器不稳。
**截了一张屏才看见真正的原因**：

```
┌────────────────────────────┐
│      小艺输入法             │
│  快捷准确、安全有趣的输入法   │
│   ……隐私声明……              │
│   [ 取消 ]      [ 同意 ]    │
└────────────────────────────┘
```
点「同意」之后**又跳出第二步**：
```
请选择中文键盘布局
  [经典布局 ✓]  [简洁布局]
        [ 完成 ]
```
两步都点完之后，app 立刻正常显示首页。

## 二、为什么会触发

测量工具找卡片要用 `uitest uiInput` **打字搜索** ⇒ **首次唤出键盘** ⇒
系统输入法弹出**一次性**的隐私同意 + 布局选择向导。
**这两步没点，键盘一直盖在 app 上，任何测量都不可能成功。**

⇒ 所以它**只在「第一次用键盘」时出现一次**，之后就再也不出现 ——
   这也是为什么 `13:08` 那次还能测成功、之后全失败。

## 三、这是 `3045` 的**第五层**

| 层 | 现象 | 判据 |
|---|---|---|
| 1 | 设备连不上 | `hdc list targets` 空 |
| 2 | 锁屏 | `aa start` ⇒ `10106102` |
| 3 | app 没装 / ID 猜错 | `bm dump -a` 里没有 |
| 4 | 能启动但全黑 | 截图暗像素 `100%` |
| **5** | **能启动、有画面，但被系统弹窗盖住** | **截图里看到「不是本 app 的界面」** |

⇒ 第 `5` 层的判据：**截一张屏，看是不是 app 的画面** ——
   `NO_CARD` 时**第一件事应该是截图**，而不是重试或怀疑模拟器。

## 四、正确的解锁步骤（记下来）

```bash
hdc shell "uitest uiInput click 1494 2007"   # 输入法隐私「同意」
sleep 5
hdc shell "uitest uiInput click 1110 2295"   # 布局「下一步」
sleep 5
hdc shell "uitest uiInput click 1110 2295"   # 布局「完成」
sleep 5
hdc shell "aa start -b com.andrewoscar.onemore -a EntryAbility"
```

⇒ 坐标取自 `2224×2496` 的竖屏机；换设备要重新看截图定位。

## 五、判据

> **`NO_CARD` 不等于「卡片不在」。先截一张屏，确认「屏幕上是不是本 app」——
> 系统弹窗（输入法/权限/更新）会让 app 永远「找不到卡片」。**

⇒ 四条：
1. **`NO_CARD`/`NOT_HOME` 第一步就是截图**，不要先重试、不要先怀疑模拟器
2. **一次性系统向导只在「首次用键盘」时出现** —— 新模拟器/新镜像必检这一项
3. **`uitest uiInput` 打字会唤出键盘** ⇒ 这是触发源
4. **截图取不到时更要查** —— 今天手动截图多次失败（`hdc` 路径引号问题），
   但**只要成功一次就能定位**；换文件名重试即可（`/data/local/tmp/z1.jpeg` 那种短名更稳）

## 六、解锁后的直接收益

修好输入法弹窗后，**同一款 `Shadow Pivot` 当场测成功**：
```
改前  lowest='重开' [62,2363][2162,2496]  blk=1/24px  blkh=133px
改后  lowest='重开' [62,2083][2162,2236]  blk=0/0px
```
⇒ `y2` 上移 **`260px`**、`blk` 归零、**截图四个面板 2×2 完整、无重叠、「重开」按钮完整**。

⇒ **一天里 `5` 次失败 + 今天 `2` 次 `TIMEOUT`，全被这一个弹窗挡住。**
   判据 `3037` 的「先量再改」在这里表现为「**先截图再怀疑**」。
