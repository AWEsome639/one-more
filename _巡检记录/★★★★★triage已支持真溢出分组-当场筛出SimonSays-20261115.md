# `triage.py` 已支持「真溢出」分组 —— **当场从旧台账里筛出 `Simon Says`**

> `2026-11-15 19:08`。**为明早准备的分析工具，装上就先抓到一个。**

## 一、⇒ 加了什么

**`工具/triage.py` 原先只解析 `blk=` 与 `lowest=`，**不认识**今天新增的 `over=` / `sumover=`。**

**⇒ 我加了：**

1. **解析** `over=(\d+)px`、`sumover=(\d+)px`（并记 `has_over` 区分「没有数据」与「值为 0」）
2. **一个新的最高优先级分组**，排在 A/B/C/D 之前：

```
=== 真溢出（over>0 或 sumover>0）N 款 ===
```

**⇒ 三种状态都打印清楚：**
- 有真溢出 ⇒ 按 `over + sumover` 降序列出
- 没有真溢出但有数据 ⇒ `0 款（N 款有数据）`
- **没有数据 ⇒ 明确写「这批测量没有 over=/sumover= 字段（旧 HAP 或旧脚本）」**（与判据 `2003` 一致：缺数据 ≠ 干净）

## 二、⇒ 当场筛出的结果

```
=== 真溢出（over>0 或 sumover>0）1 款 ===
  Simon Says   over=7   sumover=0   2026-11-15T10:50
```

**⇒ 全库 `271` 款有测量，**只有 `Simon Says` 一处真溢出**：某个子容器比父容器高 `7px`（`~2.3vp`）。**

**⇒ 而它的 `blk` 指标是 `0` —— 正是判据 `2695`/`2708` 说的盲区：
   `blk` 只统计「`y2>1576` 的块」，对**父界内**的溢出**零信息量**。**

## 三、⇒ `over=7` 要不要修

**⇒ `7px` ≈ `2.3vp`，是**亚像素级**的容器差 —— 大概率是圆角/阴影/边框的取整，**看不到任何东西被切**。**
**⇒ 但它是**唯一**一处，且 `over` 字段本就为抓这类矛盾而生 ⇒ 记档，明早结合截图判断。**
