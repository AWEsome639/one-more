# `NOT_HOME` 根因：静态分析（2026-11-14）

> **只读分析**：未改任何 `.ets`/工具、未编译、未碰模拟器。
> 数据：`_巡检记录/layout-canonical.tsv`（178 行）+ `工具/shot_game.py`（843 行）+ `entry/src/main/ets/games/*.ets`（355 款）。

---

## 结论（先说）

**`NOT_HOME` 是**同一类**，而且**不在游戏侧，在工具侧**。**

三条证据：
1. **全库 0 款实现 `onBackPress`** ⇒ 「Back 被游戏吃掉」这个说法**不成立**
2. **0 款有全屏结算遮罩**（扫 `.position({x:0,y:0})` + over/won）⇒ 「弹层挡住」**不成立**
3. **工具的回首页代码有两条路径，能力差 3 倍**：
   - Path A（`:455-470`）：**发两次 `aa start`** + 等 `25+8=33s`
   - **Path B（`:503-514`）：只发一次 + 等 `4×3=12s`** ← **`NOT_HOME` 全部从这里出**

## 一、机制（带行号）

### 1.1 `is_home()` 怎么判断（`:405-418`）

```python
def is_home():
    d = dump('home')                      # :406
    if not d: return False                # :407-408  ← dump 失败 = 不是家
    j = ''.join(t for t, _ in texts(d))
    ok = 'One More' in j and ('全部' in j or '355 款' in j or 'All' in j or '355 games' in j)   # :414
    if ok and '✕' in j: return False      # 搜索框有内容也不算初始态（:417）
    return ok
```

**⇒ 两个必要条件**：
1. **dump 必须成功抓到 App 窗口**（抓不到就只有状态栏 `['03:11','100']` ⇒ 无 `'One More'` ⇒ False）
2. **首页必须已渲染出 `'One More'` + 目录标记**

### 1.2 回首页的三条路径

| 路径 | 位置 | 做法 | 预算 |
|---|---|---|---|
| **A** | `:455-470` | Home 键 → force-stop → `aa start` → **等 25s** → **第二次 `aa start`** → 等 8s | **33s + 双 start** ✅ |
| **B** | `:495-501` | 循环 4 次：`is_home()` 假就按 Back，**固定 sleep 1.2s** | 4 次 Back |
| **C** | `:503-511` | force-stop → **一次 `aa start`** → 轮询 `4 × 3s` | **12s + 单 start** ❌ |

### 1.3 `NOT_HOME` 的唯一出口：`:514`

```python
if not is_home():                                      # :512
    finish(name, 'NOT_HOME', t0, None, 'could not reach home')   # :514
    return
```

**⇒ 只要走到这里还没 `is_home()`，就记 `NOT_HOME` 并放弃这一款。**
**⇒ 台账里 87 条 `NOT_HOME` 的备注**全是同一句**（我 grep 过：`87 could not reach home`）—— **没有任何诊断信息**，所以历史数据帮不上忙，只能从代码推。

## 三、A / B / C 分类（你给的三档）

| 类 | 判据 | 实测 | 说明 |
|---|---|---|---|
| **A：根本没有关闭控件** | 结算态只有 `Back` 一条路 | **0 款** | 287/355 款结算态是 `Button(this.over ? '再来一局' : '重开')`（`:GTarget10:358` 等），**有可点控件** |
| **B：有关闭控件但可能被遮挡/不可点** | `zIndex`/`hitTestBehavior`/尺寸 0 | **需真机**（但有强线索，见 §3.1）| |
| **C：`onBackPress` 没返回 `true`** | 拦截了但没拦住 | **0 款** | 全库 **只有 `GameHost.ets` 的注释**提到 `onBackPress`（`:502` 写着「GameHost **没有 onBackPress**」）⇒ **没有任何一款实现过它** |

**⇒ 你预设的 A/C 两类**都是 0**。**
**⇒ 「结算弹层把 Back 吃掉」这个假设（`shot_game.py:545` 的原话）在静态层面找不到支持。**

### 3.1 B 类真正的形态：**按钮被 `isShort()` 隐藏了**

**325 / 355 款**里有 `Bp.isShort() ? Visibility.None`：

```ts
// GWordSearch:388-390（355 款里 325 款同型）
Button(TG('重开'))
// ★（1880 补漏）矮屏不渲染「重开」（页头 ↻ 同动作，判据 1859/1867）
.visibility(Bp.isShort() ? Visibility.None : Visibility.Visible)
```

**⇒ 测量机是 `853×533`（`isShort()` = true）⇒ 这些按钮**在测量时根本不渲染**。**
**⇒ 工具 `:558` 找的关闭文本 `('关闭','知道了','返回','再来一局','✕','×')` 里，
`'再来一局'` 在 287 款上存在，但在矮屏上**它是隐藏的**。**

**⇒ 这是「B 类」的真实形态**：**不是被遮挡，是设计上就不渲染**（判据 1859/1867 的决定）。
**⚠️ 但注意：这是**产品的正确行为**（矮屏用页头 ↻ 代替），不是 bug。**

## 四、判断：`NOT_HOME` 主要是**同一类工具缺陷**

**不是各款各不相同。** 依据：

1. **20 款 ≥2 次、最多 4 次，分布均匀** ⇒ 不像是「某几款游戏的特殊写法」引起的
2. **A/C 两类都是 0** ⇒ 游戏侧没有系统性缺陷
3. **工具自己有两条能力差 3 倍的回首页路径**，而 `NOT_HOME` 只从弱的那条出

### 具体三个缺陷（都在工具侧）

| # | 缺陷 | 位置 | 后果 |
|---|---|---|---|
| **①** | **Path C 没应用判据 1954 的「双 `aa start`」修复** | `:504-506` vs `:469` | force-stop 后单次 start，dump 常只拿到状态栏 ⇒ `is_home()` 恒假 |
| **②** | **Path C 只等 12s**，而同一文件 `:462` 自己写着「App 冷启动要 **30~60s**」，Path A 等 **33s** | `:508-511` | 冷启动根本没完成就判死刑 |
| **③** | **Back 循环固定 `sleep 1.2s`**，不轮询 | `:501-502` | 首页有 355 张卡，渲染常 >1.2s ⇒ dump 抓空 ⇒ 再按一次 Back ⇒ **把 App 退出到后台** ⇒ 后面更回不去 |

**⇒ 三者叠加的典型链路：**
```
游戏页 → Back（1.2s 后 dump 还没渲染完）→ 判「不是家」→ 再 Back → App 退出到桌面
→ Path C：force-stop + 单次 start + 只等 12s → 冷启动未完成 → NOT_HOME
```

## 五、通用修法（只改工具，不动游戏）

### 修法 1（**最高性价比，3 行**）：Path C 对齐 Path A

```python
# :504-506 之后补上
time.sleep(25.0)
sh('aa start -a EntryAbility -b com.andrewoscar.onemore')   # 第二次 start（判据 1954）
time.sleep(8.0)
```
**⇒ 这一条就能堵住 ① + ②。**（Path A 已经验证有效：`_body` 开头的三闸流程用的就是它）

### 修法 2：Back 循环改成「轮询」

```python
# :496-502 现在：固定 4 次 × sleep 1.2
for _b in range(2):                       # 最多 2 次，别把 App 退出去
    if is_home(): break
    sh('uitest uiInput keyEvent Back')
    for _w in range(6):                   # 轮询最多 6s
        time.sleep(1.0)
        if is_home(): break
```

### 修法 3：`NOT_HOME` 行加诊断（**为下一次审计省一晚上**）

```python
# :514 现在只写 'could not reach home'
finish(name, 'NOT_HOME', t0, None,
       'could not reach home; last texts=%r' % (texts(d)[:6] if d else 'dump=None'))
```
**⇒ 有了这 6 个文本，下次一眼就能分出「dump 空」还是「卡在某个界面」。**

### 修法 4（可选，产品侧，**不建议现在做**）

给「矮屏隐藏重开按钮」补一个**隐蔽但可点的**结算关闭件（如整屏 `onClick` 关闭遮罩）。
**但这是产品决策，且 A/C 两类都是 0 ⇒ 现在没必要动游戏。**

## 六、给一句话

**`NOT_HOME` 不是「某些游戏的结算界面没有关闭件」，而是「工具的回首页兜底路径比另一条路径弱 3 倍」——
单次 `aa start` + 只等 12 秒，而同一个文件里另一条路径等 33 秒且发两次 start。**
**⇒ 把 `:504` 那段对齐 `:455` 那段，最可能一次砍掉大半 `NOT_HOME`。**

**⚠️ 诚实标注**：
- 「A/C 两类 = 0」是**静态扫描**结论（扫了 355 款），**不是真机验证**
- 「Path C 是主因」是**代码推断**：我能证明它比 Path A 弱，**但不能证明 87 条里有多大比例来自它** ——
  因为台账把诊断信息丢掉了（全是 `could not reach home`）。
  **⇒ 修法 3（加诊断）是让这个比例可见的唯一低成本办法。**
- 「325 款矮屏隐藏按钮」会**影响工具能否点到关闭件**，但**不影响 Back**（Back 走路由），
  所以它是**次要因素**，不是 `NOT_HOME` 的主因。
