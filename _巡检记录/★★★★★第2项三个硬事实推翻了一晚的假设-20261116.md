# 第 ② 项：三个硬事实**推翻「一晚跑通」的假设**

> `2026-11-16 06:53` 联网查证（非转述）。**结论直接影响今晚的排期，先纠偏。**

## 一、⇒ 事实 ①：`tokenizer` 不在 `.ms` 里

**⇒ 有一个真实项目做过同样的事（`AIChatPro`，[README](https://github.com/piagari/dev/blob/2ed67ecd330500c09d250c4ce29d0ae141d83445/HarmonyOS-Examples-main/HarmonyOS-Examples-main/AIChatPro/README.md)），它的步骤写得很清楚：**
> 将对应模型的 `config.json` 和 `tokenizer.json` 放到 `entry/src/main/resources/rawfile/` 目录。

**⇒  یعنی：`.ms` 只含**权重与计算图**，**分词/反分词要在 App 侧做**（读 `tokenizer.json`，实现 Qwen 的 BPE）。**

**⚠️ 影响：这不是「加载模型跑一次」，而是要**在 ArkTS 里实现一个 BPE 分词器**（`Qwen2` 用 tiktoken 风格 BPE）⇒ 工期从「一晚」变「几天」。**

## 二、⇒ 事实 ②：`converter_lite` 只发 Linux/Windows

**⇒ [官方转换工具文档](https://github.com/mindspore-ai/docs/blob/a406bad67b93856c2cc9e8ebd71bf9f4fbc04e0f/docs/lite/docs/source_zh_cn/converter/converter_tool.md) 的「环境准备」只有 **Linux 环境使用说明**（发布件也是 `linux-x64` / Windows）；**没有 macOS 版**。**

**⇒ 我们这台是 Mac ⇒ 三条路：**
1. **Docker/colima 跑 Linux 发布件**（他先前清掉过 `colima` 的 `13.9G` VM ⇒ 要重建）
2. **用别人转好的 `.ms`**（上面那个项目提供了 `qwen2_0.5b_chat.ms` 的网盘链接）—— **最快验证路径**
3. **云端 Linux 机转一次**（一次性，转完把 `.ms` 拿回来）

## 三、⇒ 事实 ③：参考项目要 `API 15+`，我们是 `API 12`

**⇒ 同一份 README 写明「仅支持鸿蒙 Next(API 15+)」。而 `One More` 全部 `355` 款 + `200,359` 断言都在 **`API 12`** 上 ⇒ **不能为了一个模型把 target 抬到 15**（回归面极大，与 `2792` 同一条理由）。**

**⇒ 但 `@ohos.ai.mindSporeLite` 本身 `@since 10`（已核实）⇒ **能力在 API 12 可用**，只是那份示例代码用了更高 API 的写法 ⇒ **我们自己写一遍即可，不搬它的工程。**

## 四、⇒ 修正后的排期

| 阶段 | 内容 | 预估 |
|---|---|---|
| **A** | 用别人转好的 `qwen2_0.5b_chat.ms` 在模拟器上跑通 `loadModelFromFile` + `predict`（**先证明链路通**）| **1 晚** |
| **B** | 读 `tokenizer.json`、在 ArkTS 实现 Qwen BPE（先只做 encode，decode 后补）| **2–3 晚** |
| **C** | 接「离线生成开场白」这个真实用途（构建期/首启空闲跑）| **1 晚** |
| **D** | 若要自己转模型：Docker/云端 Linux + `converter_lite` | **1 晚** |

**⇒ 所以真实工期是 **`4–6` 晚**，不是一晚。这个数字我现在就说清，免得到时候「怎么还没好」。**

## ⇒ 判据（`2793`）

**「模型能加载」和「产品能用」之间隔着分词器。**任何端侧 LLM 评估，第一时间要问 **`tokenizer` 在哪** —— 它若不在模型里，工期至少乘二。**
