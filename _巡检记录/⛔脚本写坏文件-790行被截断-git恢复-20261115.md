# ⛔ 我用 Python 整文件重写时把 `GKakuro.ets` 截断了（`790` 行），已 `git checkout` 恢复

> `2026-11-15 12:15`。**一次真实事故，记录流程缺陷。**

## 一、⇒ 发生了什么

**给 `Kakuro` 的「重开一题」按钮加条件渲染，用 Python 读改写：**

```python
lines = io.open(p, encoding='utf-8').read().split('\n')   # 读：严格 utf-8
...
io.open(p, 'w', encoding='utf-8').write('\n'.join(lines)) # 写：抛 UnicodeEncodeError
```

**⇒ 抛错的是**写入**：文件里有 emoji 的代理字符（surrogate），严格 `utf-8` 编不回去。**
**⇒ 而 `open(..., 'w')` 在抛错前**已经把文件截断** ⇒ `git diff --stat` 显示 `790 deletions`。**

## 二、⇒ 恢复

```bash
git checkout -- entry/src/main/ets/games/GKakuro.ets
```

**⇒ 恢复为 `790` 行、`git status` 干净。**
**⇒ 无损失原因：该文件当时**没有未提交的改动**（上一版已提交）。**

## 三、⇒ 三处流程错误

| 错误 | 后果 |
|---|---|
| 用 `open(p,'w')` 直接覆盖**源文件** | **写入失败时文件已被截断** |
| 没先确认「能原样编码回去」 | 代理字符触发 `UnicodeEncodeError` |
| 写失败后**没立刻查 `git diff --stat`** | 第二次跑脚本读到残文件 ⇒ `IndexError` 才发现 |

**⇒ 另外还犯了一个命令级错误：`cd X && nohup cmd &` 会把 `cd` 一起丢到后台，
  导致后续命令在 `/` 下执行（`fatal: not a git repository`）⇒ 提交与写文件都失败。
  ⇒ 正确写法：`cd X && (nohup cmd &)` 或分两条命令。**

## ⇒ 判据（`2711`）

**改写源码文件三选一（按优先级）：**
1. **`edit` 工具**（按字面替换，不重写全文）—— **首选**；
2. **临时文件 + `os.replace()` 原子替换**：写成功后才覆盖；
3. **绝不用 `open(p,'w')` 直接覆盖源文件。**

**⇒ 并且：脚本改源码后**立刻** `git diff --stat` 看行数；行数异常 ⇒ **先 `git checkout` 恢复**，别在残文件上继续跑脚本。**

## ⇒ 判据（`2712`）

**本项目源码含 emoji ⇒ Python 读写一律 `errors='surrogateescape'`；**
**⇒ 但根治是判据 `2711` 的「临时文件 + 原子替换」——编码错了也不会毁原文件。**

## ⇒ 判据（`2713`）

**`cd dir && cmd &` 会把 `cd` 一起后台化 ⇒ 同一行后续的 `git`/`写文件` 都会在**错误的 CWD** 执行。**
**⇒ 判据：后台命令必须写 `cd dir && (nohup cmd &)`，或把 `cd` 与后台命令分成两条。**
