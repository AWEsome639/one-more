## 2. 用户能看见的

### S-01 【高】新局不显示提示语，反而挂着上一局的结束语 —— `GActionSequenceRecall.ets:74`

**文件**：`entry/src/main/ets/games/GActionSequenceRecall.ets:70-75`

```ts
70:  private deal(): void {
71:    const s: number[] = [];
72:    for (let i = 0; i < this.len(); i++) { s.push(Math.floor(Math.random() * ACTS.length)); }
73:    this.seq = s; this.cursor = 0; this.showIdx = -1; this.playing = true; this.tickN = 0;
74:    TG2('看好机器人做 {0} 个动作…', this.len())      // ← 值被丢弃
75:  }
```

对照一下同一文件的其它三处写法：

```ts
83:      this.playing = false; this.showIdx = -1; this.msg = TG('轮到你了 —— 按同样顺序点一遍'); return;
234:      this.msg = TG2('❌ 第 {0} 步错了 —— 只剩 {1} 条命，重放一次', ...);
249:    this.msg = solved ? TG('🎉 六关全过，通关！') : TG2("💤 命用完了 —— 撑到第 {0} 关", ...);
324:      Text(this.msg)     // ← HUD 读的就是它
```

**为什么是 bug**：
`TG2(...)` 是纯函数，第 74 行等于把算好的句子扔进废纸篓。而 `reset()`（L62-67）**不碰 `msg`**，
所以 `msg` 只有三种来源：`step()` 播完（L83）、踩错（L234）、结束（L249）。

| 场景 | 玩家实际看到的 HUD |
|---|---|
| 第一次进游戏 | `msg` 还是声明时的 `''` ⇒ **整段播放期没有任何提示** |
| 通关/命用完后再开一局 | 上一局的 **「💤 命用完了 —— 撑到第 N 关」/「🎉 六关全过」** 一直挂到播放结束（`len × STEP_MS`） |

播放期正是新玩家最需要「看好机器人做 N 个动作」这句话的时候 —— 它是**唯一的玩法引导**。

**修法**：`this.msg = TG2('看好机器人做 {0} 个动作…', this.len());`
（顺手在 `reset()` 里补 `this.msg = ''` 兜底。）

> 这类「纯函数调用当语句」正是 2026-11-06 在 `GTracePath` 清过的那一类（commit `8f897975`）。
> 全仓再扫一遍后**只剩这一处**，但它不是多余的，是**本该赋值**。

## 3. 模板级死代码（当前不可见，但是所有 355 款的共同祖宗）

### S-03 【中】26 款的 `autoStep` 第二个 `if` 永不执行 —— 判据与第一个完全相同

**共性片段**（26 款一字不差，取 `GBinomialMatch.ets:208-214`）：

```ts
private autoStep(): boolean {
  if (this.over) { return false; }   // ① 终局 ⇒ 收工
  if (this.over) { return true; }    // ② ← 恒假，永远走不到
  this.aiPair(0);                    // ③ 真正的动作
  return !this.over;
}
```

同一位置的两种变体（同一模板槽位）：

| 变体 | 写法 | 数量 |
|---|---|---|
| A | 第二个 `if` 复制了第一个条件（`this.over`） | **26 款** |
| B | 第二个 `if` 直接写 `if (false) { return true; }` | **5 款** |

B 的 5 款：`GDualMirror:240`、`GEtymonOddball:203`、`GHomophoneHunt:197`、`GPrimeHunter:198`、`GWordSearch:200`。

**为什么是 bug**：
`GOrbitTap.ets:194-196` 里那个分支**还留着原始注释**，直接说明了模板本意：

```ts
if (this.over) { return false; }
if (this.over) {
  return true;              // 还没到能作答的时刻 / 已经答过，等推进
}
```

即槽位 ② 原本要判的是**「已作答、等游戏推进」**（返回 `true` = 保持代打在跑，但这一拍不动手）。
条件被复制成 `this.over` 以后，这个「让位」逻辑整条消失 ⇒ 在过渡窗口里 AI 会**立刻继续动作**。

**当前危害：没有可复现故障**。我把 26 款的 `autoStep` 动作函数逐个读了
（`aiPair/aiGo/tap/answer/pick/choose/press/step/...`），**没有一款在动作里加动画锁或节流**
（26 款里带「等待/锁」味道的 `@State` 只有 `demoPhase`（演示用）和 `flash`（提示文案，`GQuickMath`），
都不是作答锁；抽读 `GPatternSequenceDraw.tap` / `GTetris.aiPlay` / `GSdmt.keyTap` 也确认只有终局守卫），
答完立刻换下一题，所以「下一拍继续动作」等价于正常代打。
**风险在将来**：任何一款给动作补上「动画未完成时忽略」的守卫，这里就会变成「AI 空转 / 画面与判定不同步」。

**修法**（二选一）：
- 有过渡态的游戏：把 ② 换成真实条件，例如 `if (this.answered) { return true; }`；
- 没有过渡态的游戏：**直接删掉 ② 这段死代码**，别留着误导下一个读代码的人。

> 26 款全名单见 §7 附录。

### S-04 【低】8 处 `if (false)`：双布局的惰性占位（**故意**，但建议换成注释或删除）

| 文件:行 | 被关掉的动作 | 同文件的「启用」对照 |
|---|---|---|
| `GMancala.ets:617,620` | 对手那一行的 `playerMove(i)` | `:650,654` 用 `if (true)` 的是自己那一行 |
| `GPixelMimic.ets:314,320` | 目标图的 `paint(...)` | `:338,344` 用 `if (true)` 的是可涂格 |
| `GRoomInspector.ets:331,337` | 目标图的 `tap(...)` | `:355,361` 用 `if (true)` 的是可点格 |
| `GDoubleNBack.ets:329,331` | `selPos` 分支（只保留 `selLetter`） | `:318,320` 用 `if (true)` |

**结论**：这 8 处都是**同一段模板生成两遍、其中一遍故意不生效**，
`.backgroundColor(false && ...)`、`.fontColor(false ? A : B)` 也是同一批产物 ——
**不是 bug，游戏可正常玩**。
**建议**：这类「关掉的交互」用注释说明比 `if (false)` 好，否则每次静态扫描都要人肉重新判定一次
（本次就是 13 条里 8 条靠这个规则排除的）。

## 4. 防御缺失（现在踩不到，改了题库就会踩）

### S-05 【低】4 款直接下标 `opts[0..3]`，没有长度守卫

```ts
// GCountingSheep.ets:342 / 374
Button(String((this.opts[0])))      ...   Button(String((this.opts[3])))
.onClick(() => { Haptics.tap(); this.pick((this.opts[3])); })
```

同批还有 `GComplexFoldingNets`（`Button(TG2('{0} 层', this.opts[0..3]))`）、
`GCrossSectionSlice`、`GDistractorMatrix`（L340-381 四个按钮裸下标）。

**为什么不判成真 bug**：我逐个回读了选项生成器，**目前都保证 4 个**：

| 文件 | 生成方式 | 下界证明 |
|---|---|---|
| `GCountingSheep.ets:241-249` | `while (set.length < 4)` 双向补数 | 只有 `ans+d > CELLS*2` 时少补，但 `b=ans-d` 会补进来 |
| `GComplexFoldingNets.ets:117-123` | `while (set.length < 4)`，`a<=16 / b>=1` | ans∈[1,16] ⇒ 两侧都能补 |
| `GCrossSectionSlice.ets:83-87` | `cand` 10 个候选取 4 | 候选互异 ⇒ 必满 4 |
| `GDistractorMatrix.ets:45-51` | `cand` 7 个候选取 4 | 同上 |

**风险**：一旦有人改题库（少给一个候选 / 难度档缩小取值范围），
`opts[3]` 会变 `undefined` ⇒ 按钮渲染成 **「undefined」**，点它等于 `pick(undefined)`。
同仓的 `GContextClues`/`GDefinitionDash`/`GCryptogramAll` 就是**带守卫**的写法（`this.opts.length > 2 ? ... : ''`），
可直接照抄。

**修法**：渲染前先算 `const has3: boolean = this.opts.length > 3;`，`has3` 为假就隐藏第 4 个按钮。

## 6. 扫描方法与误报说明

**解析**：先把注释与字符串**等长掩码**（保留换行/偏移）→ 正则找函数签名 → 花括号配对取函数体；
所有「条件比较」「重复语句」判定都在**原始文本**上复核一遍（掩码会让 `c.op === '+'` 与 `c.op === '-'` 看起来一样）。

**各检测器与降噪规则**：

| 检测器 | 关键判据 | 本轮误报与排除原因 |
|---|---|---|
| 空实现 | 函数体只剩 `return 常量`；`autoStep` 无任何 `this.xxx(`；`computeHint` 无 `Hint.make`；`stopAuto` 无 `Hint.autoStop` | 0 条 —— 说明前夜那批真修完了 |
| 状态未重置 | `@State` 字段「结算侧写过、开局侧（reset/aboutToAppear/onRestart + 3 层调用展开）从没写过」 | 177 → 26：`scorePulse` 一类 140ms 自愈动画、`picked/ans` 一类在 `ask()/next()` 里每回合重置，均排除 |
| 越界 | `split()[N]`、`opts[N]`、随机下标、`[arr.length]`；`-1` 哨兵下标看前 6 行有无 `>= 0` 守卫 | `opts[N]` 4 款确认生成器保底 4 个；`-1` 哨兵 29 处逐点读过 |
| 恒假/死分支 | `if (false/0)`；同函数内**同深度、紧邻（两块之间只有空白）**的两个**文本完全相同**的 `if`，且第一块必 `return/break` | 34 → 26：`build` 里多个 `.onKeyEvent` 各自守卫、`latinOk` 行/列双趟、`.then`/`.catch` 各查一次 `gen`，全部排除 |
| 重复调用 | 同一行按顶层 `;` 切语句，**相邻**两条文本完全相同且以 `this.`/`TG2`/`Haptics` 开头 | 162 条 TV 双路径同调排除后为 0 |
| 额外（裸调用语句） | 函数体里整条语句只有 `TG/TG2/String/Digits/fmt(...)`，无赋值无返回 | 1 条 → **S-01**（本轮唯一真 bug） |

**没覆盖的**（明确说清，免得当成「零 bug」）：运行时行为、并发/定时器竞态、
`@State` 读写时序、i18n 文案长度溢出、真机渲染差异 —— 这些静态扫不出来，仍需真机/截图或断言脚本。
