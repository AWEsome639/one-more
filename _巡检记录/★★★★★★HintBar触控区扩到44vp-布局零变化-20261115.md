# ★★★★★★ `HintBar` 触控区扩到 `44vp` —— **布局零变化**（`355` 款共用）

## 一、⇒ 问题（今天唯一涉及全库的缺陷）

**`HintBar.ets` `L40`：`barHeight: number = 38;` ⇒ `355` 款的 `提示` / `AI 代打` 两个按钮只有 `38vp`，
**低于 `44vp` 触控下限**。**

**⚠️ 而作者在 `L7-10` 已明确记录过为什么不改高度：**
> 「⛔ 2026-11-09 试过「矮屏降到 32vp」，**已回退**：真机三款测下来是「一好两坏」
>  （`Sokoban 1430→1351` 好、`FreeCell 1351→1381` 略差、`Tetris 1564→1600` 差），

**⇒ 所以「改高度」这条路被作者用实测否掉了（每款会少 `18px`，且效果混合）。**

## 二、⇒ 我的解法：只扩触控区，不改高度

```typescript
.height(this.barHeight)                                  // 视觉仍是 38vp
.responseRegion({ x: 0, y: -3, width: '100%', height: 44 })   // 可点区 44vp
```

**⇒ `responseRegion` 只改**命中测试区域**：向上、下各扩 `3vp` ⇒ 触控高度 `38 + 6 = 44vp`，
**视觉高度、布局占位、相邻元素位置全部不变。** ⇒ **从原理上就不可能引起「一好两坏」那种混合效果。**

## ⇒ 判据（`2738`）

**想让「低于触控下限的按钮」变好用，**优先扩 `responseRegion` 而不是加 `.height()`**：**
**⇒ 前者只改命中测试，布局毫发不动 ⇒ 零回归风险；后者会挤占内容，且在共享组件上会引起混合效果。**

**⚠️ 注意：`responseRegion` 的扩展会**覆盖相邻元素**的触控区 ⇒ 上下各扩 `3vp` 是安全的，
   但如果元素间距小于 `6vp`，扩出去会抢邻居的点击，**必须核对相邻间距**。**
