# ★ 预测：那 `12` 款改动后**仍会 `blk≈24px`** —— 而那是「正好占满」的必然结果

## 一、怎么算出来的（用今晚新确认的头部 `104vp`）

**对全库 `26` 款「`floor` 吃掉封顶」的款，用各自实测 `max` 反推底部：**
```
底部 = max/3 − 104 − 盘面     （盘面 = max(floor, 533−X)）
总高 = 盘面 + 底部 + 104
```

| 总高 | 款数 | 含义 |
|---|---:|---|
| **`= 533`（正好占满）** | **`12`** | `2048` / `Crown` / `Gokigen Naname` / `Gomoku` / `Heyawake` / `Hitori` / `Matrix Reasoning` / `Memory` / `Path Intersect` / `Pipes`? / `Shikaku` / `Skyscrapers` / `Number Bonds All` |
| `500~521`（接近）| `5` | `TennerGrid` / `Futoshiki` / `Sum Pyramid` / `Modulo Path` / `Hitori All` |
| `< 500`（还有空间）| `9` | `MathMaze` / `NoriNori` / `Dominosa` / `Schulte` / `Sudoku` / `Countdown Math` / `Minesweeper` / `Tents And Trees` |

**⇒ **`0` 款推算会溢出**（都 ≤ `533`）。**

## 二、而「正好占满」意味着**`blk` 不会是 `0`**

**`blk` 的定义是「根内容列的直接子块里 `y2 > 1516 + 60 = 1576` 的块数与越界量」。**
**⇒ 内容占满到 `1600px` ⇒ 最底那块的 `y2 = 1600` ⇒ **`1600 − 1576 = 24px`** ⇒ **`blk = 24`**。**

**⇒ 而那 `12` 款**改动前**的 `blk` 是 `48~72px`（盘面 `813vp` 时严重超出）。**
**⇒ 改动后盘面 `240vp` ⇒ 总高正好 `533` ⇒ **`blk` 应该落到 `≈24px`，不会到 `0`。****

## 三、所以今晚会看到什么（**预注册，免得明早误判**）

| 今晚 `blk` | 含义 | 明天怎么做 |

## 四、这条预测的价值

**⇒ 明早如果看到那 `12` 款 `blk=24`，我不会误判成「改动失败」——**
**⇒ 而会知道「改动成功，只差 `8vp` 的微调」。**

**⇒ 而如果我不知道这条，很可能的反应是「怎么还是溢出？限宽这招是不是没用？」**
**⇒ 然后去改错方向（比如继续降 floor 到 `140` ⇒ 那是**过度收缩**，白丢 `67vp`）。**

## 五、判据 `2020`

> **「改动后仍有小量溢出」有两种原因：改动没生效，或**目标本身就是正好占满**。**
> **⇒ 前者的修法是查装包；后者的修法是微调几个 vp。把两者混淆会让我改错方向。**

**⇒ 所以改之前就要算好「改动后应该看到什么数」—— 这叫预注册预期。**
