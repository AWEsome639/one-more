# 判据 `3114`：**`constraintSize.maxHeight` 对「宽度驱动」的元素只裁不缩 —— 改它的数字等于没改**

## 一、缺陷

`Ghost_Tap`（幽灵点击）竖屏：底部「重开」按钮被切一点点。

```
台账：blk=1/24px   blkh=118px   lowest='重开' [62,2378][2162,2496]
```
⇒ 完整按钮应 ≈ `137px` ⇒ **缺 `19px` ≈ `6.1vp`**（判据 `3105` 的量块高法）。

## 二、第一次尝试（无效）

`GGhostTap.ets:338` 是 `- 360` 家族，我改成 `Bp.isShort() ? 360 : 378`：

```
改后实测：blk=1/24px   blkh=118px   lowest='重开' [62,2378][2162,2496]   ← 一字未动
```

**为什么无效**：`:335` 是 `.width('100%').aspectRatio(1)` ⇒ **宽度驱动高度**；
而 `maxHeight` 只能「裁」不能「缩」—— 这一点本文件 `:337` 的注释**自己就写着**
（「宽驱动 aspectRatio 无上限 ⇒ 限高让 aspectRatio 反推宽度」是期望，实际是裁）。

## 三、正解：给**显式宽度**

```diff
-      }.width('100%').aspectRatio(1).padding(Space.sm)
+      }.width(Bp.isShort() ? '100%' : Math.min(Bp.width, Math.max(200, Bp.height - 376)))
+      .aspectRatio(1).padding(Space.sm)
```

⇒ `798.7 − 376 = 422.7` ⇒ 高度自然也是 `422.7`（原来被裁成 `438.7`）⇒ 少 `16vp` ⇒ 按钮完整。

### 验收

| | 改前 | 改后 |
|---|---|---|
| `blk` | `1/24px` | **`0/0px`** |
| `blkh` | `118px` | `0`（无越界块）|
| `lowest` 底 | `2496`（屏沿）| **`2471`**（离屏沿 `25px`）|

## 四、判据

> **对 `aspectRatio(1)` 的元素，限高必须从**宽度**下手；给它 `maxHeight` 只会把它裁掉一截。**

⇒ 五条：
1. **`.width('100%') + .aspectRatio(1)` ⇒ 高度完全由宽度决定**，`maxHeight` 无法缩它，只能裁
2. **要缩就改 `.width()` 那一处**（显式宽度），这是唯一有效的位置
3. **判断「有没有生效」必须看数字**：我改完 `maxHeight` 后 `blkh` 一字未动，
   如果只看「构建成功」就会以为修好了
4. **`blkh` 缺口换算**：`(137 − blkh) / 3.125` vp 就是实际缺的高度（这里 `19/3.125 ≈ 6.1vp`）
5. **同一份文件里的注释可能描述的是「作者的期望」而不是「实际行为」** ——
   `:337` 写「限高让 aspectRatio 反推宽度」，实测是「裁」，**注释不能当规格**（同判据 `2146` 的镜像）
