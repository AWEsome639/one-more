# 第六个筛查维度：**结算弹层** —— 共用组件，验一款覆盖全库

> `2026-11-18 08:27`。**之前五个维度全在「游戏进行中」量的，从没量过「通关后」那一层。**

## 一、⇒ 为什么这层值得量

**⇒ 结算弹层上有三个按钮：`下一款` / `再来一局` / `返回列表`。**
**⇒ 如果它溢出或被切，玩家**打完一局就点不到重开** —— 这比玩到一半被切更伤（那局白打）。**

## 二、⇒ 怎么到结算态（方法，以前没记录过）

**⇒ **点 `AI 代打` 按钮**（`HintBar` 上，文字会变成 `停代打`）⇒ 游戏自己下完。**
**⇒ `Simon Says` 实测：点下去后 `3/12 → 12/12` 约 `70` 秒打完、得分 `660`；再多等 `5` 秒就出结算层。**
**⇒ 注意：`演示中 | 看这里` 那个 demo **不会自己走完**（它显示 `你来` 等你操作）⇒ 必须点 `AI 代打`。**

## 四、⇒ 为什么「一款代表全库」是成立的

**⇒ `grep -rln "下一款" entry/src/main/ets/games/` ⇒ **零命中**（`0` 款自己画结算）。**
**⇒ 结算层在 `entry/src/main/ets/pages/GameHost.ets`（共用宿主）⇒ **`355` 款共用同一份布局**。**
**⇒ 所以这一维度的结论是：**共用组件一次验证通过 ⇒ 全库通过**（前提：各款只是填不同数据，不换布局）。**

## ⇒ 判据 `2894`

**⇒ 判断一个维度能否「抽一款代表全库」，先 `grep` 这个 UI 是谁画的：**
- **共用组件（`GameHost.ets` / `HintBar` / 结算层）⇒ 抽一款即可；**
- **每款自己画的（棋盘、按钮行、选项列表）⇒ 必须逐款看。**

**⇒ 今晚六个维度里，前五个（位置/`blk`/高度/缩水/极小）都是**逐款**的，第六个（结算层）是**共用的** —— 这就是为什么它只需要一次。**
