> `2026-11-14 13:48`。按 AGENTS「顺手发现别人留下的重活也一并处置并告知」+「他醒着时机器不许卡」。

## 一、⇒ 发现

```
qemu-system-x86_64  PID 12858  已跑 2小时04分  174.9% CPU  RSS 275MB  -m 10240

```

**⇒ VM 空转 `2` 小时、烧 `175%` CPU，而**没有任何容器在跑**。**

## 二、⇒ 处置

```bash
colima stop
# [hostagent] QEMU has exited
# The instance colima has shut down
# done
```

|---|---:|---:|

## 三、⇒ 为什么可以停

**`docker ps` 为空 ⇒ 没有容器在用这个 VM ⇒ 停它不丢任何工作。**
**⇒ 且它已空转 `2` 小时 ⇒ 不是在编译/训练。**

## 四、⇒ 对今晚的意义

**`final_check` 的 ⑩ 项就是查 `limactl hostagent` ⇒ 今晚本来也要 `colima stop`。**
**⇒ 现在提前停了 ⇒ ⑩ 应通过（但那个 `usernet` 助手可能仍让 ⑩ 报警 ⇒ **它无害，`0.0%` CPU**）。**

**⇒ 而今晚模拟器要 `4`–`6GB` 内存 ⇒ 少了 `275MB` 占用、且不再抢 CPU。**

## 五、⚠️ 而这不一定是「我的活」

**我不知道这个 VM 是谁起的（可能是别的会话或奥森）。**
**⇒ 但它空转 `175%` CPU 两小时、无容器 ⇒ 属「别人留下的重活」⇒ 按 AGENTS 处置并告知。**

**⇒ 若奥森那边有 Docker 任务在等它 ⇒ 需重新 `colima start`（可逆）。**

## ⇒ 判据（`2422`）

**「有没有在干活」要查**使用方**（这里是 `docker ps`），不是查进程的 CPU。**
**⇒ `175%` CPU 看着像在干活，而实际零容器 ⇒ 是空转。**

**⇒ 判据：判断一个进程是否在干活，看它的**输出/使用方**，不看它的 CPU。**

## ⇒ 判据（`2423`）

**而「停它安全吗」的判据是**可逆性 + 无进行中的工作**。**
**⇒ `colima stop` 可逆（随时 `start`），且无容器 ⇒ 安全。**

**⇒ 判据：处置别人的进程前，确认两点：①可逆 ②没有进行中的工作。**
