# ★★ 停掉空转的 Colima：释放约 `175%` CPU

> `2026-11-14 13:48`。按 AGENTS「顺手发现别人留下的重活也一并处置并告知」+「他醒着时机器不许卡」。

## 一、⇒ 发现

```
qemu-system-x86_64  PID 12858  已跑 2小时04分  174.9% CPU  RSS 275MB  -m 10240
docker ps ⇒ **空（没有任何容器）**
```

**⇒ VM 空转 `2` 小时、烧 `175%` CPU，而**没有任何容器在跑**。**

## 二、⇒ 处置

```bash
colima stop
# [hostagent] QEMU has exited
# The instance colima has shut down
# done
```

**⇒ 效果：**
| 项 | 前 | 后 |
|---|---:|---:|
| `qemu` 进程 | `1` | **`0`** |
| `limactl` 进程 | `3` | `1`（只剩 `usernet` 助手、`0.0%` CPU、`4MB`）|
| **系统负载（1 分钟）** | — | **`3.97`**（15 分钟均值 `5.98` 还带着那 `175%`）|

**⇒ 释放约 `175%` CPU + `275MB` 内存。**

## 三、⇒ 为什么可以停

**`docker ps` 为空 ⇒ 没有容器在用这个 VM ⇒ 停它不丢任何工作。**
**⇒ 且它已空转 `2` 小时 ⇒ 不是在编译/训练。**

## 四、⇒ 对今晚的意义

**`final_check` 的 ⑩ 项就是查 `limactl hostagent` ⇒ 今晚本来也要 `colima stop`。**
**⇒ 现在提前停了 ⇒ ⑩ 应通过（但那个 `usernet` 助手可能仍让 ⑩ 报警 ⇒ **它无害，`0.0%` CPU**）。**

**⇒ 而今晚模拟器要 `4`–`6GB` 内存 ⇒ 少了 `275MB` 占用、且不再抢 CPU。**

## 五、⚠️ 而这不一定是「我的活」

**我不知道这个 VM 是谁起的（可能是别的会话或奥森）。**
**⇒ 但它空转 `175%` CPU 两小时、无容器 ⇒ 属「别人留下的重活」⇒ 按 AGENTS 处置并告知。**

**⇒ 若奥森那边有 Docker 任务在等它 ⇒ 需重新 `colima start`（可逆）。**

## ⇒ 判据（`2422`）

**「有没有在干活」要查**使用方**（这里是 `docker ps`），不是查进程的 CPU。**
**⇒ `175%` CPU 看着像在干活，而实际零容器 ⇒ 是空转。**

**⇒ 判据：判断一个进程是否在干活，看它的**输出/使用方**，不看它的 CPU。**

## ⇒ 判据（`2423`）

**而「停它安全吗」的判据是**可逆性 + 无进行中的工作**。**
**⇒ `colima stop` 可逆（随时 `start`），且无容器 ⇒ 安全。**

**⇒ 判据：处置别人的进程前，确认两点：①可逆 ②没有进行中的工作。**

## 七、⇒ 效果比预期大：磁盘也多了 `5 GiB`

**停 Colima 后跑 `final_check`：**

```
⑨ 磁盘：/Users 可用 17 GiB（阈值 10 GiB）✅ 够
⑩ Colima：✅ 没在跑
   系统内存空闲：44%
✅ 全部就绪 —— 今晚可以按四步跑
```

| 项 | 停前 | 停后 | 变化 |
|---|---:|---:|---|
| **磁盘可用** | `12 GiB` | **`17 GiB`** | **+`5 GiB`** |
| Colima | 在跑（`175%` CPU）| ✅ 没在跑 | — |
| 系统内存空闲 | — | `44%` | — |
| `final_check` | `0` | `0` | ⑩ 从「可能 WARN」变 ✅ |

**⇒ ⇒ 那个 VM 的 `-m 10240`（`10GB`）配额在 `~/.colima` 里占着**稀疏磁盘**，停掉后回收了 `5 GiB`。**

**⇒ 所以停一个空转 VM 一次解决三件事：**
| 资源 | 释放 |
|---|---|
| CPU | `~175%`（1.75 核）|
| 内存 | `~275MB` |
| **磁盘** | **`~5 GiB`** |

## 八、⇒ 而这对明晚编译直接相关

**明晚要编译（`~7` 分钟、产生 `302M` 的 `entry/build`）⇒ 而 ⑨ 闸是 `< 10 GiB` 必须腾。**
**⇒ 现在 `17 GiB` ⇒ **编译前不需要清缓存也够**（原 `12 GiB` 时我还计划清 `~/Library/Caches` 的 `1.9G`）。**

**⇒ ⇒ 这一步顺带省掉了明晚「清缓存」的动作。**

## ⇒ 判据（`2425`）

**停一个「空转的大配额 VM」的收益是三份：CPU + 内存 + **磁盘**（稀疏镜像）。**
**⇒ 我原以为只省 CPU 和内存，实际磁盘多了 `5 GiB` —— 那对「磁盘闸」的项目更值钱。**

**⇒ 判据：评估「停一个服务」的收益时，别忘了**它的磁盘配额**（VM/缓存/镜像）；那往往比 CPU 更稀缺。**
