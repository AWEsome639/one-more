# `maxHeight` 百分比 → 定值：**`5/5` 实测通过**

## 改动（`ai-fixer-a` 给的清单）

**全库 `maxHeight` 百分比 `11` 处**（`ai-fixer-a` 逐个核过）：

| 原值 | 处数 | 处置 |
|---|---:|---|
| `'70%'` | `9` | → `Math.max(140, Bp.height - 360)`（**改 `8` 处**，`GMazeNav3d` 今晚已单独修）|
| `'100%'` | `1` | `GBreakout` → 定值 |
| `'50%'` | `1` | `GPegSolitaire` **安全，未动**（`267vp` < `343` 预算）|
| `minHeight: '100%'` | `7` | **良性，未动**（语义是「至少撑满父容器」，不会长高）|

## 为什么必须换

**`ai-fixer-a` 从 `GReversi` 的注释里找到了硬证据**：
> `45% × 1280 屏 = 576vp` —— **百分比底座 = 窗口高，不是游戏区**

**⇒ 横屏（`533`）时**：`'70%'` = `373vp`（预算 `343`，**超 `30`**）、`'100%'` = `533vp`（**超 `190`**）。
**⇒ 一个百分比不可能同时满足「竖屏 `853`」和「横屏 `533`」两种比例** —— 这个坑 `GReversi` 注释里已经踩过 3 次。

```
grep -rn "maxHeight: '[0-9]*%'" entry/src/main/ets/games/   # 必须为空
```
**白名单**：`minHeight: '100%'`（良性）。
