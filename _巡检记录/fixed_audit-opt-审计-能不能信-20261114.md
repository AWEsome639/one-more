## 1. `--opt` 的实际逻辑（伪代码级，逐行核过）

```python
# 1) 取数：按游戏名，取「最后一个同时满足 board= 且第4列是数字」的行（最后一个 = 文件顺序最后）
for 每行:
    m = r'board=(\d+)x(\d+)@'      # ★ 只认「WxH@」，@ 后面的 x,y 完全不解析
    if m and 第4列.isdigit():
        last[游戏名] = (H_px/3, 第4列/3, ts)   # ← board 高(vp), max_bottom(vp)

# 2) 逐款算（HEADER_VP = 104）
底部     = max_bottom − 104 − board_h        # ← 可能为负（见 §4 B1）
盘面上限 = 533 − 104 − 底部
留余量   = 盘面上限 − margin(默认30)
现在总高 = board_h + 底部 + 104

# 3) 裁决
if 现在总高 > 533.5:  '⚠️ 现在溢出 N ⇒ 缩到 留余量'
elif 盘面上限 − board_h > 15:  '可放大 +N ⇒ 放大到 盘面上限'
else:  '· 正好 ⇒ 不动'
```

**关键代数（自己推一遍，决定后面对不对）**：

| 量 | 展开后 | 说明 |
|---|---|---|
| `现在总高` | `= max_bottom` | **恒等于 max_bottom** ⇒ 「溢出」等价于 `max_bottom > 533.5` |
| `盘面上限 − board_h` | `= 533 − max_bottom` | **与 board 无关** ⇒ 「可放大」只看「离屏底还有多少」 |
| `盘面上限` | `= board_h + (533 − max_bottom)` | 放大值 = 现有盘面 + 余量 |
| `HEADER_VP` | **约掉** | 104 只影响打印出来的「底部」列；**裁决与 cap 都对头部高度不敏感** ✓ |

⇒ **你记的阈值是对的**：溢出判 `>533.5`；放大判 `cap−board > 15`（等价于 `533−max_bottom > 15`）。

# ⛔ 更正（`2026-11-14 12:5x`）：B1 的**前提是错的**

## 真相

`shot_game.py:705-727`（判据 `1925`，`2026-11-11` 就改好了）：

```python
def _max_y2(n, acc):
    # ⚠️ 只数「叶子节点」——整树最大 y2 会被根容器(height 100%)钉死在屏幕底
    if isinstance(n, dict):
        kids = n.get('children') or []
        if not kids:                       # ← 叶子节点，**不分有字没字**
            ... nums[3] > acc ...
mb = _max_y2(d2, 0)                        # ← 台账第 4 列 = 这个
```

**⇒ `max_bottom` = 「整棵树所有**叶子节点**的最大 `y2`」，**不是只有文字的节点**。
只有 `lowest=` 那个字段是「文字节点里最深」。**

**`L134` 的 `texts()` 确实只取有字的节点，但 `mb` 不走它** —— `texts()` 用于 `lowest` 取值、
`WRONG_GAME` 标题核验、`is_home()` 判断。

## 因此 B1 的哪部分作废

| B1 的三条 | 现在 |
|---|---|
| ① `底部 = max(0, 底部)` | ✅ **仍要**（见下）|
| ② `盘面上限 = min(533 − 104, …)` | ✅ **仍要** |
| ③ 另发 `maxall=`（所有节点最大 y2） | ⛔ **作废** —— `_max_y2` 就是它 |
| 「盘面底部没文字 ⇒ `max_bottom` 小于盘面底」这条因果 | 🔴 **错**（叶子不分有字没字）|

## 为什么 ①② 仍然要

**不是因为「只量文字」，而是因为「叶子可能没铺满盘面」：**
```
盘面 bh = 400vp（一个很高的方阵，封顶没生效）
叶子最大 mx = 350vp（内容只画到 350，盘面自己撑到 400 但叶子 bounds 没超）
⇒ 底部 = 350 − 104 − 400 = −154vp ⇒ 盘面上限 = 533 − 104 − (−154) = 583 ⇒ 荒谬
⇒ 钳到 0 后 = 429 ✅
```
**⇒ 这个场景真实存在**（判据 `1925` 自己记的 `Masyu` 首帧 `732` vs 正常 `1586`，就是「叶子没铺满」）。

**⚠️ 但原审计给的「配对前后证据」（`bd=100vp / mx=66.7vp`）用的是**现实中不可能**的组合
（全树叶子最大不可能小于头部 `104vp`）⇒ 那条证据作废，改用上面的 `400/350` 场景。
