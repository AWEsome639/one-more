# 端侧 LLM 的「模型半边」：路线清楚、但必须 Linux

> `2026-11-17 09:14`。**分词半边已真机 `16/16`（见昨晚那条）；模型半边今天查清了。**

## 一、⇒ 三条路，逐条排除

| 路 | 结论 |
|---|---|
| **官方有现成 `.ms`** | ⛔ `tools.mindspore.cn` 的 Qwen2-0.5B-Instruct 目录只有 `model.safetensors`(942MB) / `vocab.json` / `merges.txt`，**没有 `.ms`** |
| **别人转好的 `.ms`** | ⛔ `gitcode.com/Tlntin/qwen_ms_llm` 明写「这里我提供一个转换好的 qwen2-0.5b-instruct 的 ms 文件。链接：**待上传**」 |
| **自己转** | ✅ 可行，但**必须 Linux**（见下） |

## 二、⇒ 为什么必须 Linux

**⇒ 官方 `2.11.0` 下载页只有四种包：`Linux-x86_64`、`Linux-aarch64`、`Windows-x86_64`、`Android-aarch64`。**
**⇒ **没有 macOS** —— 与我此前的结论一致（不是我没找到，是确实没有）。**

## 三、⇒ 配方（别人验证过的，照抄即可）

**⇒ 来源：`github.com/Tlntin/qwen-mindspore-lite-llm`（用 MindSpore-Lite 在鸿蒙上跑 Qwen2）+ `gitcode.com/Tlntin/qwen_ms_llm`（仓颉版，同样结构）。**

**⇒ 关键点：**
1. **鸿蒙上的 `mindspore-lite` **必须是 2.1.0**（项目作者实测）**
2. **手机上的 lite 只支持 **NCHW** 格式（数据格式要从 ND 换）**
3. **转换链：HF 权重 → ONNX → MindIR → `.ms`**
4. **Python 只有 3.7（2.1.0 的 lite 转换器）可用 ⇒ 作者建议用 conda 3.9 + lite 2.1.1 做验证**

**⇒ 环境（Linux x86_64）：**
```bash
wget https://ms-release.obs.cn-north-4.myhuaweicloud.com/2.1.0/MindSpore/lite/release/linux/x86_64/cloud_fusion/python37/mindspore-lite-2.1.0-linux-x64.tar.gz
export LITE_HOME=/usr/local/mindspore-lite
export PATH=$PATH:${LITE_HOME}/tools/converter/converter:${LITE_HOME}/tools/benchmark
```

## 四、⇒ 代价与风险（必须先说清）

| 项 | 值/风险 |
|---|---|
| 钱 | AutoDL CPU 机约 **¥1–3/小时**；转一次估 **1–3 小时** ⇒ **¥5 上下** |
| 传输 | 上传 `942MB` 权重 + 下载 `~1GB` `.ms` |
| **⚠️ 最大风险** | **模拟器内存**：0.5B 模型 `.ms` 约 `300MB–1GB`，而 `onemore7` 是手机镜像 ⇒ **很可能 OOM**。真机（`onemore_fold` 的 X5 镜像）同样不确定 |
| 备选 | 若 OOM：换 0.3B/更小模型，或只做「分词 + 推理接口」的骨架、把权重留给真机下载 |

## 五、⇒ 我的建议排法

**⇒ 不值得现在开：**上下文与时间都紧，而这条路的**最大不确定性是模拟器内存**，不是转换本身。**
**⇒ 更稳的顺序：**
1. **先量模拟器可用内存**（`hdc shell cat /proc/meminfo`）⇒ 决定「0.5B 有没有可能跑」
2. **若内存够** ⇒ 租机转 `.ms`（一次性，¥5 内）
3. **若内存不够** ⇒ 这条线改成「真机首启下载 + 小模型」的方案，或等真机

**⇒ 判据 `2846`：**先量约束，再买资源。**—— 转模型要花时间和几块钱，而「转了跑不起来」是白花；先看 `/proc/meminfo` 是最便宜的判断。
