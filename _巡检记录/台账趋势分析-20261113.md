## 1. 判定规则（脚本里实现的就是这张表）

| 条件 | 判定 | 依据 |
|---|---|---|
| `lowest` 相同 + `max_bottom` 变小 | **真改善** | 同一节点下界上移 = 实打实让出空间 |
| `lowest` 相同 + `max_bottom` 变大 | **变差** | 同一节点下界下移 |
| `lowest` 相同 + 不变 | **无变化** | — |
| `lowest` 不同 + 新 `lowest` 是**内容文字**（非纯数字） | **可能改善（内容进屏了）** | 判据 1973：原本被裁的内容现在量到了 |
| `lowest` 不同 + 新 `lowest` 仍是**数字读数** + `max_bottom` 变大 | **待人工确认** | 可能只是「换了个数字节点」 |
| `lowest` 不同 + `max_bottom` 变小/不变 | **待人工确认** | 换了节点，需确认新节点是谁 |

**「内容文字」的判据**：`lowest` 里除了数字/分隔符之外还有别的字符 ⇒ 内容（`提示` / `选一个释义` / `B` / `⌫` / `目标数 = 左半 + 右半…`）；纯数字读数（`121` / `8/21` / `0/40` / `60928`）不算。

## 5. 关键发现与局限

### ① 判据 1973 被台账**直接证实**（两倍独立证据）

- **`Wordle`**：17 次 OK，`max_bottom` 一直是 **1600**，但 `lowest` 依次是 `5`（12 次）→ `Q` → `A` → `Z`（3 次）⇒ **节点在换，数字没变**。
- **`Base Shift` / `Fraction Matcher`**：`±18~20px` 的波动出现在**同一款、同一操作**下，且每次 `lowest` 都不同 ⇒ `max_bottom` 的**噪声底噪约 ±20px（≈7vp）**；以后判「是否回归」**至少要同节点 + 超过 20px 才算数**。

### ② 只看「相邻两次」会漏掉更早的改善

`Object Displacement` 就是反例：1576 → 1486（**同节点**、−90px）是真改善，但它不在最后两次里，所以主表判成「无变化」。脚本为此在 `--history` 里加了「**首→末**」一行兜底；若要专门抓这类，可以跑 `--history` 看每一对（每行都标了「同节点/换节点 + Δ」）。

### ③ 样本太薄的现实

- 55 款里 **41 款只有 0~1 次有效测量**（大量 `NOT_HOME`：58 次里 45% 没进到游戏页）⇒ **趋势判定基本无法成立**。
- 建议扫描器把 `NOT_HOME` 的行也记上"卡在哪一步"（现在是 `could not reach home` 一句话），否则台账一半的行产不出信息。

### ④ 建议（给尺子）

`lowest` 现在只有**文本**。同文本可能来自不同节点（例如两处 `提示`），不同文本也可能是同一节点（动态计分）。要真正判定"同一个节点"，建议扫描时连 **bounds（x1,y1,x2,y2）** 或 **控件 id** 一起记：`lowest='提示' bounds=[120,1320][900,1380]` ⇒ 判据就能从"文本相同"升级成"节点相同"。
