# 判据 `3080`：**浏览器视口 `0×0` ⇒ 一切点击/填表失效，但 JS 与 AX 树仍正常**

## 一、现象（一条命令就能测出来）

```javascript
innerWidth, innerHeight        // 0, 0
outerWidth, outerHeight        // 0, 0
document.body.clientWidth      // 0
document.documentElement.clientWidth  // 0
screen.width, screen.height    // 1408, 881   ← 屏幕正常
```

⇒ 而 `browser_execute`（跑 JS）**正常**、`browser_snapshot`（AX 树）**正常**、
`browser_content` **正常**。

## 二、因此失效的操作

| 操作 | 结果 | 原因 |
|---|---|---|
| `elementFromPoint(x, y)` | **`null`** | 点不在可视区 |
| `browser_click({x, y})` | 落点 `(39, -0.03)` | y 为负 |
| `browser_click({text})` | 「Clicked」但**事件没触发** | 算出的坐标在视口外 |
| `browser_fill` / `browser_type` | 依赖焦点 ⇒ 不可靠 | — |

⇒ **表现极具欺骗性**：工具回「Clicked 短信验证码登录」，但页面**毫无变化**。
⇒ 我为此在一个「短信验证码登录」链接上点了 `6` 次，全是空点。

## 三、怎么区分「选择器错了」和「视口是 0」

```javascript
// 先跑这一条，比试十次点击都快
innerWidth === 0 && innerHeight === 0
```

⇒ 若为 `true` ⇒ **不是你的选择器/坐标问题，是窗口没了**。

## 四、这条对「你看不到我的标签页」的解释

同一天奥森说「我根本看不到你的标签页」「你的还不在上面那一层」——
真因就是这个：**窗口尺寸为零，等于没有画面**。
⇒ 不是任务层级问题，也不是别的会话抢占。

## 五、我这边能做的事（`0×0` 下仍然可用）

- ✅ `browser_execute`（跑 JS、读 DOM、读 `module.json` 之类）
- ✅ `browser_snapshot` / `browser_content`（AX 树与文本）
- ✅ `browser_open`（导航，只是画面不可见）
- ❌ 任何需要「点在某个像素上」的操作

⇒ **纯 JS 驱动的表单填充**（设 `.value` + 派发 `input` 事件）**可以**用，
但华为登录页校验 `isTrusted`，所以那条路也不通。

## 六、判据

> **工具回「Clicked」不等于「点到了」。**
> 有坐标的工具在零视口下会安静地全部失效 —— 它们只会报「成功」，不会报「你没窗口」。

⇒ 四条：
1. **任何「点了没反应」先量 `innerWidth/innerHeight`**，别先怀疑选择器
2. **零视口下 JS 仍可信、点击不可信** —— 需要交互就换纯 JS 路径
3. **`isTrusted` 校验会让「纯 JS 派发事件」失效** —— 这时只剩「人来点」一条路
4. **「看不见画面」与「操作失败」可能是同一个根因**（这次就是），别当成两个 bug 查

## 七、试过的四种修法（**全部无效**，记下来省得下次再试）

| # | 方法 | 结果 |
|---|---|---|
| 1 | `window.resizeTo(1400,860)` + `moveTo(0,0)` | 无异常抛出，但 `innerWidth` 仍 `0`；`outer` 从 `0` 变成 `1197×742`（窗口有尺寸了，内容区还是没有）|
| 2 | 连续多尺寸 `resizeTo`（`1400×860` / `1197×742` / `1024×700` / `800×600`）| 每次 `inner` 都 `0`、`outer` 都恒为 `1197×742` ⇒ `resizeTo` 实际不生效 |
| 3 | `window.open(url, name, 'width=1200,height=800')` | **被拦截**（`opened: false`）|
| 4 | `browser_reset_session` 后重开 | 依然 `0×0` |

### 具体数值（证明不是我看错）

```
html/body computed style : display=block · visibility=visible · width=0px · height=0px
getBoundingClientRect    : body 0×0 · html 0×0
visualViewport           : { w: 0, h: 0, scale: 1 }
outerWidth/outerHeight   : 1197 × 742      ← ★ 窗口是真的，内容区是零
screen                   : 1408 × 881
```

⇒ **`outer` 有值而 `inner` 为 `0`** ⇒ 窗口存在，但挂在窗口上的渲染视图（`BrowserView`/`webContents`）边界是零。
⇒ 这是**宿主层**的问题，页面里的任何 API 都改不了。
