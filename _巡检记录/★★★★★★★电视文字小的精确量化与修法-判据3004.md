# 判据 3004：电视上**格子 ×1.45、文字 ×1.0** —— 精确量化与两级修法

## 一、事实（读代码确认，不是推测）

**格子**走设备缩放：

```ts
// Design.ets:117
return Math.round(base * Cell.k * Bp.scale() * shrink);
```

**文字 / 间距 / 圆角不走设备缩放** —— `UiModeMgr.apply(mode)` 只按**用户档位**赋值：

```ts
// UiMode.ets:99-109
FontSize.hero = s.hero; FontSize.xxxl = s.xxxl; …
Space.xs = s.sxs; Space.sm = s.ssm; …
Radius.xs = s.rxs; Radius.sm = s.rsm; …
```

而 `s` 来自档位表（`DEFAULT / ELDER / SIMPLE`），**表里没有任何设备维度**。
`Cell.k` 也只是档位（`1 / 1.33 / 0.9`）——**`UiMode` 根本没有「电视」这一档**。

`Bp.scale()`（`Bp.ets:96`）才是设备维度：

| 设备 | `Bp.scale()` |
|---|---|
| **TV** | **`1.45`** |
| WATCH | `0.92` |
| `isLg()`（`w ≥ 840`）| `1.12` |
| `isMd()`（`600 ≤ w < 840`）| `1.06` |
| 手机 | `1.00` |

⇒ **结论：电视上格子 ×`1.45`，文字 ×`1.0`。**

## 二、算成数（`853×533` 本机横屏 vs `1280×720` 电视）

| 量 | 手机横屏 | 电视 | 倍数 |
|---|---|---|---|
| `Cell.of(30)` 格 | `29vp` | **`44vp`** | `1.52×` |
| `Cell.of(46)` 按钮 | `44vp` | **`67vp`** | `1.52×` |
| `Cell.of(14)` 小格 | `13vp` | **`20vp`** | `1.54×` |
| **`FontSize.md`** | `16vp` | **`16vp`** | **`1.00×`** |
| **`FontSize.hero`** | `36vp` | **`36vp`** | **`1.00×`** |

**文字/格子 比**：手机 `0.55` ⇒ 电视 **`0.36`** ⇒ **文字相对小了 `34%`**。

## 三、物理口径（3 米视距）

- `1vp ≈ 0.159mm`（vp 是密度无关单位，按 1/160 英寸）
- `FontSize.md = 16vp ≈ 2.5mm`
- 3 米处张角 `= 2.5/3000 mrad = 0.85 mrad ≈ 2.9 角分`（人眼舒适下限约 `2~3` 角分 ⇒ **勉强**）
- 电视字幕常见口径「字高 ≈ 视距/200」⇒ `3000/200 = 15mm ≈ 94vp`

⇒ **`16vp` 比舒适值小约 `6` 倍。** 这就是「3 米外短板是文字」的准确形式。

## 四、两级修法

### Tier 1（结构性、与代码库自身不变量一致）

在 `UiModeMgr.apply()` 里给 `FontSize / Space / Radius` 也乘 `Bp.scale()`：

```ts
const k = Bp.scale();
FontSize.hero = Math.round(s.hero * k); …
Space.xs = Math.round(s.sxs * k); …
Radius.xs = Math.round(s.rxs * k); …
```

**为什么这个改法是对的**：它让文字与格子走**同一个** `档位 × 设备` 复合因子 ——
`Cell.of` 用的是 `Cell.k × Bp.scale()`，文字用的是 `档位系数(≈Cell.k) × Bp.scale()`。
两者从此**比例恒定**，不再随设备漂移。

**为什么它安全**：`Bp.ets:12` 自己写着不变量「手机上的值必须和改造前**一模一样**（`scale = 1.0`）」——
真机手机（宽 `360~430vp`）`isLg()=false`、`isMd()=false` ⇒ `Bp.scale()=1.0` ⇒ **文字零变化**。

**唯一会变的是本模拟器**：`w=853 ≥ 840` ⇒ `scale=1.12` ⇒ 文字会长 `12%`，
而 `12%` 的文字增长有可能把已经紧张的款推过临界 ⇒ **必须先在真机量，不能直接上。**

### Tier 2（电视专属）

Tier 1 只能把 `16vp → 23vp`（×`1.45`），离 `94vp` 还差 4 倍。
真要「3 米可读」，需要**电视专属字号表**（约 `Bp.scale() × 2.0`），
那是另一个量级的改动，且要重排所有游戏的布局预算。

## 五、判据

> **「格子放大了文字没放大」这类问题，先查两个量走的是不是同一套缩放因子。**

⇒ 查法固定三步：
1. 找**内容尺寸**的缩放入口（这里是 `Cell.of`）与**文字尺寸**的入口（这里是 `UiModeMgr.apply`）
2. 看两边乘的因子集合是否相同 —— 这里一边有 `Bp.scale()`、另一边没有
3. 换算成**相对比例**（文字/格子），比换算成绝对值更能暴露问题（`0.55 → 0.36` 一眼可见）

⇒ 这条与 `3003` 互为镜像：
· `3003`：**改之前先算另一块屏**
· `3004`：**改之前先看两个量是不是同一套因子**

## 六、状态：**未实施**

⇒ **必须先在一台真机手机上取证「Tier 1 之下文字零变化」，再决定是否上。**
