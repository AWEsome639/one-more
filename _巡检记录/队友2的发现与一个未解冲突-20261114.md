# 队友 `2` 的五款大盘分析：**三条可用，但有一处冲突必须今晚定**

> 产出：`_巡检记录/五款大盘-列数能否减-20261114.md`（`99` 行，只读）

## 一、它的结论（三条我认为成立）

| 游戏 | 判定 | 依据 |
|---|---|---|
| **`GFindWord`** | ✅ **`6 → 4`（`43.2vp`）** | `L20 N=6` 硬编码；词库全 **`3` 字母**；判定 `path.length>=3` **与 `N` 无关** |
| `GLetterCancellation` | ✅ `6 → 4` **+ `TARGETS 8→4`** | `TARGETS=8`，`N=4` 只有 `16` 格 ⇒ `8` 目标占 `50%` ⇒ 必须同步减 |
| `GVisualSearch` | ✅ `6 → 4`（**难度会降**）| `36` 格里 `1` 目标 ⇒ `N=4` 只剩 `15` 干扰项；**⚠️ 它有两处宽度公式：`L288 -360` 与 `L311 -400`，要一起改** |
| **`GWordSearch`** | 🔴 **减列救不了** | 词库全 **`5` 字母**，放置用 `N-w.length+1` ⇒ **`N≥5`**；减到 `6` 也只有 `28.8vp` |
| `GWordSnakeTrail` | 🟡 `8 → 6` 折中 | 词库 `3` 字母，`N` 只用于坐标换算 ⇒ 减列几乎无风险；但 `6` 列只到 `28.8vp` |

**⇒ 最该先做 `GFindWord` —— 五款里唯一「达标且不伤玩法」的。**

**它的 `352vp` 与我算的 `233vp` 冲突：**

| 来源 | 可用高 | 怎么来的 |
|---|---:|---|

**⚠️ 而我那个反推有**已知缺陷**：那三款当时**还没被我限宽**（`Hitori All` `04:09` 测的，我的改动是后来的）**
**⇒ 它们的 `max` 里含的盘面高**不是 `173vp`** ⇒ **我的「头部 `300`」很可能不准。**

**⇒ 所以这一处**两个人都可能错**。**

## 三、今晚数据能一次定死它

**装包后，任取一款 `-360` 的已改游戏（如 `Hitori` / `Shikaku` / `Crown`），看它的 `max`：**
```
max_px = 头部_px + 盘面_px(519) + 底部_px
⇒ 头部 + 底部 = max_px − 519
```
**⇒ 若 `max ≈ 960~1000px` ⇒ 头部 `~300vp`（我的对）**
**⇒ 若 `max ≈ 1180~1250px` ⇒ 头部 `~352vp`（它对）**

**⇒ 这个数一出来，明天「能不能把 `X` 从 `360` 调到 `340`（甚至 `300`）」就有了确定答案。**

## 四、所以明天做什么（等今晚定）

## 五、我试过从截图量头部高度 —— **失败了，所以不再猜**

**思路**：截图 `2560×1600`，用行亮度突变找「头部 / 盘面 / 底部」的边界。

**实测（`Nurikabe` 截图，`PIL` + `numpy` 行均值）**
```
y=  0~100   mean=255     ← 系统状态栏（白底）
y= 200      mean=0.1     ← 深色背景
y= 500      mean=100.7   ← 有亮内容（标题/按钮？）
y= 700      mean=0.0     ← 纯黑
y= 800~1200 mean≈6       ← 盘面区（格子很暗）
y=1300~1400 mean≈14      ← 提示行
y=1500      mean=0.0     ← 纯黑
```

**⇒ 亮度确实能分出几段，但**对应到「头部/盘面/底部」需要知道每段是什么**，而截图里没有标注。**
**⇒ 也就是说：这条路只能给我**猜测式的分段**，给不了**证据**。**

**⇒ 判据：**猜出来的数和算出来的数没有区别时，就别用猜的。****

## 六、所以头部高度是**今晚由数据定死的量**

**方法（今晚装包后，任取一款 `-360` 的已改游戏）：**
```
跑 shot_game.py 拿到 max_px
头部_px + 底部_px = max_px − 519（盘面 173vp = 519px）
```
**再看 `lowest=` 的 `[x1,y1][x2,y2]` —— 那是底部最下面那行文字的坐标**

```
⇒ 头部_px = max_px − 519 − 底部_px
```
**⇒ 两个数一联立，头部高度就是**算出来的**，不是估的。**

## 十一、收敛结论（第 `5` 次也是最后一次改）：**用「界B」定，`X` 取 `340`**

## 十五、所以结论**180° 反转**：**`-360` 不能降，它已经在边缘**

**我前面第 `11~13` 节的所有「`X` 可以是 `340`/`300`」**全部作废**。**

**⇒ 因为它们都基于「头部+底部 ≈ `238~278vp`」——而真实分布**最松到 `350vp`**。**

**⇒ 也就是说：**
- **对 `header+bottom` 小的款**（`GFractionMatch` `211vp`）⇒ `173vp` 盘面确实**浪费**了

**⇒ 所以「一个全局 `X`」本身就是错的做法** —— 那个量的方差是 `211 ~ 350vp`（`± 33%`）。
