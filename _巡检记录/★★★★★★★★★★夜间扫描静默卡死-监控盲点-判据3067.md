# 判据 3067：**`sweep_all.sh` 会在模拟器起不来时静默卡死**（无输出、不退出、不报警）

## 一、事故

`23:42` 起跑 `sweep_all.sh`（队列 `252` 款）。
`23:50` 去查进度 —— **40 分钟只测了 `3` 款**（而且是 `13.3` 分钟/款，按这个速率要 `56` 小时）。

再看日志：**`23:42` 之后只有 2 行**，之后什么都没有。
而 `sweep_all.sh` 的进程**还活着**（PID `20183`、`etime 08:41`）。

## 二、根因（两条叠在一起）

### ① 模拟器**根本没起来**

```
$ pgrep -f 'mulator -start'  →  0
$ hdc list targets           →  [Empty]
/tmp/e15.log 尾部：Host Current Free Memory: 1218
```

⇒ 起模拟器那一刻**宿主只剩 `1218 MB` 空闲**（我刚做完一轮测量，内存没释放）。
⇒ 模拟器拒绝启动（磁盘 `25Gi` 是够的，不是 `00801002` 那种，**是内存**）。

### ② 脚本**不检测设备就绪**，一直在等

`sweep_all.sh` 卡在 `pin_theme: 找不到日月图标（可能不在首页）`
—— 因为**根本没有设备**，它拿到的是空画面。
之后它既不超时、也不退出、也不写日志 ⇒ **静默挂起 40 分钟**。

## 三、这违反了我们自己的判据

- `3063`：「开重活前先跑 `--dry`」—— 我跑了，队列 `252` 是对的
- 但 **`--dry` 只验队列、不验设备** ⇒ 这个前置检查**没覆盖到真正的故障点**

## 四、修复动作

```bash
kill 20183                     # 先杀卡死的脚本
Emulator -stop onemore7        # 清残留
Emulator -start onemore7       # 重起（这次内存 32% 空闲，起来了）
hdc install -r <hap>
bash 工具/sweep_all.sh         # 续跑（脚本自带断点续跑，不用 -force）
```

⇒ 续跑后 `5` 分钟测了 `4` 款（`~1.2` 分钟/款）⇒ `252` 款约 `5` 小时、`05:00` 完成 ✓

## 五、该加但还没加的护栏（下一件事）

**`sweep_all.sh` 开跑前应先验设备**：
```bash
if ! hdc shell "echo ok" 2>/dev/null | grep -q ok; then
  echo "❌ 设备不可用，拒绝开跑"; exit 1
fi
```
⇒ 现在没有这一行 ⇒ **它会带着「没有设备」跑下去**。

**外加一个「静默检测」**：脚本每测一款都应该写一行日志；
若 `10` 分钟没有新日志且进程还在 ⇒ 判为挂起。

## 六、判据

> **「进程还在」不等于「在干活」** —— 这条 `AGENTS.md` 里早写过（「有 worker 在跑 ≠ 在干活，判据是 90 秒产出增量」）。
> 今天我又按「进程 = 2」判断扫描在跑，**实际它 40 分钟零产出**。

⇒ 四条：
1. **判断进度看「产出增量」**（台账新增行数 / 日志新增行数），**不看进程数**
2. **`--dry` 只验队列，不验设备** —— 设备状态要单独查（`hdc list targets`）
3. **模拟器可能因内存起不来，而不是磁盘** —— 两者都要查；日志里的 `Host Current Free Memory` 是关键行
4. **长任务的脚本要自带「设备就绪」前置检查** —— 没有就自己加，别指望它
