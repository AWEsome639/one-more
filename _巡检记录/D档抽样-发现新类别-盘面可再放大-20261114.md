# D 档抽样：**干净，但暴露了一个我没记录过的类别 —— 「盘面可再放大」**

## 一、抽样结果（`D` 档 `128` 款，抽 `1` 款）

**`Nurikabe`（数墙）**：`blk=0`、`max=1407`、`5×5` 盘面**完整可见**，统计/按钮/提示**全部可见**。
**⇒ D 档确实有真干净的款 ⇒ 我的分档口径是可信的。**

## 二、但截图里有一件我没在追踪的事

**把这一屏的高度算一下（`1600px` 屏）：**

| 区域 | 高度 |
|---|---:|
| 头部（标题 + `提示`/`AI代打` + 统计卡）| `~480px` |
| 盘面（`5×5`）| `~525px` |
| 底部（提示行 + `提示`按钮）| `~300px` |
| **合计** | **`~1305px`** |
| **屏幕** | **`1600px`** |
| **⇒ 未用** | **`~295px`（`18%`）** |

**⇒ 盘面本可以放大约 `1.5` 倍（`525 → 780px`）而不溢出。**

**⇒ 这不违反任何判据：`blk=0`、`cov=0`、内容全可见 —— 但它**浪费了 `18%` 的屏幕**。**

## 三、为什么这件事值得记

**目标原话是「每一帧、每一处细节都值钱」。**
**⇒ 一个 `5×5` 盘面只占屏幕 `1/3`、下方空一大片 —— 这不算 bug，但在**观感**上是浪费。**

**⇒ 而这类问题，`blk` / `cov` / `max` **三个指标全都不会报**（因为它们只找「超出」和「遮挡」，不找「没用满」）。**

**⇒ 这是今天第 `4` 个「指标盲区」：**
| # | 盲区 | 例子 |
|---|---|---|
| 1 | 横向裁切 | `C` 档那批 |
| 2 | 内容顶住上方元素 | `Memory` / `Schulte` / `Number Bonds All` |
| 3 | 格子小到点不准 | 我 `-360` 那批 |
| 4 | **没用满屏幕（可再放大）** | **`Nurikabe` 等 `D` 档** |

## 四、但这**不是**现在该修的东西（附理由）

**① 它不是缺陷** —— 不溢出、不遮挡、能玩。
**② 修它要逐款调 `-320`（零余量）** ⇒ **负载波动时就溢出**，等于用「稳」换「大」。
**③ `128` 款 `D` 档大部分可能有同样空间** ⇒ 那是一次**全库调参**，必须一批做完 + 一批验证。

**⇒ 正确时机：今晚数据确认 `-360` 全绿之后**，再单独评估「要不要为观感把 `4×4` 类放宽到 `-320`」。

## 五、给「方阵盘面」的分档结论（今天第 `3` 次修正，这次应该是对的）

| `N` | `-360` 下每格 | 库里先例 | 结论 |
|---|---|---|---|
| `4×4` | `43.2vp` | `Nurikabe` 等可用 | ✅ **可用**；**可考虑放宽到 `-320`（`53vp`）换取观感**，但要承担零余量风险 |
| `5~6` | `28.8~34.6vp` | `Slitherlink` `5×5` 通过 | ✅ 可用 |
| `7~9` | `19.2~24.7vp` | `Sieve Visualizer` `10×10` `17.3vp` 通过 | ✅ 可用 |
| `15`（`Gomoku`）| `11.5vp` | **无先例** | ❌ 要减到 `9×9` |

**⇒ 所以 `-360` 这个统一值：对 `N ≤ 9` 都成立，只有 `Gomoku` 例外。**
