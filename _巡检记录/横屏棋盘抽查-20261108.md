## 1. 两款的问题细节

### ① 数独 `sudoku` —— 按钮行**贴屏底（0 边距）**
实测 dump：
```
游戏内容区 Stack : [0,117][2560,1516]        ← 内容区只到 1516
按钮行 Row       : [60,1462][2500,1600]      ← ★ 越界 84px，画到屏底
  ✕ 擦除  [60,1462][524,1600]                 y2=1600 ← 完全贴边
  提示    [554,1465][1018,1597]               y2=1597 ← 距屏底 3px（安全边距 16 的 1/5）
  AI 代打 [1048,1465][1512,1597]
  换一题  [1542,1462][2006,1600]
  放弃    [2036,1462][2500,1600]
```
- **按钮是完整可见的**（截图 `验收截图-v1.0.1/横屏棋盘/数独-底部-20261108.jpeg` + 底条放大图可证），
  但**距屏底 0–3px**：真机若启用**手势条 / 圆角 / 安全区**，这里会被压住一半。
- ⇒ **判定**：`PUSHED_OUT`（按 `屏底−16` 阈值），但性质是**"贴底"不是"被顶出屏幕"**。

### ② 聪明格 `kenken` —— **底部数字键盘被裁**
实测 dump：
```
提示 / AI 代打 : [60,1393][1265,1501] / [1295,1393][2500,1501]   ← 按钮本身 OK（y2=1501）
键盘 Row       : [60,1549][2500,1600]      ← ★ 只剩 51px 高（正常按键高度约 130px）
  1 [60,1549][534,1600]
  2 [552,1549][1026,1600]
  3 [1043,1549][1517,1600]
  4 [1535,1549][2009,1600]
  ⌫ [2026,1549][2500,1600]
```
- **数字键盘被屏幕底边裁掉约 80px**，只露上半截（截图 `聪明格-底部-20261108.jpeg` 可见键盘行只剩顶边）。
- 这一款是**真·溢出**：用户点数字键时，下半截在屏幕外。
- ⚠️ **机制更正（2026-11-08 深夜，`game-balancer` 定位）**：我当时写"**被屏幕底边裁掉**"是**现象对、机制错**。
  真正原因：**键位行在 `Column` 主轴里被 `flexShrink(1)` 压扁了**（130px → 51px），
  根容器 `Column().height('100%').justifyContent(Start)` + 子节点默认 `flexShrink(1)` ⇒ 内容一超高就压可压缩的子节点。
  ⇒ **视觉一样，修法完全不同**：当"被裁"会去改高度/加滚动；当"被压缩"才知道要给控件行 **`.flexShrink(0)`**。
  ⇒ 已并入交接文档判据 1829「第三次扩写·主轴版」。
- ⚠️ 注意：`提示/AI` 两个按钮**本身没问题**（y2=1501 ≪ 1584），问题在它们**下方**的键盘行。

> 附：我第一轮扫描时把"提示 y2=1600"记在聪明格头上，是**读数抖动**（同一款第二次扫是 1393–1501）；
> 最终以本节的**逐节点 dump**为准 —— 这也是「判据 1813/1814 之外还要**复核一次**」的例子。

## 3. 边界（必须写清楚）

1. **只抽了 12 款**（覆盖 6 类各 2 款），**其余 153 款未验**。
2. **只在这一台设备（853×533 横屏）**；手机竖屏（≈440×956vp）/ 手表**未覆盖** —— 那才是"棋盘溢出"最容易出事的方向
   （竖屏宽 440vp，`width('100%') + aspectRatio(1)` 会顶到屏底）。
3. **游戏名与 lead 给的文件名有偏差**（按注册表实际 id 落）：
   - `GWordle` → `wordle`（猜词游戏）；**`GBoggle` 无对应文件** ⇒ 用最接近的 `letter_grid_swapper`（字母换位）
   - `GMemoryGrid` → `memory_matrix`（记忆矩阵）；`GSimonSays` → `simon_says`（西蒙说）
   - `GKenken` → `kenken`（**聪明格**，中文名不是"肯肯"）；`GSlitherlink` → `slitherlink`（**数回环**）
4. "棋盘"识别用「**面积最大且近似方形**的节点（宽高比 0.8–1.25）」，像落方/字母换位/西蒙说这种**非方形布局**识别不到，
   这类我按「按钮 + 其它节点都在阈值内」判 OK —— 如果要求"棋盘必须被验到"，得给每个游戏补一条**盘面节点定位规则**。

## 4. 建议
1. **数独**：给底部按钮行加**安全区下边距**（至少 16vp，真机再考虑手势条 ~20vp）——它现在是贴屏底 0–3px。
2. **聪明格**：底部键盘行需要**限高或让整个内容区可滚动**，现在被裁掉约 80px（用户点不到按键下半截）。
   ⚠️ 注意判据 1802：约束应加在**棋盘/内容容器**上，不是加在子项上。
3. 这两款属于 **"真机 165 款是否都正常"的第一次实证反例** —— 建议把「底部按钮/键盘贴底或被裁」加入静态扫描的第 4 类判据
   （现在 `check_layout_overflow.py` 只扫 `width('100%')+aspectRatio`、固定高堆叠、`position y` 三类）。
