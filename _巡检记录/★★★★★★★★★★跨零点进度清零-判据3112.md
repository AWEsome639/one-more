# 判据 `3112`：**按「今天」筛截图，跨零点会把进度清零**

## 一、现象

`2026-11-22 00:26` 重启扫批，`pick_untested.py` 报：

```
剩 353 款 / 共 354
```

而 `00:20` 之前明明是「已测 210+ 款、剩 127 款」。

## 二、根因

`pick_untested.py` 原来这么筛「已测」：

```python
today = time.strftime('%Y-%m-%d')
...
if time.strftime('%Y-%m-%d', time.localtime(mtime)) != today:
    continue        # 不算测过
```

⇒ **日期一翻，昨天拍的 210 张截图全部「不算测过」** ⇒ 进度被清零、从第 1 款重新开始。

## 三、修法

改成**滚动窗口**（默认 36 小时，`SCREENSHOT_WINDOW_H` 可调）：

```python
cutoff = time.time() - WINDOW_H * 3600
if os.path.getmtime(p) < cutoff: continue
```

⇒ 修完立刻恢复：**窗口 36h 内已测 232 款、剩 127 款**。

## 四、判据

> **「今天」是个会自己跳变的量 —— 任何以它为界的批处理，都会在零点出事。**
> 长任务要么用**滚动窗口**，要么用**一个显式的批次 ID**（不看时钟）。

⇒ 四条：
1. **跨夜的批处理不要用 `date == today`**：用 `now − N小时` 或「本次任务开始时间」之后
2. **这个坑只在零点出现**，白天永远测不出来 ⇒ 复盘时要主动问「跑过午夜会怎样」
3. **同类风险点**：`detect_bottom_clip.py --today` 也有同样问题（它筛的是「今天」的截图），
   零点后它会认为「今天没有截图」⇒ 扫不出东西。**已改为同一套滚动窗口语义**
4. **改完要立刻验证数量**：这次修完从 `353` 回到 `127`，一眼能看出修对了
