# 判据 `3094`：`Odd Rotation`（旋转异类）竖屏 **3×3 选项的第三排被切** —— 真缺陷，补丁已算好待应用

## 一、缺陷（真机截图确认）

`onemore_fold` `2224×2496`（`711.7×798.7 vp`），`blk=1/48px`。
截图 `截图-Odd_Rotation-074049.jpeg`：**前两排 6 张卡完整，第三排只在屏底露出一条**。
⇒ 9 个选项里有 3 个用户点不到完整区域。

## 二、结构

`GOddRotation.ets`：
```
Column({ space: Space.sm }) {          // ← :377  .width('100%')
  ForEach([0,1,2], r => {
    Row({ space: Space.sm }) {
      ForEach([0,1,2], c => {
        Stack() { … }.layoutWeight(1).aspectRatio(1)   // 每张卡 = 正方形
      })
    }
  })
}.width('100%')
```

⇒ 3 行正方形卡，宽度按**整屏**（`'100%'` = `711.7`）⇒ 每张卡 `(711.7−20)/3 = 230.6`
⇒ 三行总高 `3×230.6 + 2×10 = 711.9vp`，而屏幕只有 `798.7`，上面还有 `≈201.6` 的 chrome ⇒ 装不下。

## 三、补丁（已算好，等能跑构建时应用）

`:377` 那处 `.width('100%')` 改成：

```typescript
// ★ 2026-11-21（判据 3094）：竖屏 3×3 正方形卡按整屏宽算 ⇒ 三行 711.9vp 装不下，
//   第三排被切（实测 blk=1/48px、截图确认）。
//   按实测 chrome 反推：上方 ≈201.6、下方 msg+重开+间距 ≈86 ⇒ 网格可用 ≈511vp
//   ⇒ 每张卡 163.7vp ⇒ 网格宽 511.1vp ⇒ Bp.height − 287.6，取 288。
//   横屏（isShort）走 `'100%'` 不变 —— 横屏隐藏了重开按钮、且可用高只有 533，公式不适用。
.width(Bp.isShort() ? '100%' : Math.min(Bp.width, Bp.height - 288))
```

⇒ 竖屏：`min(711.7, 798.7−288=510.7) = 510.7` ⇒ 每张卡 `163.6` ⇒ 三行 `510.7` ✓ 正好装下
⇒ 横屏：`'100%'` 逐字不变 ⇒ **零风险**

## 四、验收（三样齐了才算成）

1. `grep -c 'Bp.height - 288'` 确认落盘
2. **前台**构建，核对 HAP **字节 + mtime 都变**（判据 `3092`：后台构建被 jetsam 杀）
3. 装包 → 量 `blk` → **看截图**：**9 张卡全部完整、第三排能点**

## 六、判据

> **一晚上抓到三款同类的，说明这不是个案，是一个「写法模式」。**
> 判断方法：**看有没有「`ForEach` 竖排 + `.aspectRatio(1)` + 外层 `.width('100%')`」**。

⇒ 三条：
1. **同一类缺陷出现 ≥3 次，就该做全库静态扫描**，而不是一款一款修
2. **静态扫描要按「结构」扫**（`ForEach` + `aspectRatio` + `width('100%')`），不是按关键词
3. **每修一款都要在注释里写清「这类有几个、判据号是多少」**，方便下次一次性扫掉
