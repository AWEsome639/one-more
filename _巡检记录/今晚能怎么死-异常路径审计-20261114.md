## 2. 整批失败会被**无条件从待办删掉**

### 症状
批跑完后，`sweep_all.sh` **不看这批成功没有**，直接把它们从 `$TODO` 里删掉。

### 脚本实际行为

- `verify_layout.py:127-142` 有「失败款重试一轮」，但**只在批内重试一次**，重试仍失败就没了

### 若要修

## 4. 幂等性：**日期硬编码 `2026-11-14`**，重启就从零重测

### 症状
「哪些已测」靠台账里**写死的那一天**判定。

### 脚本实际行为
```python
# sweep_all.sh:39-46（内嵌 python）
for ln in io.open('_巡检记录/layout-canonical.tsv', encoding='utf-8'):
    …
    if not f[0].startswith('2026-11-14'):     # ← 硬编码日期

    if f[2] in ('OK', 'TIGHT', 'OVER', 'NEAR'):

```

### 实测（我刚算的）
| 「已测」口径 | done | todo |
|---|---:|---:|
| 以 `2026-11-14` 为已测（当前代码）| 144 | **210** |
| 以 `2026-11-13` 为已测 | 61 | 293 |

### 后果（两种）
1. **今晚 00:00 开跑**：done=144（今天测的）⇒ todo=210 ⇒ **不会重测今天测过的** ✓（这条符合预期）
2. **午夜后写入的行是 `2026-11-15`**：
   - 若 03:00 脚本挂了/被 Ctrl-C 再重启 ⇒ **重新读 11-14 那一行** ⇒ done 仍是 144 ⇒ **从第 1 款重新测**

3. **明天（11-15）之后**：每天新测的行都是 11-15/11-16…，**永远不计入 `done`** ⇒

- **漏测**：会（上面第 2 条「整批丢弃」，以及这一条：若某款一直失败，它连一行都不写 ⇒ 下轮不算 done ⇒ 但本轮已从 TODO 删除 ⇒ **本轮漏**）


## 5. `/tmp/todo_next.txt` 被无条件 `mv` 覆盖 —— 假「全部完成」

### 脚本实际行为
```bash
# sweep_all.sh:146-147
grep -vxFf /tmp/batch.txt "$TODO" > /tmp/todo_next.txt 2>/dev/null || true
mv /tmp/todo_next.txt "$TODO"
```

### 后果
- `grep` 若因任何原因失败（编码/参数过长/磁盘满）⇒ `todo_next.txt` 可能是**空文件或半截**
- `|| true` 把错误吞掉，`mv` 照做 ⇒ **`$TODO` 变成空**
- 循环下一轮 `n=$(wc -l < "$TODO")` = 0 ⇒ `say "全部完成"` ⇒ **脚本优雅退出、什么都没测**
- **⇒ 最坏表现：3 秒内「全部完成」，而实际一款都没跑**

### 若要修
```bash
if ! grep -vxFf /tmp/batch.txt "$TODO" > /tmp/todo_next.txt; then
  say "⚠️ TODO 更新失败，保留原 TODO 并中止本批"; continue
fi
[ -s /tmp/todo_next.txt ] || { say "⚠️ 新 TODO 为空，中止（不当成完成）"; break; }
```

## 7. 收工统计会**报错**（`grep -c` + `|| echo 0` 的经典坑）

### 脚本实际行为
```bash
# sweep_all.sh:157-158
OKN=$(printf '%s\n' "$NEW" | grep -cE '\t(OK|TIGHT|OVER|NEAR)\t' || echo 0)
BAD=$(printf '%s\n' "$NEW" | grep -cE '\t(NO_CARD|NOT_HOME|DUMP_FAIL|TIMEOUT|WRONG_GAME)\t' || echo 0)
```
```bash
# sweep_all.sh:161
say "有效: $OKN 款   环境失败: $BAD 款   （合计 $((OKN+BAD)) 款）"
```

### 实测（我刚跑的）
```
OKN=[0
0]        ← grep -c 无匹配时输出 0 并退出 1 ⇒ || echo 0 又补一个 0 ⇒ 两行
$((OKN+BAD))
bash: 0
0: syntax error in expression (error token is "0")
```

### 后果
- **只要「有效」或「失败」其中一类为 0，这一行就报语法错**
- **⇒ 跑得越干净（0 失败）越容易崩** —— 而「明早一句话」全靠这一行
- 台账数据本身没坏（`finish()` 已写 TSV）⇒ 🟡 不是数据丢失，但**无人值守的核心产出（一句话总结）失效**

### 若要修
```bash
OKN=$(printf '%s\n' "$NEW" | grep -cE '…' ); OKN=${OKN:-0}   # 不要 || echo
```

## 8. 时间判据：`hm >= 645` 的语义是「**06:45 之后**」，不是「**到 06:45 就停**」

### 脚本实际行为
```bash
# sweep_all.sh:150-151（每**批** 12 款检查一次）
hm=$(date +%H%M)
if [ "$hm" -ge 645 ]; then say "到 06:45，收工"; break; fi
```

### 实测（macOS bash 3.2，`[ ]` 用十进制）
| `hm` | 判定 |
|---|---|
| `0030` | 继续 ✓ |
| `0645` | **停** ✓ |
| `2350` | **停**（`2350 ≥ 645` 真）|

**⇒ 我原来担心的「前导 0 被当八进制」在 bash 3.2 的 `[ ]` 里**不会发生**（`0645` = 645 ✓）。**

### 但有两个真问题
1. **晚上启动会跑一批就停**：若 22:00 启动 ⇒ 第一批跑完 `hm=2200 ≥ 645` ⇒ **立刻「到 06:45，收工」**（标签还是错的）
   ⇒ **今晚计划 00:00 启动 ⇒ 00:00 < 0645 ✓ 不会触发**，但**这是个「只要启动晚于 06:45 就必停」的雷**
2. **检查粒度是「批」**：一批 12 款 × 104s ≈ **21 分钟** ⇒ 最坏在 06:44 那批开始 ⇒ **07:05 才停**（超 20 分钟）

### 若要修
```bash
# 判「跨零点窗口」而不是「大于 06:45」
now_s=$((10#${hm:0:2}*3600 + 10#${hm:2:2}*60))
if [ "$now_s" -lt $((6*3600+45*60)) ] && [ "$now_s" -ge $((23*3600)) ]; then :; fi
```
或最简单：**记下开跑时刻，用「已运行时长」判**（`SECONDS`），别再跟墙上时钟比。
