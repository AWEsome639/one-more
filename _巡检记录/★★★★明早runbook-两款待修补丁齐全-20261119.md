## 三、⇒ 补丁 2：`Odd Rotation`（`GOddRotation.ets:377`）

**⇒ 该文件**一处 `Bp.height` 都没有** ⇒ 网格 `3×3` 卡片、外层 `.width('100%')` ⇒ 高 = 宽 ⇒ 折叠屏上 `2100px` 高。**

```ts
// 在 L377 那个 .width('100%') 后面接一行
.constraintSize({ maxWidth: Math.min(Bp.width - 2 * Space.lg, Math.max(160, Bp.height - 440)) })
```
**⇒ 手机侧：`533 - 440 = 93vp` ⇒ `max(160, 93) = 160vp = 480px` ⇒ 比当前 `width('100%')`（`853vp`）**小得多** ⇒ **手机侧会变！**
**⇒ ⚠️ 所以必须先测手机基线**：如果手机上当前是铺满的，加了 `maxWidth` 会把它缩到 `480px` ⇒ 可能变丑。
**⇒ 更稳的写法（按屏型分支）**：
```ts
.constraintSize({ maxWidth: Bp.isShort() ? Bp.width : Math.min(Bp.width - 2 * Space.lg, Math.max(160, Bp.height - 440)) })
```
**⇒ 手机（`isShort()` 真）⇒ `Bp.width` ⇒ 等于现在的 `width('100%')` ⇒ 零变化。**

## 【`00:20` 补：`Crossword` 选项区的结构（离线读出，与实测矛盾 ⇒ 明天重点看这里）】

**⇒ 结构：**
```
L313  Column({ space: Space.xs })       ← 填字网格
L346  Row({ space: Space.xs })          ← 选项行
L350/361/372/383/397  Button .layoutWeight(1).height(Cell.of(42))   ← 5 个选项，**高度是固定的**（36vp = 108px）
```

**⇒ ⇒ 选项按钮**高度是写死的 `Cell.of(42)`** ⇒ **理论上它们的位置不该随网格缩小而变。**

**⇒ 但实测是反的**：网格收 `40vp` 后，最低元素从 `HEART [1506,1600]`（`94px`）变成 `EMBER [1576,1600]`（`24px`）⇒ **往下走了 `70px`**，不是往上。**

**⇒ 一个「高度写死」的元素往下走，只有两种可能：**
1. **它上面某层是 `layoutWeight(1)`**，收窄网格后那层反而变高了；
2. **选项在不同状态下是不同数量的行**（比如选项池变化），`HEART` 与 `EMBER` 根本不是同一位置的同一个元素。

**⇒ ⇒ 明天第一件：`SHOT_SAVE_DUMP` 抓一次「收紧前」和一次「收紧后」的树，对比**这 5 个按钮的 `bounds`** ⇒ 一次就能看清是 1 还是 2。**
