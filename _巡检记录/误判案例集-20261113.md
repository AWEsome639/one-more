### 一句话

**「A 被当成 B」有 3 款：`Base Shift`、`Fraction Matcher`、`Numerical Estimation`** ——
它们的共同点是 **Δ>0（数字变大，看着更糟）但新 `lowest` 是原本被挤出屏幕的内容**（规则句 / 选项字母）。

**另外挖出两类更基础的误判**（比 A/B 更该先修）：
1. **11 对是「纯内容抖动」** —— 值完全没变，只是最底那个格子换了内容（`Number Bonds '5'→'7'→'10'` 都在 1584）
2. **14 处「同文本、不同值」** —— **同一个字符串在不同 y 上**（`Counting Sheep '3'` 出现在 1499 和 1600）⇒ **撞词，对比本身无效**

## 二、A 被当成 B：3 款（你说的 `Base Shift` / `Fraction Matcher` 都在里面）

| 游戏 | Δ | 新 lowest | 为什么会被误判成 B | 实际 |
|---|---:|---|---|---|
| **Base Shift** | **+20** | `选出移位后的十进制值` | 值从 1569 涨到 1589 ⇒ 「更靠下了」 | 这句**规则说明**以前被挤出屏，现在显示了 ⇒ **改善** |
| **Fraction Matcher** | **+18** | `B` | 值从 1582 涨到 1600（顶到屏底）| `B` 是**选项字母**，以前看不见 ⇒ **改善** |
| **Numerical Estimation** | **+17** | `不用精算，挑最接近的那个` | 同上 | 规则句出现 ⇒ **改善** |

**⇒ 三款的共同形态：`Δ>0` + 新 lowest 是「解释性内容」= 改善。**

**判据**：**看新 lowest 是「内容」还是「控件」**：
- 内容（规则句 / 题干 / 选项字母 / 完整 HUD）⇒ Δ>0 也大概率是 **A**
- 控件（`提示` / `重开` / `⌫` / `换一题`）⇒ Δ>0 是 **B**（按钮被顶到屏底）

## 三、🔴 更基础的误判（比 A/B 更该先修）

### 3.1 11 对是「纯内容抖动」，根本不该算变化

**值完全没变（Δ=0），只是最底那个格子换了内容**：

| 游戏 | 序列 |
|---|---|
| `Number Bonds` | 1584 `'5'` → 1584 `'7'` → 1584 `'10'` → 1584 `'7'` |
| `Base Shift` | 1578 `'1664'` → 1578 `'507904'` → 1578 `'183'` |
| `Wordle` | 1600 `'Q'` → 1600 `'A'` → 1600 `'Z'` |
| `Word Search` | 1600 `'T'` → 1600 `'U'` |

**⇒ 这些行的「变化」全是随机内容造成的。把它们计入「有变化」= 误判。**

### 3.2 14 处「同文本、不同值」= 撞词（判据 1973 的正面证据）

**同一个字符串出现在不同的 y 上**：

| 游戏 | 文本 | 出现过的值 |
|---|---|---|
| `Wordle` | `'5'` | **1600 / 1591 / 1351** |
| `Counting Sheep` | `'3'` | **1499 / 1600** |
| `Math Maze` | `'步数 0/20 · 从左上角'` | 1597 / 1489 |
| `Word Search` | `'提示：单词只横放或竖放…'` | 1599 / 1568 / 1460 |
| `Target 10` | `'提示：连续消对会加连击分…'` | 1584 / 1512 |
| `Object Displacement` | `'提示：遮罩后只有一个物件换格'` | 1576 / 1486 |
| `Kurodoko` | `'重开一题'` | 1583 / 1480 |
| `Context Clues` | `'选一个释义'` | 1577 / 1481 |
| `Nonogram` | `'提示'` | 1395 / 1365 |
| `Prime Hunter` | `'绿=捞到 红=点错'` | 1546 / 1456 |

**两种可能，必须用 `bounds`/`id` 区分**：
1. **真布局变化**（同一节点位移）⇒ 对比有效
2. **撞词**（两个节点同名）⇒ **对比无效**（例如 `Counting Sheep` 的两个不同数字格 `'3'`）

**⇒ `Wordle '5'` 在 1351/1591/1600 三个位置出现**，最可疑 ——
键盘的 `5` 键和别的 `5` 撞了，或者测量取到了不同状态（输入前/后）。

### 3.3 测量本身不稳定

`Wordle` 同一晚 20 分钟内：`1600 → 1600 → 1591 → 1591 → 1351 → 1600 → 1600 …`
**同一款、同一构建、`lowest` 文本恒为 `'5'`，值却在 1351~1600 之间跳。**

**⇒ 这说明 `lowest` 的取值依赖游戏状态**（例如键盘出现/消失、弹层开合）。
**在这种状态下拿它做前后对比，结论没有意义。**

## 四、给判据 1973/1977 的补充条款

**现有**：比较前必须先证明「两次量的是同一个节点」（记 `bounds` 或 `id`）。

**建议补三条**：

| # | 条款 | 反例 |
|---|---|---|
| **1** | **Δ=0 的文本变化不算变化**（那是内容随机）| `Number Bonds '5'→'7'` |
| **2** | **先看「内容 vs 控件」再判 A/B** | `Base Shift` 值变大但那是规则句出现 |
| **3** | **同文本不同值 ⇒ 必须先排除撞词**（用 `bounds.x/y` 或节点 `id` 区分）| `Counting Sheep '3'` 1499/1600 |

**⇒ 更彻底的做法**：`lowest` 不该只记**文本**，应记
**`bundleId + 节点 id + bounds + 文本`** 四元组；
比较时**先按 id/bounds 对齐节点，再看文本** —— 文本只用于人眼确认，不参与判定。
