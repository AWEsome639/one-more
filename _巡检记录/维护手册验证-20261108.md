### 2.2 现在有哪些防线（我 v3 加的 F2/F3）

### 2.3 ✅ 能变成机制：10 行写盘前自检（已在沙盒验证会拦）

建议加在 `gen_catalog.py` **写盘之前**（和 F3 并列）：

```python
# 写盘前自检：新内容不得比现有文件「倒退」
cur = open(dst, encoding='utf-8').read() if os.path.exists(dst) else ''
new = ''.join(out)
holes = []
for tok in ('ACCENT_TAG', 'ACCENT_DEEP_TAG'):
    if cur.count(tok) > new.count(tok):
        holes.append(f'{tok} 会从 {cur.count(tok)} 处降到 {new.count(tok)} 处')
old_ids = set(re.findall(r"\{ id: '([^']+)'", cur))
new_ids = set(re.findall(r"\{ id: '([^']+)'", new))
if old_ids - new_ids:
    holes.append(f'会丢掉 {len(old_ids - new_ids)} 款：{", ".join(sorted(old_ids - new_ids)[:5])}')
if holes:
    sys.exit('❌ 重跑会让现有文件倒退，已拒绝写盘：\n  - ' + '\n  - '.join(holes))
```

**用「真跑出来的损坏文件」当输入测试（判据 1818：拿已知会错的输入验一遍）**：

```
用「真跑出来的损坏文件」当输入测试 guard：
  ❌ 主题哨兵 ACCENT_TAG 会从 34 处降到 0 处
  ❌ 主题哨兵 ACCENT_DEEP_TAG 会从 31 处降到 0 处
  ❌ 会丢掉 1 款游戏：go9
  ❌ tags 非空的款数 355 → 354
⇒ 识别出 4 类倒退，会 sys.exit 拒绝写盘 ✅

对照：输入是「内容没变」的文件 ⇒ 命中 0 条（不误报）
```

**为什么这比纪律强**：
- 纪律依赖"下一个人记得手册"；机制依赖"文件一倒退就写不进去"
- 它**不规定"不许跑"**，而是**允许跑但拒绝产出倒退** —— 将来真要改 `gen_catalog.py` 的逻辑时，只要新逻辑不倒退就能跑，不用先改纪律
- 三条判据都是**当前文件 vs 新内容**的自比较，不需要维护白名单

### 2.4 另一条更激进的方案（不推荐，供选择）

把 `gen_catalog.py` 改成**默认只生成、不写 GameRegistry**（`--write-registry` 才写）。
好处：把"误跑"变成"跑了也没事"；坏处：真要改 Registry 结构时多一步。
**我推荐 §2.3 的自检**（保留能力 + 拦住倒退）。

## 3 ③「新增类三处同改」：哪三处？漏一处会怎样？

### 3.1 三处（+1 处条件）

| # | 位置 | 作用 | 漏了会怎样（**均静默，不报错**） |
|---|---|---|---|
| 1 | `TAGS`（含 `group/id/icon/label`） | 决定 `GameTags.ets` 里**有没有这个芯片** | **UI 里没有这个芯片，但数据里有 `ps_xxx`** ⇒ 筛选面板看不到、`tagsIn()` 查不到；沙盒实测：删掉 `ps_card` 的 TAGS 行后，`GameTags.ets` 里 `ps_card` 出现 **0 次**，而 `game_tags.json` 里 **4 款仍带 `ps_card`** |
| 2 | `EN` | 英文 label | `EN.get(tid, label)` **回落到中文 label** ⇒ 英文界面显示中文（如「纸牌接龙」） |
| 3 | `GRP_EN` | 英文组名 | `GRP_EN.get(grp, grp)` **回落到中文组名** ⇒ 英文界面组头显示「玩法」 |
| **4（条件）** | `HIDDEN_TAGS` | 款数 <10 时隐藏 | 漏了 ⇒ 一个 2~9 款的细类**出现在筛选面板**（弱标签污染，正是 v6 要解决的问题） |

新增类还要加 **`PLAY_STYLE_RULES` 或 PIN**（否则没有游戏会拿到这个类）—— 这是第 5 处，属于"数据"而非"标签定义"。

### 3.2 ⚠️ 关键风险：**漏了不会被任何检查抓到**

- `check_key_coverage.py` 只扫 `TG()`/`T()` 调用，**`GameTags.ets` 的 label 是纯字符串数组，不在它的视野里**
- 断言基线 `200359 / 0` 也**不会变**
- `gen_tags.py` 的 `EN.get(tid, label)` / `GRP_EN.get(grp, grp)` **就是设计成 fallback 的**，所以漏了反而"看起来正常"
- 唯一能发现的时机：真机切英文/繁体看，或人工对 `GameTags.ets` 与 `TAGS` 的一致性

⇒ **这就是"三处同改"要在手册里强调的原因**：它是**唯一**的防线。

### 3.3 建议补一条「生成后自检」（可选，5 行）

在 `gen_tags.py` 生成完 `GameTags.ets` 后自检：

```python
ids_in_tags = {t[1] for t in TAGS}
missing_en = [t for t in ids_in_tags if t not in EN]
missing_grp = [g for g in {t[0] for t in TAGS} if g not in GRP_EN]
if missing_en or missing_grp:
    sys.exit(f'❌ EN 缺 {missing_en} / GRP_EN 缺 {missing_grp}（会回落中文）')
```

这样"漏一处"就会 fail-fast，而不是等真机切语言才发现。

## 4 结论：三条纪律 → 一条已是机制、两条可升级

| 规则 | 现状 | 建议 |
|---|---|---|
| ① 加款只改 PIN | ✅ 已正确（沙盒验过 1 行 → ps_card 3→4） | 手册补一句「**加款 ≠ 加类**」+「款数跨过 10 要动 `HIDDEN_TAGS`」 |
| ② 绝不跑 `gen_catalog.py` | ❌ **纯纪律**，实测会丢 `go9` + 65 处哨兵 | **升级为机制**：§2.3 的 10 行写盘前自检（已验证会拦、且不误报） |
| ③ 新增类三处同改 | ⚠️ 实际 **3 必改 + 1 条件改**，漏了静默 | 手册写全 + 可选加 §3.3 的生成后自检 |

**一句话**：**「绝不跑 X」是纪律，但"跑了也不许把文件写倒退"是机制** —— 后者不依赖任何人记得这条规矩。
