## 四、这说明什么 / 不说明什么

### ✅ 说明
- **`2.0.0` 的 release 包能装、能启动、能跑完 `50` 个兼容性用例**
- 在**两台不同 API（21/24）、不同形态（折叠/直板宽屏）的云真机**上，核心功能通过率 **`100%`**
- **零崩溃、零 ANR、零 UI 异常**被工具识别

### ⚠️ 不说明
- **不等于我那 `9` 款版面修复被逐款验证了** —— 兼容性用例是「自动遍历」，它验的是
  「能不能启动/运行/不崩」，**不是**「西蒙说的第 4 块按钮在不在屏内」
- `Pura 80 Pro+` 的 `2848×1276` 是**横向像素多于纵向**，但它跑的是**默认方向**（未证实是横屏模式）
- **平板/智慧屏/手表一次都没测**

## 五、判据

> **「兼容性 100% 通过」与「我的版面修复成立」是两件事。**
> 前者说「装得上、跑得完、不崩」，后者要「特定控件在特定形态下完整可见」。
> 用兼容性通过去证明版面修好，就是拿 `2605` 里那个「指标为零」当结论。

⇒ 三条：
1. **自动化遍历类的「通过」只能证明可用性，不能证明版面** —— 后者要截图 + 逐控件核对
2. **报告里的「警告」往往比「通过」更有信息量**：这次唯一警告是「设备类型覆盖不全」，
   而我恰好知道**智慧屏（TV）正是短板** —— 与我的静态分析对上了
3. **云真机把「换一台设备」从不可能变成 7 分钟** —— 以后每改一批就走一次

### ★ 这一轮用的通道：STP（Safari Technology Preview）+ AppleScript

```bash
osascript -e 'tell application "Safari Technology Preview" to do JavaScript "<js>" in front document'
```
⇒ AGC 是 SPA，内容在 `iframe#mainIframeView` 里；同源可直接
`f.contentDocument.body.innerText` 读，比截图省时且不漏字段（旧台账第 `103` 条也这么写）。

⚠️ 但 **JS 点击点不动 `Element-UI` 的表格**（`mousedown/mouseup/click` 派发无效）
⇒ 「读」能用 JS，「点」还得真人或有视口的浏览器。
