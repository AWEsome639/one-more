# ★★★★ 缺口只能给**区间**：两个算法各偏一边

> `2026-11-14 14:2x`。修正我上一轮的「重算」——新算法**高估**了。

## 一、两个算法的偏差方向

| 算法 | 量 | 偏差方向 | 原因 |
|---|---|---|---|
| **A** | `blk` 的超屏量 | **偏低** | `blk` 只数「根内容列的**直接子块**」⇒ 嵌套元素（提示格/键盘行）不计 |
| **B** | `y1` + 元素应有高度 | **偏高** | 假设「文字在元素内垂直居中」+「字高固定 `40px`」⇒ 两者都不准 |

## 二、⇒ 证据：B 会算出不可能的值

**`Pythagorean Triple Builder`：**
```
模型 B：y1=1521 + 40 + (138−40)/2 = 1610px（元素估底）
模型 A：blk=48px ⇒ 最深块 1588px
⇒ 一个元素的底不可能比「最深块」还深 ⇒ **B 高估了 ~22px**
```

## 三、⇒ 所以正确的做法：给区间

**对每款，真实缺口在「A 的下界」与「B 的上界」之间：**

| 游戏 | A（`blk` 下界）| B（`y1` 上界）| 真实缺口区间 |
|---|---:|---:|---|
| `Magnets` | `4vp` | `27.7vp` | **`4`–`28vp`** |
| `Kakuro Mini` | `8vp`（`blk=24px` ⇒ `1564px`，`36px` 差）| `24.7vp` | **`12`–`25vp`** |
| `Fraction Matcher` | `16vp`（`blk=48px`）| `26.0vp` | **`16`–`26vp`** |
| `Percentage Shopping` | `16vp`（`blk=48px`）| `30.0vp` | **`16`–`30vp`** |
| `Pythagorean Triple Builder` | `16vp`（`blk=48px`）| `3.3vp` | **`3`–`16vp`** |

**⚠️ `Pythagorean Triple Builder` 的区间上下颠倒（B < A）⇒ 说明 B 在该款完全不适用
（它的 `y1=1521` 离屏底远，是**多行**结构，不能按「单元素居中」建模）。**

## 四、⇒ 这对改法意味着什么

**好消息：区间上界都 `<= 30vp`，而各款的可省量都 `>= 40vp`：**

| 游戏 | 缺口上界 | 原计划可省 | 结论 |
|---|---:|---:|---|
| `Magnets` | `28vp` | `47`–`52vp` | ✅ **A+B 够** |
| `Kakuro Mini` | `25vp` | `40vp`（只改偏移 `-400`）| ✅ **只改偏移就够，不必动 padding/字号** |
| `Fraction Matcher` | `26vp` | `28vp`（`Cell.of(48→40)`）| ✅ **缩尺寸就够，不必改 `2×2`！** |
| `Percentage Shopping` | `30vp` | `40vp`（统计卡 20 + 图标 20）| ✅ **减元素就够，不必动选项尺寸！** |
| `Pythagorean Triple Builder` | `16vp` | `20vp`（`46→40`）| ✅ 够 |

**⇒ ⇒ **五款的改动都可以缩小一档**：**
- `Kakuro Mini`：只要 `-360 → -400`（一处），不必动 `padding`/状态行
- `Fraction Matcher`：只要 `Cell.of(48) → Cell.of(40)`（一处），**不必改 `2×2` 布局**
- `Percentage Shopping`：只要统计卡 + 图标（两处减元素），**不必缩选项尺寸**

## ⇒ 判据（`2230`）

**当两个算法给出**不同方向**的偏差时，不要选一个「更可信」的，而是给**区间**。**
**⇒ 区间上界决定「改法够不够」，下界决定「会不会改过头」。**
**⇒ 而若区间足够窄（这次 `<= 30vp`），而可省量 `>= 40vp`，那么**无论真值落在区间哪里都够**
⇒ 这时不需要精确值。**

**⇒ 判据：算不清精确值时，看「区间上界 vs 可省量」——若上界 < 可省量，就不用再纠结精确值。**

## ⇒ 判据（`2231`）

**我上一轮用模型 B「重算」五款，并直接宣布「缺口是 28vp 不是 43vp」——那是**把上界当成了真值**。**
**⇒ 而 `Pythagorean Triple Builder` 立刻给出了反例（B 算出 `1610px` 比最深块还深）。**

**⇒ 判据：一个新算法算出的值，先拿一个已知量去校验（这次拿 `blk` 的最深块）。
⇒ 校验不过 ⇒ 那个算法只能当上界/下界用，不能当真值。**
