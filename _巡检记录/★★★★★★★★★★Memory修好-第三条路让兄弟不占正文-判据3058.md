# 判据 3058：`Memory` 修好 —— **前两次失败之后，第三条路是「让兄弟不占正文空间」**

## 一、三次尝试，前两次都失败

| # | 改法 | `blk` | 截图 | 诊断 |
|---|---|---|---|---|
| 1 | 下限 `240 → 160`（只缩宽）| `0` ❌ | 「重新开始」+ 提示文字压在卡片上 | 网格 `layoutWeight(1)` ⇒ 缩宽**不回流** |
| 2 | 下限 + **去掉 `layoutWeight(1)`** | `0` ❌ | 卡片全可见，**但按钮消失** | 按钮被挤出父容器裁剪区 |
| 3 | **下限 + 矮屏不渲染按钮与提示文字** | `0` ✅ | **16 张卡片完整、无重叠、无切边** | ✅ **成功** |

## 二、第三条路的依据：作者已有先例

`GShadowPivot.ets:405`：
```typescript
// 矮屏不渲染『重开』（页头 ↻ 同动作，判据 1859/1867）
.visibility(Bp.isShort() ? None : Visible)
```

⇒ **`Memory` 页头本来就有 ↻**（同一个 `reset()` 动作）⇒ 正文那个「重新开始」在矮屏是**重复的**。
⇒ 提示文字「每次翻两张，找相同的」的意思，页头副标题「**成对翻出，考的就是记性**」已经说完。

⇒ 所以矮屏不渲染这两个，**功能一点没少**。

## 三、最终改动（三处，全部 `Bp.isShort()` 门控）

```typescript
// ① 网格下限 240 → 160（横屏应得 533−360=173vp）
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(160, Bp.height - 360)))
// ② 正文「重新开始」
.visibility(Bp.isShort() ? Visibility.None : Visibility.Visible)
// ③ 提示文字
.visibility(Bp.isShort() ? Visibility.None : Visibility.Visible)
```

| 形态 | 效果 |
|---|---|
| **横屏 `533`** | 网格 `173vp`（原 `240`）+ 省掉按钮 `133px` 与提示 ⇒ **`blk=0`、16 张卡片完整、无重叠** |
| **竖屏 `832`** | 下限 `472 > 160` 不生效 + `isShort()` 为假两处照常渲染 ⇒ **按构造完全不变** |

## 四、结果

```
改前  blk=1/24px  blkh=88px   （最后一行只剩 88px，被切 104px = 54%）
改后  blk=0/0px   blkh=0px
```
截图：**16 张卡片 `4×4` 完整、无重叠、底部无切边** ✓

## 五、判据

> **`layoutWeight(1)` 容器缩宽不回流、去掉又让兄弟掉出裁剪区 ——
> 这时要动的不是它，而是「让兄弟不占正文空间」。**

⇒ 四条：
1. **先找「这个兄弟是不是重复的」** —— 页头/别处已有同样动作的，矮屏直接不渲染
2. **这是作者已有的模式**（`Shadow Pivot:405`）⇒ **同类问题优先照抄作者的先例**，比自己发明稳
3. **`isShort()` 门控能让「横屏修好、竖屏按构造不变」同时成立** —— 比调数值安全得多
4. **`blk=0` 之后仍然必须看截图** —— 这一款三次 `blk` 全是 `0`，只有截图能分出「好、压、消失」三种
