## 1. 口径修正：该看的是 `maxHeight`，不是 `maxWidth`

判据 1963 原文写「没有 `constraintSize({ maxWidth })` 兜底」。**扫完全库后要改一个字**：

| 兜底写法 | 处数 | 是否真的防住 |
|---|---:|---|
| `.constraintSize({ maxHeight: ... })` | **43** | ✅ **防住了** —— `aspectRatio` 的病灶是"高度被宽度锁死"，限制**高度**才能让它反推宽度 |
| `.constraintSize({ maxWidth: ... })` | **1** | ⚠️ 与 `aspectRatio(1)` 组合时只管宽，不解决"宽度一大高度跟着大" |
| 无任何 `constraintSize` | **22**（本文清单） | ❌ |

⇒ **如果只按 `maxWidth` 筛，会把 43 处已经修好的也算进来（66 处假警报）。**
建议把判据 1963 改成：**「`aspectRatio(1)` + 百分比宽 + 无 `constraintSize(maxHeight)`」**。
（`G2048:813`、`GYajilin:449`、`GLifeGame:443`、`GMatch3:539` 都是**已经修好的正面例子**：它们都在 `aspectRatio` 后面跟了 `maxHeight`。）

## 2. 扫描方法（可复现）

```bash
# 1) 找出所有 aspectRatio(1)
grep -n "aspectRatio(1)" entry/src/main/ets/games/*.ets | wc -l     # 285
# 2) 剥注释（`/* */` 与 `//` 换成空格，保持行号）后再匹配 —— 否则会把注释里
#    "原来是 .width('86%') + .aspectRatio(1)" 这种历史说明当成代码（我第一版就踩了，多报 60 处）
# 3) 大括号感知取"该组件自己的修饰链"，只认链上的 .width('NN%') 与 .constraintSize
```

**判"同一组件"的规则**：从 `aspectRatio` 行向上/向下收集连续以 `.` 开头的修饰行；
组件主体以 `}` 收尾时，后面还接着的 `.` 行仍属于这个组件（这一步不做的话会漏掉
`}` 之后的 `.constraintSize` —— `GYajilin` 就是这么被误报的）。

## 5. 建议改法（三种情况）

### 5.1 「棋盘」这一类（`PathRecall` / `PolyominoTiling` / `FrequencyTap`）

**不要**直接把手上的百分比换成死数（853×0.86=733 在竖屏会过小、在手表会过大）。照 `G2048`/`GYajilin` 的现有写法：

```ts
.width('86%')
.aspectRatio(1)
.constraintSize({ maxHeight: Math.max(120, Bp.height - 380) })   // ← 补这一行，让高度封顶后再反推宽度
```

`Bp.height - 380` 是项目里已有的口径（`GYajilin` 用 `-380`、`GLifeGame`/`GMatch3` 用 `-360`），
**留多少取决于该款 HUD/按钮/说明占多高**，改完要真机 dump 复核。

### 5.2 「N×N 方格」这一类（`ChangeBlindness` / `ObjectDisplacement` / `PeripheralFocus`）

格子本身不要动（`width('100%')` + `aspectRatio(1)` 是"正方形格子"的正确写法）；
**要给包裹它们的那一行/那一列加高度上限**，或者整块用一个 `constraintSize({ maxHeight })`。

### 5.3 棋子/装饰（16 处）

**不动。** 见 §4.2。

---

**补充（2026-11-12 核过）**：上面 6 款**都用了根 `Column`、没有 `Scroll()`**（`grep -c "Scroll()"` 全为 0）
⇒ 布局一旦超过 533vp 就是**真的裁掉**，不像可滚动页面那样还能滑到。这条让 P0/P1 的定性更硬。
