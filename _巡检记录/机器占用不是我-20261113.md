# 机器上那个 `176%` CPU 的进程**不是我的**，也没动它

## 现象

**`19:10` 查机器：`load 3.88`（不高），但 `ps` 里有个 Python 占 `176%` CPU。**
**我第一反应是「我留下的孤儿进程」—— 差点直接 `kill`。**

## 查完发现不是

```
PID 81373  Python baseline.py
  cwd: /Users/a0000/.dsh/work/finstress      ← ★ 不是 One More
PID 81371  timeout 1500 python3 baseline.py
PID 81369  bash -c cd ~/.dsh/work/finstress …
```

**`ELAPSED = 00:42`（**刚启动 `42` 秒**）—— 不是跑飞的僵尸，是**另一个工作流正在正常跑**。**

## 所以没动它

**按「不是我的活只说一句，不动手」：**
- **那是 `~/.dsh/work/finstress` 的活（不是 `One More`）**
- **它刚启动，`timeout 1500` 也还没到**
- **`kill` 掉会毁掉别人的一轮计算**

## 顺带一条判据 1994

> **看到高 CPU 进程，先看 `ELAPSED` 和 `cwd`：**
> · **`ELAPSED` 远超 `timeout` 设的值** ⇒ 跑飞了，可以处置
> · **`ELAPSED` 很小 / `cwd` 是别的项目** ⇒ **别人的正常活，别动**
>
> **依据**：今天差点把 `finstress` 刚起 `42` 秒的 `baseline.py` 当僵尸杀掉。

## 我的处置

**我的进程 `0` 个**（模拟器、编译、后台脚本全停）。
**⇒ 机器热是那个 `finstress` 任务 + `WindowServer`，不是 `One More`。**
