# `63` 款共用同一宽度惯用法，**只有 `15` 款处理了短屏** ⇒ 那 `48` 款在 `533` 高屏上掉到 `FLOOR`

> `2026-11-19 01:07`。这条不依赖奥森回答方向 —— 它用**代码内部的一致性**定案。

## 一、⇒ 实测清点

```
63 款用 Math.min(Bp.width - 2*Space.lg, Math.max(FLOOR, Bp.height - N))
  ├─ 15 款在该表达式里带 isShort() 分支：Gomoku / Kakuro / Kurodoko / MathPath /
  │   MatrixReasoning / PathFinder / PrimeHunter / RotatingMaze / Skyscrapers /
  │   CountingSheep / Crossword / FindWord + 3
  └─ 48 款没有
```

**⇒ ⇒ 作者**知道**短屏要单独调（否则不会写 `Bp.isShort() ? 180 : …`），但只调了 `15` 款。**
**⇒ ⇒ 剩下 `48` 款在短屏上会掉到 `FLOOR`（多为 `200vp`）⇒ 只占 `853` 宽的 `23%`。**

## 二、⇒ 为什么这不是「等奥森回答方向」才能定的

**⇒ 无论真实设备是竖还是横，`48` 款都是**同一类缺口**：**
- **若真实是竖屏** ⇒ 它们恰好在竖屏下正常 ⇒ **但换到横屏设备（电视/PC/折叠屏展开）就会掉到 `FLOOR`** ⇒ 是**多设备缺陷**；
- **若真实是横屏** ⇒ 它们现在就掉到 `FLOOR` ⇒ 是**当前缺陷**。

**⇒ ⇒ 两种情况都要修，只是优先级不同。所以不必等答案，可以开始设计。**

## 三、⇒ 建议：把这套算式收进 `Bp`，一处处理短屏

**现在 `63` 处各写一遍，`N` 与 `FLOOR` 各不同、短屏逻辑 `15` 处有 `48` 处没有。**建议加：
```ts
// core/Bp.ets
/** 方阵棋盘的边长上限（vp）。N = 棋盘上下要留给其他控件的总高度。
 *  ★ 2026-11-19：原来 63 处各写一遍 Math.min(Bp.width-40, Math.max(FLOOR, Bp.height-N))，
 *    其中 48 处没处理短屏 ⇒ 短屏上掉到 FLOOR（只占 23% 宽）。
 *    这里统一：短屏时 N 按比例缩小，让棋盘吃满剩余高度。 */
static boardMax(n: number, floor: number): number {
  const w = Bp.width - 2 * 20;                    // Space.lg = 20
  const reserved = Bp.isShort() ? n * 0.72 : n;   // 短屏：chrome 只按 72% 计
  return Math.min(w, Math.max(floor, Bp.height - reserved));
}
```
**⇒ 迁移方式（可分批、可回滚）：**
1. **先改 `15` 款已有的** ⇒ 用 `Bp.boardMax(N, FLOOR)` 替换，**必须逐款验证数字与原来一致**（`isShort()` 分支要等价）；
2. **再改 `48` 款** ⇒ 每款一次「改前/改后」测量 + 一张截图（`2605` 的纪律）；
3. **每批 `5–8` 款**，一批一提交。

**⇒ ⚠️ `n * 0.72` 这个系数是**待定的**：必须先用 `5` 款量出「chrome 实际占多少」，不能拍。**
**⇒ ⚠️ 方阵棋盘在短屏上真正受限于**高度**（`533 - N`），单靠这个 helper 不会让棋盘变大 —— 它只是把「短屏该留多少 chrome」这件事**集中到一个地方**、并且**让 `48` 款也能感知短屏**。**

## 四、⇒ 诚实标注这条的边界

**⇒ 它**不能**让 `48` 款在 `533×853` 横屏上凭空变大 —— 方阵棋盘就是被高度卡死（`533 - 360 = 173vp`）。**
**⇒ 它能做的是：① 让短屏的 `N` 有统一口径、不再 `48` 处各拍一次；② 给「减少 chrome」这个真正的杠杆提供一个改动点。**
**⇒ ⇒ 真要让棋盘变大，必须动 **chrome（`N`）本身** —— 那是每款逐个判断的活，没有捷径。**

## ⇒ 判据 `2980`

**⇒ 同一个算式被抄了 `63` 遍、其中 `48` 遍漏了同一个分支 ⇒ 这不是 `48` 个疏忽，是**缺少一个抽象**。**
**⇒ ⇒ 但也别指望这个抽象能变出空间：**集中**解决的是「口径不一致」，**不**解决「空间不够」。后者必须逐个改 chrome。**
