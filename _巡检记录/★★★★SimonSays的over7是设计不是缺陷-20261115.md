# `Simon Says` 的 `over=7px`：**是设计，不是缺陷**

> `2026-11-15 19:05` 真机实测 + 截图（`截图-Simon_Says-190530.jpeg`）。

## 一、⇒ 线索来源

**`triage.py` 新增「真溢出」分组后，从 `271` 款旧台账里筛出唯一一处：**

```
Simon Says   over=7   sumover=0   2026-11-15T10:50
```

**⇒ 而它的 `blk=0`（在那次记录里）—— 正是判据 `2695`/`2708` 说的盲区。**

## 二、⇒ 从 dump 定位到具体节点

**`over=7px` 来自两个 `Stack`：**

```
子 Stack 高 851 > 父 844  (超 7px)  path=/0/0/0/1/0/2/0/0
子 Stack 高 851 > 父 844  (超 7px)  path=/0/0/0/1/0/2/0/1
```

**⇒ 它们是同一父节点（`/0/0/0/1/0/2/0`）下的两个兄弟 —— 即屏幕上 `A`（绿）与 `B`（红）两个大面板。**
**⇒ 与测量值一致：`board=985x851`。**

## 三、⇒ 截图确认：**是设计**

**`截图-Simon_Says-190530.jpeg`：两个面板从 `749` 铺到 `1600`（屏幕底边），**故意全出血**。**

**⇒ 这是「点面板做动作」游戏的正常设计（大面板 = 大触控目标）。**
**⇒ `7px` 是**面板高度与容器圆角取整**的差 —— **没有任何内容被切、没有文字被截。**

## 四、⇒ 结论

**✅ `over=7px` **不是缺陷**，不需要修。**

**⚠️ 但它值得记下来，因为它验证了判据链：**
- **`2695`/`2708`**：`blk` 对父界内的溢出无信息量 ⇒ 需要 `over`/`sumover`
- **`2722`**：指标能报出“哪里不对”，但**“是不是缺陷”必须看截图**
- **`2692`**：`over=0` + 贴边也可能被切；反过来 **`over>0` 也可能是设计**

## ⇒ 判据（`2750`）

**`over>0` 是**线索**，不是**结论**。**判断三连：**
1. **从 `path` 定位到具体节点**（哪个子、哪个父）
2. **看该节点在屏幕上的位置**（是否全出血/浮动层）
3. **看截图**（有没有东西被切）

**⇒ 今天这条：`over=7px` + 全出血面板 ⇒ 设计；若换成文字节点，`7px` 就该修。**

**⚠️ 顺带：`Simon Says` 的 `blk=2/48px` 是**面板贴底**造成的（与 `Snake 3D` 的 `blk=3/72px` 同源）—— 贴底不是缺陷。**
