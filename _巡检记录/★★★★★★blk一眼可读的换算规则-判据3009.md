# 判据 3009：`blk` 的 `px` 能一眼换成「出屏多少 vp」

## 一、规则

`shot_game.py` 里：

```python
over = nums[3] - (GAME_BOTTOM + SLACK)      # GAME_BOTTOM=1516, SLACK=60 ⇒ 减 1576
```

而屏幕底是 `1600`。所以：

```
出屏 vp = (y2 - 1600) / 3 = (1576 + blk_px - 1600) / 3 = (blk_px - 24) / 3
```

⇒ **`vp 出屏 = (blk_px − 24) / 3`**

| `blk` | `vp 出屏` | 读法 |
|---|---|---|
| `24px` | **`0`** | **正好贴屏幕边，一点没出屏**（只是压过阈值 `8vp`）|
| `48px` | `8` | 出屏 `8vp`（`24px`）|
| `72px` | `16` | 出屏 `16vp`（`48px`）|
| `> 200px` | `> 59` | 真的在屏幕外一大截 |

⇒ 这也解释了为什么台账里的 `blk` 值**几乎全是 `24` 的倍数**：一个块底 `y2` 落在屏幕边上就是 `24`，
   再往下每多 `24px` 加一档。

## 二、立刻能用上的结论

按每款**末次 `OK`** 统计（`359` 款里 `24` 款有 `blk>0`）：

| 形状 | 款数 | 真实出屏 |
|---|---|---|
| `blk=1/24px` | **4**（`Collatz` / `Crossword` / `Memory` / `Word Surge`）| **`0vp`** |
| `blk=2/48px` | 5 | `8vp` |
| `blk=3/72px` | 4 | `16vp` |
| 其余零散 | 11 | `0~16vp` |

⇒ **`blk=1/24px` 那 4 款根本没出屏**，它们只是「最低元素正好排在屏幕最下沿」。
   `2605` 那种「`blk=0` 也可能有问题」的反面是：**`blk=24` 也可能根本没问题。**

## 三、判据

> **`blk` 是「相对 `1576` 的溢出」，不是「出屏多少」。要看真实出屏，先减 `24` 再除 `3`。**

⇒ 三条用法：
1. **报告里说「出屏 N vp」前，先做这个换算** —— 直接读 `blk` 会把「贴边」说成「出屏」
2. **`blk ≤ 24` 一律视为「贴边」，不进 A 档**（现在 `triage` 的 A 档门槛就是 `24`，刚好把「贴边」也收进去了）
3. 与 `2990`（`over=0` 不等于安全）对照：
   · `2990`：**贴边也可能压住手势条** ⇒ 不能只看 `over`
   · `3009`：**贴边不等于出屏** ⇒ 不能只看 `blk`

⇒ 两个数各有各的口径，**都换成人能看懂的单位（vp 出屏 / 手势条重叠）再下结论**。

## 四、对 `triage.py` 的建议（未改）

A 档门槛从 `blk >= 24` 改成 `blk > 24`，并在打印里直接给「出屏 vp」：

```
Collatz   blk=24  出屏 0vp   ← 贴边
Snake 3D  blk=63  出屏 13vp
```

⇒ 这一条改动很小，但会让 A 档从 `18` 款降到 `14` 款，**少看四款本来就没问题的**。

## 五、`triage.py` 已改（`04:35`）

三处：
1. A 档门槛 `blk >= 24` → **`blk > 24`**
2. 标题改为「`blk > 24px`（真出屏，判据 `3009`）」
3. 每行直接打印 **`出屏 N vp`**（`(blk − 24) / 3`）

### 效果（`18` 款 → `13` 款）

```
Simon Command           blk=72  出屏  16vp  ~切156.5%
Shadow Pivot            blk=72  出屏  16vp  =切120.0%
Odd Rotation            blk=48  出屏   8vp  ~切 76.2%
Simon Says              blk=48  出屏   8vp  ~切 48.5%
Classic Maze            blk=35  出屏   4vp  ~切 38.9%
Wordle                  blk=40  出屏   5vp  =切 20.8%
Skyscrapers             blk=26  出屏   1vp  ~切 19.7%
Wireframe 3D Rotation   blk=72  出屏  16vp  ~切 18.8%
Snake 3D                blk=63  出屏  13vp  =切 15.9%
Double N Back           blk=48  出屏   8vp  ~切 13.3%
```

⇒ **最狠的也只有出屏 `16vp`（`48px`）** —— 即 `Simon Command` / `Shadow Pivot` / `Wireframe 3D`。
  而这三款里 `Shadow Pivot` 已被 `2992`/`2994` 证明是横屏专属。

⇒ `Skyscrapers` 只有 **`1vp`** —— 之前 `blk=26` 看着像回事，换算完是「差一个像素」。

### 这条改动的价值

原来读 `blk=72` 要心算「72 减 60 再除 3」，还容易算错方向；
现在直接写 `出屏 16vp`，**一眼就知道值不值得看**。

⇒ 与 `3005` 合起来，A 档每行现在给了三样：
1. **`blk`**（原始口径，可复算）
2. **`出屏 N vp`**（人能懂的单位）
3. **`切 N%`**（严重度比，带 `=`/`≤`/`~` 精度标记）

⇒ 三个数各管一件事，**缺一个都可能把「贴边」当「出屏」、或把「大块上的小溢出」当「严重」**。
