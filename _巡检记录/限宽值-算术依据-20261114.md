# 限宽值不是估的 —— **每个值都有算术依据**（`2026-11-14` 修正后）

## 通用公式

**网格 `R` 行 × `C` 列，宽封顶 `W`（vp）⇒ 每格宽 `W/C`**
- **方形格**（`aspectRatio(1)`）⇒ 高 = `W/C` ⇒ 盘面高 = `R × W/C`
- **竖长格**（`aspectRatio(0.82)`）⇒ 高 = `(W/C)/0.82`

**必须满足**：`盘面高 + 头部(≈320vp) ≤ 533vp` ⇒ **盘面高 ≤ 213vp**

## 全库现在的主导值：`-360`（`98` 处）

**`Bp.height - 360` ⇒ `533 - 360 = 173vp`** ⇒ 留 `40vp` 余量。**这是库里的既定约定，我今天的修正统一到这里。**

## 一条判据

> **封方形盘面的宽度之前，先算「盘面高 = 封顶值」** ——
> 因为 `N×N` 方阵的高**恰好等于**宽度封顶值，不是「比它小一点」。
> **⇒ 凭「看起来够小」估出来的值，会系统性地偏大 `100+ vp`。**

**⇒ 并且先 `grep "Bp.height - "` 看库里的既有约定，别另立一套。**

## 八、而这也给了 `boardPx()` 重构的正确公式

**不是 `Math.min(w, h)` 那么简单，而是：**
```ts
const FIXED = <每款不同：顶栏 + 提示条 + 信息卡 + 按钮行的绝对高度>
const h = (Bp.height - FIXED) * 0.70;
return Math.min(Math.max(160, Bp.width - 40), Math.max(120, h));
```

**⇒ `FIXED` 是**绝对值**，不是比例** —— 这是那个复盘最关键的一句（「固定部分是绝对值，不是比例」）。
**⇒ 而 `0.70` 系数是为了给底部按钮行留余量。**

**⇒ 所以 `boardPx()` 重构不是「换个写法」，是**每款都要实测自己的 `FIXED`**。**
**⇒ 这解释了为什么库里 `22` 款各自写了一份 `boardPx()` 而没抽公共函数 —— `FIXED` 本来就因款而异。**

**⇒ 因此 `-360` 作为**统一近似**是合理的：它把所有款的 `FIXED` 都当成 `360vp`，
对 `FIXED ≤ 360` 的款**安全**，对 `FIXED > 360` 的款**不够**。**
**⇒ 今晚数据会告诉我们有没有 `FIXED > 360` 的款（即 `blk` 没归零的那几款）。**
