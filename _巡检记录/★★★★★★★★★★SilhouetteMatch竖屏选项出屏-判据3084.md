# 判据 `3084`：竖屏下「容器宽」被当成了「屏幕宽」—— 三处同一个病

## 一、症状（真机竖屏 `2224×2496`，`741×832vp`）

`Silhouette Match`：`blk=3/72px`。
截图（`截图-Silhouette_Match-203754.jpeg`）显示**第二排选项卡片整排被切掉**，
用户只能看到 2 个选项、看不到另外 2 个。

## 二、根因：`gs()` / `go()` 都用 `Bp.width`，而它们的容器不是整屏宽

三处尺寸算式，全都有同一个错误：

| 算式 | 原写法 | 真实容器 | 竖屏后果 |
|---|---|---|---|
| `gs()`（积木预览格）| `byW = (Bp.width - 80) / n2` | **固定 `104vp`**（`.width(104)`）| `n2=3` 时 `byW=220`、`gs=120vp` ⇒ 3 格要 `364vp`，容器只有 `104vp` |
| `go()`（选项格）| `byW2 = (Bp.width - 80) / n3` | **半屏 × 72%**（`.width('72%')` 在 `.layoutWeight(1)` 里）| `n3=5` 时 `byW2=132`、5 格要 `660vp`，容器只有 `248vp` |
| `go()`（选项高度）| `byH2 = (Bp.height - 480) / n3` | **两排卡片**（每排 2 个、共 4 个）| 只扣了一排的预算 ⇒ 第二排整排出屏 |

⇒ **横屏从来没暴露**：`Bp.height=533` 时 `byH=(533-470)/n2≈21` 主导，
`byW` 再大也被 `min` 压住 ⇒ 看起来「算法没错」。竖屏 `832` 高，`byH` 变大，`byW` 就开始吃人了。

## 三、修法（三处都改成「按真实容器算」）

```typescript
// ① 预览格：容器固定 104vp
const byW = Math.floor((104 - (n2 - 1) * 2) / n2);

// ② 选项格：容器 = 半屏 × 72%
const cw  = Math.floor(((Bp.width - Space.sm) / 2 - Space.sm * 2) * 0.72);
const byW2 = Math.floor((cw - (n3 - 1) * 2) / n3);

// ③ 选项高度：竖屏两排卡、横屏一排
const cardRows = Bp.isShort() ? 1 : 2;
const byH2 = Math.floor((Bp.height - 480) / (cardRows * n3));
```

## 四、实测（每一次只改一处、每次量一个数、每次都看截图）

| 版本 | `blk` | 截图结论 |
|---|---|---|
| 原始 | `3/72px` | 第二排选项**整排不见** |
| 只修 ① | `3/72px` | 预览变小了（题面 `y 1782→1063`），但**选项仍是巨块** ⇒ ① 不是瓶颈 |
| 修 ①+② | `3/72px` | 每张卡内 `5×5` 整齐了，但**第二排仍被切** ⇒ ② 不是瓶颈 |
| 修 ①+②+③ | **`1/24px`** | **4 张卡全部完整可见** ✓，余下 `24px` 是「重开」按钮底部贴屏沿（视觉完整）|

⇒ 三次都出现「`blk` 没变」，但 `lowest` 的坐标每次都变了 —— **这正是判据 `3083` 说的：`blk` 相同 ≠ 没改对地方**。

## 五、横屏为什么安全（算式核对，不是感觉）

```
gs(): 新 min(byH=21, byW=33) = 21   改动前 min(21, 257) = 21   ✓ 不变
go(): 新 min(byH2=10, byW2=56) = 10 改动前 min(10, 154) = 10  ✓ 不变
```
⇒ `cardRows` 用 `Bp.isShort()` 门控，横屏 `533` 取 `1` 排，与旧式完全等价。

## 六、判据

> **写尺寸算式时，「`Bp.width`」几乎总是错的答案，除非容器真的铺满整屏。**
> 正确的量是**那个组件的容器宽度** —— 它写在布局树的另一行（`.width(104)`、`.width('72%')`）。

⇒ 四条：
1. **凡是 `.width(固定值)` 或 `.width('百分比')` 的子组件，尺寸算式一律不能用 `Bp.width`**
2. **横向溢出 `blank` 指标（`blk`）看不见** —— 它只统计 `y2 > 阈值`。横向爆了会让纵向连带变高，才被顺带抓到
3. **「只在大屏暴露」的布局 bug，先怀疑「算式按整屏算、容器是小盒子」**
4. **改完必须看截图**：三次「`blk` 没变」里，只有截图能告诉你哪一段真的动了
