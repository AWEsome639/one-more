# 判据 3005：`blk` 的**数值大小不反映严重程度** —— 严重度 = 溢出 ÷ 元素高度

## 一、两个都是 `blk>0`，但严重度差 27 倍

⇒ `Simon Says` 的 `blk` 比 `Crossword` **大一倍**（`48` vs `24`），
  但真实严重度**反过来**：`0.8%` vs `22%`。

## 四、判据

> **`blk` 只说「超出阈值多少像素」，不说「被测元素被切掉多少」。**
> 严重度要 `/元素高度` —— 同一个 `24px`，落在 `281vp` 的方块上是 `0.8%`，落在 `40vp` 的按钮上是 `22%`。

⇒ 三条用法：
1. **看 `blk` 之后必须接一句「这个元素本身多高」**，否则排序会反
2. **`over=0` 不等于没事** —— `Crossword` 的 `over` 是 `0`（底边正好压屏幕边），但 `22%` 被切、`5.3vp` 在手势条下
3. **`triage.py` 排序应当用 `blk / 元素高`**，不是 `blk` 的绝对值（这条待改）

## 五、与既有判据的关系

- `2605`–`2608`：**指标能归零 ≠ 问题解决**（`Scroll` ⇒ `blk` 必 `0`）
- `2990`：**`over=0` 不等于安全**（块进 `1516–1600` 手势区仍压按钮）
- **`3005`（本条）**：**指标有了、也非零了，但「数值大小 ≠ 严重程度」**

⇒ 三条串起来是同一个主题：**指标只在它自己的坐标里有意义，换成用户的视角（遮了多少、能不能点）常常反过来。**

### ⚠️ 必须写清的局限（否则又变成「指标看着有、其实在骗自己」）

`blk` 是**多块累计**溢出（`group(2)` 是对 `blk=块数/溢出px` 的**第二项之和**），
而 `lowh` 是**最低文字节点**的高度。**两者量的不是同一个对象。**

判例：`Simon Says` 的 `blk=48`，但真正溢出的是那个 `281vp` 的答题方块；
`lowh` 量到的是方块上的 `🐸` 文字（`99px`）⇒ 比值 `48/99 = 0.49` 与真实严重度无关。

⇒ 所以这个比值**只能用来分开「48px 落在大方块上」和「24px 落在小按钮上」这两种情形**，
   **不能当成「被切掉百分之几」。** 打印里已按这个口径标注。

## 七、真正的修法（下一步，未做）

让 `shot_game.py` 在记录 `blk` 时，**同时记下「溢出那一块自己的高度」**：

```
blk=<块数>/<累计溢出px> blkh=<溢出块的最大高度px>
```

⇒ 有 `blkh` 之后，`严重度 = 累计溢出 / blkh` 才是真比例。
⇒ 这需要改 `shot_game.py`（跑批每款新起进程 ⇒ 下一款即生效，不用重启），**但要跑够样本才能验**。

## 八、判据的最终形态

> **一个指标只有在「分子与分母量的是同一个对象」时才能相除。**
> 分子是「累计溢出」、分母是「文字节点高」时，相除得到的是**排序用的粗代理**，
> 不是比例 —— **必须在对人的输出里写明这一点**，否则下一个人会拿它当比例用。

## 九、★ `blkh` 已落地并**实测验证**（`03:15`）

### 改了什么

`shot_game.py` 在扫描越界块时，记下**溢出最多那一块自身的高度**：

```python
if over > block_over_max:
    block_over_max = over
    block_over_h = nums[3] - nums[1]   # bounds 是 x1,y1,x2,y2
```

台账格式从 `blk=<n>/<px>px cov=…` 变成 `blk=<n>/<px>px blkh=<h>px cov=…`。

`triage.py` 解析 `blkh`，**优先用它当分母**（打印标 `✓`），老行没有 `blkh` 时退回 `lowh`（标 `~`）。

### 实测（第一条带非零 `blkh` 的真实记录）

```
2026-11-19T03:11:21  Wordle  OK  71.0s
lowest='换一题' [60,1500][857,1596]  blk=2/40px blkh=96px …
```

`triage.py` 现在显示：

```
Wordle   blk=40  blkh=96   ✓ 切 41.7%   max=1596  lowest=换一题
```

⇒ **`40 ÷ 96 = 41.7%`** —— 分母是溢出块自己的高度，不再是「最低文字节点」。

### ⚠️ 还剩一层不精确（必须写明）

**分子仍是「多块累计溢出」**（`block_over_px` 是 `+=` 累加），
所以：

| `blk` 块数 | 这个比值的含义 |
|---|---|
| `= 1` | **精确**：这一块自己溢出 / 自己高度 |
| `> 1` | **上界**：多块累计溢出 / 其中最高的那一块 ⇒ 会**高估** |

`Wordle` 是 `blk=2/40px` ⇒ 严格说 `41.7%` 是**上界**，真实单块比例 ≤ 它。

⇒ 要彻底精确，分子也得改成「溢出**最多那一块**的溢出」而不是累计 ——
  那是 `blkh` 的配套改动（`blkh` 已有，只需同时记 `blkmax=<over>`）。

### 判据的最终形态（第三次修订）

> **一个指标只有在「分子与分母量的是同一个对象」时才能相除。**
> 第一版：分子=累计溢出、分母=最低文字高 ⇒ **不是同一对象**，只能排序（`~`）。
> 第二版：分子=累计溢出、分母=溢出块自身高 ⇒ **同一类对象**，块数为 `1` 时精确、`>1` 时是上界（`✓`）。
> 要做到完全精确：**分子也必须取「那一块自己的溢出」**。

## 十、★ 三档比值已落地（`03:20`），`Wordle` 真值是 `20.8%`

### 关键发现：`max=` 就是「单块最大溢出」，不用再加字段

`shot_game.py` 的台账格式里，`max=%d` 填的是 `block_over_max`：

```python
over = nums[3] - (GAME_BOTTOM + SLACK)
if over > 0:
    block_over_px += over
    if over > block_over_max:
        block_over_max = over
        block_over_h = nums[3] - nums[1]      # ← 判据 3005 加的
```

⇒ **`max` 与 `blkh` 是同一块的两个量**（`blkh` 恰在 `over > block_over_max` 时才更新）
⇒ **`max / blkh` 是精确的单块比例，本来就能算，不需要新字段。**

### 一个差点踩的陷阱：`max=` 与 `mb` 是两个东西

| 记号 | 来源 | 含义 |
|---|---|---|
| `mb`（`triage.py:28`）| 台账**第 4 列** `f[3]` | `y2`，最低元素底边 |
| `max=`（详情里）| `block_over_max` | **溢出最多的那一块的溢出量** |

⇒ 同一个词根，两个完全不同的量。差点把 `max=20` 当 `y2` 用。

### 一个真 bug：`px?` 不是「可选 px」

```python
re.search(r'(?:^|\s)max=(\d+)px?', ln)     # ❌ 永远匹配不到 `max=20`
```
`px?` = 字面 `p` + 可选 `x` ⇒ `max=20` 后面没有 `p` 就失败，`maxov` 恒为 `-1`。
改成 `(?:px)?` 后立即正确：

```
Wordle   blk=40  blkh=96    = 切 20.8%   max=1596  lowest=换一题
```

⇒ **`20 / 96 = 20.8%`**，比上界 `41.7%` 小一半，比 `blk` 绝对值 `40px` 的含义清楚得多。

### 三档标记（打印里直接看得出来）

| 标记 | 公式 | 何时出现 | 含义 |
|---|---|---|---|
| `=` | `max / blkh` | 有 `max` 且 `blkh>0` | **精确**（分子分母同一块）|
| `≤` | `blk / blkh` | 有 `blkh`、无 `max` | 上界（累计 ÷ 单块高）|
| `~` | `blk / lowh` | 连 `blkh` 都没有（老行）| 粗代理，只能排序 |

### 判据最终形态（第四版，定稿）

> **一个比值要可信，分子与分母必须是「同一个对象的同一个量」。**
> 三个版本走过：`blk/lowh`（不是同一对象）→ `blk/blkh`（同一类对象但仍高估）→ `max/blkh`（同一块，精确）。
> **打印时一定要标出属于哪一档**，否则读的人会把上界当精确值用。

## 十一、★ 交叉验证：指标与像素扫描**互相印证**（`03:16`）

| 游戏 | 台账指标 | 像素扫描（截图） | 差 |
|---|---|---|---|
| `Crossword` 答案按钮 | `max=24px`（单块溢出）| 可见 `94px`、应为 `120px` ⇒ 切 **`26px`** | **`2px`** |

⇒ `2px` 的差来自阈值（`1576` vs 屏幕边 `1600`）与取整，**不是矛盾**。

⇒ `Crossword` 的精确严重度 = `24 / 120 = 20%`，而我按截图算的是 `21.7%` —— **量级与结论一致**：
   「四分之一不到的按钮被切，且底部压在手势条下」。

### 这条验证的意义

以前 `blk=48px` 这种数只能凭经验猜严重不严重（`Simon Says` 的 `48px` 其实是 `0.8%`）。
现在同一个数能**从两条独立的路得到**：
1. 布局树（`max` ÷ `blkh`）
2. 截图（紫色像素扫描，量可见高度 ÷ 应有高度）

⇒ **两条路差 ≤2px ⇒ 指标可信。**这正是判据 `3005` 想达到的状态。
