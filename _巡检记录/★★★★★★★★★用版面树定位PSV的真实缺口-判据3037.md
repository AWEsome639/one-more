# 判据 3037：用**版面树**代替盲改 —— `Perspective Shift View` 的真凶量出来了

## 一、为什么换方法

`Shadow Pivot`（4 次）+ `Perspective Shift View`（1 次）都是**盲改**：`padding` / `margin` /
`constraintSize` / `layoutWeight` —— **5 次全部零效果或更坏**。

⇒ 盲改的问题不是「改错地方」这么简单，而是**根本不知道版面实际长什么样**：
`blk` 只给「有几个块越线」，「截图」只给「视觉哪里怪」，**都不给「哪一层容器多高、超了多少」**。

⇒ 工具支持 `SHOT_SAVE_DUMP=/path`（判据 `2931`）—— **把整棵 ARKUI 树连同 `bounds` 存下来**。
   这次第一次用它来定位版面问题。

## 二、量出来的版面（`Perspective Shift View` 竖屏 `741×832vp`）

```
root            y=  122..2496  h=2374
  Stack         y=  122..2496  h=2374
    Column      y=  122..2334  h=2212      ← 这一列本身装得下（2334 < 2496）
      Row       y=  122.. 396  h= 274      ← 头部「提示 / AI 代打」
      Column    y=  396..2298  h=1902      ← 游戏区
        Column  y=  396..2236  h=1840
          Row   y=  446.. 565  h= 119      ← 「原形」预览
          Text  y=  615.. 666  h=  51      ← 说明文字
          Row   y=  716..1804  h=1088      ← ★★ 真凶
            Column y=62..1087   x,  y=716..1804  h=1088  w=1025   ← 问题棋盘（342×363vp）
            Column y=1137..2162 x,  y=1159..1362 h= 203  w=1025
          Row   y= 1854..2496  h= 642      ← ★ 三块答案面板，**终点越过父列 2236 达 260px**
```

### 精确缺口
- 游戏区 `Column` 只有 `1840px`，而它两个 `Row` 子节点合计 `1088 + 642 = 1730px` 加间距仍超
- 三块面板的父 `Column` 底边是 `2236`，**面板实际画到 `2496`（= 屏幕最底边）** ⇒ **超出父容器 `260px`**
- 需要省的量：**`260px = 87vp`**

## 三、所以真凶是「问题棋盘 `h=1088`」，不是答案面板

我之前改的是 `mini(kind)`（答案面板）的 `constraintSize` —— **改错了对象**：
- 答案面板 `642px` 高、`679px` 宽 ⇒ `aspectRatio(1)` 实际由**宽度**决定（`226vp`），
  `constraintSize(maxHeight: 392vp)` **永远触发不到**
- 真正的挤压来自那个 `1088px`（`363vp`）的**问题棋盘** —— 它把下面的面板推了出去

## 四、下一步（交给能改版面的人，一次就能改对）

**目标**：让问题棋盘的高度从 `1088px` 降到 `≤ 828px`（省 `260px`）。
对应的代码是 `GPerspectiveShiftView.ets` 里画问题棋盘的那个容器
（树里是 `Row(62,716,1087,1804)` 左边那个 `Column`，`1025×1088`）。

三种改法，**任选其一都要真机验**：
1. 给它加 `constraintSize({ maxHeight: Math.max(200, Bp.height - 720) })`
   ⇒ 竖屏 `832−720 = 112vp = 336px`… **算过了不够**，要用 `Bp.height - 460` ⇒ `372vp = 1116px`，仍大于 1088 ⇒ **不触发**
   ⚠️ **必须让上限 < 1088px（363vp）**：即 `Bp.height - N < 363` ⇒ `N > 469`
2. 给它 `.layoutWeight(1)`（让它在剩余空间里收缩）
3. 缩小它内部格子的 `Cell.of(...)` 基数

⇒ **这次不用再猜** —— 上面每个数都是从真机树上量的。

## 五、判据

> **盲改版面的次数上限是 1 次。第二次之前，必须先把版面树 dump 下来看 `bounds`。**

⇒ 三条：
1. **`SHOT_SAVE_DUMP` 是版面问题的第一工具**，不是最后手段 ——
   `blk` 给「越线几块」、截图给「视觉哪里怪」、**只有树给「哪层容器多高、超了多少」**
2. **看树先看「父容器底边 vs 子节点底边」** —— 这次子节点 `2496` 超出父 `2236` 达 `260px`，
   一眼就看出来；而只看 `blk=4/96px` 会以为是「4 个块各多 24px」的小问题
3. **改 `constraintSize` 前先算「上限值 vs 元素实际尺寸」** ——
   这次 `392 > 226`（不触发）；`Shadow Pivot` 的 `332 < 348`（该触发却没反应）；
   `Gravity Sort` 的 `422 < 442`（触发且有效）。**三个游戏三种情况，只有算过才知道**
