# 声明 `5` 种设备，只验过 `1` 种 —— **判据 `2808`**

> `2026-11-16 09:31`。**这是「`334` 款有未测分支」那条盲区的**真实分量**。**

## 一、⇒ 项目自己声明支持五种设备

**⇒ `entry/src/main/module.json5`：**
```json
"deviceTypes": [ "phone", "tablet", "2in1", "tv", "wearable" ]
```

**⇒ 而 `Bp`：**
```ets
static isShort(): boolean { return Bp.height < 690 && !Bp.isTv(); }
static isTv(): boolean { ... }        // tv 单独一条路
```

## 二、⇒ 三条分支，只有一条被跑过

| 设备类型 | 走哪条路 | 被测量过吗 |
|---|---|---|
| `phone` | `isShort == true`（`533vp`）| ✅ **全部 `355` 款的唯一证据都来自这里** |
| `tablet` / `2in1` | `isShort == false` | ❌ **`334` 款的 `else` 分支，`0` 次** |
| `tv` | `Bp.isTv()` 单独 | ❌ **`0` 次**（无 `onemore_tv` 实例）|
| `wearable` | `isShort == true`（超小屏）| ❌ **`0` 次** |

**⇒ 也就是说：`deviceTypes` 里写了 `5` 个，而**所有测量证据只覆盖第 `1` 个**。**

## 三、⇒ 为什么这比「少测几个游戏」严重

**⇒ 少测一款 = 那一款不确定。**
**⇒ 少测一种设备 = **同一款在那种设备上的全部布局都不确定** —— 而 `334` 款都有这个分支。**

**⇒ 判据 `2799`（「我截了图 ≠ 我覆盖了场景」）的更狠版本：**

> **「我声明支持 ≠ 我验过支持」。**

## 四、⇒ 今晚的第一步（执行单里已写）

**```bash
bash 工具/test_nonshort.sh
```**
**⇒ 判据：输出 `✅ 尺寸已生效（下边界 > 2000）`。通了就说明 `wm size` 能伪造大屏，`tablet/2in1` 那条路从此可测。**

## ⇒ 判据（`2808`）

**「支持的设备类型」这张清单，每多一项就多一整套未验布局。**
**⇒ 要么验，要么在 `module.json5` 里删掉 —— ⛔ **留着不验等于对用户撒谎**。**

## 【`09:32` 更正】不是「声明了没处理」，是「**设计了四档、只验过一档**」

**⇒ 查代码发现项目**认真处理过手表**：**

> **`core/WatchGames.ets`：「手表是 `466×466` 圆形屏 …… `355` 款全塞进手表 = `355` 个坏体验 ⇒ 手表上只放『**纯点按、无大棋盘、无长文本、单屏能玩完**』的款，其余的不显示（而不是显示一个点不动的坏界面）。」**

**⇒ 而 `Bp` 有**四档**：`narrowHeight()`（`<420`，手表级）/ `isShort()`（`<690 && !tv`）/ `isWatch()` / `isTv()`。**

**⇒ 所以准确的说法是：**

| 档 | 设计 | 验过 |
|---|---|---|
| `phone`（`isShort==true`）| ✅ | ✅ **`355` 款全在这档** |
| `tablet`/`2in1`（`isShort==false`）| ✅ | ❌ **`334` 款有分支、`0` 次** |
| `tv`（`isTv()`）| ✅ | ❌ `0` 次（无实例）|
| `watch`（`narrowHeight`+白名单）| ✅ **有白名单筛选** | ❌ `0` 次 |

**⚠️ 这比「声明了没管」好得多 —— 作者想过，还专门做了取舍（白名单）。**
**⇒ 但「想过的」和「验过的」仍是两件事：`3` 档设计、`0` 次测量。**

**⇒ `2808` 修正为：**「设计了 `4` 档设备、只验过 `1` 档」** —— 不验的那 `3` 档，等于把作者的判断（白名单够不够、`else` 分支对不对）当成已证实。**
