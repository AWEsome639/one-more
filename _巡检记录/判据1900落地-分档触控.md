# 判据 1900 落地：`50` 处「可点 `32`」改成**按屏高分档**

## 改法

**`.height(Cell.of(32))` → `.height(Bp.isShort() ? Cell.of(32) : Cell.tap(32))`**

- **横屏 `533`（`isShort()` 真）**：仍用 `Cell.of(32)` ⇒ **和改前完全一样**（不改变横屏溢出修复）
- **竖屏 `744+`（`isShort()` 假）**：用 `Cell.tap(32)` ⇒ **`max(32, 44) = 44`** ⇒ **触控达标**

**⇒ 「有空间就用满、没空间才让」** —— 这正是判据 1900 要的自适应。

## 范围

**按 `ux-auditor` 的逐行清单，精确到行号替换**：
- 清单里「可点 + 值 `32`」共 **`50` 处 / `22` 个文件**
- 全部替换成功（`50` 处）

## 编译

**第一次编译失败**：`GSlide15.ets` 没导入 `Bp` ⇒ `Cannot find name 'Bp'`
**⇒ 补上 `import { Bp } from '../core/Bp';`（`1` 个文件）后通过。**

## ⚠️ 还没验的

**竖屏（`744+`）现在会走 `Cell.tap(32)` ⇒ 格子从 `32` 变 `44`** ——
**这会让竖屏的格子变高 `12vp × 行数`** ⇒ **可能把某些游戏的竖屏撑溢出**。
**⇒ 必须用「临时改 `Bp.isShort()` 返回 `false`」的办法量一遍（判据 1883）**，这是下一步。
