# `FreeCell` 横屏溢出：真 bug（有截图），但「彻底修」需要横屏重排

## 证据（两张截图）

| 时点 | 截图 | 状态 |
|---|---|---|
| **修前** | `_巡检记录/截图-FreeCell-043410.jpeg` | **槽位行高 ~`400px`，把牌堆和按钮全挤到屏外** |
| **修后** | `_巡检记录/截图-FreeCell-044342.jpeg` | **槽位行降到 `52vp`，牌堆可见了，但「重开/自动归位」仍压在牌上** |

**`max_bottom`：`1597 → 1469`**（**降 `128px`**）—— **有改善，但没修完**。

## 修前是什么样（第一张图）

- **6 个槽位一行，每个 `layoutWeight(1) + aspectRatio(1)`** ⇒ **宽度 `2500/6 ≈ 417px`** ⇒ **高度也是 `417px`**
- **⇒ 一整行槽位吃掉 `417px`（`139vp`）**，**牌堆和「重开/自动归位」全被推到屏外**
- **「重开」直接压在牌上**（**两张图都有**）

## 修了什么

```diff
- .layoutWeight(1).aspectRatio(1)
+ .layoutWeight(1)                       // 去掉 aspectRatio（判据 1822）
  ...
  Row({ space: Space.xs }) { ... }
    .width('100%')
+   .height(Cell.of(52))                 // 固定 52vp
```

**⇒ 「`aspectRatio` 是撑高祸根」判据 1822 的又一次现场**，而且这次是**「乘法」形态**：
> **`Row` 里 N 个 `layoutWeight(1)+aspectRatio(1)` 的子项 ⇒ 每个高 = `可用宽 / N`。**
> **`N` 越小编排越高：`N=6 ⇒ 417px`、`N=4 ⇒ 625px`、`N=3 ⇒ 833px`。**
> **⇒ 「横屏 `2500px` 宽」时，这类写法「几乎必炸」。**

## 为什么没彻底修（诚实说）

**`FreeCell` 的竖屏信息密度「在横屏 `533vp` 高里放不下」**：
- **3 张统计卡 + 提示/AI 两按钮 + 6 槽位 + 4 列牌堆（每列最多 8 张）+ 重开/自动归位两按钮**
- **牌堆可用高只剩 ~`66vp`**，**8 张牌每张只能 `8vp`** ⇒ **「字都看不清」**

**⇒ 「压像素」到这里就到头了**。**真正的解法是「横屏专用布局」**：
- **统计卡搬到「左侧竖排」**（**横屏左右分栏**）
- **提示/AI/重开/自动归位 收进「顶部一排小按钮」**
- **牌堆占「右侧主区」**，**筹码/牌面按「可用高 / 列内最多牌数」算**

**⇒ 这是「重排」，不是「改参数」—— 明天开一条「横屏布局重排」的活。**

## ⭐ 而这背后是「一整类」

**静态扫描：`entry/src/main/ets/games/` 里「`.layoutWeight(1)` 附近有 `.aspectRatio(`」的游戏 = `159` 款。**

**⇒ 和 goal 里那句「`165` 款横屏棋盘溢出」几乎对上了。**

**⇒ 建议的「类修法」（按风险排序）**：

| 方案 | 做法 | 风险 | 覆盖 |
|---|---|---|---|
| **A** | **`GameHost` 给游戏区包 `Scroll`**（横屏时） | **高**（`height('100%')` 的根会被「无界高」影响）| **全部** |
| **B** | **每款去掉 `aspectRatio` + 给父行固定高**（像 FreeCell） | **中**（要逐款量）| **同类** |
| **C** | **横屏专用布局**（左右分栏） | **高工作量** | **重灾款** |

**⇒ 明天先用「B」批量过「`aspectRatio` 且子项数 ≤6」的款**（**这类「高度 ≥ 417px」必炸**），
**「C」只留给「`B` 压到极限仍放不下」的（如 `FreeCell`）。**
