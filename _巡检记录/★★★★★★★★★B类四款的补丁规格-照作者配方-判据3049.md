### `Shadow Pivot` 的完整改法（唯一算完的）

```typescript
// 现在（约 line 295 附近，答案格那个）
}.width('100%') }.width(104)        // ← .width(104) 是「原形」预览，别动
// 答案格的那个容器，加：
.width(Math.min(Bp.width - 2 * Space.lg,
                Math.max(120, Bp.height - (Bp.isShort() ? 360 : 643))))
```

- **横屏**：`533 − 360 = 173vp`（与作者 `Crossword` 的矮屏取值一致）
- **竖屏**：`832 − 643 = 189vp` ⇒ 格子 `232vp → 189vp` ⇒ 两行省 `258px ≈ 缺口 260px`
- **下限 `120`** 而不是作者的 `200`：因为 `Shadow Pivot` 竖屏只能到 `189`，`200` 的下限会盖掉它

⇒ ⚠️ **`Math.max` 的下限必须小于目标值**，否则算式被下限吃掉（今天在 `constraintSize` 上栽过一次：
   上限 `332vp` 比实际 `232vp` 还大 ⇒ 摆设）。

## 七、`Simon Command` 的算式**算完了**（`16:2x` 补；原文这里是「待量」）

### 结构（`GSimonCommand.ets:283-300`）

```
Column({ space: Space.xs })
  Row({ space: Space.xs }) { …指令卡… }
  Row({ space: Space.sm }) { this.pad(0) this.pad(1) }.width('100%')   ← ★ 两行之一
  Row({ space: Space.sm }) { this.pad(2) this.pad(3) }.width('100%')   ← ★ 两行之二
  Button(TG('不做动作 ✋'))
```

`pad()`（`:332-341`）= **`.layoutWeight(1).aspectRatio(1.4)`** ⇒ **B 类**（宽由 Row 分配、高由 `aspectRatio` 定）。

### 算式

| 量 | 值 |
|---|---|
| 横屏宽 | `853vp` ⇒ 每行 `~840vp` ⇒ 每块 `~420vp` |
| `aspectRatio(1.4)` ⇒ 高 | `420 / 1.4 =` **`300vp`** |
| 两行 | **`600vp`** |
| 游戏区可用（横屏，`533 − 156` chrome）| **`377vp`** |
| ⇒ 结论 | **第二行整行屏外**（`3017` 的截图实证吻合）|

**要装下**：`2 × h ≤ 377` ⇒ `h ≤ 188vp` ⇒ 每块宽 `≤ 1.4 × 188 = 263vp` ⇒ 每行 `≤ 2×263 + 10(间距) = 536vp`。

### 改法（两行 `Row` 的 `.width('100%')` 各改一处）

```typescript
.width(Math.min(Bp.width, Math.max(200, 1.4 * (Bp.height - (Bp.isShort() ? 156 : 200)))))
```

| 形态 | 算式 | 结果 |
|---|---|---|
| **横屏 `533`** | `1.4 × (533−156) = 528vp` | 每块 `259vp` ⇒ 高 `185vp` ⇒ 两行 `370vp ≤ 377vp` **装下** |
| **竖屏 `832`** | `1.4 × (832−200) = 885vp` ⇒ `Math.min(741, 885)` | **`741vp` 原样** ⇒ **竖屏一行不动** |

⇒ 与 `Perspective Shift View` 那次一样的性质：**只改横屏分支**，竖屏零影响。

### 验证要求（比前几款更严）

`Simon Command` 是**功能性损坏**（`4` 块只够得着 `2` 块），所以验收要：
1. 横屏 `blk` 应为 `0`（现在 `72px`）
2. **截图必须看到 4 块全部完整、都能点**
3. **竖屏必须仍看到 4 块**（现在 `4.0%`，不能被这次改动弄坏）
4. 每块的高宽比仍 `1.4`（不能被压成长条）
5. 按钮「不做动作 ✋」仍在屏内、仍可点

⇒ 第 `4`、`5` 条是这次特有的：缩宽度会让 `pad` 变矮，**要确认它没矮到文字放不下**。

### 仍然没验

⇒ 算式是**读代码 + 已知测量**推出来的（`3017` 的 `pad` 可见 `215vp`、`aspectRatio` 隐含 `286vp`），
   但**没有在真机/模拟器上跑过**。按纪律：**应用前先量一次现状**，应用后再量一次，两个数配对才算证据。
