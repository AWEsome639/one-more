# `Base Conversion Run`：**真的装不下**（超 `159px`），不是调几个数字能解决的

> `2026-11-15 13:42` dump（`44` 节点）。**把预算算清了，结论是「需要设计取舍」。**

## 一、⇒ 缺陷

**`lowest='把进制换算对，答错扣 3 秒'` 位于 `y=1594-1600` ⇒ **只剩 `6px` 可见**。
而 `blk=0/0px`、`over=0`、`sumover=0` —— **三个指标全绿，一句反馈文字几乎看不见**（又一类 `blk` 盲区）。**

## 二、⇒ 预算（dump 实测）

**父容器：`Column y=381-1351 h=970px`（`323vp`）**

| 子元素 | 高度 |
|---|---:|
| `AI 代打` 行 | `114px` |
| 统计行 | `171px` |
| **题目卡片** | **`250px`** |
| 四个选项（`4 × 96`）| `384px` |
| 间隙（约）| `~120px` |
| **合计** | **`~1129px`** |
| **超出父预算** | **`~159px`** |

**⇒ 结果：那一行反馈文字被推到父界（`1351`）之外 `243px` 处，屏底只截到 `6px`。**

## 三、⇒ 为什么不能靠「缩一点」解决

| 元素 | 能否缩 | 原因 |
|---|---|---|
| 四个选项 `96px`（`32vp`）| ⛔ **不能** | **已低于 `44vp` 触控下限** |
| `AI 代打` / 统计行 | ⚠️ 有限 | 各是 `114`/`171px`，缩一点杯水车薪 |
| **题目卡片 `250px`** | ⚠️ **缩到 `~90px` 才够** | 卡片要显示 `111100₂ = ?₁₀`，`90px` 会挤死 |

**⇒ 即：**没有任何单一元素能补上 `159px`**，除非把题目卡片砍掉三分之二。**

## 四、⇒ 所以这是设计取舍，不是 bug 修复

**可选方向（需人拍板）：**
1. **把「答错扣 3 秒」这条说明并入页头 `?`**（不在主界面占位）—— **但它是 `this.msg`，同时承载答对/答错反馈，不能简单删**
2. **把四个选项改成 `2×2` 网格** ⇒ 省 `2×96=192px` + 间隙 ⇒ **单独就能补上 `159px`**
3. **接受现状**（反馈文字几乎看不见，但答题本身不受影响）

**⇒ 方向 `2` 最干净：`2×2` 选项在 `Pattern Sequence Draw`/`Fraction Matcher`/`Percentage Shopping` 已有先例
（判据 `2146` 一类的「按形态选布局」），且省下的高度**正好够**。**

## ⇒ 判据（`2723`）

**当「内容合计 − 父预算」的缺口大于**任何单一元素的合理可缩量**时，就不是调参问题，是**布局形态**问题。**
**⇒ 判据：先算缺口（dump 求和），再对照各元素的「合理下限」；
    若缺口 > 所有元素下限余量之和 ⇒ 必须换形态（如 `4` 行 → `2×2`），而不是继续微调。**

**⚠️ 今天 `Base Conversion Run` 的缺口 `159px`，而唯一可缩的题目卡片下限约 `~150px` 余量，
    但砍到 `90px` 会毁掉题目显示 ⇒ 换 `2×2` 才是正解。**
