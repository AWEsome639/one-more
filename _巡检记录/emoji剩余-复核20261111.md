## 四、替换方案：我核实过的 4 个选项

### 选项 A：`SymbolGlyph`（系统矢量符号）—— **推荐**

| 核实项 | 结果 |
|---|---|
| 项目现状 | **0 处真实使用**（`SettingsTab:1294` 那处只是**注释**，写的是 1875 那次教训）|
| SDK 是否支持 | ✅ `symbolglyph.d.ts` 存在，`SymbolGlyphAttribute` 有 10 个方法 |
| 符号名是否存在 | ✅ 我在 SDK 的 `resources.txt`（1.9MB 符号表）里逐个 grep 到：`magnifyingglass` / `bubble` / `xmark` |
| 关键 API 事实 | ① **`fontColor` 收 `Array<ResourceColor>`**（不是单色）② 尺寸由 `fontSize` 决定，`width/height` 只定占位框 ③ **`textAlign` 是 `Text` 专有**，SymbolGlyph 没有 ④ **`.mirror()` 在整个 SDK 里不存在** |

**⇒ 唯一能覆盖 🔍💬✕ 三个语义的方案。**

### 选项 B：`Image($r('sys.media.xxx'))` —— **不可行**

**核实**：全库 `Image($r(...))` **0 处**、`sys.media.*` **0 处** ⇒ 项目**零图片资源**。
要走这条路得先加图标资源（`AppScope`/`resources/base/media/`），成本远高于 A。

### 选项 C：`Path()` 自绘矢量 —— **不推荐**

**核实**：`Path(` 的命中全在 `games/` 的 Canvas 逻辑里（`ctx.beginPath()`），
**`components/` 与 `pages/` 里 0 处**。为一个放大镜手写 Path 数据不划算。

### 选项 D：文本符号（`Text('⌕')` / `Text('×')`）—— **可作为零依赖兜底**

**核实**：项目**已经在用**这个惯例 —— `Text('↻')` ×1、`Text('✓')` ×4、`Text('✕')` ×1。
**优点**：零新依赖、跨平台稳定、不引入组件布局语义（避开了 1875 那个坑）。
**缺点**：可选字形少（没有合适的「对话气泡」），且字重/对齐依赖字体。

## 五、推荐方案与三条必须的防护

**只改那 3 处图标按钮，用 `SymbolGlyph`，并必须带齐：**

| # | 防护 | 为什么 |
|---|---|---|
| **1** | **`.flexShrink(0)`** | **1875 的根因**：`SymbolGlyph` 是组件不是文字 ⇒ 在 `Row`/`Flex` 里会被拉伸，`backgroundColor` 跟着铺满 ⇒ **一大片紫色** |
| **2** | **显式 `.width()/.height()`** | 同上，给它确定的盒子；尺寸由 `fontSize` 定，`width/height` 定占位框 |
| **3** | **不用 `textAlign`** | `SymbolGlyphAttribute` 没有这个方法（只有 `Text` 有）⇒ 留着直接编译错 |
| 4 | `fontColor([...])` 用数组 | SDK 签名就是 `Array<ResourceColor>` |
| 5 | 保留 `.accessibilityText` | 这三处现在都有（项目规矩：图标按钮必须说清是干什么的）|

**另外**：`GamesTab:1726` 与 `1760` 各有一行 `.offset({ y: -1 })` ——
那是**专门补偿 emoji 字形偏下**的（判据 305 有注释）。**换成矢量符号后必须去掉**，
否则符号会反过来偏高 1vp。

## 六、我的建议（一句话）

**真正该改的只剩 3 处**（`GamesTab` 的 🔍搜索 / 💬对话找游戏 / ✕清除），
**其余 31 处保持彩色 emoji** —— 它们不是“没修完的图标”，而是这个 App 的视觉语言
（而且你已经拍定「355 款小游戏合集，彩色更活泼」）。

**方案推荐 `SymbolGlyph`**（唯一能覆盖这三个语义、且 SDK 里确认有对应符号的方案），
但**必须带 `flexShrink(0)` + 显式宽高 + 不用 textAlign**，并**去掉 emoji 时代的 `offset({y:-1})`**。
