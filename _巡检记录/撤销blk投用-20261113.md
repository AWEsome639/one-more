# 撤销：`blk` **不投用** —— 它比 `max_bottom` 更抖

## 我 45 分钟前宣布「`blk` 校准成功、投用」，**这是错的**

**队友 `82fcab75` 用台账里 `14` 条带 `blk=` 的实测（同一台机、`23` 分钟内连跑）排开一看：**

| 游戏 | `max_bottom` | `blk` 序列 |
|---|---|---|
| **`Wordle`** | `1600 → 1600 → 1600 → 1600`（**一个像素没动**）| **`1/60 → 0 → 0 → 2/48`** |
| **`Nonogram`** | `1365 → 1323 → 1323 → 1323` | **`1/60 → 1/24 → 0 → 0`** |
| `Kakurasu Sums` | `1464 → 1464` | **`1/24 → 0`** |
| `Magnets` | `1600 → 1600` | **`0 → 2/48`** |

**⇒ `max_bottom` 稳定，`blk` 在 `0 ↔ 2` 之间来回跳。**
**⇒ 抖动没有消失，只是从**叶子层**搬到了**块层** —— 块也会随浮层/键盘/提示条生灭。**

## 我的「`5/5` 校准」是**幸存者偏差**

**每款只测了**一次**。同款多跑两次就对不上（`Wordle` `1→0→0→2`、`Nonogram` `1→1→0→0`）。**

**⇒ 这正是判据 1978 说的事：单次测量不能作为证据 —— 而我用单次测量给新指标"校准"，重犯了同一个错。**

## 队友列的 `10` 条盲区（都成立）

| # | 盲区 | 后果 |
|---:|---|---|
| 1 | **`blk` 本身抖 `0↔2`** | **不能用** |

| 3 | `Stack` 在 SKIP ⇒ `28` 款根级有 `Stack` | 漏报 |

## 撤销决定

**⇒ `blk` 从「权威判据」降级为「实验性输出」**：
- **仍然打出来**（作为参考，且已证明它对**深度 ≤4 的容器类溢出**有提示作用）
- **但不再用它排序、判定、或作为「修好了」的依据**
- **权威判据回到**：**截图（人眼）> `max_bottom`（多次取中位）> `blk`（仅参考）**

## 真要修，按队友的六条建议（明天，不是今晚）

1. 文字单独一档 `blkText`（救 `215` 款）

6. 块统计**排除空容器**（只数有叶子子节点的块）
