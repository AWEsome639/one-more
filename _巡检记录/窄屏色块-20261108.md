## 1. 判据 1824：`Bp.width` 在 `@Builder` 里可用吗？——**读实现，不是看名字**

```ts
// core/Bp.ets:48 —— 字段与写入唯一入口
static update(w: number, h: number, dev?: string): void {
  if (w > 0) { Bp.width = w; }
  if (h > 0) { Bp.height = h; }
  ...
}
```
```ts
// entryability/EntryAbility.ets:150,153 —— 谁在写
Bp.update(wVp, hVp, dev);
Bp.update(px2vp(sz.width), px2vp(sz.height));   // 窗口尺寸变化监听
```

| 问题 | 答案 |
|---|---|
| `Bp` 是静态类，`@Builder` 里能读吗？ | **能**。它只是普通静态字段，`@Builder` 展开成普通 build 代码，读静态字段合法 |
| 有先例吗？ | **有**。`components/Common.ets:1250` 在 `bestText()` 里就写着 `Bp.width < 420 ? … : …`，而且它在卡片 `build()` 链上 |
| 谁保证它在设置页渲染前有值？ | `EntryAbility.onWindowStageCreate` 里先 `Bp.update(...)` 再 `loadContent` ⇒ 页面首帧时 `Bp.width` 已是真实值 |
| **有什么坑** | `Bp.width` **不是 ArkUI 的观察状态** ⇒ 窗口变宽变窄时，**只有页面因别的原因重建**才会换列。窗口 resize 本身会触发重建（本工程 `EntryAbility` 也挂了尺寸监听），所以实际可用；但**严格说这不是"响应式"** |

> 结论：**可用，且不引入新的错误类型**；只是"换列"依赖重建时机，不是数据绑定。

## 2. 本机实测：色名宽度与 elder 放大倍率（853vp，密度 3.0）

用 `uitest dumpLayout` 取**最窄的那个节点**（= `Text` 本体，不是外层 chip 格）的 bounds：

| 色名 | normal（micro=10）| elder（micro=15）| 倍率 |
|---|---:|---:|---:|
| `Как в системе` | 66.0 vp | 99.0 vp | **1.50** |
| `Индиго` | 35.7 vp | 53.3 vp | **1.49** |
| `Красный` | 42.0 vp | 63.0 vp | **1.50** |
| `Оранжевый` | 56.3 vp | 84.3 vp | **1.50** |
| **`Небесно-голубой`（最长）** | **84.7 vp** | （推算 127.0）| 1.50 |
| 格宽（cell）| **189 vp** | 185.3 vp | — |

- **elder 的放大就是 `FontSize.micro` 的 10→15 = ×1.50**（四组样本全部吻合，不是猜的）。
- 本机 853vp 下最长名占格宽 **44.8%**（84.7/189）⇒ 四列完全放得下 ⇒ **这与上一轮截图结论一致**。

## 3. 推算：360vp 手机（含 elder）的容量表

内容宽 = 屏宽 − 2×`Space.lg` − 2×`Space.md`（这两个间距在 elder 档也会变大：20→30、16→24）。

| 场景 | 内容宽 | 4 列 23% | **3 列 30%** | 2 列 45% | 1 列 100% | 俄语最长名需要 |
|---|---:|---:|---:|---:|---:|---:|
| normal | 288 vp | 66.2 | **86.4** | 129.6 | 288 | **84.7** |
| **elder** | **252 vp** | 58.0 | **75.6** | 113.4 | 252 | **127.0** |

**读法**：
- **normal 360vp**：23% 的 66.2 < 84.7 ⇒ **会截断**；**30% 的 86.4 > 84.7 ⇒ 刚好放下（余 1.7vp）** ✓ ← 这就是方案 A
- **elder 360vp**：30% 只有 75.6，**连两列 45%（113.4）都不够 127** ⇒ **只能一列才够**（252vp）——太丑
  ⇒ 所以我不降列，改成**三列 + 两行**：每行 75.6vp × 2 行 ≈ 151vp 容量 > 127vp ✓
