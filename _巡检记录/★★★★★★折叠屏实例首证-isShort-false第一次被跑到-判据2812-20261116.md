# `isShort == false` 那条路，**第一次被跑到了**

> `2026-11-16 10:04`。**`334` 款有未测分支的那条盲区，今天第一次有了真实证据。**

## 一、⇒ 怎么做到的（关键：不用下载任何镜像）

**⇒ 项目里已下载的镜像有 `phone` / `foldable` / `triplefold` / `widefold`，而 **`tablet` 没下载**。**
**⇒ 所以不去下几个 GB 的平板镜像，而是建一台**折叠屏**：**

```bash
Emulator -create onemore_fold -deviceType foldable \
  -osVersion "HarmonyOS 7.0.0(26.0.0)" -screenProfile "Mate X5"
```

**⇒ `Mate X5` = `2224 x 2496 @500dpi` ⇒ 约 **`711 × 798 vp`** ⇒ `Bp.height ≈ 798 > 690` ⇒ **`isShort() == false`** —— 正是那条从没跑过的路。**

## 三、⇒ 过程中发现的两件事（都会影响自动化）

**① 新设备第一次启动有「隐私说明」弹窗**
**⇒ `同意并继续` 按钮（原图约 `1103,1456`）不点掉，**所有 `uitest` 点击都会被它吃掉**。**
**⇒ 这正是「新实例上 `shot_game.py` 报 `NO_CARD`」的一种成因** —— 与判据 `2603` 同源：**不是游戏坏了，是没进得去**。
**⇒ 以后任何新实例，第一步先 `dump` 看有没有「隐私说明」。**

**② `shot_game.py` 的搜索框/卡片坐标是按 `2560x1600` 写死的**
**⇒ 在 `2224x2496` 上点不中 ⇒ 进不了游戏。**
**⇒ 所以要在这块屏上做**逐款测量**，得先把坐标参数化**（按 `Bp` 或按 dump 里的实际 `bounds` 找）。**
