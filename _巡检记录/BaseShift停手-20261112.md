# `Base Shift`：截图确认是**功能裁切**，但我改错了元素（第 20 次同类错误）

## 截图判定（判据 1957 的 A 类：功能被裁）

**改前截图 `Base_Shift-161716.jpeg`**：
- 题目 `₈里 32 末尾添 1 个 0 = ?`
- 选项 `A 208` / `B 26` / **`C 1664` 只露顶边** / **`D` 完全在屏外**
- **⇒ 玩家只有 2 个选项可选，游戏玩不了**

**⇒ 这是「功能被裁」，优先级最高。**

## 我改了什么（**改错了**）

`GBaseShift.ets` 里只有一处 `.height(Cell.of(46))`（`L532`），我把它改成矮屏 `Cell.of(30)`。
**改后截图 `Base_Shift-162916.jpeg`：选项行反而**更高**了（`A 63612` 那行约 `110px`），`C` 仍被切。**

**⇒ 说明 `L532` 不是选项行的修饰** —— 选项在 `ForEach` 里，高度可能来自 `Cell.of(52)`（`L495`）或另有出处。

**⇒ 已回退**（判据 1869：一款两次没成先停）。

## 下次的正确做法（明确到步骤）

1. **先 `probe_batch "Base Shift"`**，看「最靠下 4 个」里 `A/B/C/D` 那些 `Row` 的高度是多少像素
2. **按那个高度反推**它对应 `Cell.of(N)` 里的哪个 `N`（`px ÷ 3 ÷ 0.85`）
3. 再 `grep` 那个 `N`，找到**在 `ForEach` 内**的那一处

**⇒ 又是判据 1932：先拿 `bounds`，别猜。**

## `probe` 拿到的精确数字（补上最后一环）

```
Column h=492 y=[1108..1600]   ← 选项区总高 492px
Row    h=132 y=[1468..1600]   ← 单个选项行：132px
Text   '183' / 'C'            ← 行内文字
```

**⇒ 选项行 `132px = 44vp = Cell.tap(44)` —— 触控下限，不能缩（判据 1899）。**
**⇒ 4 行 × `132` = `528px` > 可用 `492px` ⇒ 超出 `~120px`。**

**⇒ 唯一杠杆在**上方**：题目卡 `Column h=250 y=[810..1060]`（`250px`）。**

### 下次的具体改法（不用再猜）

**题目卡里那句话 `₈里 32 末尾添 1 个 0 = ?` + 副行 `第 1/10 题 · 生命 ❤❤❤`** ——
**副行是纯状态重复（页头已有 `题号 1/10`、`答对 0/7`），矮屏可隐藏，省 `~30px`；**
**再收题目卡的 `padding` 与根间距，凑够 `120px`。**

**⇒ 这是一款「选项行不可缩、只能从上方腾」的典型** ⇒ 归入判据 1957 的处理方式：
**先确认底部是什么（`Cell.tap` 就放弃缩它），再往上找可砍的块。**
