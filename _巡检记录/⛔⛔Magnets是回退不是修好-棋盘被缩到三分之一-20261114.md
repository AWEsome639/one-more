# ⛔⛔ `Magnets` 是**回退**、不是修好 —— 我把棋盘缩到了可用宽度的 `1/3`

> `2026-11-14 23:4x`。看 `截图-Magnets-210739.jpeg` 才发现。**这条必须立刻纠正记录。**

## 一、⇒ 截图里是什么样

- **`4×4` 棋盘全在**屏幕左侧**，四列格子只占到约 `30%` 宽度**
- **右边 `~70%` 是一片空黄底**
- **右侧 `4` 个线索格（`2+ 现 0`）与底部线索行（`3+ 1+ 1+ 3+`）都在**
- **内容一处不缺、`blk=8px`**

## 二、⇒ 为什么变成这样

**我的修法是给格子加：**

```typescript
.constraintSize({ maxWidth: Bp.isShort() ? 50 : 9999 })
```

**⇒ 每格被限制成 `50vp` 宽 ⇒ `4` 列只有 `200vp`，而这一行可用的横向空间约 `460vp`。**

**⇒ 于是 `layoutWeight(1)` 不再起作用（`maxWidth` 先卡死了），整个棋盘缩成左边一小块。**

**⇒ `blk` 从 `48px` 降到 `8px` —— 指标好了，**但画面变差了**。**

## 四、⇒ 明天怎么修才对

**目标：格子要**铺满可用宽度**、同时整个棋盘不超过一屏。**

**⇒ 不该限制格子 `maxWidth`；应该限制**整个棋盘容器**的尺寸：**

```typescript
// 错（今天）：格子层加 maxWidth ⇒ 格子变小、棋盘缩成一块
.constraintSize({ maxWidth: 50 })

// 对（明天）：棋盘容器层给 maxWidth + aspectRatio(1)，让格子跟着铺满
Column() { ... }.width(Math.min(Bp.width - 2*Space.lg, Bp.height - 368)).aspectRatio(1)
```

**⇒ 参照已修好的 `GMatrixReasoning`（`L394`：`.width(Math.min(Bp.width - 2*Space.lg, Math.max(145, Bp.height - 388))).aspectRatio(1)`）——
   那是**容器定尺寸、格子 `layoutWeight(1)` 自适应**，棋盘会铺满且不超屏。**

**⚠️ 而那 `8px` 溢出可能根本不是棋盘造成的 —— 是底部线索行。明天先量清楚再改。**

## ⇒ 判据（`2658`）

**`constraintSize({ maxWidth })` 加在**格子**上会让 `layoutWeight(1)` 失效 ⇒ 棋盘缩成一块、留下大片空白。**
**⇒ 判据：要让棋盘变小又不留白，必须限制**容器**（配 `aspectRatio`），而不是限制每个格子；
    格子层只该用 `layoutWeight(1)`。**
