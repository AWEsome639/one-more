# 两个「我」同时开模拟器 ⇒ `319%` CPU，机器直接吃不消

> `2026-11-17 10:37`。**奥森原话：「怎么同时开两个模拟器呀……电脑真吃不消」。他是对的。**

## 一、⇒ 实测

**⇒ `ps axo pid,pcpu,comm | grep -i emulator`：**
```
 7610  69.1 /Applications/DevEco-Studio.app/Contents/tools/emulator/Emulator
26361 319.7 /Applications/DevEco-Studio.app/Contents/tools/emulator/Emulator
```
**⇒ 两个实例，一个 `69%`、一个 **`319%`**。后者就是让他卡的那个。**

## 二、⇒ 为什么我没发现

**⇒ 我一直在用 `pgrep -f "qemu-system"` / `pgrep -f "Emulator -start"` 判断「有没有模拟器在跑」—— **这两个都匹配不到**。**
**⇒ 判据 `2818` 早就记过这件事（`pgrep -f qemu-system` 返回 0 而模拟器在跑），**我今天又踩了同一个坑**。**
**⇒ 正确的查法（已验证）：**
```bash
ps axo pid,pcpu,comm | grep -i emulator | grep -v grep
```
**⇒ 或者干脆 `hdc list targets`（但那是「设备在不在」，不是「进程在不在」）。**

## 三、⇒ 为什么会同时开两个

**⇒ 今天有两个「我」在同一台机器上（一个做 One More，一个清磁盘）⇒ 各自都可能有 `Emulator -start`。**
**⇒ 而这种冲突**不会报错**：第二个 `-start` 只是又起一个实例，两边各自以为「只有一个在跑」。**

## 四、⇒ 处置与预防

**⇒ 处置（已做完）：先 `$EMU -stop onemore7` / `-stop onemore_fold` ⇒ 剩下一个不理 SIGTERM 的孤儿再 `kill -9`。**
**⇒ 预防：**
1. **开模拟器之前**先 `ps axo comm | grep -i emulator`**，有就**不要再开****
2. **收工时**同样查一遍，**确认 `剩余 0`** 才算收干净
3. **两个「我」协同时**，模拟器这种独占资源要**先问一句「你那边在用吗」**

## ⇒ 判据（`2852`）

**「我以为没有」比「确实没有」危险得多。**
**⇒ 用错的检查命令（`pgrep -f qemu-system`）得到的「0」，会让我放心地再开一个 —— 而机器已经在冒烟了。**
