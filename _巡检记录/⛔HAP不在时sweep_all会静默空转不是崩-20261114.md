# ⛔ HAP 不在时 `sweep_all` 会**静默空转**，不是崩

> `2026-11-14 21:x`。查 HAP 路径引用时发现的降级路径。

## 一、⇒ 代码

```python
# sweep_all.sh:44-47
try:
    _hap_ts = os.path.getmtime('entry/build/default/outputs/default/entry-default-signed.hap')
    BASELINE = time.strftime('%Y-%m-%d', time.localtime(_hap_ts))
except Exception:
    BASELINE = ''
```

**⇒ HAP 不在 ⇒ `BASELINE = ''`**（`getmtime` 抛 `FileNotFoundError` ⇒ 被 `except` 吃掉）。**

## 二、⇒ 而后续逻辑是「行日期 >= 基线」

**`BASELINE = ''` ⇒ 空字符串比任何 `2026-11-14…` 都小 ⇒ **每一行都满足 `>=`** ⇒ **所有款都被当成「已测」**。**

**⇒ ⇒ 于是 `sweep_all` 会**什么都不跑、正常退出**（`06:45` 前就结束）。**

## 三、⇒ 所以这是「静默空转」

| 若 HAP 不在 | 表现 |
|---|---|
| 崩掉 | ❌ 不会崩（有 `try/except`）|
| **跑 0 款** | ✅ **会 —— 而且不报错** |
| 明早看台账 | **没有新行 ⇒ 会以为「跑批没生效」⇒ 去查别的原因** |

**⇒ ⇒ 这比崩更危险：崩了会看到错误，空转会让人以为是别的问题。**

## 四、⇒ 今晚不受影响

**HAP 已确认存在（`44.4 MB`、`11-14`）⇒ 走 `try` 分支 ⇒ 正常。**

## 五、⇒ 但值得改（下次）

**建议：`except` 里改成「报错退出」而不是「静默置空」：**

```python
except FileNotFoundError:
    sys.exit('❌ HAP 不存在：entry/build/…/entry-default-signed.hap ⇒ 先编译')
```

**⚠️ 但现在不改（判据 `2314`：关键运行前只做已验证的改动）。**

## ⇒ 判据（`2430`）

**`try/except` 把「致命缺失」降级成「空值」时，要问「空值会让后续逻辑以为『都正常』吗」。**
**⇒ 这次 `''` 让「全都已测」⇒ 静默空转。**

**⇒ 判据：写兜底时，宁可**明确失败**（`exit 1`），不要「给个空值继续跑」。
⇒ 空值往往让下游判定反了，而错误信息消失。**

## ⇒ 判据（`2431`）

**而今晚能不能跑，除了看「脚本有没有崩」，还要看「**它跑了几款**」。**
**⇒ 若「正常退出但台账没新行」⇒ 先查 HAP 与 `BASELINE`，别先查模拟器。**

**⇒ 判据：批处理的健康判据是「跑了多少」，不是「有没有崩」。**
