# ⛔ `Countdown Math`：隐藏底部规则文字**无效** —— 腾出的空间又被吃掉

> `2026-11-15 12:27` 真机实测（HAP `46550492`）。**今天第三次「小改被吸收」，已回滚。**

## 一、⇒ 改法

**`GCountdownMath.ets:634` 有一行纯静态规则说明（无状态、无反馈）：**

```typescript
Text(TG('除法只在整除时可用')).fontSize(FontSize.xxs)...
```

**⇒ 用 `if (!Bp.isShort())` 包住 ⇒ 矮屏不渲染，**预期给它下面的 `提示` 按钮让出约 `39px`**。**

**⇒ 高度**一个像素都没变**。**

## 三、⇒ 为什么

**底部那一行的高度不是「内容加起来」决定的，而是被上方的 `layoutWeight` 元素**重新分配**掉的。**
**⇒ 我拿掉 `39px` 的文字 ⇒ 上方元素多吃 `39px` ⇒ 按钮位置不动。**

**⇒ 这已经是今天第三次同类失败：**
1. `Magnets` 缩棋盘 ⇒ 只移 `3px`（判据 `2684`）
2. `Pipes` 缩格子 ⇒ 底部整行消失（判据 `2694`）
3. `Countdown Math` 隐藏文字 ⇒ `0px` 变化（本次）

## ⇒ 判据（`2715`）

**在「页面高度已被 `layoutWeight` 填满」的布局里，**移除任何小元素都不会给它下面的元素让位**——
空间会被上方可伸缩元素立刻吃掉。**
**⇒ 判据：要移动底部元素，必须**改分配规则**（给容器定高 + 行 `layoutWeight`，`Pipes` 配方），
   而不是「拿掉一点内容」。**
**⇒ 三次失败的共同点：都在「拿掉/缩小一点」，而没有改「谁分配空间」。**

## 四、⇒ 所以 `4` 处被切按钮的正确修法统一了

**`Wordle` / `Kakuro` / `Countdown Math` / `Snake 3D` 四处，都必须：**

1. `dump` 拿到「底部行所在容器的**确定高度**」与「它上方各元素的高度」。
2. **给底部行一个确定高度**（“我先占住 `132px`”）。
3. **让它上方的元素去吃剩下的**（`layoutWeight(1)` 给上方容器）。

**⇒ 即「先保底部、再分剩余」，而不是「先排上方、余下给底部」。**
