# `Kakurasu Sums` 的精确坐标（明天的明确打法）

## dump 实测：游戏区内容的四块

```
Column [381..1351]                     ← 游戏区内容（高 970px = 323vp）
  Row    h=114  y=[ 387.. 501]         ← 统计卡（黑格/达标线/步数）
  Row    h=171  y=[ 507.. 678]         ← 提示 + AI 代打
  Column h=810  y=[ 684..1494]         ← ★ 棋盘：810px = 270vp（**空间占主**）
  Row    h=100  y=[1500..1600]         ← 底部工具栏（涂黑/擦白 + 提示）
```

**屏幕可用区到 `y=1516`**（之前量过），**而工具栏在 `1500..1600`** ⇒ **只露出 `16px`** —— 这就是截图里「只露上半截」。

## 算式（明天直接照做）

| 项 | 值 |
|---|---:|
| 需要腾出 | **`~84px`（`28vp`）** |
| 棋盘是几行 | `5~6` 行（截图数） |
| **每行要减** | **`84 ÷ 6 ≈ 14px` ≈ `4.7vp`** |
| **对应改法** | 棋盘格 `Cell.of(N)` 的**矮屏分支**从 `34` 再降到 **`28`** |

**⇒ 若 `Cell.of(34)` 是现在的矮屏值，改 `Cell.of(28)` 就够**（`6vp × 6 行 = 36vp = 108px`，留 `24px` 余量）。

## 判据 1939（把 1938 量化）

> **`bounds` 的差值直接告诉你「每行该减多少」**：
> **`需要腾出的像素 ÷ 行数 = 每行要减的像素`**，再除以 `3`（`@3x`）就是 `vp`。
>
> **⇒ 这样“改多少”不用猜，`dump` 一次就能算出来。**
>
> **依据**：`Kakurasu Sums` 需要 `84px`、`6` 行 ⇒ `14px/行` ⇒ `4.7vp/格` ⇒ **从 `34` 改到 `28` 就有余量**。
> **而我今晚两次「凭感觉缩」都没量出这个数，所以都没改对。**
