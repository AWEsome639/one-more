## 模板（三刀，全部是「零风险」的密度压缩）

```ts
// ① 统计卡：竖排 → 横排（标签左 / 数值右）
- Column({ space: 2 }) {
+ Row({ space: Space.xs }) {
    Text(label).fontSize(FontSize.xxs)...
    Text(value).fontSize(FontSize.lg)...
  }
- .padding(Space.sm)
+ .padding(Space.xs)
+ .justifyContent(FlexAlign.SpaceBetween)

// ② 根 Column 间隙降一档（sm 10 → xs 6；7 个子块 = 6 个间隙 ⇒ 省 24vp = 72px）
- Column({ space: Space.sm }) {
+ Column({ space: Space.xs }) {

// ③ 次级说明行：矮屏不渲染（比「裁一半」好）
+ if (!Bp.isShort()) { Text(长说明).fontSize(FontSize.xxs)... }
```

**⇒ 三刀合计 `~150–190px`，`Go 9x9` 与 `Double Trouble` 都一次过。**

## ⚠️ 但「模板不是万能的」—— 判据 1851 的教训

**`FreeCell` 用同一套三刀后仍是 `1361`（数字上 OK），但「重开/自动归位」压在牌堆上**：
- **因为它的信息密度是「3 卡 + 6 槽位 + 4 列牌 × 8 张 + 2 按钮」** —— **压到极限仍塞不下**
- **⇒ 这类要「横屏左右分栏重排」，不是「三刀」能救的**
