# ⛔ 用 `mtime` 严谨核实：**`0` 张截图晚于当前 HAP**

> `2026-11-14 17:4x`。把我先前「按文件名时间比较」的错误方法纠正了。

## 一、先前的方法错在哪

**截图文件名是 `截图-<safe>-HHMMSS.jpeg` —— **只有时分秒、没有日期**。**
**⇒ 我用 `HHMMSS > '073100'` 判断「晚于 `07:31`」⇒ 会把 `11-13` 的 `21:03` 也算成「新」。**
**⇒ 实测因此得出「`73` 张新截图」——错的。**

## 二、⇒ 正确方法：文件 `mtime`

```python
hap = os.path.getmtime('entry/build/…/entry-default-signed.hap')   # 11-14 07:31
shots = {name: os.path.getmtime(path) for …}
fresh = [n for n,t in shots.items() if t >= hap]
```

**⇒ 结果：**
```
当前 HAP mtime:        11-14 07:31
晚于当前 HAP 的截图:   0 张 / 195 款
```

**⇒ ⇒ **`555` 张截图（覆盖 `195` 款）全部来自当前构建之前。***

## ⇒ 判据（`2302`）

**判断「证据是否新鲜」必须用**文件的 `mtime`**，不能用文件名里的时间片段 ——
文件名可能只有时分秒（没有日期）、可能是生成时刻而非构建时刻。**

**⇒ 这次我按文件名比，得出「`73` 张新图」；按 `mtime` 比，是 `0` 张。**

**⇒ 判据：比「谁更新」时，两个对象一定要用**同一种时钟**（都用 `mtime`，或都用 git 提交时间）。
⇒ 拿「文件名的字符串」和「另一个文件的 `mtime`」比，是两种时钟混用。**
