## 2. 三层结论（今晚的完整证据链）

| 层 | 结论 | 证据 |
|---|---|---|
| 数据层 | **正常** | `diag: refresh … initMs=1022`（值确实变了）、`rev=2`（版本号确实变了） |
| 组件重建层 | **断的** | 标题 `AI 诊断 1` → 点击后仍是 `1`；标题区域**像素差 0** |
| `@Builder` 层 | **正常** | 页面重建（退出再进）时卡面能显示新值 `1034` |

⇒ 问题被夹在「**`@State` 赋值 → 组件重建调度**」这一层。

## 3. 终解（**明天做，今晚只定案**）

**把 `LocalLLM.stat` 五个字段写进 `AppStorage`，卡片用 `@StorageProp` 读** —— 真观察源，不依赖手动重建调度。

```ts
// LocalLLM.init()/chat() 的写入点（4 处）里同步：
AppStorage.setOrCreate('llmReason', LocalLLM.stat.reason);
AppStorage.setOrCreate('llmInitMs', LocalLLM.stat.initMs);
// … calls / ready / firstTokenMs

// SettingsTab：
@StorageProp('llmReason') llmReasonV: string = 'idle';
@StorageProp('llmInitMs') llmInitMsV: number = 0;
// 卡片直接用这些，不再依赖 refreshDiag() 手动抄
```
⚠️ 注意：`@StorageProp` 变化**会**触发重建（这是框架保证的），
但**前提是它被读在 `build()` 或参与渲染的属性里** ⇒ 终解实施后仍需用**同一套像素差分**验一次。
