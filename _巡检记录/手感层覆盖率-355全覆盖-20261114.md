# 「每一帧」的另一面：**手感层 `355/355` 全覆盖** —— 而 `3` 款「没有动画」是假阴性

> 目标里「每一帧、每一处细节都值钱」。我今天一直在看**布局**，这一轮看**手感**。

## 一、覆盖率（`grep -rl` 实测）

| 机制 | 覆盖 | 意义 |
|---|---|---|
| **`stateStyles({ pressed })`** | **`355 / 355`** | **每次按压都有缩放/变色反馈** |
| **`Haptics.*`** | **`355 / 355`** | **每次点击都有振动** |
| `.animation(` 声明式动画 | `352 / 355` | 见下（不是缺口）|

**⇒ 前两项 `355/355` ⇒ 手感层**不缺任何一款**。**

## 二、那 `3` 款「没有 `.animation(`）是**假阴性**

**它们是 `GDoodleJump` / `GFlappy` / `GPong` —— **全部是实时街机类**。**

**⇒ 查了驱动方式：每款都有 `setInterval` 游戏主循环**
```
GFlappy:152   this.timer = setInterval(() => { ... })
GDoodleJump/GPong  各 2~3 处 setInterval/setTimeout
```

**⇒ 实时游戏靠**状态每帧更新**来动，不需要声明式 `.animation()`。**

**⇒ 所以这不是缺口，是**两种动画范式**：**
| 范式 | 用在哪 | 机制 |
|---|---|---|
| **声明式**（`.animation()`）| 回合制（`352` 款）| 属性变化自动补间 |
| **状态驱动**（`setInterval`）| 实时街机（`3` 款）| 每帧改 state ⇒ 重渲染 |

## 三、这条判据要记（防止未来的我误报）

> **`grep '\.animation('` 少了 `3` 款 ≠ 少了 `3` 款动画。**
> **实时游戏（`Doodle Jump` / `Flappy` / `Pong`）本来就靠主循环驱动。**

**⇒ 这又是一次「**差点误报**」：如果我不查 `setInterval`，就会写「`3` 款游戏没有动画，需要补」。**
**⇒ 而实际上它们**动得比其他 `352` 款都多**。**
