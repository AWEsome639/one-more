# 判据 3068：**解锁用的 `swipe` 会误聚焦搜索框，键盘盖住结果**（我自己造成的）

## 一、现象

夜间扫描中途失败率升到 `40%`，失败形态是：
```
NOT_HOME   could not reach home; last texts=[]
TIMEOUT    budget exhausted at enter-game
DUMP_FAIL  no in-game dump
```

`last texts=[]` 的意思是**屏幕上读不到任何文字**。

## 二、截图一看就明白

屏幕上是：
```
[搜索框]  视角切换
1 款
[卡片]  视角切换 / 换视角看        ← 结果卡片
[ 英 文 键 盘 ]                    ← ★ 整个键盘盖在下面
```

⇒ **键盘开着**，把结果卡片挡住了 ⇒ 工具读不到卡片 ⇒ `last texts=[]`。

## 三、根因是**我自己的解锁动作**

我为了解锁跑的：
```bash
hdc shell "uitest uiInput swipe 1280 1400 1280 300 300"
```
这条**从屏幕中部往上滑**刚好划过首页的搜索框 ⇒ **把搜索框聚焦了** ⇒ 键盘弹出、
而且之后没有任何操作去关它。

⇒ 屏幕本身没睡（截图暗像素 `0%`），所以「以为是休眠」是错的 —— **是键盘**。

## 四、修法

```bash
hdc shell "uitest uiInput keyEvent Back"    # ×2，关键盘
```
⇒ 关掉后结果卡片立刻完整可见，扫描自行恢复。

**以后解锁请不要往上滑**：改用
```bash
power-shell setmode 602 && power-shell wakeup
uitest uiInput keyEvent Back        # 或直接不滑、只 wakeup
```
—— 解锁不需要滑动，滑动反而会误聚焦。

## 五、顺带：`setmode 602` 在模拟器重启后会丢

`AC` 常亮是**实例级**设置。今晚模拟器重起过一次，之后我没重设 ⇒ 这也是「以为是休眠」的诱因之一。
⇒ **每次重启模拟器后都要重跑 `power-shell setmode 602`**。

## 六、判据

> **「读不到文字」有三种原因：屏幕睡了、app 崩了、被输入法盖住。
> 前两个看截图能立刻区分，第三个只有截图能看出来 —— 而且它可能是「你自己上一次操作」留下的。**

⇒ 四条：
1. **`last texts=[]` 先截图**，不要先怀疑工具或游戏
2. **解锁别用 `swipe`** —— 会误聚焦搜索框；`wakeup` + `Back` 就够
3. **`setmode 602` 是实例级的**，模拟器重启后要重设
4. **自己刚做的 UI 操作要记着**：这次 40% 失败是我 20 分钟前那次 swipe 留下的，不是游戏的问题
