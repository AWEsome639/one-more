# 判据 1813 / 1814（2026-11-08 立）

## 1813 · 验「首帧卡片数」必须先收起筛选面板

**来源**：perf-hunter 在验 `LazyForEach` 首帧卡片数时，12:51 冷启有 8 张、13:01 冷启 0 张 —— 他一度以为网格坏了。

**真因**：**筛选面板冷启时可能默认展开**（`按喜好挑游戏, 收起 ▲`）⇒ 面板占满列表区
⇒ **`Grid` 节点根本不存在** ⇒ 0 卡。**这是布局设计，不是渲染失败**。

**判据**：**验「首帧卡片数」之前，先 `dump` 确认面板是「展开 ▼」（收起态）**，
否则量到的是「面板态」，会误判成网格坏了。

---

## 1814 · 验真机前先 dump 确认「语言=中文、页面=游戏页」

**来源**：今早设备被别的 agent 切成 **阿语 + RTL + 设置页**，perf-hunter 一上来就量错。

**判据**：**每次真机验证前，先 `dump` 两件事**：
1. **语言** —— 有 `全部` / `经典` 这类中文芯片才算中文
2. **页面** —— 有 `One More` / `355 款` 才算首页

否则量的是别人留下的状态。

---

## 为什么这两条值得立

**它们都不是「app 的 bug」，而是「验证方法会骗人」**。

今天已经栽过 3 次：
- `cachedCount` 在 Grid 下是死配置（**但 List 下有效** —— perf-hunter 自己纠正了第一版）
- `uitest dumpLayout -p <固定路径>` **超时会读到旧文件**（**perf-hunter 误判过多次页面状态**）
- `input keyevent 3` **不可用但不报错**（**判据 1809**，我第一次也差点拿假数据交差）

**共同点**：**命令没生效 / 状态不是我以为的，但都不报错**。
