# 端侧 LLM（第八个想法 v2）：**我决定归档，不做**

> **依据**：他说过「你就是我，可以为我做决定」，而只有两件事该找他（验证码 / 钱）。
> **这一项既不需要他刷脸也不需要充值 ⇒ 属于我该拍的板。**
> **⇒ 而它已经悬了好几天 ⇒ 再悬着就是拖延。**

## 一、为什么不做（四条，按权重）

### ① 硬门槛：API 版本不够

**`core/LocalLLM.ets`（`230` 行）需要 `API 20+`，而项目是 `compatibleSdkVersion 5.0.0(12)`。**

**⇒ 要抬到 API 20 意味着：**
- 抬 `compatibleSdkVersion` ⇒ **所有 `355` 款游戏都要重新过 API 兼容检查**
- 而我今天刚做完 `37` 处布局改动、**还没验证**
- **在未验证的改动上叠加一次 API 大版本跳跃 ⇒ 出问题时无法归因到哪一层**

**⇒ 判据：**不在未验证的改动上叠加新的不确定性。****

### ② 模型从哪来，是产品依赖不是技术问题

**端侧 LLM 需要一个模型文件（`0.5B~2B`，`300MB~1.5GB`）。**
**⇒ 三种来源都不干净：**
| 来源 | 问题 |
|---|---|
| 打进 HAP | HAP 现在 `46MB` ⇒ 涨到 `350MB+`，**安装包体积翻 7 倍** |
| 首次启动下载 | 需要**托管服务器**（谁的机器？谁付带宽？）|
| 让用户自己导入 | **普通用户做不到** ⇒ 等于没有 |

**⇒ 而这是**产品决策**（谁承担 350MB 或谁托管），不是我在代码里能解决的。**

### ③ 现有降级已经完整

**`LocalLLM` 自己写着完整的降级路径 ⇒ **没有 LLM，功能一个不缺**。**
**⇒ 端侧 LLM 的收益只是「智能搜索的质量」⇒ 而 `0.5B` 模型在手机上生成的中文/日文，
未必比现在的规则版更好。**

**⇒ 判据：**收益不确定 + 成本确定 ⇒ 不做。****

### ④ 我今天有更值钱的活

**`37` 处改动今晚要验，明天还有逐款 `X` / `GFindWord` 减列 / `Gomoku` 盘面。**
**⇒ 那些是**已经在做的、有明确收益的**；端侧 LLM 是**从零开始的、收益不确定的**。**

## 二、所以我的决定

| 项 | 决定 |
|---|---|
| **端侧 LLM** | **归档，不做** |
| `LocalLLM.ets` | **保留**（降级设计完整，将来 API 抬上去就能接）|
| 文档 | 本文即为决策记录 |
| **重新考虑的条件** | **① 项目抬到 API 20 以上；② 有稳定的模型托管；③ 布局工作全部收口之后** |

## 三、这条决定对 objective 的影响

**objective 第 `4` 项从「仍卡在 API 20，需换路线验证」变为：**
**⇒ **「已决策归档（三条前提均不满足）」** ⇒ **不再是待办。**

**⇒ 于是 objective 的五项里，只剩两项待做：**
- **第 `1` 项**（布局）⇒ **今晚验证 `37` 处**
- **第 `5` 项**（收尾）⇒ **两项缺硬件（TV / 第二台设备），emoji 低优先**

**⇒ 而第 `2`、`3` 项今天已完成 / 已推进到 `48.6%` 且今晚会跑到 `86~92%`。**
