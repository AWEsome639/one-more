
# ★★★★ `Kakuro Mini` 升级：**半副键盘在屏外**（`6/7/8/9/删除`），不是「缺一个键」

> `2026-11-14 12:3x`。判据 `2204`（回代码找构造处）的执行结果。

## 一、代码

```ts
// 数字键盘（L576）
Row({ space: Space.xs }) {
  ForEach([1, 2, 3, 4, 5], (d: number) => { this.keyBtn(d) })
}
Row({ space: Space.xs }) {
  ForEach([6, 7, 8, 9], (d: number) => { this.keyBtn(d) })
  this.delKey()                      // ← 删除键也在第二行
}
```

**⇒ 键盘是**两行**：第一行 `1-5`，第二行 `6/7/8/9/删除`。**

## 二、而实测

```
lowest = '6'   bounds y 1588-1600  ⇒ 可见高度 12px
```

**⇒ `'6'` 是第一行之后的**第二行第一个键**。

**⇒ 既然它 `y1 = 1588`（`529vp`），而屏高 `533vp` ⇒ 第二行整行都压在底部。

**⇒ 也就是：`6`、`7`、`8`、`9`、**删除**五个键，全在屏幕边缘或屏外。**

## 三、⇒ 后果：从「缺一个键」升级为「半副键盘不可用」

| 之前判 | 现在 |
|---|---|
| 「缺一个数字键」⇒ 有替代（其他格还能填）| **缺 `6/7/8/9` + 删除** ⇒ **超过 `5` 的数填不了、填错删不掉** |

**⇒ `Kakuro` 类谜题的答案常常是两位数（`6`–`9`、`10+`）⇒ **缺 `6/7/8/9` 等于无法完成大部分题。**
⇒ 加上**删除键也不可用** ⇒ 一旦手滑就再也改不回来。**

**⇒ 所以它应与 `Magnets` 同级：都是「玩不了」。**

## 四、⇒ 严重性重排（功能级 `5` 款）

| 序 | 游戏 | 缺什么 | 替代路径 |
|---|---|---|---|
| `1` | **`Magnets`** | 行列提示（规则信息）| 无 |
| `2` | **`Kakuro Mini`** | **`6/7/8/9` + 删除键** | **无（两位数题做不了、错了改不回）** |
| `3` | `Pythagorean Triple Builder` | 确认键 | 无（交不了）|
| `4` | `Fraction Matcher` | 三个选项 | 部分（能猜 `A`）|
| `5` | `Percentage Shopping` | 选项值 | 有（看题推）|

**⇒ `1`–`3` 都是「无替代」⇒ 都该按最高优先处理。**

## 五、⇒ 它的修法也要重估

**先前我说「减元素」但没算够。现在要腾出的量更大：**
```
第二行键盘 ~45vp（每键 Cell.tap(44)）+ 与第一行间距 ~8vp = ~53vp
而当前它压在屏底 ⇒ 至少要腾出 53vp 才能让整行可见
```

**⇒ 三档可能：**
1. **键盘改一行**（`10` 个键挤一行 ⇒ 每键 `~34vp` < 触控下限，不理想）
2. **键盘改横向滑动单行**（只露 `4-5` 键，可滑）
3. **把键盘移到顶部/浮动层**（不占垂直空间）
4. **减上方元素腾 `53vp`**（需查它上方有什么）

**⇒ 状态：**需读全布局 + 需 `board=` 数据**。但修法性质已定：必须动结构。**

## ⇒ 判据（`2206`）

**「缺一个键」与「缺半副键盘」的差别，靠**数那一行有几个**才能看出来。
⇒ 这次 `lowest` 只给了 `'6'` 一个字符，看不出它背后还有 `7/8/9/删除`。**

**⇒ 判据：被裁文字若是**同一容器里的一组元素**，要看**那一组有几个**，
而不是只看露出来的那一个。⇒ 而「那一组有几个」只有读代码（`ForEach([6,7,8,9])`）才知道。**

## ⇒ 判据（`2207`）

**一个被裁元素若是「删除/撤销」类，严重性额外加一档 —— 因为它让错误不可恢复。**
**⇒ 这次删除键也在第二行 ⇒ 玩家填错后改不回来 ⇒ 不只是「少功能」，是「错误会被永久保留」。**

**⇒ 判据：评估功能缺失时，单独看「有没有撤销/删除路径」。
没有 ⇒ 用户一旦出错就只能重开。
