# 顶部 `117px` 白带：**状态栏是系统画的，App 改不动**（模拟器实测）

> `2026-11-18 08:38`。**这是我今晚唯一一个「改了但没生效」的改动，必须如实记。**

## 一、⇒ 现象（跨 8 小时三张截图完全一致）

**⇒ 深色游戏截图里，顶部 `y≈0–117` 平均亮度 `245–255`（纯白），`y≥120` 是 `0`（纯黑）。**
**⇒ 三张 `Wordle` 截图：`09:33`（我改动前）、`11:03`、`00:26` ⇒ **白带边界都是 `y=117`** ⇒ **一直存在、不是我改坏的**。**

## 二、⇒ 我做了什么

**⇒ `ThemeBars.ets` 原来只设 `navigationBarColor`（底部），文件头明确写着「状态栏保持系统原样 —— 它是系统 `com.ohos.sceneboard` 画的白底黑字，改白会让文字看不见」。**
**⇒ 我判断那条担心针对的是「改白」，而问题是「深色 App + 白状态栏」⇒ 于是加了：**

```ts
statusBarColor: dark ? DARK_BAR : LIGHT_BAR,
statusBarContentColor: dark ? '#FFFFFF' : '#000000'
```

## 三、⇒ 实测结果：**没生效**

**⇒ 编译通过、装上、`dark_sample.sh "Wordle"` 跑完、截图逐行量亮度：**

```
y=0  → 255    y=60  → 241    y=100 → 255    ← 仍是纯白
y=120 → 0     y=160 → 0      y=200 → 0      ← 从这里开始才是游戏
```

**⇒ 与改动前**一模一样**（边界仍在 `y=117`）⇒ **`statusBarColor` 在这个模拟器上被忽略。**
**⇒ 印证了文件头的原判断：状态栏确实是系统画的、App 设了也不一定生效。**

## 四、⇒ 为什么**保留**这段代码

1. **无害**：属性被忽略等于没设（`apply()` 全程 `try/catch`、失败只记日志）；
2. **真机可能生效**：模拟器的系统栏（sceneboard）与真机实现可能不同 —— 真机上大概率会被尊重；
3. **下次别再试**：代码里留着注释就是「已经试过、模拟器无效」的证据，省一次重复劳动。

## ⇒ 判据 `2895`

**⇒ 「App 页面变黑了但顶部/底部还是系统浅色」这件事，要分两半看：**
- **底部导航条** ⇒ App 能改（`navigationBarColor`，`2026-11-17` 已修、`130/355` 款受益）；
- **顶部状态栏** ⇒ **模拟器上 App 改不动**（本判据），别把它当缺陷去追。

**⇒ 而且「白带」这个现象**必须用亮度逐行量**，不能看缩略图 —— 我今晚是把截图裁到顶部按 `20px` 步长量出来才确认边界的。**
