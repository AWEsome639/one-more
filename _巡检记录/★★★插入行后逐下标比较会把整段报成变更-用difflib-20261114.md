# ★★★ 插入/删除行后，逐下标比较会把整段报成「变更」——要用 `difflib`

> `2026-11-14 21:x`。写 `apply_wordle_scroll.py` 的 diff 显示时踩到的。

## 一、⇒ 现象

**我在脚本里这样算「哪些行变了」：**
```python
diff = [(n+1, L[n], new[n]) for n in range(len(L)) if n < len(new) and L[n] != new[n]]
```

**⇒ 而 `new` 里**插入了两行**（`Scroll() {` 与 `}`）⇒ 插入点之后的**所有下标都后移** ⇒
⇒ 逐下标比较的结果是：**`187` 行「都变了」**。**

**⇒ 而实际只改了 `3` 行（两插入 + 一注释）。**

## 二、⇒ 危险在哪

**这个 diff 是我用来**检查补丁范围**的。**
**⇒ 若它报 `187` 行，我会以为「补丁动了大半个文件」⇒ 要么不敢用、要么根本不看。**

**⇒ 更糟的情况：若插入发生在**中间**，逐下标比较会把「插入点之后的所有行」都标成「改了」，
⇒ 而真正**改错的那一行**淹没在 `187` 行噪声里 ⇒ **看不见**。**

## 三、⇒ 修法

```python
import difflib
dl = list(difflib.unified_diff(L, new, 'before', 'after', lineterm='', n=1))
chg = [x for x in dl if x.startswith(('+','-')) and not x.startswith(('+++','---'))]
```

**⇒ `difflib` 做的是**对齐**比较 ⇒ 插入算「新增 1 行」、不动其余。**

**⇒ 修后输出：**
```
实际改动 4 行（+/- 合计）：
  + Scroll() {
  - .height('100%')
  + // .height('100%')  ← 注释掉
  + }
```

**⇒ 一眼就能看出补丁干了什么。**

## ⇒ 判据（`2436`）

**任何「逐下标比较两个长度可能不同的列表」的代码，都是错的（除了长度相同的纯替换）。**
**⇒ 插入/删除会让之后全部失配 ⇒ 结果无意义。**

**⇒ 判据：比「改了什么」一律用 `difflib`（或先对齐）；不要写 `[i] != new[i]` 的循环。**

## ⇒ 判据（`2437`）

**这次差点被自己的验证工具骗：它报 `187` 行变更，而实际 `3` 行。**
**⇒ 若我信了它、把脚本当真改，就会在「看起来动了大半个文件」的错觉里提交。**

**⇒ 判据：验证工具的输出要**先自己看一遍是否合理**（`187` 行 vs 预期 `3` 行 = 明显不对）。
⇒ 工具报出反常数字时，先怀疑工具。**
