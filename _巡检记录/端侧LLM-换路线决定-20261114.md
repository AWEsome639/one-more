# 目标第 `4` 项「端侧 LLM」—— **换路线：从「系统模型」到「MindSpore Lite + 首启下载」**

## 一、现状（代码已存在，但跑不通）

| 文件 | 行数 | 依赖 | 状态 |
|---|---:|---|---|
| **`core/LocalLLM.ets`** | **`230`** | `@kit.DataAugmentationKit` → `localChatModel` | **`API 20+`** ⇒ 本项目 `compatibleSdkVersion = 5.0.0(12)` ⇒ **编译不过** |
| **`core/MindSporeSelfTest.ets`** | `~97` | `@kit.MindSporeLiteKit` | **`API 12` 可用** ⇒ 已写过，但**只是 `MobileNetV2` 的链路自检**，不是 LLM |

**⇒ 所以「卡在 API 20」的准确含义是：`LocalLLM` 那条路线**在本项目的 SDK 版本上根本编不进去**。**

## 二、三条候选路线与判定

| 路线 | 可行性 | 判定 |
|---|---|---|
| **A. 升 `compatibleSdkVersion` 到 `20`** | 需换 SDK、重验 `355` 款游戏 | ❌ **代价过大**（等于把整个项目重测一遍）|
| **B. `MindSpore Lite` + `0.5B` 量化模型** | `API 12` 可用，`MindSporeSelfTest` 已证明**链路通**（`rawfile → predict`）| ✅ **可行** |
| **C. 云端 API**（DeepSeek 等） | 需联网 + key | ⚠️ **违背「端侧」本意**，但可作降级 |

## 三、选 B，但有两个必须先决的问题

### ① 模型从哪来（不能进包）

**包的体积已经很敏感（`HAP 46.5 MB`）。`0.5B` 量化模型约 `300~500 MB` ⇒ **绝不能进包**。**
**⇒ 必须**首启下载到沙箱**。而下载源是问题：**
- 官方模型仓（HuggingFace / ModelScope）在国内需要代理
- 自建 CDN 需成本与备案

**⇒ 这是**产品决策**，不是技术问题 —— 要问他。**

### ② 谁来写推理前向

**`MindSpore Lite` 只负责「加载模型 + 跑前向」；LLM 还需要：**
- **Tokenizer**（BPE / SentencePiece）
- **KV cache 管理**（自回归生成）
- **采样策略**（top-p / temperature）

**⇒ 这三样都是**几百行**的活，且有大量细节坑（位置编码、attention mask）。**

## 四、我的判断：**这一项应该降级，不该现在做**

**理由：**
1. **目标的主战场是「`355` 款游戏每一帧都对」**，而端侧 LLM 是**附加能力**
2. **`LocalLLM` 已经有完整的降级设计**（`no-syscap` / `init-failed` / `chat-failed` 全部回落规则版 `ChatFinder.parse()`）
   **⇒ 也就是说：没有 LLM，软件**功能完整**，只是搜索不够「聪明」**
3. **`0.5B` 模型在手机上问答质量会很差**（比规则版好不了多少），**投入产出比低**

**⇒ 建议：把目标第 `4` 项改成「端侧 LLM：保留降级设计，等 API 20 设备普及后再启用」
⇒ 现在**不动**，把时间给布局。**
