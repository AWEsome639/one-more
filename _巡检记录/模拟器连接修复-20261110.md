# 模拟器「起不来」其实是「`hdc` 没连上」—— 一行命令解决

## 真相

**模拟器一直在跑**（`Emulator` 进程在 `127.0.0.1:5557` 监听），
**只是 `hdc list targets` 不会自动发现它** —— 因为 **`5555` 被 `adb` 占着**，模拟器退到了 `5557`。

**⇒ `hdc tconn 127.0.0.1:5557` 一条命令，设备立刻出现**：

```
$ hdc tconn 127.0.0.1:5557
Connect OK
$ hdc list targets
127.0.0.1:5557
$ hdc -t 127.0.0.1:5557 shell "echo alive"
alive
```

**装包、测量全部恢复正常**（`AppMod finish` + `Affair Factory 1598`）。

## 我在诊断里猜错了一半

**诊断文件里我写「模拟器起不来」** —— **实际是「起来了但没连上」**。
**⇒ 判据 1882（立）**：
> **`hdc list targets` 为空 ≠ 模拟器没起来。**
> **先 `lsof -iTCP:5557` 看有没有 `Emulator` 在监听**；
> **有的话 `hdc tconn 127.0.0.1:5557` 就能连上**；
> **`5555` 被 `adb` 占用时这是常态。**

**依据**：本次 `0` 个 qemu 进程、`list targets` 空、多次 `-start` 报 already running ——
**但 `lsof` 显示 `Emulator` 在 `5557` 监听，`tconn` 后一切正常。**

## 以后的开机顺序（写进交接）

```bash
EMU=/Applications/DevEco-Studio.app/Contents/tools/emulator/Emulator
$EMU -start onemore -noWindow &
sleep 90
hdc tconn 127.0.0.1:5557      # ★ 关键：5555 被 adb 占时必须显式连
hdc list targets              # 应该看到 127.0.0.1:5557
```
