# 尺子重复性实测：`Wordle` **`3/3` 完全一致**

## 做法

**修好 `Wordle` 之后，连跑三次完整测量：**

```
run1: Wordle  OK  1600
run2: Wordle  OK  1600
run3: Wordle  OK  1600
```

**⇒ `mb` 三次都是 `1600`，**跨度 `0`**。**

## 而队友此前在台账里看到的抖动

**`Wordle` 在 `20` 分钟内 `1600 → 1591 → 1351 → 1600` 抖 `±250px`**（`_巡检记录/误判案例集-20261113.md`）

**⇒ 那次抖动发生在 `Wordle` **还没修好**的时候** ——
它的键盘和棋盘时有时无（`blk` 也是 `1/60 → 0 → 0 → 2/48` 跳）。

## 由此得到一条新认识（判据 1983）

> **测量抖动可能不是「尺子不稳」，而是「被测对象本身在变」。**
>
> **⇒ 判断方法：同一款连跑 `3` 次 ——**
> · **`3/3` 一致 ⇒ 尺子稳、对象稳，这个数字可信**
> · **`3` 次不同 ⇒ 先怀疑「游戏本身有状态跳变」（渲染不稳定/元素生灭），再怀疑尺子**
>
> **依据**：`Wordle` 修好前抖 `±250px`、修好后 `3/3` 跨度 `0`。

**⇒ 这条推翻了我今晚写判据 `1978` 时的一个判断**：
我当时以为「`max_bottom` 这个指标本身不可靠」，
**其实当时是 `Wordle` 真的在变（键盘时有时无）—— 尺子忠实地报了它的变化。**

## 所以判据 1978 应该修正为

**旧表述**：`max_bottom` 单值不能作为证据（±250px 抖动）。

**新表述**：
> **单值可以作证据，前提是「同一款连跑 `3` 次跨度 ≤ `20px`」。**
> **跨度大 ⇒ 不是尺子的问题，是游戏状态不稳定 —— 那本身就是一个要修的 bug。**
