# 六个模拟器实例的方向 —— **不启动就能查（读 `config.ini`）**

## 方法（比启动快 100 倍）

```bash
grep -oE "hw.lcd.single.width=[0-9]+"  ~/.Huawei/Emulator/deployed/<实例>/config.ini
grep -oE "hw.lcd.single.height=[0-9]+" ~/.Huawei/Emulator/deployed/<实例>/config.ini
```

## 结果

| 实例 | 分辨率 | 方向 | 备注 |
|---|---|---|---|
| **`onemore`** | **`2560×1600`** | **横屏** ✓ | 今天用了一整天，**已不稳**（掉线）|
| `onemore2` | `2400×3840` | **竖屏** | 不能用 |
| `onemore3` | `1320×2232` | **竖屏** | 今天我误用了半小时 |
| `onemore4` | `699×699` | 横屏（方形）| 尺寸怪，不是手机比例 |
| **`onemore5`** | **`2880×1620`** | **横屏** ✓ | **今天没动过 ⇒ 最可能是健康的** |
| `onemore6` | `585×585` | 横屏（方形）| **太小**，`585` 宽连 `44vp` 的 `8` 列都放不下 |

## 结论

**⇒ 今晚应该用 `onemore5`（`2880×1620`，横屏，今天没被折腾过）。**

**⇒ 判据 1996 补充**：
> **换实例前先读 `config.ini` 的 `hw.lcd.single.width/height`** ——
> **不用启动就知道方向**；`w < h` 的是竖屏，直接排除。

## ⚠️ 更要紧的一条：**`onemore5` 的 vp 尺寸和 `onemore` 不一样**

```
onemore : 2560×1600 px @ density 480  ⇒  853 × 533 vp     ← 我今天全部数据的基准
onemore5: 2880×1620 px @ density 480  ⇒  960 × 540 vp     ← 不一样！
```

**⇒ `vp = px / (density / 160)`。两个实例 density 都是 `480`，但**像素不同**，所以 vp 不同。**

### 这意味着什么

| 量 | `onemore` | `onemore5` |
|---|---:|---:|
| `Bp.width` | `853` | **`960`** |
| `Bp.height` | `533` | **`540`** |
| 游戏区预算（`Bp.height - 190`） | `343` | **`350`** |
| `isShort()` | `true` | `true`（同） |
| `shrink`（`height < 600`） | `0.85` | `0.85`（同） |

**⇒ 竖向差 `7vp`、横向差 `107vp`。**

**⇒ 在 `onemore5` 上测出的 `max_bottom`/`blk` **不能直接和台账比**（横向多了 `107vp`，很多"溢出"会消失）。**

### 判据 1997

> **换实例测之前，先算 `vp = px / (density/160)`，确认和基准一致。**
>
> **依据**：`onemore` `853×533`、`onemore5` `960×540` —— **像素不同就是不同的设备**，
> 在不同尺寸上量出来的数**不能进同一张台账**。

### 所以今晚的选择变了

| 方案 | 问题 |
|---|---|
| **`onemore`（`853×533`）** | ✅ 和台账可比，**但今天用一天已不稳（会掉线）** |
| `onemore5`（`960×540`） | ✅ 可能更稳，**但数据不可比** ⇒ 只能当「另测一台设备」记录 |

**⇒ 结论：**优先 `onemore`**（为了可比）；它掉了就**重启再续**，不需要一次跑完 `14` 款。
**⇒ `onemore5` 的数据单独记，作为「换一台设备也成立」的旁证（objective 的证据标准里正好有这一条）。**

## 全部六个实例的 vp 尺寸 —— **只有 `onemore` 是 `853×533`**

```
onemore    2560x1600 px @480  ⇒  853 x 533 vp   ← 唯一基准
onemore2   2400x3840 px @480  ⇒  800 x 1280 vp  （竖屏平板）
onemore3   1320x2232 px @480  ⇒  440 x 744 vp   （竖屏手机）
onemore4    699x699  px @480  ⇒  233 x 233 vp   （太小，不是手机）
onemore5   2880x1620 px @480  ⇒  960 x 540 vp   （横屏，但宽 107vp）
onemore6    585x585  px @480  ⇒  195 x 195 vp   （手表级，不能用）
```

**⇒ 结论：**要「和台账可比」，只有 `onemore` 一个选择**，而它今天已经不稳。**

### 三个可选方案

| # | 方案 | 代价 | 可复算性 |
|---|---|---|---|
| **1** | **用 `onemore`，掉线就重启续测**（每次重启 `~5` 分钟） | 慢，但可行 | ✅ **和台账完全可比** |
| 2 | `onemore5`（`960×540`）| 快 | ⚠️ **不可比**，只能当「另一台设备」的旁证 |
| 3 | **新建一个 `2560×1600 @480` 的实例** | 要 `Emulator -create`，且要配 OS 镜像 | ✅ 干净的新实例 + 可比 |

**⇒ 我选 `1` 先跑通 `14` 款；同时把 `3` 记下来 —— 以后要长期跑测量，新建一个专用实例是对的。**
