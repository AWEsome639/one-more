# 今天真正的教训：**答案两天前就写在库里，而我没先搜**

> `2026-11-16 07:07`。**刚写的检索工具第一时间就把我今早的错误搜出来了。**

## 一、⇒ 事实

**⇒ 今早我花两小时建立「文本截断」这条轴：写了 `check_truncation.py`、跑了 `42` 份 dump、推出假容量界、改了三次工具、回滚一次提交。**

**⇒ 然后 `工具/find_doc.sh 截断` 第一条文件名命中就是：**
```
文本截断审计-151假阳性-20261114.md
```
**⇒ 打开一看（`11-14` 写的）：**
- 粗扫 `151` 处「有 `maxLines` 但无 `textOverflow`」
- 收窄到「变量文本」（`Text(this.msg/note/hint/…)`）⇒ **真风险 `0`**
- **结论清清楚楚：「反馈类长文本全部已经设了 `textOverflow`」**

**⇒ 我今早得出的结论，与它**一字不差**。而我不知道它存在。**

## 二、⇒ 为什么没搜到

**⇒ 两个原因，都在这两天的工作里埋下的：**
1. **索引停在 `11-14 10:40`** —— 之后 `610` 份文档没进索引（我今天才补）
2. **我没有「开工前先搜」的习惯** —— 直接开始造工具

**⇒ 判据 `2799` 说「有索引不等于找得到」；今天补一句：**有文档不等于会被读**。**

## 三、⇒ 已做的补救

**⇒ 写了 `工具/find_doc.sh`（三步：文件名 → 首行标题 → 正文），一条命令就能定位。**

**⇒ 并把「先搜」写成规矩：**

> **★★★ 开任何新分析轴之前，先跑：**
> ```bash
> bash 工具/find_doc.sh <关键词>
> ```
> **⇒ 若命中已有文档，先读它；只有确认它没回答、或结论已过时时，才重新开轴。**

## 四、⇒ 今天第四次「重复劳动」的代价清单

| # | 事 | 代价 |
|---|---|---|
| 1 | 假容量界（`tx[:40]`）| 两小时 + 假工具 |
| 2 | 台账截断误判（`t[:26]`）| 一次差点发出的误报 |
| 3 | 未读 `11-14` 的截断审计 | **整条轴白做**（真风险本来就是 `0`）|
| 4 | 索引停更两天 | 上面三条的共同原因 |

**⇒ 而 `3` 与 `4` 是同一件事：**我当时没有能力在 `1066` 份文档里找到那一份**。**

## ⇒ 判据（`2803`）

**「我记得没做过」不等于「没做过」。**
**⇒ 在一个 `1000+` 文档的仓库里，任何「新发现」都先当作**可能已有人做过**处理：先搜，再干。
**⇒ 而搜索能力本身要当成基础设施维护（索引要新、检索要一条命令），否则它就是今天的我 —— **重复发明，还发明得不如原来。****
