# 判据 3027：**竖屏实测拿到了** —— `Collatz` `blk=0`，最后一条缺口填上

## 一、怎么做到的

之前所有测量都在 `onemore7`（`2560×1600` **横屏**）。今晚第一次起 `onemore_fold`：

```
$ Emulator -start onemore_fold -noWindow
$ hidumper -s RenderService -a screen
  render resolution=2496x2224        ← 误导：这是「横向」数值
$ snapshot_display -f /data/local/tmp/s.jpeg
  截图 width: 2224, height: 2496      ← **实际是竖屏**
```

⇒ **`hidumper` 的 `render resolution` 字段会骗人，`snapshot_display` 的宽高才是真的。**
⇒ 真实形态：**`2224×2496` = `741×832vp` 竖屏**（与那 `84` 张孤儿截图同尺寸）。

### 测量常量
```
SHOT_SCREEN_H=2496    SHOT_GAME_BOTTOM=2412 (=2496-84，与横屏 1600-84=1516 同构)    SHOT_GESTURE=2480
```

## 二、三款实测结果

```
[1/3] Collatz        OK  77.1s  lowest='提示：考拉兹猜想…'   blk=0/0px
[2/3] Simon Command  OK  72.6s  lowest='绿'  [559,2290][600,2338]  blk=3/72px  blkh=599px
[3/3] Wordle         OK  71.0s  lowest='Z'   [62,2377][239,2477]   blk=2/10px  blkh=338px
```

| 游戏 | 竖屏 `blk` | 精确严重度 | 横屏对照 |
|---|---|---|---|
| **`Collatz`** | **`0/0px`** | **`0%`** | `blk=1/24px`、按钮被切 `42px`（`3011`）|
| `Simon Command` | `3/72px` | `24/599 =` **`4.0%`** | **`2/4` 色块整行在屏外**（`3017`）|
| `Wordle` | `2/10px` | `5/338 =` **`1.5%`** | `blk=2/40px`、`20.8%` |

## 三、这意味着什么

### ① `Collatz`：`3026` 的机制推断被实测证实

`3026` 说它「高度驱动、无 `aspectRatio` ⇒ 竖屏无触发通道」。
**实测 `blk=0/0px`** ⇒ 推断正确。

⇒ 今晚四条「横屏专属」**全部有了竖屏证据**（三条截图 + `Collatz` 实测数值）。
   `3003`/`2992`/`2994` 一路下来的算术，到这里闭环。

### ② `Simon Command`：横屏专属**坐实**，且竖屏不是「零」而是「可忽略」

竖屏 `blk=3/72px` —— **与横屏的 `blk=3/72px` 一模一样**。
但 `blkh=599px` ⇒ 精确严重度 **`4.0%`**；而横屏是**两个可点色块整行在屏外**。

⇒ **同样是 `blk=3/72px`，一个 4% 可忽略、一个是功能性损坏** ——
   这是判据 `3005`（`blk` 绝对值不反映严重度）**第二次**在真机数据上成立。

⇒ 也修正了 `3025` 的说法：竖屏不是「`0` 个溢出」，而是「**`0` 个内容缺失** + 小数级别溢出」。
   `3025` 的说法要精确成：**没有可交互内容缺失**，不是「所有指标都为 0」。

### ③ `Wordle`：竖屏比横屏更宽松

横屏 `blk=2/40px`（`20.8%`）→ 竖屏 `blk=2/10px`（`1.5%`）⇒ **竖屏余量明显更大**，与 `Bp.height` 更大一致。

## 四、判据

> **`hidumper -s RenderService -a screen` 的 `render resolution` 不能用来判断横竖屏 ——
> 用 `snapshot_display` 出来的图片宽高才算数。**

⇒ 三条：
1. **判断屏幕形态只看「截图的 width/height」** —— 这次的 `2496x2224` 与真实 `2224×2496` 正好相反
2. **`GAME_BOTTOM` 的推法有规律**：`屏幕高 − 84`（横屏 `1600-84=1516`、竖屏 `2496-84=2412`）
3. **换设备测之前，先确认「同一款游戏在两种形态下 `blk` 能不能比」** ——
   这次的 `Simon Command` 两边都是 `3/72px`，**只看 `blk` 会得出「两种形态一样糟」的错误结论**；
   加上 `blkh` 才看出一个是 `4.0%`、一个是功能损坏
