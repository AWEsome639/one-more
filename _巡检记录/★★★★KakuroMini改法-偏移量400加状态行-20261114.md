# ★★★★ `Kakuro Mini` 改法：偏移量 `-360 → -400` + 状态行让位（守住触控下限）

> `2026-11-14 13:3x`。判据 `2213`（廉价查证）的执行结果：这款**不必重构键盘**，有组合解。

## 一、现状与缺口

```
L562: .constraintSize({ maxWidth: Bp.height < 600
         ? Math.min(Bp.width - 2*Space.lg, Math.max(120, Bp.height - 360))
         : 9999 })
⇒ 手机 (533 < 600): min(821, max(120, 173)) = 173vp
⇒ 盘面 173vp，3×3 ⇒ 每格 57.7vp

缺口：键盘第二行（6/7/8/9/删除）需 ~53vp 才能进入视野
```

## 二、⚠️ 不能直接 `-360 → -420`

**`-420` ⇒ `max(120, 113) = 120vp` ⇒ 每格 `120/3 = 40vp` < `touchMin 44`** ❌

**而代码注释（`L561`）自己写着**：
> ⇒ 再收 40vp：`Bp.height - 360`（3×3 ⇒ 每格 ~58vp，**仍在 44 触控下限之上**）

**⇒ 作者明确把「每格 ≥ 44vp」当约束 ⇒ 不能破。**

## 三、⇒ 组合解：`-400` + 状态行让位

```
改 1：-360 → -400
  ⇒ max(120, 133) = 133vp ⇒ 每格 133/3 = **44.3vp** ✅ 刚好守住 44
  ⇒ 盘面缩 40vp

改 2：状态行 L567 让位（矮屏不渲染或缩到一行）
  Text(this.over ? '🎉 六条线全对，通关！' : …)   ≈ 17vp
  ⇒ 省 17vp

合计 57vp > 需 53vp ✅ 余 4vp
```

## 四、⇒ 状态行能不能藏？（判据 `2215`）

**`L567` 是「通关/步数用尽」的提示。**
- 它不是「操作入口」，只是**结果告知**
- **⇒ 藏了不影响「完成一局」**（玩家看到盘面状态就知道）
- **⇒ 但它也不是纯装饰**（通关时该有反馈）

**⇒ 折中：不删，改成 `FontSize.xs` + `maxLines(1)`（约 `17 → 12vp`，省 `5vp`），
或矮屏时把它并入头部统计行。**

**⚠️ 若只藏不缩：省 `17vp` 但丢了通关反馈 ⇒ 建议缩不藏。**

**⇒ 缩后合计 `40 + 5 = 45vp` < 需 `53vp` ⇒ 还差 `8vp`。**

**⇒ 那 `8vp` 从哪来？三选一：**
| 方案 | 省 | 代价 |
|---|---|---|
| 键盘两行的 `space` `xs → 2` | `~4vp` | 无 |
| 盘面 `padding(Space.sm)` → `xs` | `~8vp` | 无 |
| `-400 → -410`（每格 `43.7vp`）| `+3vp` | 略破触控 |

**⇒ 推荐「盘面 padding `sm → xs`」⇒ 省 `8vp` ⇒ 总 `53vp` 正好。**

## 五、⇒ 最终改法（三处）

```
1. L562:  Bp.height - 360  →  Bp.height - 400      （盘面 173 → 133vp）
2. L563:  .padding(Space.sm) → .padding(Space.xs)   （省 ~8vp）
3. L567:  status text 矮屏 FontSize.xs + maxLines(1) （省 ~5vp）
```
**合计省 ~53vp ⇒ 键盘第二行进入视野。**

**一款「结构性」问题，有时能靠**两三个小改**凑够，而不必重构。**
**⇒ 这次我原以为 `Kakuro Mini` 要重构键盘（一整晚），实测算下来
`-400` + `padding` + `字号` 三处小改就能凑够 `53vp`。**

**⇒ 判据：在说「必须重构」之前，先把「每一处能省多少」列一遍；
