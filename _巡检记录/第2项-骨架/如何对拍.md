# 分词器对拍：怎么用这两个文件

## 今晚的步骤（`10` 分钟）

```bash
cd "/Users/a0000/dev/One More/_巡检记录/第2项-骨架"
pip3 install --user transformers
python3 gen_tokenizer_vectors.py        # 生成 tokenizer_vectors.json
```

**⇒ 得到 16 条用例的「标准答案」（token id 序列 + 是否往返一致）。**

## 然后（ArkTS 侧）

**⇒ 把 `QwenBpeTokenizer.ets.txt` 落成 `entry/src/main/ets/core/QwenBpeTokenizer.ets`，写一个临时测试入口：**
1. 读同一个 `tokenizer.json`（`model.vocab` + `model.merges`）
2. 对 `tokenizer_vectors.json` 里的 `text` 逐条 `encode`
3. **逐 `id` 比对**，任何一条不一致就打印「第几条、期望什么、实际什么」

**⇒ 只有当 16 条**全部一致**时才允许接模型推理 —— 否则后面所有「模型输出乱码」都无从判断是分词还是模型的问题（判据 `2793`）。**

## 已知会不一致的地方（先知道，免得到时候慌）

| 情况 | 原因 |
|---|---|
| 往返丢空格 | `decode` 可能合并尾随空格；HF 自己也会，看 `roundtrip_ok` 字段 |
| emoji 变体选择符（`❤️`）| `U+FE0F` 是否单独成 token 取决于词表 |
| 长文本 | 只验证性能，不验证逐 id |

## ⚠️ 这一步的价值

**⇒ 它把「分词器对不对」从「看着像中文」变成「16 条向量逐 id 一致」—— 这就是判据 `2026-11-15` 说的「同一把尺子」。**
