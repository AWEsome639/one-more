## 1. ⚠️ 先修正模板：`maxHeight` 只裁不缩，不是有效修法

你给的模板：
```ts
.constraintSize({ maxHeight: Math.max(120, Bp.height - 400) })
```
**对这 19 款无效**：它们的格子是 `layoutWeight(1) + aspectRatio(1)`，**高度由宽度决定**。
给容器加 `maxHeight` 只会把容器压矮，格子仍按**宽度**算 ⇒ **下半截被裁掉**（判据 1928 已在仓库里写下这个坑，
`GNumberBondsAll.ets:397-399` 就是照它改的：**同时给 maxHeight + maxWidth**）。

**首选写法（限宽即限高，项目里已验过 9 款）**：
```ts
.width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 360)))
```
**等价的安全写法（只加约束、不改宽度语义）**：
```ts
.constraintSize({ maxWidth: Bp.isShort() ? Math.max(140, Bp.height - 360) : 9999 })
```
533 下两者都 ⇒ **173vp**；竖屏 744 下 `min(817, 384) = 384` ⇒ 更大，合理。

## 3. 为什么这 7 款不需要改（逐条依据）

| 款 | 依据 |
|---|---|
| `GLetterCancellation` / `GWordSnakeTrail` | **内层 `Row` 已经是封顶写法**：`}.width(Math.min(Bp.width - 2 * Space.lg, Math.max(140, Bp.height - 360)))`（L340 / L361）⇒ 每行宽 173、格子 173/N、行高 = 173/N ⇒ 整盘高 ≈ 173 ✓。它们的棋盘外层还写 `100%`，但**高度已经被行宽决定**，不需要再改（若想外框贴合可顺手把外层也换成同一式）。 |
| `GNumberBondsAll` | L399 已同时有 `maxHeight` **和** `maxWidth`（判据 1928 的正确写法）✓ |
| `GShapeShifter` / `GSilhouetteMatchOrtho` | 盘面在一个 **4 格平铺 Row** 里，每个 tile `.layoutWeight(1)`（L325 / L286）⇒ tile 宽只有屏宽/4，再乘 78% / 74% ⇒ 盘面 **166 / 158vp**，**远低于 343**。这正是你提醒的「格子按父格 layoutWeight 分配」⇒ 不需要改。 |
| `GModuloPath` / `GPatternSequenceDraw` | 盘面容器自身 `.layoutWeight(1)`（**纵向**权重）⇒ 它只吃掉「剩余高度」，**不会把兄弟节点推出屏**；格子仍按宽度撑到 813 ⇒ 视觉上会溢出容器、盖住下面的按钮，但**不改变布局位置** ⇒ 不是本次"横向撑高"问题；低优先可加 `maxWidth` 收掉视觉溢出。 |
