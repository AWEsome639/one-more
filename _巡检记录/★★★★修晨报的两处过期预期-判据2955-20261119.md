# 晨报脚本的两处过期预期（判据 `2955`）：明早差点又误判

> `2026-11-19 00:14`。**这是今晚第三个「检查器自己过期」的实例**（前两个：`2947` 校验器、`2943` 台账）。

## 一、⇒ 修之前它会说什么

**⇒ `工具/morning_check.sh` 第 ① 项：**
```
期望 87–90 行（队列 84 款）
```

**⇒ 而今晚真实情况：队列 `353` 款、一晚只能做 `~125` 款。**
**⇒ 两个数**都错**：
- `84` 是 `优先 84 款`（**强制重测的子集**），不是队列；
- 即便抓到 `353`，写成「期望 356–359 行」也错 —— **窗口根本做不完**。**

## 二、⇒ 两处修改

| # | 原来 | 改成 |
|---|---|---|
| 1 | 抓 `优先 [0-9]+ 款` | 抓 **`待测 [0-9]+`**（真队列），抓不到才回退「优先」|
| 2 | `期望 = 队列 + 3~6` | **同时报「队列」与「可达」**：`min(队列, 400×60/191)` |

**⇒ 现在它说：**
```
期望 最多 ~125 行（队列 353 款，窗口只够一部分）
```
**⇒ ⇒ **看到 `125` 就知道是正常完成，不会以为跑批坏了。****

## ⇒ 判据 `2955`

**⇒ 「检查器」比被测对象更容易过期 —— 因为它把**当时的数字**硬编码成了期望。**
**⇒ 今晚三个实例：**
1. `verify_changes_present.py`：期望字符串是改动前的 ⇒ 报「4 处不在位」⇒ 挡住整晚跑批（`2947`）；
2. 折叠屏台账：还是 `11-16` 的数据 ⇒ `triage` 报已修好的款（`2943` 已记）；
3. `morning_check.sh`：期望行数抓错了数、且没考虑窗口 ⇒ 明早会误判（本判据）。

**⇒ ⇒ 凡「检查器」，一律**从当前事实推导期望**（读日志/读台账/算窗口），**不写死数字**；写死的数字必须在同一处注明「什么时候会失效」。**
