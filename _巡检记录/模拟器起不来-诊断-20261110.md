# 模拟器「起不来」的诊断（05:30–06:00）

## 现象

`Emulator -start onemore -noWindow` ⇒ **日志写「cold boot」但没有 `qemu-system` 进程**，`hdc list targets` = `[Empty]`。
`Emulator -stop` 报成功、`-start` 又报「already running」——**状态不一致。**

## 日志里的两条硬证据

### ① 端口被别的程序占了

```
~/.huawei/Emulator/deployed/onemore/Log/qemu.log:
E [express_bridge.c(bridge_socket_listen:105)] can't bind on socket port 5555 48.
I [express_bridge.c(bridge_socket_listen:117)] listen bridge socket port 5557
```

**查 `lsof -iTCP:5555`**：
```
COMMAND  PID  USER   FD   TYPE ... NAME
adb     4513 a0000   18u  IPv4 ...  TCP 127.0.0.1:5555 (LISTEN)
```

**⇒ 端口 `5555` 被 `adb`（Android 调试桥，不是本项目）占着**，
**模拟器只能退到 `5557`** —— 而 `hdc` 默认找 `5555` ⇒ **看不见设备**。

### ② 图形栈在报错

```
W [express_gpu.c(drain_gl_errors:785)] #fun_id 10013 ... gl error 500
E [express_display.c(opengl_paint_composer_layers:708)] not support transform_type 8
```

**⇒ GPU/GL 上下文创建失败**（`gl error 500`），**`QemuManager` 一直刷 `CheckGPUThread` 的 Critical 日志。**

## 我做了什么（都没能救回来）

1. `-stop` + `-start`（多次，含 `onemore2`）
2. **杀掉卡住的 `Emulator -start` 进程**（当时有 `3` 个在烧 `~80%` CPU 各）
3. **等负载从 `95` 降到 `8`** 再起 —— 仍然 `0` 个 qemu
4. 检查端口、日志、实例目录

## 结论与建议（给奥森/明天的我）

**⇒ 根因是「`adb` 占了 `5555`」+「GL 报错」，不是我的代码、也不是磁盘满。**
**建议**：
1. **让模拟器用 `5557`**：`hdc` 侧应能 `tconn 127.0.0.1:5557`（明天试）
2. **或先停 `adb`**（`adb kill-server`）再起模拟器
3. **GL 报错**可能要重启 `WindowServer` 或换 `-noWindow` 之外的启动方式
