# 模拟器会自己锁屏 ⇒ 测量**静默失败**（判据 `2869`）

> `2026-11-17 23:22`。**今晚测 `Skyscrapers` 时撞到的。**

## 一、⇒ 现象

**⇒ `shot_game.py "Skyscrapers"` 跑完没有任何输出（日志空）、`uitest dumpLayout` 抓到的还是**首页**（`One More` / `355 款小游戏` / `全部` / `🎯`）。**
**⇒ 查 `aa dump -l` 才看到关键字段：**

```
Mission ID #28  mission name #[#com.andrewoscar.onemore:entry:EntryAbility]  lockedSta…
```

**⇒ **`lockedState` ⇒ 屏锁着**。App 在前台、但锁屏盖在上面 ⇒ 点击都点在锁屏上。**

## 二、⇒ 处置（有效）

```bash
hdc shell "power-shell wakeup"          # → WakeupDevice is called
hdc shell "uitest uiInput swipe 1200 1400 1200 400 200"   # 上滑解锁
hdc shell "uitest uiInput keyEvent Home"
```

**⇒ 唤醒后 App 能正常启动（`start ability successfully`）。**

## 三、⇒ 为什么危险

**⇒ 它**不报错**：`shot_game` 可能一直空转、最后给一个看似正常的失败码；`dumpLayout` 抓的是首页而不是游戏。**
**⇒ 已有的 `NO_CARD` 诊断（判据 `2681`）会带上 `aa dump -l` 的 `state/lock` 字段 —— 这次就是靠它认出来的。**

## ⇒ 判据 `2869`

**⇒ 跑批前先查一次屏锁状态**（`hdc shell "aa dump -l" | grep -i locked`）；**
**⇒ 任何「跑完没输出」或「dump 抓到的文本是首页」的情况，**第一件事是查锁屏**，不要先怀疑游戏或脚本。**
**⇒ 建议在 `sweep_*.sh` 的开头加一句 `power-shell wakeup`（无害、幂等）。**
