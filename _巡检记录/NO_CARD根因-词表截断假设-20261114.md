### 2.1 结论：截断只影响 1 款，且不致命

- **只有 `Ab Reversal Oddball` 被截掉一个 token（`Ab`）**；但它的 `_base`（`Ab Reversal Oddball`）与 `name` 都**排在最后且必然被尝试**，
  且 `Ab` 是 `Ab Reversal Oddball` 的子串 ⇒ 这个 token **完全冗余**。
- 其余 23 款：`tokens[:4]` **一项没丢**（中文名 + ≤3 个英文词，正好 4 个）。
- ⇒ **A 假设量化为：0 款致命 / 45 行 NO_CARD 中贡献 0。**

### 2.2 但发现另一件事：2 款的名字**根本不在注册表**

| NO_CARD 名 | 注册表里实际存在的 enName |
|---|---|
| `Word Snake` | **`Word Snake Trail`**（`GameRegistry.ets:347`，中文名 `单词蛇`）|
| `Matcher` | 查不到完全同名；最接近 `Fraction Matcher`（`分数匹配`）|

⇒ `game_title_map()` 对这两个名字返回 `` ⇒ `want_zh` 为空 ⇒ 只用英文词搜**中文界面** ⇒ 必然 `NO_CARD`。
⇒ 这是**输入名单与注册表不一致**（不是截断、也不是定位）⇒ 占 **2 / 45**。

## 3. B 方向：卡片定位这一环具体坏在哪

### 3.1 `hit` 判定把**搜索框自己**算作命中 ⇒ 循环永远只试第一个 token（L602）

```python
602:        hit = any(((want_zh and want_zh in (t or '')) or (name in (t or ''))) for t, _ in texts(d))
603:        if hit:
604:            break
```

· 这一步**没有 y 过滤、也没有排除搜索框**：搜索框里刚被 `uinput` 打进去的 `时序判断` 本身就是 dump 里的一个 text 节点；
  ⇒ `want_zh in t` 对**搜索框自己**成立 ⇒ `hit=True` ⇒ **第一轮就 `break`**。
· 后果有两个：**① 后面的 token 永远不会被尝试**（A 假设即使成立也执行不到）；**② 没有"卡片没出来就再等/再试"的机会**——`d` 就是这一张 dump，直接进入卡片定位。

🤔判：这一条是**结构性**的（不依赖设备），但它只决定「不再重试」，不直接决定「找不到卡」。

### 3.2 卡片定位的 y 窗口 `560 < y1 < 1000`（L620）可能把第一行结果排除在外

```python
619:    for t, (x1, y1, x2, y2) in texts(d):
620:        if 560 < y1 < 1000 and x2 > x1 + 100:
```

· 搜索框的点击坐标是 `(2276,264)` 与 `(1280,435)`（L592-593）⇒ **输入框在 y≈435**，结果网格紧贴其下（首行标题很可能落在 `y1≈500~560`）。
· 若首行标题 `y1 ≤ 560` ⇒ **被过滤掉** ⇒ `card` 仍为 `None` ⇒ 直接 `NO_CARD`（L631-633），尽管屏幕上有卡。
· 这能解释「词对、也点了、仍 NO_CARD」以及报错里 `fallback=(1280,675)`（fallback 只取 y 窗口内**第一个**文本节点，不是目标卡的坐标）。

### 3.3 `x2 > x1 + 100`（同 L620）：窄标题被跳过

· 要求文本节点宽 >100px（≈33vp）。4 字标题（`时序判断`）在 `FontSize` 正文档约 52~64vp ⇒ 通过；
  但**2~3 字/短英文**（`蛇`/`Go`/`Matcher`）可能 <100px ⇒ 直接被跳过。NO_CARD 里恰有 `Snake`/`Matcher` 这类短名。
· 🤔判：对 4 字名不是主因，对短名是**硬性排除**。

### 3.4 打字后只等 2.4s（L597-598）

```python
597:        sh("uinput -K -t '%s'" % tok)
598:        time.sleep(2.4)
599:        d = dump('r')
```

· 这一批 NO_CARD 的耗时是 **217~236s**（台账），而全库均值 111s ⇒ **设备当时很慢**；2.4s 内结果网格可能还没渲染完。
· 同款 `Temporal Order Judgment` 在 20:23 **成功过一次**（229.6s）⇒ 支持「时序/负载」而非「词不对」。

### 3.5 `_find_text_node` 是**完全匹配**（L344），但只用于非卡片场景

```python
344:            if a.get('text') == want:
```

· 用于：关闭结算弹层（`关闭/知道了/返回/再来一局/✕/×`，L563）、清空搜索框（`✕`，L589）。
· **不用于找卡片**（卡片用 L602 子串 + L618-631 循环）⇒ 若卡片标题被 dump 拆成 `时序`+`判断` 两个节点，L602 也会失败（但这是**同一根源**：都在找"一段完整文字"）。

## 审查提到的一条历史隐患

`shot_game.py:405-418` 的 `is_home()`：

```python
ok = 'One More' in j and ('全部' in j or '355 款' in j or 'All' in j or '355 games' in j)
if ok and '✕' in j:     # 搜索框有内容时不算初始态（判据 1910）
    return False
return ok
```

**⇒ 它只检查「首页文字在不在 dump 里」，不检查「有没有弹层盖在上面」。**

**⇒ 若某个弹层压着首页，而首页文字仍在 dump 树里（只是被遮挡），`is_home()` 会返回 `True`**
⇒ 工具认为已经回到首页 ⇒ **开始在「被挡住的首页」上搜游戏卡**
⇒ 点不到卡 ⇒ `NO_CARD`。

## 为什么这条值得查

- 它**不依赖词表、也不依赖 y 窗口**，是第三个独立机制
- 而 `shot_game.py:475` 的注释已经说过「必须点掉三道闸，否则后面全部 `NO_CARD`/`NOT_HOME`」
  ⇒ **说明这类弹层确实存在**，只是**点掉一次之后会不会再出现**（比如 `force-stop` 重启后）
- **`force-stop → start` 之后，首启弹窗（隐私说明/欢迎页）很可能再次出现** ⇒ 而这条路径正好是失败恢复路径
