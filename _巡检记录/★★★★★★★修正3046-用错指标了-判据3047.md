# 判据 3047：**修正 `3046`** —— 我用错了内存指标，真问题是**换页**不是「没内存」

## 一、`3046` 错在哪

`3046` 的结论是「这台机器可用空闲内存总量只有约 `1.4 GB`，模拟器占 `1.3 GB` ⇒ 余量 `77 MB` ⇒ 跑不动」。

⇒ 依据是 `vm_stat` 的 **`Pages free`**，和「`-stop` 之后从 `77 MB` 跳到 `1399 MB`」。

### 但三个数字放在一起就矛盾了

```
vm_stat Pages free           :  70 MB      ← 我用的指标
memory_pressure              :  System-wide memory free percentage: 47%   ← 系统说还有 47%
sysctl vm.swapusage          :  total 4096M  used 2776M  free 1320M      ← ★ 换页用了 2.8 GB
```

⇒ 如果可用内存真的只剩 `70 MB`，`memory_pressure` 不可能说 `47%`。
⇒ **`Pages free` 是「立即可用的空闲页」，不含可压缩/可回收/文件缓存** —— 它窄得多。
⇒ **`memory_pressure` 的 `free percentage` 才是「可用内存」的可用代理。**

## 二、所以真问题是什么

**换页 `2.8 GB / 4 GB`。** 症状与观察完全吻合：

| 现象 | 换页能解释吗 |
|---|---|
| 模拟器崩、`etime` 只有 `00:15` | ✅ 被换页拖死 / 被内存压力杀掉 |
| `hdc` 会话反复 `need connect-key` | ✅ 会话心跳超时 |
| `bundle manager service is died` | ✅ 服务被换页卡住看门狗判死 |
| 一次测量 `70s` → `130s`/`300s` | ✅ 换页 |
| 截图 `100%` 全黑 | ✅ 渲染管线拿不到连续内存 |

⇒ **同一个根因换成「换页」后，`3046` 描述的那六个症状一个都不用改。只有「为什么」变了。**

## 三、修法因此不同

| `3046` 的修法（错的）| `3047` 的修法（对的）|
|---|---|
| 「腾出 `500 MB` 以上空闲再跑」—— 但 `Pages free` 本来就低，腾不出来 | **「不要再加重换页」**：一次只做一件重活 |
| 「这台机器跑不了模拟器」—— 过于绝对 | **能跑，但会话会闪**：跑的时候别编译、别开第二个模拟器、别跑大批量脚本 |
| —— | **判据换成 `memory_pressure`**：`free percentage` 低于 ~`30%` 才真的该停 |

⇒ 今天真实发生的：我一边跑测量一边编译（`12:xx` 那次 `12` 分钟的编译就是在模拟器跑批时做的）⇒
   **换页被推高 ⇒ 之后模拟器与 `hdc` 全线不稳**。

## 四、判据

> **判断「内存够不够」不能用 `vm_stat` 的 `Pages free` —— 用 `memory_pressure` 的 `free percentage`。
> `Pages free` 低不代表没内存，它只代表「立即可用的页少」；真正会杀进程的是 `swap` 用水位。**

⇒ 四条：
1. **看内存用 `memory_pressure | tail -1`**（一个百分比，一眼可判）
2. **同时看 `sysctl vm.swapusage` 的 `used`** —— 它接近 `total` 时任何重活都会开始抖
3. **`Pages free` 只适合判断「刚分配的那一兆能不能立刻拿到」**，不适合判断整体余量
4. **一次只做一件重活**：编译、模拟器、大批量脚本**三者不并行**（今天违反了这条）

## 五、这条修正了 `3046` 的哪几句

| `3046` 原话 | 修正 |
|---|---|
| 「可用空闲内存总量只有约 `1.4 GB`」| ❌ 撤回。`memory_pressure` 说 `47%` 可用 |
| 「模拟器占 `1.3 GB`」| ⚠️ 大致对（`-stop` 后 `Pages free` 回升 `1.3 GB` 是它的真实占用）|
| 「余量 `77 MB` ⇒ 跑不动」| ❌ 撤回。真实是换页 `2.8/4 GB` ⇒ 会话会闪，不是跑不动 |
| 「六个不同故障一个根因」| ✅ **保留** —— 根因换成换页，六个症状照样全解释 |
| 「跑测量前关掉别的重活」| ✅ **保留且加强** —— 这是唯一有效的修法 |
