# 模板级缺陷：**`6` 款网格类游戏底行被屏沿切掉** —— 批量修复单

> `2026-11-18 08:48`。**从「`board` 字段语义修正」追出来的第一笔真账。**

## 一、⇒ 病征（同一副样子）

**⇒ 网格的最底一行只露上半截、下半截在屏外 ⇒ 最下排格子**看不全也点不准**。**

| 款 | `blk` | 证据 |
|---|---|---|
| `Shadow Pivot` | `72px` | 裁 `y=900–1600`：两个网格底行都切 |
| `Silhouette Match` | `72px` | 同上 |
| `Silhouette Match Ortho` | `72px` | 同模板 |
| `Triple Sequence` | `48px` | 底行切 |
| `Trace Path` | `48px` | 底行切 |
| `Perspective Taking` | `48px` | 底行切 |
| `Odd Rotation` | `48px` | 三块面板底部都在屏沿 |

## 二、⇒ 根因（同一个模板）

**⇒ 网格用 `Stack().layoutWeight(1).aspectRatio(1)` 铺格，父容器**没有高度上限** ⇒ 撑满可用高后仍溢出。**
**⇒ 对照：同项目的 `GPerspectiveShiftView.ets` **有**这条上限（`L392`）：**

```ts
.width('100%').aspectRatio(1).padding(Space.xs)
.constraintSize({ maxHeight: Math.max(140, Bp.height - 360) })
```

**⇒ ⇒ 这 `6` 款是**漏抄了这一行**。**

## 三、⇒ **不能照抄那个常数**（重要）

**⇒ `Bp.height - 360` 在 `Perspective Shift View` 上成立，是因为它那块式样不同；直接搬到这 `6` 款，网格会**被压到一半**（`1600-1080=520px` 只剩可用高 `1220px` 的 `43%`）。**
**⇒ 正确做法（每款一步）：**
1. 先量**当前**网格区的高度（截图里量像素，或 `dump` 看容器 bounds）；
2. 缺口 = `blk` 的像素数（`72` 或 `48`）；
3. 上限取「当前高度 − 缺口 − 余量 `20px`」；
4. **一次只改一款、改完立刻量 + 裁图**（判据 `2873`：连测两次 `blk` 都为 `0`）。

## 四、⇒ 验收（每款三条）

1. `shot_game` **连测两次**，两次 `blk=0`；
2. **裁图**：最底一行格子**完整可见**（含圆角）；
3. `lowest` 高度仍是设计值（没有为了塞下而压扁别的元素）。

## ⇒ 判据 `2898`

**⇒ 「同一模板复制到多个文件」的缺陷，要**先按模板归族、再逐款量缺口** —— 不能拿一款的常数套全族。**
**⇒ 归族方法：`grep` 一个模板特有的字面量（这次是 `}.width(104)`，只命中 `2` 个文件；同族的其余靠**视觉同形**找出来）。**
**⇒ 而且这一族是「`lowest` 高度判据看不见」的（`2875` 的盲区）：`lowest` 是提示行/按钮，被切的是**棋盘**。**
