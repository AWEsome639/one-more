# 模板级缺陷：**`6` 款网格类游戏底行被屏沿切掉** —— 批量修复单

> `2026-11-18 08:48`。**从「`board` 字段语义修正」追出来的第一笔真账。**

## 一、⇒ 病征（同一副样子）

**⇒ 网格的最底一行只露上半截、下半截在屏外 ⇒ 最下排格子**看不全也点不准**。**

| 款 | `blk` | 证据 |
|---|---|---|
| `Shadow Pivot` | `72px` | 裁 `y=900–1600`：两个网格底行都切 |
| `Silhouette Match` | `72px` | 同上 |
| `Silhouette Match Ortho` | `72px` | 同模板 |
| `Triple Sequence` | `48px` | 底行切 |
| `Trace Path` | `48px` | 底行切 |
| `Perspective Taking` | `48px` | 底行切 |
| `Odd Rotation` | `48px` | 三块面板底部都在屏沿 |

## 二、⇒ 根因（同一个模板）

**⇒ 网格用 `Stack().layoutWeight(1).aspectRatio(1)` 铺格，父容器**没有高度上限** ⇒ 撑满可用高后仍溢出。**
**⇒ 对照：同项目的 `GPerspectiveShiftView.ets` **有**这条上限（`L392`）：**

```ts
.width('100%').aspectRatio(1).padding(Space.xs)
.constraintSize({ maxHeight: Math.max(140, Bp.height - 360) })
```

**⇒ ⇒ 这 `6` 款是**漏抄了这一行**。**

## 三、⇒ **不能照抄那个常数**（重要）

**⇒ `Bp.height - 360` 在 `Perspective Shift View` 上成立，是因为它那块式样不同；直接搬到这 `6` 款，网格会**被压到一半**（`1600-1080=520px` 只剩可用高 `1220px` 的 `43%`）。**
**⇒ 正确做法（每款一步）：**
1. 先量**当前**网格区的高度（截图里量像素，或 `dump` 看容器 bounds）；
2. 缺口 = `blk` 的像素数（`72` 或 `48`）；
3. 上限取「当前高度 − 缺口 − 余量 `20px`」；
4. **一次只改一款、改完立刻量 + 裁图**（判据 `2873`：连测两次 `blk` 都为 `0`）。

## 四、⇒ 验收（每款三条）

1. `shot_game` **连测两次**，两次 `blk=0`；
2. **裁图**：最底一行格子**完整可见**（含圆角）；
3. `lowest` 高度仍是设计值（没有为了塞下而压扁别的元素）。

## ⇒ 判据 `2898`

**⇒ 「同一模板复制到多个文件」的缺陷，要**先按模板归族、再逐款量缺口** —— 不能拿一款的常数套全族。**
**⇒ 归族方法：`grep` 一个模板特有的字面量（这次是 `}.width(104)`，只命中 `2` 个文件；同族的其余靠**视觉同形**找出来）。**
**⇒ 而且这一族是「`lowest` 高度判据看不见」的（`2875` 的盲区）：`lowest` 是提示行/按钮，被切的是**棋盘**。**

## 【`08:50` 追加：两个关键新认识】

### ① `blk=3/72px` 里的 `3` 个块是**全屏容器**，不是真溢出

**⇒ `uitest dumpLayout` 列 `y2 > 1576` 的元素，只有三个：**

```
root    y=117..1600  x=0..2560     ← 页面根
Stack   y=117..1600  x=0..2560     ← 页面栈
        y=0..1600   x=0..2560      ← 屏幕本身
```

**⇒ 也就是说：`blk` 那 `3` 个块**全是设计上就该到 `1600` 的容器** ⇒ **这一款的 `blk` 是纯噪音。**
**⇒ 而**真正被切的那一行格子，`blk` 根本没数到**（它在容器内部被裁、自身 `y2` 没超过阈值）。**

### ② 视觉确认（务必以此为准）

**⇒ 裁 `y=1380–1600`：能看到**最底一整行格子已经在屏外、下一行刚开始** ⇒ **底行确实被切。**

### ⇒ 这给修复单带来的修正

**⇒ 不能用 `blk` 验收这 `7` 款（它对它们是噪音）⇒ **验收只能靠裁图数行数**：**
1. `bash 工具/shot_game.py "<款>"` 跑一次拿截图；
2. 裁 `y=1200–1600`；
3. **数「完整可见的行数」是否等于 `ROWS`**（若最底一行只有上半截 ⇒ 没修好）。

**⇒ 而「缺口多少像素」要从**裁图**里量（最底行被切掉的比例 × 行高），不能从 `blk` 读。**

**⇒ 判据 `2899`：当 `blk` 的块全是全屏容器（`root`/`Stack`/屏幕）时，`blk` 对这款**完全无效** —— 必须改用裁图数元素。**

## 【`08:52` 测量进展（明天从这里接着做）】

**⇒ 想给「上限」一个**算出来的数**而不是猜，量了 `Shadow Pivot` 的截图亮度剖面：**

| y | 亮度 | 是什么 |
|---|---|---|
| `230` | `22` | 顶部行（`原形`/`光线` 标签那层）|
| `430` | `105` | **`HintBar` 青色按钮**（很亮，一开始被它骗了）|
| `530` | `0` | 黑间隙 |

**⇒ 结论：面板从 `y≈1000` 起，而底部格子在 `1380+` 仍在继续 ⇒ **面板高度 ≈ `600px+`，明显超过 `1600-1000=600px` 的可用空间。**
**⇒ 明天要做的第一件事：dump 出**面板这个容器**的 bounds（不是格子、不是选项），拿到它的**实际高度**；上限取 `Math.max(140, Bp.height - <面板顶部换算成 vp>)`。**

**⇒ 已知的坑：`y=430` 那排青色 `HintBar` 亮度 `105`，会骗过任何「按亮度找面板」的自动检测 ⇒ 找面板必须用**深灰区间 `18–60`**。**

**⇒ 七款最底部 `200px` 逐个裁图复核：**

| 款 | 底部 |
|---|---|
| `Shadow Pivot` / `Silhouette Match` / `Silhouette Match Ortho` | ❌ 格子延续到屏外 |
| `Triple Sequence` / `Trace Path` / `Perspective Taking` | ❌ 同上 |
| **`Odd Rotation`** | ✅ **三块面板底部圆角完整、在屏内结束**（只是贴边，不是被切）|

**⇒ 所以待修是 `6` 款，不是 `7` 款。**
**⇒ 依据判据 `2885`：贴边看的是「内容」还是「容器边」—— `Odd Rotation` 贴边的是面板的**容器边**、内容（格子）完整 ⇒ 按判据不修。**

## 【`08:50` 处方修正：**dump 拿不到面板 bounds**】

**⇒ 试着按原处方「`dump` 出面板容器的 bounds」，结果：**

**⇒ `dump` 里宽 `>800`、高 `>200` 的元素只有这些：**

```
Grid       y=639..1264   2560x625    ← 选项区（不是网格面板）
Row        y=117..363    2560x246    ← HintBar
Column     y=117..1264   2560x1147   ← 内容容器
Tabs/Column y=117..1444  2560x1327
root/Stack y=117..1600
```

**⇒ **两边的网格面板根本不在 dump 里**（大概率是自绘/非标准元素，`uitest dumpLayout` 只报有 `accessibility` 语义或标准控件的节点）。**

**⇒ 而同一时刻的**截图**清楚显示：底部 `260px` 里格子延续到屏沿、下一行已开始 ⇒ **被切是真的**。**
**⇒ ⇒ **`dump` 说「内容到 1264 结束」、截图说「格子到 1600 还在」—— 两者冲突时，**以截图为准**（判据 `2857`/`2899`）。**

## ⇒ 所以处方要改成这样（明天照这个做）

**⇒ 不再依赖 `dump`，直接从**代码 + 截图**推：**
1. 读该款代码，找到网格的那层 `Column`（`GShadowPivot.ets` `L284` 一带）；
2. 给它加 `.constraintSize({ maxHeight: Math.max(140, Bp.height - 300) })`（**初值**，因为 `HintBar` 在 `y=117..363` ⇒ 顶部占约 `120vp`，底部再留余量）；
3. **编译 → 装机 → 裁 `y=1200–1600` 数行数**；
4. 行数不对就调这个减数（`300 → 320 → 280`…），**每次只改这一个数**。

**⇒ 预计要 `2–3` 轮才收敛，别指望一次对。**
