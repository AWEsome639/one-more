### 判断（按证据强弱）
1. **不要先归罪 app**：桌面进程在 onemore 之前 5 秒就已经 `THREAD_BLOCK_6S`，而且 `render_service` 反复 sysfreeze ⇒ 这台**模拟器本身在卡**。
2. **app 是放大器不是根因**：414 MB RSS（127 秒生命周期）+ 冻结发生在 `GameHost → Index` 返回瞬间 ⇒ 返回列表时重建 **355 张卡片**（`ForEach` 全量 + 每卡读 `ProgressStore` 的 `clearedGames`/`perGameBest`）是重活。但仅凭这份日志**不能证明**是它卡死的。
3. **怎么定论**（成本从低到高）：
   - ① 重启模拟器后**只跑这一条路径**（进一款游戏 → `‹` 返回列表 ×10 次），看是否复现 `APP_INPUT_BLOCK`；
   - ② 复现时立刻 `hdc shell hidumper -s RenderService -a screen` + `top -H -p <pid>`，看主线程是否在 100%；
   - ③ 若复现且只在返回路径 ⇒ 再做「355 卡分批渲染 / `LazyForEach`」或给 `ProgressStore` 加缓存（`bestOf`/`clearedGames` 现在每次全量 `JSON.parse`）。

## 4. 复现配方（今晚最终跑通的版本，照抄即可）

```bash
HC=/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc
D=127.0.0.1:5557
# 0) 语言：中文（设置 tab → 语言 → 🇨🇳 简体中文；语言面板是语言无关的，最稳）
# 1) 列表页点右上 🔍（实测 (2284,264) px）→ 输入游戏名
$HC -t $D shell "uitest uiInput click 2284 264"
$HC -t $D shell "uitest uiInput inputText 1200 260 猜球"
# 2) 点「卡片」（判据：文本含游戏名 且 y > 200px 的 Stack 节点；不要点输入框里那个）

$HC -t $D shell "uitest dumpLayout -p /data/local/tmp/hud.json"
$HC -t $D file recv /data/local/tmp/hud.json /tmp/hud.json
# 4) 返回：点左上角 ‹（Text('‹')，y≈100px）—— ⛔ 不要按系统 Back，会退出 app
```
