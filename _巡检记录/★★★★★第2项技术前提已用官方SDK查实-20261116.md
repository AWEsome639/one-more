# 第 ② 项（端侧 LLM）的技术前提 —— **已用官方 SDK 查实**

> `2026-11-16 07:05`。**用 `hms_api` 读本地 SDK 的 `@ohos.ai.mindSporeLite.d.ts`（`SDK API 26`、`Apache-2.0`、本地读取），不是文档转述、不是猜。**

## 一、⇒ 能力清单（全部在 `target API 12` 可用）

| 能力 | 成员 | `@since` |
|---|---|---|
| 从文件/缓冲/fd 加载模型 | `loadModelFromFile` / `loadModelFromBuffer` / `loadModelFromFd` | `10` |
| 模型对象 | `Model`（`get inputs` / `predict` / `resize`）| `10` |
| 量化配置 | `QuantizationType` | `12` |
| 优化级别 | `OptimizationLevel` | `12` |
| 性能模式 | `PerformanceMode` | `12` |
| 调度优先级 | `Priority` | `12` |
| **NPU 卸载（NNRT）** | `NNRTDevice` / `NNRTDeviceDescription` / `getAllNNRTDeviceDescriptions` | `10`/`12` |
| 训练（可选） | `loadTrainModelFromFile` 等 | `12` |
| 张量 | `MSTensor` / `DataType` / `Format` | `10` |

**⇒ 结论：`mindSporeLite` 在 API 12 上**能加载、能推理、能量化、能上 NPU** ⇒ **技术上没有阻塞。**
**⚠️ 关键前提仍是**模型本身**：需要一个「许可证允许商用」的小模型，并用 MindSpore Lite 的转换工具转成 `.ms`（**转换在开发机上做，不在 App 里**）。**

## 二、⇒ 与 `AgentFramework` 的对比（先前结论不变）

| 方案 | 最低 API | 代价 |
|---|---|---|
| `mindSporeLite` | **`10`** | 只需模型 + 转换工具；**不动 targetSdkVersion** |
| `AgentFramework` | `20` | 需 `target 12 → 20`，而全库 `355` 款 + `200,359` 断言都在 API 12 上验过 ⇒ **回归面极大** |

**⇒ 所以选 `mindSporeLite` 是对的；现在只差选模型。**

## 三、⇒ 选模型的三条硬标准

1. **许可证允许商用**（Apache-2.0 / MIT / 明确可商用；**排除** CC-BY-NC、研究-only）
2. **体积与端侧可跑**（量化后建议 `< 600 MB`，`Q4` 量化）
3. **能转 `.ms`**（MindSpore Lite 转换器支持 ONNX/TF/Caffe 输入 ⇒ 优先选有 ONNX 导出的模型）
