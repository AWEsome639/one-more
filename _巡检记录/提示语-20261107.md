**用户看到什么**：点了正确答案，屏幕上闪一下「✅」，还没读完就跳到下一题（380ms 相当于**一个字都看不完**）；
错答的反馈同理——玩家学不到「为什么错」，因为解释句只活了 0.4 秒。

**一句话修法（按优先级）**
1. **纯答题类**（#3~#10、#17~#26 共 18 处）：把 `NEXT_MS/FEED_MS/GAP_MS` 常量抬到 **≥ 900**（一行改常量，最省）。
2. **反应时/实验类**（#1 `GPosnerSpatialCueing`、#8 `GSternbergTask`、#13 `GTemporalOrderJudgment`、#2 `GSpatialConflict`）：
   **别动试次节奏**（会改变实验难度）——把这句反馈改成**常驻结果行**（不在下一题被覆盖的位置），或只在答错时显示解释。
3. **视觉搜索类**（#11/#12 `GVisualSearch*`）：`GAP_MS 550` 只影响「✅ 找到了」那一句，抬到 900 不影响玩法。

## 2. ① 写了立刻被覆盖 —— 0 处真（附排查证据）

- 同字段 **3 行内连续赋值 213 对**，逐对看上下文，**全部是 if/else 或早退分支**（例：`GAlgebraicBalance:258/260` 是 ✓/✗ 两条互斥分支），不存在「同一路径写两次」。
- 同一行两次赋同字段 **7 处**，同上，都是 `if (ok) { … } else { … }`。
- **跨方法 13 处**（赋值后紧跟调用一个会再写 msg 的方法）：其中 **11 处** 是 `advance()/next()/load()` 在 **FEED_MS 之后**才执行（⇒ 归入 ③）；
  剩下 2 处 `GVisualSearch:231 / GVisualSearchConjunction:250`（`✅ 找到了！+N` 后立刻 `endRound(true)`）——`endRound` 只有失败分支才改写 msg，
  真正的覆盖发生在 **GAP_MS=550ms 后的 newRound()** ⇒ 同样是 ③。
- 裸 `TG2(...)` 当语句（你修的那类）：全库再扫 **0 处**（已用「上一行不是逗号/左括号」排除跨行参数后确认）。

## 3. ② 写了但从未渲染 —— 0 处

- 33 个含 `this.tip` 的文件：**26 个**有 `Text(this.tip…)`；另外 7 个里 6 个是 `private tip(): string` **方法**（`GWaterSort` 等，渲染 `Text(this.tip())`），
  1 个 `GChainReaction` 的 `this.tip` 是 **number**（格子高亮索引，渲染在 `backgroundColor` 里）——都不是文案缺渲染。
- `this.msg`：300 个文件全部有渲染点（含三元/拼接形态，如 `Text(this.phase === 0 ? … : this.msg)`、`Text(TG2('{0}…', this.msg))`）。

## 4. ④ 永不清空 —— 0 处；但 **跨局残留 1 处**

- 只有 2 个文件 msg 只写「反馈/错误」、从不写「提示语」：`GGrammarPolice`、`GWordSurge` —— 但两者写完都紧接着 `finish()`，结算接管，不会残留。
- **跨局残留（真）**：`GWordLadderStep.ets` —— `reset()` → `buildRound()` 都不写 msg；
  「再来一局」后，上一局的 `❌ 生命耗尽，撑到第 N 题`（:281）/**`🎉 N 题全过，通关！`**（:284）会**停在新一局开头**，直到玩家点第一个选项。
  **修法**：`buildRound()` 末尾加 `this.msg = TG('选出只差一个字母的词');`（或 `reset()` 里 `this.msg = ''`）。
- 另两个候选已排除：`GMandelbrot`（msg 是方法）、`GReadingSpan`（`newSet()→showSentence()` 里有 `this.msg = '第 N/M 句…'`）。

## 5. 附加：29 处「结算盖住总结句」（低危，不改也行）

`this.msg = …; this.finish(…)` 同行 29 处，例如 `GWordMastermind:242`、`GSumPyramid:248/255`、`GWordSearch:106/324`。
**用户不损失信息**：结算弹窗本身显示成败、分数、按钮；msg 只是同义重复（也正因如此，这类不影响体验）。
唯一略可惜的是 `GFibonacciMerge:262`——它写的是**规则解释**（「只能合相邻两格、且和要是斐波那契数」），被弹窗盖住。

## 6. 局限（静态扫描，截图为准）

- 只按源码判「显示多久」；有 `@Builder` 间接渲染、`HintBar` 之类公共组件的文件，渲染点可能被算到别的函数里（本报告里已人工复核 9 个疑似 0 渲染的文件，全部为误报）。
- **反应时类**的短间隔可能是**实验设计**（避免被试预测），修法 2 特意分开写，不敢一刀切。
- 判定「用户读得完」用 800ms 阈值（lead 口径）；实际可读时间还要看字号/屏宽，建议改完真机截一帧。
- 未覆盖：`tip`/`msg` 被**布局遮挡**（如被棋盘盖住）——这需要真机截图，静态扫不出来。
