# ★★★ bash 坑：`$var` 后紧跟**中文标点**会报 `unbound variable`

> `2026-11-14 21:x`。写 `apply_fixes.sh` 时连踩两次。

## 一、⇒ 现象

```bash
desc='①Magnets 盘面 -375'
echo "❌ $desc：第 21 行找不到"
# ⇒ 工具/apply_fixes.sh: line 21: desc：: unbound variable
```

**⇒ 报错信息里的变量名是 **`desc：`** —— 连全角冒号一起被当成变量名了。**

**⇒ 同理：**
```bash
ok=4; bad=0
echo "==== 成功 $ok、失败 $bad ===="
# ⇒ ok、: unbound variable      ← 全角顿号 `、` 也被吃掉
```

## 二、⇒ 原因

**bash 的变量名解析在遇到「非 `[A-Za-z0-9_]`」时才停。
⇒ 而 **UTF-8 多字节字符**（`：`是 `U+FF1A`、`、`是 `U+3001`）的首字节 `0xEF`/`0xE3` 高位为 `1`，
⇒ bash 在某些 locale 下不把它当「非名字字符」⇒ 继续吞进变量名 ⇒ 找不到该变量 ⇒ `unbound variable`（`set -u` 下直接退出）。**

## 三、⇒ 修法

**`$var` 后紧跟中文标点时，一律写 `${var}`：**
```bash
echo "❌ ${desc}：第 21 行找不到"
echo "==== 成功 ${ok}、失败 ${bad} ===="
```

**⇒ 我的修法是正则批量替换：`\$([A-Za-z_]\w*)(?=[^\x00-\x7f])` → `${$1}`**
**⇒ 即「`$` + 变量名 + 紧跟非 ASCII」全部加花括号。**

## 四、⇒ 所以规矩

| 写法 | 安全? |
|---|---|
| `"$desc 文字"`（半角空格分隔）| ✅ 安全 |
| `"$desc，中文"`（全角逗号紧跟）| ❌ **可能炸** |
| `"${desc}，中文"` | ✅ **永远安全** |

**⇒ ⇒ 结论：**只要 `$var` 后面不是 ASCII，就加花括号。** 这是一个一秒钟的预防、一次调试的代价。**

## ⇒ 判据（`2434`）

**脚本里凡「`$var` 紧跟中文」的地方，一律 `${var}`。**
**⇒ 不为此写注释、不为此记特例 —— 统一加花括号就没有这个问题。**

**⇒ 判据：写含中文输出的 shell 脚本时，**默认给所有变量加花括号**；省下的是排查 `unbound variable` 的时间。**

## ⇒ 判据（`2435`）

**而我这次是**同一个坑连踩两次**（先 `$desc：`、再 `$ok、`）—— 因为第一次只修了那一处、没意识到是「全角标点」这个类别。**

**⇒ 判据：修一个 bug 时，先问「这是**一个实例**还是**一类问题**」；同类就一次改完。**
