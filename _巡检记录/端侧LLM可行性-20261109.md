# 端侧 LLM 可行性分析（2026-11-09 00:4x）

> **只读分析**，未改任何 `.ets`。
> 依据：**官方本地文档**（`devecocli docs`，非网络搜索）+ **真机 `hdc` 实测** + 源码函数体。

---

## 结论（先说）

| 问题 | 答案 |
|---|---|
| 这条路能不能走？ | **技术上能走，但不能当主路径** |
| 模拟器为什么 `init=false` | **不是 API 不可用 —— 是「模型没就位」**（证据见 §2）|
| 真机需要什么 | HarmonyOS **6.0.0(20)+ 真机** + **系统「模型管理应用」里有模型** |
| 覆盖率天花板 | **只覆盖 API 20+ 且模型已下载的华为设备**；本应用 `compatibleSdkVersion` 是 **API 12** ⇒ **12~19 的设备永远没有** |
| 该不该为它改产品设计 | **不该**。现在的「规则保底 + LLM 锦上添花」就是正确形态 |

## ① SDK 约束（官方文档原文，不是猜）

**文档**：`API参考/Data_Augmentation_Kit_数据增强服务/ArkTS_API/localChatModel_端侧问答模型`

| 项 | 值 |
|---|---|
| **起始版本** | **6.0.0(20)** |
| **系统能力** | `SystemCapability.DataAugmentation.LocalChatModel` |
| **模型约束** | **仅可在 Stage 模型下使用** |
| 导入 | `import { localChatModel } from '@kit.DataAugmentationKit';` |
| 暴露的能力 | **只有 `init()` 和 `chat()`** —— ⚠️ 见下 |

**参数约束**：

- `questionId` ∈ **[0, 65535]**，同一应用运行期必须唯一
- `content` **建议 ≤ 4500 字节**（超了部分设备性能下降甚至模型异常）

**错误码**（`chat` 侧）：

| 码 | 含义 |
|---|---|
| 1021900001 | 调用超时 |
| **1021900002** | **模型加载失败**（未初始化 / 未就绪）|
| 1021900003 | 请求失败 |
| 1021900004 | 模型忙 |
| 1021900005 | 参数不符合约束 |

**⇒ 关键缺口：这个 Kit 只暴露 `init` / `chat`，没有任何「查询模型状态 / 触发下载 / 监听就绪」的 API。**
**⇒ 应用侧无法驱动模型获取，只能被动等系统就绪。**

## ② 模拟器为什么 `init=false`：**是「模型没就位」，不是「API 不可用」**

### 证据链（全部真机实测）

| # | 检查 | 结果 | 说明 |
|---|---|---|---|
| 1 | 设备 syscap 里有没有这个能力 | **有** ✅ | `cat /system/etc/syscap.json` 里明确列了 `SystemCapability.DataAugmentation.LocalChatModel` |
| 2 | 应用侧 `canIUse()` 结果 | 通过 | 否则 `reason` 会是 **`no-syscap`**，而不是 `init-false` |
| 3 | 设备 API 版本 | **26** | 远高于要求的 20 |
| 4 | `init()` 返回值 | **false**，耗时 **1131ms** | 走了 IPC、等了 1.1s、系统回了「模型不可用」|
| 5 | 文档对 `init()` 的描述 | **「初始化端侧问答模型，负责拉起模型管理应用」** | 它要拉起系统的模型管理应用 |

**⇒ 结论：API 在、能力声明在、Stage 模型也对，唯独「模型本体」没有。**
**1131ms 这个耗时本身就说明它真的去试了**（不是瞬间 false，也不是抛异常）。

**⇒ 模拟器上没有真机那套「模型管理应用 + 端侧模型」，所以必然 false。**
这也意味着：**端侧 LLM 在模拟器上永远测不了**，只能真机验。

## ③ 真机前置条件

| 条件 | 说明 | 我们能控制吗 |
|---|---|---|
| **HarmonyOS 6.0.0(20)+** | 低于此版本 syscap 不存在 | ❌ |
| **真机（非模拟器）** | 模型管理应用是系统组件 | ❌ |
| **系统模型管理应用里已下载并启用模型** | `init()` 会拉起它 | ❌（**Kit 没有查询/下载 API**）|
| Stage 模型 | 本应用已是 | ✅ |
| 问题 ≤4500 字节 | 我们的 prompt 很短 ✓ | ✅ |

**⇒ 四个条件里三个我们控制不了。**
**⇒ 这不是「修 bug 能解决」的问题，是「依赖系统能力就绪」。**

## ④ 降级方案评估

### 方案 A：规则版（**已经实现了**）

`ChatFinder.parseWithLLM()` 的实际函数体（我逐行看过）：

```ts
static async parseWithLLM(text: string): Promise<Intent> {
  const base: Intent = ChatFinder.parse(text);   // ← 规则版先算好
  try {
    const ready: boolean = await LocalLLM.init();
    if (!ready) { return base; }                  // ← LLM 不ready，直接用规则版
    const ok: boolean = await LocalLLM.chat(...);
    if (!ok) { return base; }                     // ← 问答失败，回规则版
    return ChatFinder.mergeLLM(base, acc);        // ← 合并前还要校验 JSON
  } catch (e) {
    return base;                                  // ← 连抛了也回规则版
  }
}
```

**⇒ 四层兜底，任何一层失败都回规则版。这个设计是对的，不需要改。**

**而且规则版本身已经很能打**：今天把它从 **6.5% → 88%**（v4 验证），
`playStyle` + 别名 + 二级排序全部落地。

### 方案 B：云端 API —— **❌ 与已发布隐私政策冲突**

隐私政策原文（`core/I18n.ets`，10 语言都有）：

> **「需联网的只有两项：局域网对战、华为游戏服务的账号校验。」**

**加云端 LLM 就变成三项** ⇒ 必须改隐私政策 → 重新做 10 语言 → 商店重新审核。

而且这与产品的核心卖点直接冲突：
- 首页文案「**355 款小游戏，不用联网也能玩**」
- 隐私政策「本应用不收集、不存储、**不传输**…」

**⇒ 云端方案不是技术问题，是产品定位问题。不建议。**

### 方案 C：自带模型（打包 GGUF / 转 MindSpore Lite）

| 项 | 量级 |
|---|---|
| 一个可用的小模型（Qwen2.5-0.5B-int4 级）| **~300-400 MB** |
| 当前 HAP 体积 | **~46 MB** |
| **涨幅** | **≈ +7 倍** |

**⇒ 与「355 款小游戏合集」的定位严重冲突。不建议。**

## ⑤ 结论：这条路「能走，但只能是锦上添花」

### 判断

| 维度 | 判断 |
|---|---|
| **技术上可行** | ✅ 代码写对了，官方 API 就是这么用 |
| **能不能依赖它** | ❌ **不能** —— 覆盖率由「系统版本 + 模型是否下载」决定，我们控制不了 |
| **现在该做什么** | **什么都不用改** —— 现有四层兜底已经是最优形态 |
| **模拟器上能不能验** | ❌ **永远不能**（没有模型管理应用），只能真机 |
| **要不要为它改设计** | ❌ **不要**。规则版已到 88%，投入产出比更高 |

### 一句话

**端侧 LLM 是「系统给就有了」的红利，不是「我们做了就有」的功能。**
**把它当保底之上的增强是对的；把它当主路径会翻车。**

---

## ⑥ 如果还要继续推，建议的最小动作

1. **真机验一次**（唯一有意义的一步）：
   - 找一台 **HarmonyOS 6+ 的华为真机**，在系统「模型管理/小艺」里确认模型已下载
   - 装本应用 → 打开聊天找游戏 → 看 `LocalLLM.stat.reason`
   - **期望**：`reason='ok'`、`firstTokenMs > 0`
   - **若仍 false**：说明模型管理应用没被拉起，这条路在消费级设备上基本封死

2. **诊断面板**：`LlmStat` 已经有 `reason/initMs/firstTokenMs/totalMs/calls` 五个字段，
   建议在设置页的「诊断」里显示出来（**用户报问题时能一句话定位**）

3. **不要投入**：云端 API、自带模型 —— 前者违反隐私政策，后者体积涨 7 倍
