# 模拟器**不遵守 `portrait`** ⇒ 台账里的横屏配置，真机不会出现

> `2026-11-19 01:12`。实测：转了方向，帧缓冲还是横屏。

## 一、⇒ 实测

```bash
Emulator -instance onemore7 -rotation left      # 报 "Scenario simulation success"
hdc shell snapshot_display -f /data/local/tmp/x.jpeg
#  → width: 2560, height: 1600      ← 仍是横屏！
```

**⇒ ⇒ 旋转命令「报成功」但**帧缓冲没变**。截图实测 `2560×1600`，横向。**
**⇒ 已转回（`-rotation right`），跑批继续（`[retry 2/5] Find Word OK`）。**

## 二、⇒ 这条意味着什么

**⇒ App 的 `module.json5` 写 `"orientation": "portrait"`（`EntryAbility` 级），没有任何运行时代码覆盖它（全项目搜 `setPreferredOrientation` 为空）。**
**⇒ ⇒ 所以：**真机上 App 应该是竖屏**（`533×853`），而**模拟器里它跑在横屏**（`853×533`）。**

**⇒ ⇒ ⇒ 今晚全部台账数据（`layout-canonical.tsv`）都来自横屏，而**真机不会出这个配置**。**
**⇒ ⇒ 这不是「数据有点旧」，是「数据描述的配置在用户那里不存在」。**

## 三、⇒ 但别急着把台账全废掉

**⇒ `blk`（溢出块数/像素）**在横屏下抓到的溢出是**真实存在**的（内容确实压到了 `y2 > 1576`）——只是真机竖屏下这些溢出可能不出现。**
**⇒ 所以：**台账可用于「找出哪些款在紧凑布局下会溢出」，不能用于「判断用户看到的尺寸」。**
**⇒ ⇒ 「棋盘只占 `16%`」这类结论**必须**等真机竖屏截图，不能拿横屏台账说话。**
