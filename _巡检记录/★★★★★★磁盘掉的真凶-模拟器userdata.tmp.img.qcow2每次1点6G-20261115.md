# 磁盘掉的**真凶**：模拟器的 `userdata.tmp.img.qcow2`（每次 `1.6G`，不自动清理）

> `2026-11-15 21:27`。**今天磁盘从 `20.1` 一路掉到 `13.9 GiB`（低于 `15` 闸门），查出来的原因不是我的代码。**

## 一、⇒ 现象

| 时刻 | 磁盘 |
|---|---:|
| 早上 | `20.1 GiB` |
| `20:49` | `17.0 GiB` |
| `21:26` | **`13.9 GiB`（低于闸门 `15`！）** |

**⇒ 期间我没做大文件操作（编译产物 `entry/build` 只有 `0.3G`、截图几百 MB）。**

## 二、⇒ 真凶

**`~/.Huawei/Emulator/deployed/onemore7/` 下同时存在：**

```
1.8G  userdata.img.qcow2       ← 活的磁盘镜像
1.6G  userdata.tmp.img.qcow2   ← **临时文件，不会被自动清理**
```

**⇒ 每轮「启动 → 运行 → 停止」都会留下一个 `1.6G` 的 `.tmp`** ⇒ 我今天启停了十几次 ⇒
   **磁盘就被这一堆临时文件吃掉了。**

## 三、⇒ 处置

**⇒ `rm -f .../userdata.tmp.img.qcow2`（临时文件、非活镜像）⇒ `13.9 → 17.6 GiB`。**

**⚠️ 我**没有**动 `userdata.img.qcow2`（活镜像，删了会清空模拟器数据、输入法引导要重点）。**

## 四、⇒ 对今晚的影响（重要）

**⇒ 今晚跑批会启停模拟器约 `16` 次（`126` 款 ÷ 每 `8` 款重启一次）⇒ 会反复产生 `.tmp`。
   ⇒ **虽然同时只存在一个（旧的被覆盖），但 `1.6G` 的净占用会一直在。**
   ⇒ 当前 `17.6 GiB` ⇒ 扣 `1.6` 得 `16.0` ⇒ **仍高于闸门 `15`**，但如果日志与其它临时文件再涨，就会破线。**

**⇒ 建议：把这条加进 `run_tonight.sh` 的预检（开跑前先 `rm -f` 一次）：
```bash
rm -f ~/.Huawei/Emulator/deployed/onemore7/userdata.tmp.img.qcow2 2>/dev/null
```
**⚠️ 但今晚我不改那个脚本**（跑批前改脚本 = 引入新风险；`2767` 的教训）。**明早确认今晚跑通后再加。****
